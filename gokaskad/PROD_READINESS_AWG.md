Ветка `test` (коммит `8f16cb1`). **На main НЕ мержить до твоей команды.** Бесшовное

## Что сделано
- **Единый пул**: «Прокси для API Telegram» принимает VLESS, подписки и AmneziaWG
  (`vpn://` и `.conf`, v1.5 и v2.0) в один пул; AWG-ключи стоят рядом с VLESS в панели.
- **Парсер v5**: авто-определение формата; хранение `awg://<base64>`; режимы
  extract/list/config/awglist/awgconf.
- **AWG как xray-outbound**: `amneziawg-go` интерфейс `kawg<i>` + `freedom`-outbound с
  `sockopt.mark=256+i` + `ip rule fwmark`/таблица → балансир/observatory/ручной-авто
  выбор/фейловер работают одинаково для VLESS и AWG. Один ключ → прямой маршрут.
- **Импорт**: многострочная вставка (.conf), мини-инструкция в меню с форматами.
- **Дашборд**: AWG-ключи с ★, пинг до endpoint (ICMP), тип `amnezia-x.y/udp`.
- **Бинарники**: `amneziawg-go` (amd64+arm64) и `awg` (amd64) в `bin/`; качаются по
  GitHub-токену (как self_update); boot-persist через ExecStartPre/ExecStopPost.

## Известные ограничения (не блокеры, ~2% до 100%)
- Идентичность AWG-интерфейсов позиционная (по номеру ключа): при удалении ключа индексы
  сдвигаются; sync на рестарте сам приводит в порядок, но churn. (BUG6 — низкий риск.)
- «Потери трафика» для активного AWG-ключа = «—» (ретрансмиты TCP меряются для VLESS;
  для UDP-туннеля метрика не применяется). Пинг до узла показывается.
- Ручной пин сбрасывается в авто при добавлении/удалении ключа (BUG8).
- `awg`-tool только amd64 (arm64-сервера: AWG недоступен, VLESS работает).
