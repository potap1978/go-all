# Архитектура: единый egress-пул VLESS + AmneziaWG

Цель: «Прокси для API Telegram» принимает в **один пул** ключи VLESS и AmneziaWG
(форматы: `vless://`, подписка, AWG `vpn://`, AWG `.conf`; линии 1.0, 1.5, 2.0 и 3.1), показывает
их в одной панели с одинаковым функционалом (пинг, ★, авто/ручной выбор, фейловер,
потери), и бот по-прежнему ходит в **один** `BOT_PROXY=socks5h://127.0.0.1:10808`.

## Ключевая идея
xray остаётся единственной точкой входа (SOCKS5 :10808). Каждый ключ пула — это
xray **outbound**:
- **VLESS** → обычный `vless` outbound (как сейчас).
- **AWG** → поднимаем интерфейс `amneziawg-go` (`kawg<i>`) и делаем xray `freedom`
  outbound с `sockopt.mark=<Mi>`; пакеты с этой меткой через `ip rule fwmark` уходят
  в таблицу маршрутов, где `default dev kawg<i>` → в туннель.

Балансировщик/observatory/leastPing работают одинаково для смешанных outbound'ов →
фейловер VLESS↔AWG, ручной/авто выбор, ★ — «из коробки». Один ключ → прямой маршрут
без балансира (как у VLESS сейчас).

```
бот → BOT_PROXY socks5h://127.0.0.1:10808
        │
     xray (SOCKS) ──balancer/observatory──┬─ out_1 vless  → нода VLESS
                                          ├─ out_2 freedom(mark 0x102) → kawg2 → AWG-сервер
                                          └─ out_N …
```

## Хранение (единый пул)
`/etc/kaskad/egress/upstream.txt`, одна строка на ключ:
- `vless://…` — как есть.
- `awg://<base64 нормализованного .conf>` — AWG (многострочный конфиг кодируется в одну строку).
Импорт `vpn://`/`.conf`/подписки → нормализуются и кладутся в этот файл.

## Парсер (встроенный python)
- `extract`: `vless://` пропускает; `vpn://`/`[Interface]` → `awg://b64`; подписка base64 → разворачивает.
- `list`: смешанные строки — `name<TAB>endpoint<TAB>type<TAB>net` (`reality/tcp` или `amnezia-3.1/udp`).
- `awginfo`: по ключу AWG `номер<TAB>линия<TAB>ok|lost3x` — нужно ли ядро 3.x и какой ключ 3.x потерял поля (сохранён парсером ≤ 2.12).
- `config`: генерит xray-конфиг — `vless` outbound'ы + `freedom`+`mark` outbound'ы для AWG;
  балансир при ≥2 ключах, прямой маршрут при 1.
- `awgconf <line>`: из `awg://b64` отдаёт stripped `.conf` (для `awg setconf`) + адрес.

## Интерфейсы AWG (bash)
- `egress_ensure_awg` — скачивает `amneziawg-go` + `awg` (релиз-ассеты репозитория, по arch).
- `egress_awg_sync` — для каждого AWG-ключа поднимает `kawg<i>` (amneziawg-go + awg setconf +
  ip addr + fwmark-таблица `default dev kawg<i>`); снимает интерфейсы/правила, которых нет в пуле.
- Метки/таблицы: mark `0x100+i`, table `100+i`, интерфейс `kawg<i>`.
- Подлежащий UDP к AWG-серверу идёт по основному маршруту (не маркируется) → петли нет.

## egress_rebuild (смешанный)
1. парсинг пула → типы; 2. `egress_awg_sync` (поднять/снять AWG-интерфейсы);
3. xray-конфиг (mixed); 4. `xray -test`; 5. старт службы; 6. `BOT_PROXY`; 7. рестарт бота.

## Дашборд
- строка ключа: `★ N) <name> <endpoint> <reality/tcp|awg-2.0/udp> <ping> ms`.
- пинг AWG = до endpoint (UDP) / свежесть handshake; пинг VLESS = как сейчас.
- потери: VLESS = TCP-ретрансмиты до ноды; AWG = ретрансмиты TCP к Telegram внутри туннеля
  (та же метрика, другая точка). active/manual/auto — через `xray api bo` (балансир).

## Дистрибуция бинарей
`bin/` репозитория: `amneziawg-go` (у апстрима нет готовых сборок — собран из тега v3.1.20260828,
amd64+arm64) и `awg` (amneziawg-tools 3.1.20260812, amd64+arm64); происхождение и sha256 — `bin/VERSIONS.txt`.
`egress_ensure_awg` берёт пару по arch: сначала диск (`bin/` клона), потом сеть с ключом GitHub.
`egress_ensure_awg 3` (в пуле ключ 3.1) требует ядро, понимающее 3.1 (`egress_awg_is3x`: строки
`disable_cookies`/`DisableCookies` в бинарниках — версия amneziawg-go для этого бесполезна, а ядро 3.0 ключ 3.1
не примет). Кандидат собирается и проверяется в `awg/.stage` и встаёт на место переименованием; работающее
ядро до этого не трогается (Ctrl-C, обрыв SSH, перезапуск службы ничего не ломают). Нет ядра 3.1 — остаётся
прежнее: ключи 1.x/2.0 работают, меню предупреждает и пробует снова (диск — каждый вход, сеть — раз в час).

## Fail-closed
`egress_awg_sync` ставит правило `fwmark → table` и запасной `unreachable default metric 1000` для каждой ноги
ДО проверки ядра: умершая нога или нога без ядра закрыта, помеченный трафик не уходит в main-таблицу напрямую.

## Импорт (UX)
- многострочная вставка (AWG `.conf` многострочный): «вставьте, завершите строкой `.` или Ctrl-D».
- авто-определение формата; мини-инструкция в меню: какие форматы поддерживаются и как вставлять.

## Безопасность/совместимость
- VLESS-путь не трогаем (обратная совместимость). Бесшовное обновление 2.3→2.x сохраняется.
- AWG-ключи — креды (приватные ключи), только на сервере, не в репозитории.
- Один ключ AWG → прямой маршрут; ≥2 → балансир. Само-хилинг конфигов.
