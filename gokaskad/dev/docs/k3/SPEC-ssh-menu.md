## 3. Шапка

### Откуда данные

Один вызов: `kaskadctl summary --json` (lib/kaskad/summary.py). Только файлы, ни одной команды и ни одного
сетевого запроса:

- `state.json` — движок, пробросы, шлюз, входы, люди, устройства, маршрут по умолчанию, домен;
- `/run/kaskad/live.json` сборщика (не старше 30 с) — работают ли входы, кто в сети, проблемы раунда
  (`gateway.issues` — те же строки, что `gateway.problems`, с видами);
- `/run/kaskad/watch.json` — последний отчёт минутного сторожа (`net check --repair`): что он нашёл и **не смог**
  исправить; старше 3 минут — не в счёт;
- пул выходов и снимок их здоровья (`gw.ops.exits_view` — разбор ключей в процессе, без команд);
- движок AmneziaWG (`gw.awgengine.status` — файлы);
- `/etc/kaskad/panel/config.json` — адрес панели (путь на домене — только маской `conf.mask_path`);
- копия сертификата домена `/etc/kaskad/site/tls/current` (свой разбор DER, без openssl);
- `/etc/kaskad/update.json` — что нашла последняя проверка обновления (пишут меню 11 и `kaskadctl update check`).

Снимок живёт в меню 5 секунд (`K3_HEAD_TTL`): Enter и неверный номер перерисовывают без нового вызова; после
любого пункта снимок берётся заново. Шапка сама обновляется раз в 30 секунд, пока меню ждёт ввода (как в goAmnezia:
первый знак читается отдельно — набранная цифра не пропадает). Вызов `kaskadctl` — около 0,1 с.

Кроме снимка bash спрашивает только `systemctl is-active kaskad-panel` (панель стоит) и, на старом движке,
`iptables -S` для числа пробросов.

### «Что не так»: правила ядра, не свои

Проблемы — ровно те, что видят ядро, панель и `gw check`:

1. сборщик (`live.json`, раунд раз в 10 с): вход не работает, DNS или xray шлюза не работают, ошибка сборщика;
2. сторож (`netcheck.check` + `gw.ops.check`): таблица пробросов, маршрутизация шлюза, ip6, правило
   совместимости, ip_forward, подменённая команда gokaskad… — только то, что он не исправил;
3. «нет интернета у устройств» — `gw.ops.no_exits_problem`, то же правило, что красная строка меню 17 и
   `gateway_check`; при пустом пуле и молчащем сборщике — предупреждение панели `exits.offline_empty`;
4. прерванная установка шлюза (отметка мастера);
5. сертификат домена истёк или Let's Encrypt не продлился (меньше 21 дня);

и то, что видит bash: веб-панель стоит, но не работает; ядро не отвечает.

Одинаковые строки сборщика и сторожа сливаются в одну. К каждой проблеме ядро добавляет номер пункта и совет
(`summary.ADVICE`): шлюз — 17 (обычно «17 → 5 «Состояние»»), пробросы — 16, сертификат — 19, подменённая
команда — 11, панель — 18.

В шапке — первая проблема и её совет одной строкой с «· ещё N — 21»; без проблем — «✓ Неполадок не видно».

### Строки и что из них убирается

| Строка | Когда | Важность |
|--------|-------|----------|
| заголовок, `IP: … · пробросов: N (движок) · ветка … · есть X.Y.Z: 11` | всегда («ветка» — если записана и влезает; «есть …» — если в кэше версия новее) | 0 |
| `Домен: имя · сайт · сертификат до ДД.ММ` (жёлтый < 21 дня, красный — истёк) | домен задан | 1 |
| `Панель: https://домен/app-AbCd••••WxYz/ F1 или «п» — показать` / адрес открытого режима / `✗ не работает — 18` | панель установлена | 1 |
| `Панель: работает, вход через SSH-туннель — 18` | панель только через туннель | 2 |
| `Шлюз: ● WireGuard  ● AWG 3.1  ✗ L2TP  ○ SSTP · устройств: 12, в сети 5` | шлюз включён | 1 |
| `Шлюз: ○ выключен · входов: 3 · устройств: 12 — включить: 17 → 6` | шлюз выключен | 1 |
| `Шлюз: не настроен — телефоны и роутеры через этот сервер: 17` | шлюза нет | 2 |
| легенда значков (только встреченные) | есть вход не «●» | 2 |
| `Выходы: живы 3 из 5 · AmneziaWG: модуль ядра` / `нет — устройства без интернета — 17 → 3` | шлюз включён | 1 |
| `Адрес для устройств: …` | адрес в настройках устройств — не IP сервера | 2 |
| `✗ <проблема>` и совет | есть проблемы | 1 |
| `✓ Работает нормально · подробная проверка — 21` | проблем нет, свет здоровья сервера `ok`, шлюз не выключен | 2 |
| `○ Работает, проверки здоровья выключены · …` / `? Ждём данных сервера · …` | проблем нет, свет `off` / `wait`, шлюз не выключен | 2 |
| `✓ Неполадок не видно · подробная проверка — 21` | проблем нет, свет никто не судил (нет `summary.host`) или шлюз выключен (это уже сказано строкой «Шлюз») | 2 |
| `! Здоровье сервера: есть предупреждения — 22` (`✗ … требует внимания — 22`) | проблем нет, свет здоровья сервера (пункт 22, `summary.host.level`) — `warn` (`crit`); тогда строки «✓» нет (К2-3, T-KT2) | 1 |

Слова уровней — те же, что в панели (владелец 28.10 «статусы одними словами везде»): `warn`/`crit` — «Здоровья
сервера» (`ovb.hh.*`), строка без проблем — вердикта Сводки (`ovb.v.*`); равенство держит `tests/test_state_words.py`.

Входы не влезают в строку — работающие числом, остальные по именам («● работают 9  ✗ L2TP  ? SOCKS5»); и так не
влезают — числа по значкам («входов 11: ● 3  ✗ 4  ○ 4  ? 3»). Значки: ● работает, ✗ не работает, ○ выключен,
? нет свежих данных (сборщик молчит — неизвестно, а не «мёртв»).

Высота: шапка получает 24 − 11 (пункты) − 2 (черта и «Выбор:») = 11 строк. Не влезает — убираются строки
важности 2, с конца, потом 1. Строка шире окна считается за столько строк экрана, сколько займёт.

Правой рамки нет: коды цвета не занимают места, и закрывающий столбец разъезжался бы (так решила и goAmnezia).

### Адрес панели на домене

В шапке — только маска (`app-AbCd••••WxYz`): шапка на каждом экране и уходит с любым скриншотом. F1 (у терминалов,
которые забирают F1, — «п» или «p») показывает адрес целиком прямо в шапке на 5 минут с жёлтой строкой «Адрес —
секрет, как пароль: не показывайте экран. Скрою через N мин.». Адрес даёт ядро (`kaskadctl site panel-url --show`),
в журнал он не пишется. Панели на домене нет — «Панели на домене нет — показывать нечего (сайт и панель: 19)».

### Без цвета

`NO_COLOR` (no-color.org) — цветов нет во всей программе. Состояние в шапке не держится на одном цвете: значки
● ✗ ○ ? и слова («не работает», «живы 3 из 5»).
