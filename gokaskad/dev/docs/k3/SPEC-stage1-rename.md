## 2. Правило имени — общий модуль `lib/kaskad/names.py`

Контракт — по коду N1 (`dev-s1-w0`, `5008ab7`; ТЗ сведено с кодом — «Сведение с кодом R1/N1 и проверка 20»):

```python
MAX = 40
WHAT = ("name", "user", "device", "exit", "inbound", "sub", "forward", "server", "group", "level")
def check(value, what="name", lang=None) -> str   # чистое имя или KaskadError(code=USAGE): текст RU/EN («Имя группы: …»),
                                                  # data {"reason": empty|long|char|unassigned|private|invisible|type,
                                                  #       "what", "max", ...}
def same(a, b) -> bool                            # равны для дублей: NFKC + casefold + без знаков нулевой ширины +
                                                  # заполнители и пробелы → один пробел
def duplicates(items, name, self_id=None) -> [id] # id из items (словари {"id","name"} или пары (id, name)) с тем же
                                                  # именем, кроме self_id; элемент без имени (None) — не дубль
```
Тексты — `i18n/catalog/{ru,en}/names.json` (`names.err.*`, `names.what.*`).

**Проверка `check` при переименовании и при создании новых имён — отказ, а не тихая замена:**
- нормализация NFC; по краям — `strip()`; внутренние пробелы схлопываются; не строка — отказ `type`;
- длина 1–40 знаков (`len` по кодовым точкам) — **решено**: лимит 40 записан в плане H (D-017);
- запрещены **в любом месте значения, до обрезки краёв** (`\n` в конце — отказ, а не обрезка); текст отказа называет
  знак как U+XXXX и сам знак не печатает:
  - категории Unicode `Cc` (в том числе `\x00-\x1f`, `\x7f`, `\x80-\x9f`), `Zl`, `Zp` и одиночные суррогаты `Cs` —
    отказ `char`;
  - неназначенные знаки `Cn` (нет в Юникоде этой системы: U+2065, U+FFFF) — отказ `unassigned` (D-090), **кроме блоков
    эмодзи** U+1F000–U+1F0FF и U+1F300–U+1FAFF: там неизвестный знак — новое эмодзи, оно проходит (D-096), и одно и то же имя
    проходит или нет на любом Python узла; знаки частного использования `Co` (U+E000–U+F8FF, плоскости 15–16) — отказ
    `private`;
  - **все `Cf`** (управление направлением U+200E, U+200F, U+202A–U+202E, U+2066–U+2069, U+061C и невидимые U+200B,
    U+2060–U+2064, U+FEFF, U+00AD …), **кроме** U+200C и U+200D (ZWNJ, ZWJ: без ZWJ не пройдут эмодзи-семьи и
    профессии, без ZWNJ — часть письменностей; подделку вида они не дают) и **знаков-тегов U+E0020–U+E007F только
    внутри флага** (U+1F3F4, теги, U+E007F — флаги Англии, Шотландии, Уэльса); тег вне такой последовательности —
    отказ (`char`);
  - `|` — разделитель aliases и `state.clean_name`;
- **имя без единого видимого знака** (только заполнители U+3164, U+2800, U+115F, селекторы вариантов, комбинирующие
  знаки) — отказ `invisible`;
- **сравнение для дублей** (`same`) (D-082, D-090) выбрасывает знаки нулевой ширины (`Cf`, в том числе ZWJ/ZWNJ и теги, селекторы
  вариантов, U+034F, монгольские селекторы), а заполнители U+3164, U+FFA0, U+2800, U+115F, U+1160 и пробелы любого вида
  (`Zs`) считает обычным пробелом и схлопывает повторы: «Вена» и «Вена» + ZWJ — одно имя, «Вена⠀Вена» = «Вена Вена» ≠
  «ВенаВена»;
- ведущий `-` разрешён в имени. CLI принимает его через `--name=…` или после `--` (§4.2). MCP не пропустит такое
  имя позиционной ссылкой (`mcp/server.py:531`): к сущности с таким именем агент обращается по id — правило в
  `AGENT_GUIDE` (§4.3).

**Где проверка действует при создании** (задача N2, ядро; поверхности — N4, N5):
- люди и устройства — `model.add_user` (`model.py:300`), `model.add_device` (`:410`); через них идут `gw/ops.py`
  `user_add` (`:996`), `device_add` (`:1088`), бот (`bot/gateway.py:745` `cb_add_user` и выдача устройства), мастер

  (`install.sh:4275`, `bot/aliases.py`); подпись выхода — `exit_set`;
- лимиты поверхностей приводятся к 40: панель — поля людей, устройств и пробросов `max: 60` (`app.js:3161`, `:3843`,
  `:3919`), API (`api.py:146-157,844,875,999`); MCP — типы `person_name`, `device_name` (64);

**Связь с SPEC-exits.** Имя уровня политики выходов проверяет `policy.validate` (T2): пустое — имя по умолчанию
(«Уровень N», SE §3.1 «Имена по умолчанию»), непустое — `names.check(…, what="level")`. Имя группы — `names.check(…,

`names.check`, а не свою проверку (до слияния N1 — заглушка с тем же контрактом, §6.0).

**Старые имена длиннее 40** (созданы до этапа 1, лимит был 64) читаются и показываются как есть. При переименовании новое
имя должно уложиться в 40. Тихо их не режем.

**HTML-безопасность — на выводе, не в хранении.** `<`, `>`, `&`, `"`, `'`, `\` в имени допустимы:

- `/p/` — `html.escape(…, quote=True)`;
- бот — `telegram.h()` на каждом пути;
- SSH-меню — вывод имён через `printf '%s'`, без `echo -e`;
- заголовки: `profile-title` — base64 (как сейчас); имя файла — транслит и `FILE_NAME_RE`;

**Подпись входа — только для показа**: панель, схема, SSH-меню, бот, `/p/` (карточка входа). Строка собирается одной
функцией `gw/rename.inbound_shown(st, kind, lang)`. Подпись **не попадает** в выдаваемое: `issue_os.TITLES`,
`issue_os.app_label`, `conf_filename`, фрагмент `vless://#…` (`vless.py:781`), описание `vpn://` (`awg.py:498`),
`# Kaskad · … · OpenVPN` (`openvpn.py:607`), тексты ошибок. Иначе выдаваемое менялось бы без `apply` и расходилось бы с
уже выданным. Тест-страж: смена `label` не меняет ни одной выдачи (§7).

### 3.2. Операции — лёгкий путь без `apply`

`lib/kaskad/gw/rename.py` — переименования шлюза; пробросы и серверы — в своих модулях:

```python
def rename(runner, what, ref, name, allow_duplicate=False, via="cli") -> dict
    # what: user | device | exit | inbound | exitsub ; name "" — сброс (не для user/device)
    # -> {"ok": True, "what", "id", "old", "name", "shown", "duplicates": [ids], "note": "<подсказка §5>"}
forwards.rename(proto, port, name, allow_duplicate=False)     # lib/kaskad/forwards.py
aliases.rename(ip, name, allow_duplicate=False)               # lib/kaskad/bot/aliases.py (общий для бота и CLI)
```

- Под `state.locked()`; **без** `gsys.hold()` и **без** `gw apply`: имя не входит в конфиги WG, xray, nft, PPP, ocserv.
- После записи — `snapshot.bump()`. `live.json` и кэши догонят на следующем тике сборщика (≤10 с, `collect.py:241`,
  `live.py:601-604`).
- Переименование выхода переводится на этот путь: `exit_set` с одним именем больше не вызывает `apply`. С `enabled` —
  как раньше.
- Журнал: `util.log_action('RENAME <what> <id>: «старое» -> «новое» (via=panel|ssh|cli|mcp|bot)')`. Имена — не
  секреты; перевод строки исключён проверкой.
- **Не меняется:** `login`, ключи, пароли, токены `/p/`, строка пула и её `#фрагмент`, `exit:<id>` в маршрутах,
  раскладка карты. Тест-страж сравнивает `secrets.json`, пул и отрисованные конфиги до и после (§8).

### 3.3. Выход из подписки: подпись по id выхода и перенос

Подпись хранится в `gateway.exits[eid].name` по id выхода — как у своего. Обновление подписки её не трогает.

**Проблема.** id = sha1 всей строки, вместе с `#фрагментом` (`exits.py:279`). Провайдеры часто пишут во фрагмент
остаток трафика или срок. Тогда после обновления у того же сервера **новый id**, подпись и выключатель «осиротели»
(`exitsubs.plan`, `exitsubs.py:471-512`, перенос не делает).

**Механизм** — выпуск **3.3.5** (D-065) (решение координатора 15.10; `SPEC-stage1-exits/06-model-events-time-rename.md` §3.8 — контракт и что добавляет
этап 1). Переименование своей записи не делает. Задача N3 добавляет только итог для человека (п. 5), если 3.3.5 его
не дал. Ниже — требования переименования; их проверяют по коду 3.3.5 до начала N3, расхождение — вопрос
координатору, а не свобода исполнителя.

**Требования (сверено с SE §3.8 15.10):**
1. **Когда тот же выход** (правка 2, С1: так в 3.3.5). «Ключ поменялся» = другой `exits.identity`: у VLESS и новых
   схем это `peer_key`, у AWG — `peer_key` плюс хеш своего приватного ключа (два клиента одного сервера — два выхода).
   Поменялось **только имя или параметры** при той же `identity` — тот же выход, **id сохраняется** (3.3.5,
   способ (а); новая строка встаёт на место старой). Только 1:1; два кандидата → не сопоставлено: старый ключ снят, новый добавлен (как в 3.3.5).
2. **`peer_key` для всех видов ключей.** (D-062) `vless://` и `awg://` — в 3.3.4/3.3.5; `hy2`, `ss`, `trojan`, `vmess` — T11,
   в самом `exits.peer_key` на stdlib: 3.3.5 зовёт его без разборщика (SE §3.8, З2).
   Фрагмент `#…` и параметры (`sni`, `obfs`, `fp`) в ключ не входят. `peer_key` содержит секрет — только в
   памяти; в `subs.json` — только 16 hex `identity_hash` (3.3.5).
3. **Что сохраняется:** id выхода не меняется, поэтому сохраняется всё, что к нему привязано, — подпись
   (`exits[eid].name`), выключатель `enabled`, ручное
   состояние, страна, квота, уровни и веса (`exit_policy`), закрепления (`pins.json`), счётчики, история
   (`metrics.db`). **Маршруты `exit:<id>` людей и устройств сохраняются вместе с подписью** — решение
   координатора 14.10, владелец может поменять (план §9 «Решено 14.10 (вечер)»; вопрос 3 этого SPEC = О10 SPEC-exits) (D-023).
4. **Без окна.** Выключенный владельцем выход ни на одном шаге не получает трафик; пока замена пула не закончена,
   трафик **не** уходит по правилу «при сбое»; неудачная замена откатывается, чужая правка не затирается. Это
   обеспечивает 3.3.5: карта id (`subs.json → ids`) пишется до замены пула; сохранение подписи `apply` не требует.
5. **Видно человеку** (задача N3; решение координатора 15.10, Р4) (D-066). Итог — **итог 3.3.5**: `updated` — число выходов,
   у которых ключ тот же, а имя или параметры сменились (`exitsubs`, тексты `gw_exitsubs.result.updated`,
   `result.updated_too`, `log.updated`). Новых полей нет: пар «старый id → новый» при способе (а) не бывает, а другой
   ключ — это снятый и добавленный выход в том же итоге. N3 сверяет тексты RU/EN; панель и CLI `--json` показывают
   `updated` (через N4/N5), журнал — как в 3.3.5.

## 8. Риски

- **Случайная смена `login`** — тогда отвалятся VLESS, SOCKS5 и PPP. Закрыто: `rename` не трогает поле; тест-страж
  на побайтное равенство конфигов.
- **Переименование под нагрузкой** — без `apply`, только запись `state.json` под замком. Нет гонки с применением,
  нет перезапуска xray.
- **Сопоставление по `identity`**: два ключа одного сервера в одной подписке. `plan` уже берёт «один сервер — один
  раз» (`exitsubs.py:479-482`), перенос — только 1:1, иначе не переносить и сказать.
- **Выключенный выход оживает при обновлении подписки** — закрыто в 3.3.5: id сохраняется, карта id пишется до замены
  пула (§3.3).
- **Механизм в другом выпуске (3.3.5)** — требования §3.3 сверены с `dev-335` 15.10 (правка 2); после слияния 3.3.5
  в `dev` и перебазирования `dev-s1` (до T1, SE §10) сверить ещё раз; N3 до этого не начинается.
- **Совпадение подписи подписки с доменом другой** — CLI ищет по id → номеру → домену → подписи. Неоднозначность →
  отказ со списком.
- **Параллельные агенты этапа 1** в `install.sh`, `app.js`, `actions.json` — владение функциями, слияние по очереди.
- **Bidi и невидимые символы** в имени подделывают вид (два одинаковых на глаз имени, текст «задом наперёд») — закрыто
  запретом `Cf` (кроме ZWJ и ZWNJ, вида они не подделывают).
