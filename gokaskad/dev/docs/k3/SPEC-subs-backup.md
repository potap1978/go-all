# Kaskad 3.x — подписки выходов и копия настроек файлом

Дата: 2026-10-09. Ветка `k3-feat` от `k3-branch` (604e712). Решение владельца: обе функции входят в первую версию
мастера «Быстрый старт». Здесь — команды и форматы, которые зовут мастер (`lib/kaskad/setup/`, другой исполнитель),
панель, SSH-меню, бот и MCP. Живой проверки ещё не было (будет отдельно, с goAmnezia по домену и по IP).

## 1. Подписки выходов

### 1.1. Что это

Ссылка подписки — источник ключей пула «Прокси для API Telegram» (он же — выходы шлюза). Человек добавляет ссылку
(по домену или по IP, http или https) и выбирает «обновлять раз в сутки» или «только вручную». Раз в сутки (таймер) и
по кнопке Kaskad скачивает её заново и меняет **только ключи этой подписки**: новые добавляет, исчезнувшие убирает.
Ключи, добавленные вручную, и ключи других подписок не трогаются.

Код: `lib/kaskad/gw/exitsubs.py` (логика), `lib/kaskad/gw/subfetch.py` (безопасное скачивание), `lib/kaskad/gw/cli.py`
(`gw exit-sub …`), `lib/kaskad/panel/api.py` (маршруты), `install.sh` (`--egress-replace`, разборщик PARSER_VER=9).

### 1.2. Хранение

`/etc/kaskad/egress/subs.json`, 0600 (адрес подписки — секрет: это пароль её ключей). Рядом с пулом `upstream.txt`:
«Удалить шлюз» (`gw purge`) не трогает ни пул, ни подписки.

```json
{"schema": 1, "next": 3, "subs": [{
  "id": "s-1a2b3c", "n": 1,                 // n — «подписка 1» для адреса по IP; домен называется сам
  "url": "https://…", "auto": true,         // auto — таймер раз в сутки, иначе только кнопка
  "pin": "",                                // SHA-256 самоподписанного сертификата IP по https (§1.4)
  "keys": ["e-…"],                          // выходы, которые ПРИНАДЛЕЖАТ подписке: она добавила — она уберёт
  "seen": ["e-…"],                          // все ключи последней удачной загрузки (свои и чужие)
  "excluded": ["e-…"],                      // удалённые человеком вручную — обновление их не возвращает (3.3.0)
  "added": "2026-10-09T12:00:00Z", "last_try": 1791000000, "last_ok": 1791000000,
  "error": "", "count": 4, "full": 0}]}
```

### 1.3. Правила

- **Чей ключ.** Ключ, который подписка принесла, а он уже был в пуле (добавлен вручную или другой подпиской), ей не
  принадлежит и остаётся, когда она его уберёт. Свой ключ, который подписка убрала, а другая подписка его ещё
  перечисляет (`seen`), переходит к той — и остаётся в пуле.
- **Удалён вручную — исключён** (3.3.0, решение владельца). Ключ, который человек удалил из пула руками (панель,
  меню, бот, `gw exit-del`), становится исключённым у каждой подписки, которая его перечисляет: обновление его не
  возвращает. Запись — в одном месте, где строка уходит из пула руками (`install.sh egress_pool_drop`): id ключа
  дописывается в `/etc/kaskad/egress/subs-excluded.pending` (0600, только id), ядро переносит его в `excluded` при
  следующем изменении подписок (блокировку подписок удаление не ждёт). У подписки — `excluded` (сколько из её
  последней загрузки исключено) и в тексте «исключено вручную: N». «Вернуть исключённые» — `gw exit-sub restore
  <подписка>`, панель (кнопка у подписки), меню (17 → 3 → «Подписки выходов» → 7), MCP `exit_sub_restore`: подписка
  забывает исключения и скачивается заново. Ключ, которого в подписке пока нет, ждёт её (`returning`) и вернётся с прежним
  id; ожидание снимается, когда ключ вернулся, пришёл повтором ключа из пула или уже стоит в пуле строкой, добавленной
  вручную (у той строки свой id и свои маршруты, прежний id не возвращается; REV-335-5 №3, REV-336-nits №1).
- **Один ключ — один раз** (3.3.5 №4, REV-335-2; понятие — `exits.peer_key`, SPEC-wave2-gateway §«Тот же ключ»). Ключ,
  который уже есть в пуле другой строкой, не добавляется — ни подпиской, ни вручную, ни импортом с заменой пула:
  VLESS — тот же uuid на том же `host:port`; AmneziaWG — тот же ключ сервера и тот же клиент (открытый ключ из
  закрытого) при любом адресе: по IP и по домену, `vpn://` и `.conf` одного подключения. Причина — «этот ключ уже
  есть как e-… («имя»), по другому адресу | записан иначе»; у подписки — «Пропущено дублей: N — …», и для двух строк
  одного ключа в одном её ответе тоже. Известное ограничение: сервер, восстановленный из резервной копии этого (те же
  ключи), — тот же ключ; при двух IP или двух доменах причина подсказывает выдать там новый ключ.
- **Две копии одного ключа из пула 3.3.4** (по IP и по домену) Kaskad сам не удаляет: «Поиск неполадок» (пункт 21),
  `gw exits` и панель говорят «Ключ «…» добавлен дважды: по IP и по домену. Работать будет только один — удалите
  лишний, маршруты перейдут на оставшийся». Обновление подписки сопоставляет строки пула сначала по паре «ключ +
  адрес», потом по ключу: обе копии сохраняют свои id. Удаление одной копии руками исключает у подписки эту копию
  (`excluded_idents` — хэш ключа с адресом, `places`), а не весь ключ, пока в пуле есть вторая; маршруты `exit:`
  удаляемой копии (базовый, людей, устройств) переходят на оставшуюся (`gw exit-handover` из install.sh
  `egress_remove_key_now` — меню, панель, мастер, CLI, MCP; подтверждение удаления это говорит, только если маршруты
  есть). Итог — по метке `@K3:egress_handover:<N>` после install.sh (REV-335-3): маршруты не перешли или оставшаяся
  копия выключена для шлюза / с проблемой в пуле — строка не удаляется, код 7. Слова: блокировка состояния занята —
  «Маршруты не перешли — удаление отменено, повторите»; ядро не смогло их перевести (state.json не читается, ядро
  упало — метка `handover_broken`) — причина ядра и «Повтор не поможет: сначала проверьте шлюз — kaskadctl gw check»
  (3.3.6, REV-335-4 №2). Удаление из SSH-меню пишет в журнал ту же строку `GW exit del: <id>`, что и панель (3.3.6,
  С3). Подписка, которая перестала отдавать одну копию, переводит маршруты только после успешной замены пула (и
  применяет их сразу); не перешли — предупреждение в итоге. Между двумя применениями (`gw apply` замены пула и
  `gw apply` передачи, обычно несколько секунд) маршруты `exit:` ушедшей копии указывают на выход, которого в пуле
  нет: такой маршрут шлюз собирает по его политике отказа (`fail: block` — блок, `direct` — напрямую;
  `gw/xray.py` `target`, у входов без xray — `gw/exits.py`), затем они переходят на оставшуюся копию. Порядок «сначала пул, потом маршруты» оставлен намеренно:
  неудачная замена пула не должна трогать маршруты (REV-335-3; окно описано по REV-335-4 №3). Две строки одной учётки VLESS работают обе — для них свой текст («вторая лишняя»), «работать будет только
  один» — только для AmneziaWG.
- **Отказы.** Не скачалась (нет ответа, 404, сертификат, внутренний адрес), ответ пустой или без ключей (страница
  сайта, профиль Clash) — пул не трогается, у подписки `error` и строка «не обновлялась N ч: причина».
  `stale: true` — последняя попытка неудачна или подписка «раз в сутки» не обновлялась больше 26 ч.
- **Предел пула** — 100 ключей (EGRESS_MAX): входит, сколько влезает, остальное — `full` и слова «Предел пула (100
  ключей): не вошло N — удалите ненужные ключи».
- **Одна запись пула за раз.** Новый пул ядро считает само и отдаёт целиком: `gokaskad --egress-replace <hex16>`,
  пул — на stdin (§1.6). Пул изменился за это время (другое окно) — код 3, пересчёт, до трёх попыток.
- **Журнал** (`/var/log/kaskad.log`): `GW exit-sub add s-1a2b3c (раз в сутки): ключей 4, добавлено 4`,
  `GW exit-sub refresh s-1a2b3c: ключей 4, +1 −1` — без адреса и ключей.
- **Отметка у выхода**: у строк `gw exits --json`, `GET /api/gw/exits` — `source: {sub, name}` (null — добавлен
  вручную); `name` — домен подписки или «подписка N».

### 1.4. Скачивание (`subfetch.fetch_sub`)

Те же проверки, что у `exit-add --public-only` (подписка от агента MCP): только http/https, без `user:pass@`,
**каждый** адрес хоста глобальный (не узел, не локальная сеть, не CGNAT, не метаданные облака), соединение — на
проверенный адрес (имя только в Host/SNI), перенаправления — вручную, до 3, каждое проверяется; до 1 МБ, 20 с на
запрос. По домену сертификат проверяется по центрам сертификации всегда. **По IP через https** сертификат обычно
самоподписанный: при добавлении запоминается его отпечаток SHA-256 (доверие при первом использовании), при каждом
обновлении он должен совпасть; сменился — отказ «Сертификат сервера подписки сменился… удалите подписку и добавьте её
заново». По IP через http — без шифрования, как дала подписка. **По IP, а сертификат — от центра сертификации на домен**
(goAmnezia с доменом): такой не запоминается (он меняется каждые 60–90 дней), отказ словами «Сертификат выдан на домен
<имя> — добавьте подписку по домену или по http.», в `data` — `cert_domain` и `same_server` (домен ведёт на этот же
адрес). Тогда панель и меню предлагают тот же адрес по домену — собирают его сами из введённого (адрес ядро не
возвращает). Подписка, уже взятая по отпечатку такого сертификата, работает, пока отпечаток тот же.

### 1.5. Форматы

Разбирает тот же разборщик пула `egress_parse.py` (PARSER_VER 9; старый файл на диске ядро само переписывает через
`gokaskad --egress-ensure-parser`):

| Тело | Пример | Что берётся |
|---|---|---|
| base64-список | 3X-UI, Marzban: `dmxlc3M6Ly8…` | `vless://` (и `vpn://`, `amneziawg://` внутри) |
| список `vless://` | по строке на ключ | каждый ключ |
| список `vpn://` | goAmnezia `all.vpn`, `awgNN.vpn` | AmneziaWG 1.0/1.5/2.0/3.1 |
| `amneziawg://<base64url .conf>#<имя>` | goAmnezia `all.txt` (подписка incy) | AmneziaWG, имя из `#` |
| текст `.conf` | goAmnezia `awgNN.conf` | одна линия |
| смесь | `vless://` + `vpn://` | всё |

**goAmnezia Pro** (`/s-<43 знака>/<суффикс>`, docs/SUBSCRIPTION.md goAmnezia): для продуктов серии предназначен
`all.vpn`. Адрес без суффикса и `all.yaml` / `mihomo.yaml` (профиль Clash — Kaskad его не читает) ядро само
заменяет на `all.vpn` той же подписки и говорит об этом (`note`). Подписка goAmnezia живёт на домене с доверенным
сертификатом; адрес по IP — это подписки других панелей (3X-UI на `http://IP:2096/sub/…` и т. п.) или goAmnezia за
самоподписанным сертификатом — тогда работает §1.4.

### 1.6. `gokaskad --egress-replace <hex16>` (install.sh)

Весь пул со stdin одной пересборкой, под блокировкой пула (`/run/kaskad/egress-pool.lock`). `<hex16>` — первые 16
hex sha1 непустых строк пула (пробелы по краям сняты, строки через `\n`), каким его видело ядро. Коды: 0 — заменён
(или уже такой), 1 — строка не `vless://`/`awg://` или пересборка не прошла (пул прежний), 3 — пул изменился, 5 —
больше EGRESS_MAX, 6 — пул занят. Пустой ввод — пул пуст, «Прокси для API Telegram» выключается. Первая нога
AmneziaWG — тот же выбор движка, что при добавлении ключа. Ключи — только stdin и файлы, ни одного аргумента внешней
программы. Им же пользуется перенос настроек (§2).

### 1.7. Команды (`kaskadctl gw exit-sub …`, у всех `--json`)

| Команда | Ответ `--json` |
|---|---|
| `add [--manual]` (адрес — stdin) | `{ok, sub, result: {id, name, ok, added, removed, count, full, text, warnings}, note, text, warnings}`; уже есть — код 3; предел подписок 20 — код 3; плохой адрес — код 2; не скачалась — код 1, ничего не сохранено |
| `list` | `{ok, subs: [{id, n, name, domain, auto, keys, exits, count, full, added, last_ok, last_try, error, stale, text, pinned}]}` |
| `refresh [<sub>] [--auto] [--quiet]` | `{ok, results: [{id, name, ok, added, removed, count, full, text, error?}], text}`; код 1, если хоть одна не обновилась |
| `del <sub> [--keep-keys]` | `{ok, id, removed, text}`; нет такой — код 2 |
| `auto <sub> on\|off` | `{ok, sub}` |

`<sub>` — `s-xxxxxx`, номер или домен. `gw exits --json` — ещё и `subs` (тот же список).

Таймер: `kaskad-exit-sub.timer` (OnCalendar=daily, RandomizedDelaySec=1h, Persistent=true) →
`kaskad-exit-sub.service` (`kaskadctl gw exit-sub refresh --auto --quiet`). Есть, пока есть подписка «раз в сутки»;
нет — оба юнита сняты. Удаление Kaskad (меню 15) снимает их вместе с прочими `kaskad-*`.

### 1.8. Где видно

- **Панель** «Выходы»: окно «Добавить ключ» → вкладка «Подписка» (адрес, «обновлять раз в сутки»); блок «Подписки» —
  строка состояния, переключатель «раз в сутки», «Обновить», «Удалить» (с её ключами / оставить ключи), «Обновить
  все»; метка источника у строки выхода. API: `POST /api/gw/exit-subs {url, auto?}`, `POST /api/gw/exit-subs/refresh`,
  `POST /api/gw/exit-subs/<id>/refresh`, `PUT /api/gw/exit-subs/<id> {auto}`, `DELETE /api/gw/exit-subs/<id>[?keep_keys=1]`;
  `GET /api/gw/exits` — `subs` и `source`.
- **SSH**: меню 17 → 3 «Выходы и маршрут по умолчанию» → «Подписки выходов» (выбор цифрами); в «Добавить ключ
  выхода» одна ссылка `http(s)://` — вопрос «как подписку / ключи один раз».
- **MCP**: `exit_sub_list`, `exit_sub_add` (адрес — stdin), `exit_sub_refresh`, `exit_sub_restore`, `exit_sub_auto`, `exit_sub_delete`
  (разрушительное, `confirm`). Скачивание — только внешние адреса (§1.4).

## 2. Копия настроек файлом и перенос

### 2.1. Что переносится (части)

| Часть | Что | Чего нет |
|---|---|---|
| `gateway` | люди, устройства, протоколы с их ключами, портами и параметрами, маршруты, правила, имена выходов — `gateway` из state.json и secrets.json | выбор движка AmneziaWG, MTU-карта и «включён ли» (узла, не настроек); сертификат узла `tls.server.*`, если адрес сменился |
| `exits` | пул `upstream.txt`, подписки `subs.json` | состояние выходов (проверит сторож) |
| `forwards` | пробросы (`forwards`), имена серверов (`aliases`), мониторинг (`monitors/`) | счётчики трафика |
| `site` | домен, почта Let's Encrypt, шаблон сайта | сертификат (выпускается заново), файлы сайта (шаблон ставится заново по id) |
| `bot` | `BOT_TOKEN`, `BOT_CHAT_ID`, `BOT_ADMINS`, `MENU_STYLE` | `bot_state`, `BOT_PROXY` (его ставит пул) |
| `mcp` | наши строки `/root/.ssh/authorized_keys` (ключи ИИ-агентов) | чужие строки |
| `panel` | «спрашивать пароль», путь на домене, «Вид», раскладка | **пароль панели**, открытый доступ (включается заново: меню 18) |
| `github` | `GITHUB_PAT`, `KASKAD_BRANCH` | — |

По умолчанию — все части; `--without bot,mcp` (или `parts`) — без них.

### 2.2. Формат — один с резервными копиями переезда

Снимки переезда (`/var/backups/kaskad/<id>/`, `kaskad.migrate.snapshot`) — манифест вида `kaskad-snapshot` (id,
created, reason, from, to, files с sha256 и размером) и файлы `files/<путь на сервере>`. Копия настроек — **тот же
манифест и те же имена файлов**, только собранные в один JSON и зашифрованные; копия текущих настроек перед импортом —
обычный снимок этого формата (reason `backup-import`, его показывает «Резервные копии» меню 16 → 3 и `migrate backups`,
`backup undo` возвращает его). Третьего формата нет. `gw awg export/import` остался тем, чем был: перенос людей и
AmneziaWG одного узла в другой узел (слияние), а не копия узла; его файл копия узнаёт и отсылает в «Протоколы → Движок
AmneziaWG → Импорт».

Внутри (до шифрования, только ASCII — `ensure_ascii`):

```json
{"kind": "kaskad-backup", "v": 1,
 "manifest": {"kind": "kaskad-snapshot", "id": "20261009T120000Z-k3-3.2.23", "created": "…", "reason": "export",
              "from": {"edition": "k3", "version": "3.2.23", "engine": "nft"}, "to": "3.2.23",
              "parts": ["gateway", "exits", …], "node": {"host": "203.0.113.10", "domain": "vpn.example.org"},
              "summary": {"gateway": {"users": 2, "devices": 5, "inbounds": ["awg2", "wg"], …}, …},
              "files": {"files/etc/kaskad/state.json": {"sha256": "…", "size": 1234}, …}},
 "files": {"files/etc/kaskad/state.json": "<текст>", …}}
```

Известные имена файлов: `files/etc/kaskad/{state.json (только части gateway, forwards, site), secrets.json, config
(только ключи частей bot и github), aliases, monitors/<ip>.conf, egress/upstream.txt, egress/subs.json,
panel/config.json, panel/appearance.json, panel/layout.json}`, `files/root/.ssh/authorized_keys` (только строки
агентов). Любое другое имя — отказ «В копии чужой файл»: импорт никогда не пишет файл по пути из копии — каждую
часть кладёт её собственный код.

### 2.3. Файл и шифрование

Текст (переносится почтой, мессенджером, в браузере):

```
KASKAD-BACKUP 1
{"check":"<hex16>","cipher":"aes-256-cbc","created":"…","format":"kaskad-backup","iter":600000,"kdf":"pbkdf2-sha256","parts":[…],"salt":"<b64>","v":1,"version":"3.2.23"}
<base64 шифротекста, по 76 знаков>
MAC <hex64>
```

- Ключи: PBKDF2-HMAC-SHA256(пароль, соль 16 случайных байт, 600 000) → 64 байта: 32 — шифрование, 32 — подпись.
- Шифрование — `openssl enc -aes-256-cbc -pbkdf2 -iter 1 -md sha256 -nosalt -a -A` (есть на любом Debian/Ubuntu,
  OpenSSL 1.1.1 и 3.x). Ключ уходит openssl **в его окружении** (`-pass env:KASKAD_BACKUP_KEY`; окружение процесса
  читает только его владелец, argv — все); `-iter 1 -nosalt` — ключ уже стойкий и свой у каждого файла. `-aes-256-gcm`
  `openssl enc` не умеет (AEAD), поэтому CBC + HMAC.
- Подпись: HMAC-SHA256 строки заголовка и шифротекста (encrypt-then-MAC); проверяется **до** расшифровки.
- `check` — HMAC постоянного текста: неверный пароль («Неверный пароль копии.») отличается от повреждения («Файл копии
  повреждён…»). Пароль ≥ 8 знаков, одной строкой; из stdin (первая строка) или `KASKAD_BACKUP_PASSWORD`, не из argv.
- Заголовок открыт (дата, версия, части) — секретов в нём нет. Версия формата выше — «обновите Kaskad».
- Предел файла — 16 МБ; через панель — до 20 МБ тела запроса (только маршруты `backup/preview` и `backup/import`, только после входа; за nginx — тот же предел для этих двух путей), остальная панель — 1 МБ.

### 2.4. Команды (`kaskadctl backup …`, у всех `--json`)

| Команда | Что делает | Ответ `--json` |
|---|---|---|
| `export [--file F \| --save \| --stdout] [--parts …] [--without …]` | копия этого узла; по умолчанию `/root/kaskad-<адрес>-<дата>.kbk` (0600); `--save` — `/var/backups/kaskad/exports/`; `--stdout` — сам текст (с `--json` — в поле `text`) | `{ok, file?, name, parts, summary, size, text?}` |
| `import FILE [--parts …]` | предпросмотр, ничего не меняет; `FILE` «-» — текст на stdin, пароль тогда в `KASKAD_BACKUP_PASSWORD` | `{ok, applied: false, preview}`; код 3 — есть `blockers`; код 2 — пароль, чужой или повреждённый файл |
| `import FILE --yes [--agents]` | применение: снимок, части по порядку, откат при сбое; ход — строками «[*] …» в stderr; `--agents` — и ключи ИИ-агентов копии (3.3.7.2, SEC-3372 З-3: без него не переносятся) | `{ok, applied: true, parts, backup, warnings, notes, address, text}` |
| `undo [--yes]` | вернуть снимок, сделанный перед последним импортом (и перед этим — свой снимок `backup-undo`) | без `--yes`: `{ok, applied: false, from, created, parts, agent_keys_gone}` (`agent_keys_gone` — сколько ключей агентов удалится: их не было в снимке, агенты с ними отключатся; вопрос говорит это заранее); с `--yes` в ответе есть `agents_cut` — сколько подключений агентов прервано (панель показывает такой итог предупреждением); снимка нет — код 3 (панель — 409) |
| `summary [--parts …]` | что вошло бы в копию: числа и имена, без секретов; есть ли что вернуть | `{ok, parts, titles, summary, size, undo: {available, created, path, agent_keys_gone}}` |

### 2.5. Импорт — порядок, адрес, откат

1. Предпросмотр. **Блокер**: шлюз или пробросы в копии, а движок здесь iptables — «меню 16 → 1, потом повторите».
2. Снимок всех частей этого узла (`take_snapshot`, reason `backup-import`, `/var/backups/kaskad`, хранится 5 новейших).
3. Части по порядку: `github` (ключ GitHub и ветка обновлений — только если здесь своих нет), `bot` (токен, чаты; бот перезапускается,
   если его служба есть), `panel`, `mcp` (ключи агентов добавляются к здешним через `mcp key add` — **только явно**: с 3.3.7.2 по умолчанию не
   переносятся, ключ из копии — агент, который управляет узлом по SSH; перенос — отметка в предпросмотре панели
   (`"agents": true` в `/api/backup/preview|import`), «2» на вопрос меню, `--agents`; предпросмотр без отметки — строка
   «не переносятся» и поле `agents: {keys, on}`; «Вернуть как было» и откат — ключи ровно как в снимке), `forwards`
   (замена целиком; проброс на порт SSH этого сервера не переносится — предупреждение), `exits` (пул через
   `--egress-replace`, подписки, таймер), `gateway`, `site` (домен и почта; сертификат — когда A-запись укажет сюда).
4. **Шлюз**: здешний выключается, его протоколы снимаются; записи протоколов копии кладутся как «удалённые с
   сохранёнными настройками» и ставятся заново `inbound install` — тот же порт, если свободен, те же ключи из
   secrets.json, пакеты ставятся (минуты). Порт занят — берётся другой, и итог называет, каким устройствам выдать
   настройки заново.
5. **Адрес в выданных настройках**: в копии IP старого сервера, а у этого другой — адрес шлюза становится здешним
   (определяется заново), сертификат узла — здешний, предупреждение «устройствам выдайте настройки заново; чтобы при
   следующих переездах этого не делать — задайте шлюзу домен». В копии домен — «укажите его A-запись на этот сервер, и
   выданные настройки заработают без новых».
6. **Бот**: один токен — один сервер; предупреждение «остановите бота на старом сервере».
7. Сбой на любой части (любая ошибка, не только отказ записи — 3.3.7.2, SEC-3372 З-2) — снимок возвращается теми же функциями в точном режиме (часть, которой не было, убирается:
   шлюз — `gw purge --users`, домен — `site clear`, ключи агентов — ровно как в снимке), текст: «Перенос не удался на
   шаге «шлюз»: <причина>. Вернул как было (копия: …)». Не вышло и вернуть — путь снимка и «Вернуть как было» (панель, меню 16 → 6 → 3, `kaskadctl backup undo`).

### 2.6. MCP — решение

`backup_summary` (чтение: числа, без секретов) и `backup_export` (`backup export --save`): копия с паролем, который
назвал человек, ложится **на сервер** в `/var/backups/kaskad/exports` (0600); агенту возвращаются только путь, части и
числа. Текст файла агенту не отдаётся никогда: в копии токен бота, ключ GitHub, ключи всех устройств — ключи от всего
узла; агент не берёт их, как не выдаёт себе пароль панели. Пароль — через stdin (в аудит — длина). `backup import` и
`backup undo` — в `hidden`: заменяют людей, протоколы и ключи узла — решение только человека.

### 2.7. Где видно

- **Панель** «Настройки» → «Копия настроек»: «Скачать копию» (части, пароль дважды), «Загрузить копию» (файл, пароль,
  предпросмотр, «Перенести»), «Вернуть как было». API: `GET /api/backup/summary`, `POST /api/backup/export {password,
  parts?, without?}` → `{file: текст, name, …}` (no-store), `POST /api/backup/preview {file, password, parts?}`,
  `POST /api/backup/import {file, password, parts?}`, `POST /api/backup/undo`.
- **SSH**: меню 16 → «Копия настроек и перенос на другой сервер» (меню 16 уже держит «Резервные копии» и возврат на
  2.13 — главное меню не растёт): сохранить в файл (пароль дважды, путь и `scp` для скачивания), загрузить из файла
  (предпросмотр, «1) Перенести 0) Отмена»), вернуть как было.
- **Мастер «Быстрый старт»**: этап «Импорт» — «загрузить файл копии» = `POST /api/backup/preview` → `POST
  /api/backup/import` (или `kaskadctl backup import FILE --json` → `--yes`); этап «Дополнительно» — «скачать копию» =
  `POST /api/backup/export` (или `kaskadctl backup export --stdout --json`, текст — в `text`). Окна панели открываются
  функциями app.js (см. отчёт исполнителя панели).
