## 0. Итог в шести строках

1. Новый вход **`hy2`** — Hysteria2 внутри **того же** xray шлюза (`kaskad-gw-xray.service`), как VLESS и SOCKS5.
   Свой процесс и sing-box не нужны.
   - Вход Hysteria в xray есть с **26.3.27**.
   - Версию xray закрепляет 3.3.4 (`gw/xray.py` `XRAY_VERSION = "26.3.27"` + sha256). Вход проверяет её сам.
2. UDP-порт: 443/udp, занят — 8443/udp.
   - Маскировка **Salamander** по умолчанию включена: для DPI это не QUIC, а случайный UDP.
   - Смена портов (диапазон) — опция, по умолчанию выключена.
3. Каждое устройство — пользователь xray: `auth` = свой секрет, **`email` = `<login>.h2`** — свой, не общий с VLESS,
   чтобы трафик не считался дважды. Маршрут устройства, kill switch и «Россия напрямую» работают так же, как у VLESS
   (правило по `user`).
4. Сертификат: есть домен узла — **своя копия** сертификата домена (общую копию VLESS тот удаляет); нет домена —
   самоподписанный, **отпечаток (`pinSHA256`) — в ссылке**, с предупреждением, как у SSTP и OpenConnect
   (**решение владельца 14.10**) (D-020).
5. Выдача: ссылка `hysteria2://…`, QR (≤2 частей), поля для ручного ввода, приложения по платформам
   (`install_apps.json`), строка в подписке человека.
6. Блокировки UDP/QUIC в мобильных сетях РФ **не проверены**. Панель и SSH-меню честно это пишут и советуют держать
   рядом TCP-вход (VLESS).

**Проверено 14.10 настоящим `xray -test` (v26.3.27, кэш тестов `tests/realbin.py`)** — схема входа:

```json
{"tag": "gw-hy2", "listen": "::", "port": 443, "protocol": "hysteria",
 "settings": {"version": 2, "clients": [{"auth": "<секрет устройства>", "level": 0, "email": "<login>.h2"}]},
 "streamSettings": {"network": "hysteria", "hysteriaSettings": {"version": 2},
   "security": "tls",
   "tlsSettings": {"alpn": ["h3"], "certificates": [{"certificateFile": "…", "keyFile": "…"}]},
   "finalmask": {"udp": [{"type": "salamander", "settings": {"password": "<общий пароль входа>"}}],
                 "quicParams": {"congestion": "bbr"}}}}
```

- `settings.clients[].auth` и `.email` — строки, типы проверяются (`HysteriaUserConfig`). `users` вместо `clients`
  молча игнорируется — **только `clients`**.
- `finalmask.udp[].settings.password` у Salamander — строка (`Salamander.password`).
- `quicParams.congestion` — строка. `brutalUp`/`brutalDown` разбираются как скорость с единицами.
- `"port": "24443-24445"` — xray открывает **по сокету на каждый порт** диапазона (видно по `lsof`). Значит, смена
  портов не требует DNAT, но размер диапазона ограничиваем (§3.3).
- `"port": "24443,24500-24502"` (порт и диапазон через запятую) — принимается.
- `hysteriaSettings` у входа строго типизирован (`udpIdleTimeout` — число).
- Один и тот же `email` в `gw-hy2` и `gw-vless` `xray -test` принимает **молча** — поэтому свой `email` (§2) обязателен
  и проверяется тестом, а не xray.

**Проверено T0 14.10** (`k3/stand/logs/T0-stage1.md` §7, С0.13):
- сервер Hysteria2 в 26.3.27 умеет добавлять и убирать пользователя на лету, но **CLI `xray api adu` hysteria не
  знает** (`unsupported inbound type`). Добавление — только своим вызовом gRPC `HandlerService/AlterInbound` с
  `AddUserOperation{User{email, hysteria.account.Account{auth}}}` (проверено вручную, `grpc-status: 0`);

  соединение): отзыв устройства, новый секрет и уход — перезапуск xray, как и было в §2;
- счётчики `user>>><login>.h2>>>traffic` и `email` в журнале **есть**, но **только без `statsInbound*`** в
  `policy.system` (с ними пропадают). Kaskad их не включает и не включит (SPEC-exits §5.6);
- клиенты-выходы Hysteria2 xray запоминает по `host:port` (касается выходов, SPEC-exits §9.1, не входа).

**Не проверено (только на стенде):**
- поведение клиентов с `pinSHA256`;
- перечитывает ли xray сертификат входа Hysteria без перезапуска — тоже С0.13.

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Имя вида | **`hy2`** | Регулярки видов `[a-z0-9]{2,8}` в `panel/api.py:698` и `panel/scheme.py:74`; `hysteria2` не пройдёт |
| Процесс | общий xray шлюза | как VLESS и SOCKS5: маршрут, правила, счётчики — те же механизмы |
| Схема ссылки | `hysteria2://` | шире понимают приложения, чем `hy2://`. Разбор выходов (B9) принимает обе |
| Порт | **443/udp, занят — 8443/udp** | по умолчанию, владелец может поменять (§9) |
| Salamander | **вкл.** по умолчанию, пароль общий на вход | исследование §5.1: без маски это QUIC, который режут по SNI. По умолчанию, владелец может поменять |
| Смена портов | **выкл.** по умолчанию, до 100 портов | по умолчанию, владелец может поменять |
| Пользователь | `auth` — 24 байта `secrets.token_urlsafe`; **`email` = `<login>.h2`** | xray считает трафик и правила по `email`. Общий с VLESS `email` = двойной счёт в «Обзоре» и лимитах этапа 3 (находка С5). `<login>.h2` проходит `_USER` (`rules/apply.py:51`, `[A-Za-z0-9._@+-]{1,64}`); `login` не меняется при переименовании (`SPEC-stage1-rename.md`) |
| Перезапуск | как у VLESS: новое, включённое или сменившее маршрут устройство — горячо (добавление пользователя — вызовом gRPC `AlterInbound`, T0); уход, отзыв, новый секрет — перезапуск (`rmu` не рвёт открытое QUIC-соединение, T0) | горячими правила `h2-…` становятся только через `xray_hot_prefix` контракта T5 (§3.0). Запасной путь `xray_hot = False`: любая смена устройств = перезапуск xray (§8, риск 1) |
| Сертификат без домена | **разрешён**: самоподписанный, пин в ссылке, предупреждение | **решение владельца 14.10** (D-020), как у SSTP и OpenConnect |
| Congestion | `bbr`; **Brutal — после стенда** | Brutal требует честных скоростей от человека. По умолчанию, владелец может поменять |
| Мастер | Hysteria2 в списке протоколов, **выключен** по умолчанию (как VLESS) | по умолчанию, владелец может поменять |

## 3. Контракты

### 3.0. Зависимость от T5 SPEC-exits (горячие правила и контракт xray)

T5 (`SPEC-stage1-exits/13-tasks.md` §10.1) владеет `gw/xray.py` и меняет:
- `HOT_PREFIX` (`xray.py:88`, `"vl-"`; используется в `:542`, `:557`) — на префиксы из адаптеров (атрибут
  `xray_hot_prefix`: `"vl-"`, `"sk-"`; SPEC-exits §2.4);
- контракт цели: `exits.target(route, device)` и `render(…, decision)`;
- сигнатуру `xray_routing` в `gw/inbounds/base.py`;
- «API всегда, `stats` всегда» и `internal_ports` (`xray.py:714-724`; сейчас порт статистики — только при `vless`).

Поэтому:
- **T12 (Y1) начинается после слияния T4+T5** в `dev-s1` (шаг 3 SPEC-exits §10.2; сливается на шаге 6) и пишет
  `xray_routing`/`route_target` по
  новому контракту `target(route, device)`, а не по `vless.py:815` из `6a6c410`;
- **префикс `"h2-"`** — по контракту T5 горячие входы перечисляют свои префиксы атрибутом адаптера
  `xray_hot_prefix` (SPEC-exits §2.4). Hy2 ставит `xray_hot_prefix = "h2-"`; `gw/xray.py` T12 **не правит**. Без
  префикса цепочки `h2-…` попадут в «прочие» правила, и любая смена устройства Hy2 перезапустит xray (обрыв VLESS и
  SOCKS5). Флаг `xray_hot = True` сам по себе не поможет;
- порт API и статистики `10854` после T5 есть всегда, когда включён API (`internal_ports`) — Hy2 ничего не добавляет;
- маскировка ссылок `hy2://`/`hysteria2://` в журнале — T11 (SPEC-exits §9.7: всё до `@` и `obfs-password`);
  `util.py` T12 не правит, но тест Y1 проверяет, что выдаваемая ссылка входа маскируется.
- **добавление пользователя Hysteria2 горячо — через gRPC** (T0: CLI `adu` его не знает). Решение координатора 14.10 (D-036):
  это часть контракта T5 — `hot_apply` получает путь `AddUser` через `HandlerService/AlterInbound` для входов, которые
  CLI не поддерживает; адаптер Hy2 даёт атрибут `xray_add_user = "grpc"` и функцию `xray_account(d)` (поля
  `hysteria.account.Account`). `xray.py` T12 по-прежнему не правит; без этого пути новое устройство Hy2 —
  перезапуск. **Как именно** (находка С5, 15.10): помощник T5 `gw/xraygrpc.py: add_user(...)`, protobuf вручную,
  вызов системным `curl --http2-prior-knowledge`, тело через stdin (секрет `auth` не попадает в `argv`), удача —
  `grpc-status: 0`; нет `curl` с HTTP2, тайм-аут или ошибка → «нужен перезапуск»; тесты — SE §2.4;
- правила со списками («всегда через выход», «Россия напрямую», российская цель T15) после T0 — **общие на вход с
  перечнем пользователей** (`ls-`, SPEC-exits §2.4): `email` `<login>.h2` попадает в перечни, цепочка `h2-` — одно
  правило маршрута;
- если окажется, что контракта T5 не хватает, — запрос координатору, а не правка `xray.py`.

### 3.1. Модель и секреты

```
gateway.inbounds.hy2 = {"enabled": true, "port": 443, "hop": null | "20000-20099",
                        "obfs": true, "cert": "domain" | "self", "congestion": "bbr", "label": ""}
secrets.json:  inbound.hy2.obfs        пароль Salamander (32 знака urlsafe)
               dev.<id>.hy2.auth       секрет устройства
/opt/kaskad/gw/tls-hy2/self/{cert.pem,key.pem}        самоподписанный
/opt/kaskad/gw/tls-hy2/domain/{fullchain.pem,privkey.pem}   своя копия сертификата домена
     каталоги 0750 root:kaskad-xray, ключи 0640, цепочки 0644
gateway.inbounds.hy2.pin = "<sha256 сертификата self, hex>"   не секрет, нужен ссылке
```

- `label` — подпись входа из `SPEC-stage1-rename.md` (только для показа, в выдаваемое не попадает).
- `removed_inbounds.hy2` хранит порт и параметры, как у других входов. Переустановка возвращает их и пароль из
  `secrets.json`.
- Префикс секретов адаптера: `secret_prefixes() = ("inbound.hy2.", "dev.%s.hy2.")`. `reset_secrets(dev)` — новый
  `auth`.
- Пара `self` и копия `domain` лежат в **разных** каталогах: смена режима туда и обратно не меняет пин.

### 3.2. Адаптер `lib/kaskad/gw/inbounds/hy2.py`

Методы базового класса (`base.py:60-215`, сигнатуры — по `dev-s1` после T5):

### 3.3. Порт, смена портов, соседи

- **Порт.** UDP, 1024–65535 или 443. Смена — `PUT /api/gw/inbounds/hy2/port`, `kaskadctl gw inbound hy2 port <N>` —
  общий путь `ops.inbound_port` (`ops.py:952-995`).
  - После смены выданные ссылки недействительны.
  - Список устройств «выдать заново» — как при смене ключей VLESS.
- **Смена портов (`hop`)** — опция, по умолчанию выкл.
  - Диапазон до **100 портов**: xray держит сокет на каждый.
  - Вне 1024–65535, пересечение с занятыми — отказ со списком занятых.
  - В ссылку попадает как `host:443,20000-20099` (формат Hysteria URI).
  - **Не все приложения понимают** — пометка «не проверено» у приложений без подтверждения.
- **Соседи — в обе стороны.**
  - Hy2 против соседей: `ops.port_conflicts` (`ops.py:525`) и `conflicts.check(proto="udp", port)`
    (**`lib/kaskad/conflicts.py:252`**, `ss -Hlnup`) для порта и **каждого** порта диапазона — одним вызовом `ss`, не по
    разу на порт.
  - Соседи против Hy2: `ports(st)` возвращает весь диапазон (§3.2), значит `_port_conflicts` других входов и пробросов
    его видит — **даже при выключенном xray** (диапазон держится в состоянии).
  - Типичные: ocserv на 443/udp, свои WG/AWG, OpenVPN-UDP, x-ui или goAmnezia на том же сервере, панель 3x-ui с
    Hysteria.
  - Конфликт — текст с именем процесса; в панели — выбор «Взять 8443/udp / Ввести порт / Отмена», в `kaskadctl` и MCP —
    код ошибки с подсказкой `port N` (в SSH-меню вход не настраивается — решение владельца 15.10) (D-051).
- **UFW.** Сейчас `gwsys._rule_spec` (`gw/sys.py:296-299`) понимает только целый порт, а `sync_ufw` зовёт `ufw` на
  каждый порт (~0,5 с; 100 портов ≈ 50 с внутри `apply` под замком). Правка (Y2): `_rule_spec` принимает диапазон и
  пишет **одно** правило `20000:20099/udp`; `sync_ufw` получает диапазон одной записью. Комментарий `kaskad-gw hy2`,
  `close_ufw` при удалении. Правила UFW для IPv6 — тем же вызовом (`ufw` с `IPV6=yes`).
- **Внешняя доступность.**
  - UDP с узла не проверить без клиента, поэтому статус «порт слушается на узле; снаружи не проверено».
  - В «Проверить» (issue) — отдельная строка «UDP/QUIC: блокировки в мобильных сетях РФ **не проверены**; если не
    подключается — VLESS (TCP)».

### 3.4. Сертификат

| Режим | Когда | Ссылка | Обновление |
|---|---|---|---|
| `domain` | у узла есть домен с сертификатом (`site/model.py:207` `use_for`, `tls_pair` `:221`) | `sni=<домен>`, без `insecure` | **своя копия** в `/opt/kaskad/gw/tls-hy2/domain/`; потребитель `hy2` в `site/consumers.py:224` (`reload`) и `:262` (`cert_installed`): копия + перезапуск xray, если он не перечитывает сертификат сам (проверить на стенде) |
| `self` | домена нет | `sni=<IP или имя из SAN>`, `insecure=1`, **`pinSHA256=<hex>`** | 10 лет; смена — «Новый сертификат» (все ссылки заново) |

- **Почему своя копия, а не общая с VLESS.** `vless.sync_tls(False)` делает `rmtree` каталога `/opt/kaskad/gw/tls`
  (`vless.py:313-324`) и вызывается из `vless.apply` при `security != "tls"` (Reality — режим по умолчанию) и из
  `vless.uninstall` (`vless.py:644-650`). Узел с доменом, VLESS-Reality и Hy2 в режиме `domain` терял бы файлы при
  каждом `apply` VLESS → `xray -test` падает → не стартует весь xray шлюза (VLESS, SOCKS5, Hy2). Своя копия Hy2 не
  трогает `vless.py` (его `xray_routing` у T5).
- Копирование — своя функция в `hy2.py` по образцу `vless.sync_tls` (атомарная замена при отличии, права как в §3.1);
  удаление — только своего каталога и только при снятии режима `domain` или удалении входа.
- Режим выбирается сам при включении и снятии домена — как у VLESS (`site mode`). Смена режима — выдать заново.
- IP-сертификат `ipcert` к xray не подключён и в этапе 1 не подключается.
- **Без домена — разрешено (решение владельца 14.10)** (D-020), как у SSTP и OpenConnect: самоподписанный сертификат,
  отпечаток в ссылке и предупреждение в панели, окне выдачи и строке состояния входа в SSH-меню: «Без домена — самоподписанный сертификат.
  Часть приложений проверяет только «небезопасно: да» и примет любой сертификат. Надёжнее — домен».
- **Пин.** `pinSHA256` — SHA-256 сертификата (DER), hex. Приложения, которые игнорируют пин при `insecure=1`, примут
  любой сертификат — риск перехвата. Поэтому:
  - режим `domain` рекомендуется в панели;
  - у приложений в `install_apps.json` отметка «проверяет пин» — только после проверки на стенде.

## 8. Риски

1. **Горячее добавление Hysteria в 26.3.27 может не работать** → каждое новое устройство перезапускает xray и рвёт
   соединения VLESS и SOCKS5. Решение по стенду; при неудаче — `xray_hot = False` для `hy2` и предупреждение в панели.
2. **Версия xray.** 3.3.4 уже закрепил бинарь (`XRAY_VERSION = "26.3.27"` + sha256, xray не берётся из PATH или x-ui);
   гейт берёт версию оттуда. Будущее обновление xray: в предрелизах меняется `udpHop` (клиентская сторона — для
   выходов B9). REALITY `minClientVer` к Hysteria не относится.
3. **UDP режут** на части мобильных сетей — вход не заменяет VLESS. Подсказки в панели, SSH и выдаче.
4. **`insecure=1` без проверки пина** у части приложений — режим `domain` рекомендуется; уровни приложений по стенду.
5. **Память**: QUIC держит буферы на соединение; диапазон портов — сокеты. Лимит 100 портов, замер на стенде.
6. **Правила волны 3** не применятся, если забыть `XRAY_PROTOCOLS` — тест-страж.
7. **Общий `email` с VLESS** — двойной счёт; xray это не ловит. Закрыто `<login>.h2` и тестом.
8. **Порядок с T5** — без `xray_hot_prefix = "h2-"` любая правка устройства Hy2 рвёт VLESS и SOCKS5. Закрыто
   зависимостью §3.0 и тестом `hot_plan`.
9. **Параллельные агенты** в общих файлах — §6.2.
10. ~~**Нет счётчиков `user>>><login>.h2>>>traffic`**~~ — **закрыт T0 14.10**: счётчики есть, пока в `policy.system`
    не включены `statsInbound*` (Kaskad их не включает, тест §7).
11. **Показ портов при диапазоне** — `ports()` отдаёт каждый порт для проверок; показ — только через `ports_view`
    (§3.2), иначе 100 записей в «Обзоре».
