# Kaskad 3.1: проверка шлюза на настоящих устройствах

Для тестировщиков. Стенд проверял шлюз только Linux-клиентами (`wg`, `awg`, strongSwan, `sstpc`, `openvpn`,
`openconnect`, `curl`). Здесь — то, чего стенд не видел: настоящие Windows, iPhone, Android, роутеры и
приложения. Нужно подтвердить, что настройки, которые выдаёт Kaskad, работают, а если нет — прислать всё,
что поможет найти причину.

Проверяйте по одному входу на устройство: так ясно, что именно сработало. Входы L2TP, SSTP и PPTP к тому же
делят один адрес на устройство: пока оно в сети по одному, по другому не подключится.

## Перед началом

- **Узел:** Debian 12/13 или Ubuntu 24.04/26.04+, доступ по SSH под root, Kaskad 3.1.0 (в шапке меню:
  `Kaskad PRO v3.1.0 · движок: nftables`).
  - Уже Kaskad 3: меню 11 «Обновить скрипт» (пока в `main` 2.13, оно само берёт ветку `test`).
  - Бесплатный Kaskad или PRO 2.x: поставьте командой с веткой `test`, см. [README](../../README.md#как-обновиться).
  - На чистом сервере движок nftables включается сам, потом Kaskad предлагает мастер шлюза.
- **Выходы:** для пунктов с маршрутами нужен хотя бы один ключ VLESS или AmneziaWG в пуле (меню 8 → 7),
  лучше два. Без ключей проверьте «напрямую» и «блок».
- **С чего начать:** с WireGuard (пункт 7) — самый простой вход. Если он не работает, дальше проверять нечего:
  дело в узле, DNS или выходах.
- **Порты:** если у хостера есть внешний файрвол, откройте порты протоколов (их показывает 17 → 1). UFW
  Kaskad настраивает сам.

  | Протокол | Порт на узле |
  |---|---|
  | WireGuard | UDP 51820 (если занят — другой) |
  | AmneziaWG 1.5 / 2.0 / 3.1 | свой случайный UDP у каждой линии |
  | L2TP/IPsec | UDP 1701, 500, 4500 |
  | IKEv2 | UDP 500, 4500 (и ESP) |
  | SSTP | TCP 4433 |
  | OpenVPN | UDP 1194 |
  | OpenConnect | TCP и UDP 4443 |
  | SOCKS5 | TCP 1080 (и UDP) |

- **Установка L2TP, SSTP и PPTP** собирает accel-ppp из исходников (до двух минут). Если система ещё ставит
  обновления, Kaskad скажет об этом заранее и предложит подождать.

## Общий порядок

1. **Поставить протокол:** 17 → 1 «Протоколы» → номер протокола → «Установить». В мастере отмечены только
   WireGuard, AmneziaWG и L2TP/IPsec; IKEv2, SSTP, OpenVPN, OpenConnect и SOCKS5 отметьте или поставьте здесь.
2. **Завести устройство:** 17 → 2 «Пользователи и устройства» → «Добавить устройство» (нет пользователя —
   сначала спросит его имя) → тип устройства → название → отметить **один** вход, который проверяете. Входы,
   рекомендованные для системы, Kaskad предлагает первыми; нужного среди них нет (например, L2TP для iPhone,
   OpenVPN для macOS, SOCKS5 для телефона) — он ниже, среди установленных: отметьте его номером.
3. **Выдать настройки:** 17 → 2 → «Выдать настройки устройству» → номер устройства. «Другой вход» переключает
   протокол. Экран с ключами и паролями никому не показывайте.
4. **Перенести файлы:** «Сохранить в файлы» кладёт их в `/root/kaskad-issue/<логин>/` (доступ только root;
   QR — картинками PNG). Скопируйте на свой компьютер, например
   `scp root@<узел>:/root/kaskad-issue/<логин>/<файл> .`, дальше — на устройство. Закончили — удалите:
   `rm -r /root/kaskad-issue/<логин>`.
5. **Проверить на узле:** `/opt/kaskad/bin/kaskadctl gw sessions` — в списке устройство;
   `/opt/kaskad/bin/kaskadctl gw status` или меню 17 → 5 — вход «работает».

**Успех (общий):** устройство подключилось; сайты открываются по именам (DNS шлюза работает); внешний адрес
устройства (любой сайт «мой IP») — адрес выхода пула, а при маршруте «напрямую» — адрес узла; отключили и
подключили снова — работает.

## Что присылать

Всегда:

1. Что проверяли: протокол, приложение или встроенный клиент (версия), система и её версия, модель
   устройства или роутера и версия прошивки.
2. Итог и шаг, на котором остановились; время попытки.
3. Скриншоты ошибок целиком (с кодом ошибки), при необходимости — окна настроек подключения.
4. С узла: `/opt/kaskad/bin/kaskadctl gw status` и `tail -n 50 /var/log/kaskad.log`.

**Не присылайте:** пароли, ключи, ссылки `vpn://`, `vless://`, `awg://`, QR-коды, файлы `.conf`, `.ovpn`,
`.mobileconfig`, `.ps1` (в скрипте L2TP общий ключ IPsec), `/root/kaskad-issue/*`, `/etc/kaskad/config` и
`/etc/kaskad/secrets.json`, токен бота, ключ GitHub. Журнал и `gw status` секретов не печатают, но перед
отправкой просмотрите их; адреса можно заменить на `X.X.X.X`. Если секрет всё же ушёл — 17 → 2 → 5
«Сменить ключи и пароли устройства».

Шаблон:

```
Проверял:  IKEv2, Windows 11 23H2 (сборка 22631), встроенный клиент
Итог:      не подключилось, ошибка 13801 на «Подключиться», 14:32
Скриншот:  приложен
gw status: (вывод)
Журнал:    (последние 50 строк)
```

## Чек-лист

В каждом пункте «Прислать» — дополнительно к общему списку выше (скриншоты ошибок, версия системы и устройства,
`gw status`, 50 строк журнала).

### 1. IKEv2 · Windows 10/11

- **Поставить** (17 → 1 «Протоколы»): IKEv2.
- **Выдать:** платформа «Windows», вход IKEv2 → «IKEv2 — скрипт PowerShell» (`kaskad-ikev2.ps1`) и поля:
  логин (EAP), пароль. Файл — на ПК.
- **Подключить:** PowerShell от имени администратора:
  `powershell -ExecutionPolicy Bypass -File .\kaskad-ikev2.ps1`. Скрипт кладёт сертификат центра Kaskad в
  доверенные корневые и создаёт подключение «Kaskad IKEv2». Параметры → Сеть и Интернет → VPN →
  «Kaskad IKEv2» → «Подключиться»; логин и пароль Windows спросит сам.
- **Успех:** «Подключено», адрес сменился, в `gw sessions` строка `ikev2`.
- **Ошибка 13801** (в английском Windows — «IKE authentication credentials are unacceptable»): Windows не принял
  сертификат сервера. Проверьте и пришлите результат:
  1. скрипт запущен от администратора и закончился без красных ошибок;
  2. `certlm.msc` → «Доверенные корневые центры сертификации» → «Сертификаты»: есть «Kaskad IKEv2 CA …»;
  3. адрес в подключении совпадает с «Сервер» в выдаче (на него выпущен сертификат; другое имя или IP — 13801
     ожидаема);
  4. дата и время на ПК верны;
  5. адрес узла меняли (17 → 4) или центр сертификации (17 → 1 → IKEv2 → 5) — тогда выдайте настройки заново и
     запустите скрипт ещё раз.

  Если пункты 1–4 в порядке, а 13801 остаётся, это самый ценный результат: центр сертификации Kaskad ограничен
  адресом узла (nameConstraints), и нужно узнать, как с этим справляется Windows.
- **Прислать дополнительно:** версию Windows (`winver`) и событие 20227 («Просмотр событий → Журналы Windows →
  Приложение», источник RasClient) за время попытки. Ошибка 691 — неверные логин или пароль.

### 2. IKEv2 · iPhone, iPad и macOS

- **Поставить** (17 → 1 «Протоколы»): IKEv2.
- **Выдать:** платформа «iPhone или iPad (iOS)» или «macOS», вход IKEv2 → «IKEv2 — профиль .mobileconfig»
  (`kaskad-ikev2.mobileconfig`). В профиле пароль устройства: передавайте файл только его владельцу (AirDrop,
  «Файлы», почта самому себе).
- **Подключить:**
  - iPhone/iPad: открыть файл → Настройки → «Профиль загружен» → «Установить»; затем Настройки → VPN →
    «Kaskad IKEv2».
  - macOS: открыть файл → Системные настройки → Конфиденциальность и безопасность → Профили → «Установить»;
    затем Системные настройки → VPN.
- **Успех:** статус «Подключено», значок VPN в строке состояния, адрес сменился, `gw sessions` — `ikev2`.
- **Прислать:** версию iOS/macOS и модель, установился ли профиль (Настройки → Основные → VPN и управление
  устройством), скриншот ошибки («Сервер не отвечает», «Ошибка проверки подлинности» и т. п.).

### 3. IKEv2 · Android 12+

Встроенный клиент:

- **Поставить** (17 → 1 «Протоколы»): IKEv2.
- **Выдать:** платформа «Android», вход IKEv2: инструкция «встроенный клиент Android 12+», файл
  `kaskad-ikev2-ca.crt` (центр сертификации) и поля (сервер, удалённый идентификатор, логин, пароль).
- **Подключить:**
  1. Установить сертификат: Настройки → Безопасность → Шифрование и учётные данные → Установка сертификата →
     «Сертификат ЦС» → `kaskad-ikev2-ca.crt` (предупреждение Android ожидаемо; названия пунктов у
     производителей разные).
  2. Настройки → Подключения (Сеть и интернет) → VPN → «+»: тип «IKEv2/IPSec MSCHAPv2», адрес сервера,
     идентификатор IPsec — логин, сертификат ЦС — установленный, сертификат сервера — «получен от сервера»,
     имя пользователя и пароль.
- **Успех:** значок ключа в строке состояния, адрес сменился, `gw sessions` — `ikev2`.

Приложение strongSwan (Google Play): профиль «IKEv2 EAP (логин и пароль)», сервер, логин, пароль; сертификат
ЦС — импортируйте `kaskad-ikev2-ca.crt` (⋮ → «CA certificates» → ⋮ → «Import certificate») или оставьте
автоматический выбор, если сертификат уже установлен в систему.

- **Прислать:** версию Android, модель и оболочку (One UI, HyperOS и т. п.), какой клиент, на каком шаге
  остановились; для strongSwan — журнал приложения (без пароля). Особенно интересно, какое значение в поле
  «идентификатор IPsec» сработало.

### 4. L2TP/IPsec · iPhone, Windows, роутеры

- **Поставить** (17 → 1 «Протоколы»): L2TP/IPsec (отмечен в мастере). Для роутеров без IPsec (Huawei, Xiaomi, ASUS,
  старые TP-Link): в карточке L2TP/IPsec пункт 3 «L2TP без шифрования» — трафик тогда не шифруется, включайте
  только для проверки.
- **Выдать:** вход L2TP/IPsec: поля (сервер, логин, пароль, общий ключ IPsec) и «как подключить» под систему.
- **iPhone/iPad:** Настройки → Основные → VPN и управление устройством → VPN → «Добавить конфигурацию VPN»:
  тип L2TP, сервер, учётная запись, пароль, общий ключ, «Для всех данных» включить.
- **Windows:** вход L2TP/IPsec → «L2TP/IPsec — скрипт PowerShell» (`kaskad-l2tp.ps1`; в нём общий ключ). Запуск
  как в пункте 1, затем подключение. Ошибка 809 (NAT, закрыты UDP 500/4500): перезагрузите ПК — скрипт уже записал
  `AssumeUDPEncapsulationContextOnSendRule=2`; не помогло — порты у хостера или провайдера. Ошибка 789 —
  обычно не сошёлся общий ключ IPsec.
- **Keenetic:** Интернет → Другие подключения → VPN-подключения → «Добавить подключение»: тип L2TP/IPsec, адрес
  сервера, логин, пароль, общий ключ, «Использовать для выхода в интернет».
- **TP-Link:** новая прошивка (Archer): Дополнительные настройки → VPN-клиент → «Добавить»: L2TP/IPsec. Старая:
  Сеть → Интернет → тип «L2TP» (IPsec там нет — нужен «L2TP без шифрования»).
- **MikroTik:** платформа «Роутер MikroTik», вход L2TP/IPsec → «L2TP/IPsec — скрипт RouterOS 7»
  (`kaskad-l2tp.rsc`) → New Terminal; `192.168.88.0/24` замените на свою сеть.
- **Успех:** подключение активно, устройства за роутером выходят через узел (адрес сменился), `gw sessions` —
  `l2tp`.
- **Прислать:** модель и версию прошивки роутера, скриншот страницы VPN-клиента (без пароля и ключа), системный
  журнал роутера за время попытки (MikroTik: `/log print`, последние строки про l2tp и ipsec). Android 12+
  встроенного L2TP не создаёт — там IKEv2.

### 5. SSTP · Windows и MikroTik

- **Поставить** (17 → 1 «Протоколы»): SSTP (в мастере не отмечен), TCP 4433.
- **Windows:** вход SSTP → «SSTP — скрипт PowerShell» (`kaskad-sstp.ps1`): кладёт сертификат узла в доверенные и
  выключает проверку отзыва для **всех** SSTP-подключений этого ПК. Запуск и подключение как в пункте 1.
  **Главный вопрос:** принимает ли встроенный клиент Windows адрес с портом (`узел:4433`). Сведения
  противоречивы: одни источники пишут, что `узел:порт` работает, другие — что клиент ходит только на TCP 443.
  Если подключение не пошло — пришлите код ошибки и попробуйте сменить порт на 443 (карточка SSTP, пункт 2), если
  он свободен на узле; запасной вариант — IKEv2.
- **MikroTik:** платформа «Роутер MikroTik», вход SSTP → «SSTP — скрипт RouterOS 7» (`kaskad-sstp.rsc`) →
  New Terminal. Скрипт не проверяет сертификат (`verify-server-certificate=no`).
- **Успех:** Windows — «Подключено»; MikroTik — `/interface sstp-client print` показывает флаг `R`; адрес
  сменился; `gw sessions` — `sstp`.
- **Прислать:** версию Windows или RouterOS, код ошибки, `/log print` (строки про sstp).

### 6. AmneziaWG 1.5 / 2.0 / 3.1 · приложения и Keenetic

- **Поставить** (17 → 1 «Протоколы»): AmneziaWG (одна отметка в мастере ставит три линии: 1.5, 2.0 и 3.1, у каждой
  свой порт; в «Протоколах» они отдельные строки).
- **Выдать:** платформа «iPhone или iPad», «Android», «Windows» или «macOS»; вход — одна из линий. Выдача:
  ссылка `vpn://` (для AmneziaVPN: «+» → «Вставить из буфера»), QR для AmneziaVPN, QR файла `.conf`, файл
  `.conf` (для AmneziaWG). В AmneziaVPN линию 3.1 импортируйте только через `vpn://` или его QR: импорт `.conf`
  теряет поля 3.x. QR AmneziaVPN занимает около 117 столбцов: если он не влез в окно, растяните терминал или
  «Сохранить в файлы» (PNG).
- **Проверить каждую линию** в каждом приложении, которое её понимает (минимальные версии из каталога выдачи):

  | Линия | AmneziaVPN | AmneziaWG (отдельное) |
  |---|---|---|
  | 1.5 | iOS любая; Android, Windows, macOS 4.8.8.3 | 2.0.0 |
  | 2.0 | iOS 4.8.14; остальные 4.8.12.9 | 2.0.0 |
  | 3.1 | iOS 5.0.1; остальные 5.0.1.5 | 3.1.4 (Windows 3.1.0), только `.conf` |

  В российском App Store AmneziaVPN недоступен: на iPhone — AmneziaWG или DefaultVPN.
- **Keenetic 5.1+:** платформа «Роутер Keenetic», вход AmneziaWG 2.0 (или 1.5) → файл `.conf` → Интернет →
  Другие подключения → WireGuard → «Загрузить из файла», затем «Использовать для выхода в интернет». Линию 3.1
  KeeneticOS не умеет; до 5.1.1 — только 1.0 (с 4.2).
- **Успех:** туннель поднялся, рукопожатие есть, адрес сменился, `gw sessions` — `awg1`, `awg2` или `awg3`.
- **Прислать:** приложение и версию, линию, текст ошибки, журнал приложения (без ключей); для Keenetic — версию
  KeeneticOS и раздел журнала.

### 7. WireGuard

- **Поставить** (17 → 1 «Протоколы»): WireGuard (отмечен в мастере), UDP 51820.
- **Выдать:** iPhone и Android — «WireGuard — QR-код»: в приложении WireGuard «+» → «Создать из QR-кода»
  (Android: «Сканировать QR-код»). Windows и macOS — файл `kaskad-wg.conf` → «Импорт туннелей из файла».
  Keenetic — «Загрузить из файла». MikroTik (RouterOS 7) — «WireGuard — скрипт RouterOS 7».
- **Успех:** общий; `gw sessions` — `wg`.
- **Прислать:** общее; для роутеров — модель и прошивка.

### 8. OpenVPN Connect

- **Поставить** (17 → 1 «Протоколы»): OpenVPN, UDP 1194.
- **Выдать:** платформа iPhone, Android, Windows или macOS, вход OpenVPN → файл `kaskad-openvpn.ovpn`
  (сертификаты внутри). OpenVPN Connect: «Import Profile» → «File»; на Windows ещё подойдёт OpenVPN GUI, на
  macOS — Tunnelblick.
- **Успех:** «Connected», адрес сменился, DNS работает, `gw sessions` — `openvpn`.
- **Прислать:** версию приложения и его журнал подключения (без ключей).

### 9. OpenConnect · Cisco Secure Client

- **Поставить** (17 → 1 «Протоколы»): OpenConnect, TCP и UDP 4443; сертификат узла самоподписанный.
- **Выдать:** вход OpenConnect: сервер (`https://узел:4443`), логин, пароль, отпечаток сертификата (`pin-sha256`)
  и «как подключиться».
- **Подключить:** Cisco Secure Client (iOS, Android, Windows, macOS): в настройках выключить «Block connections
  to untrusted servers», добавить подключение, на вопросе о сертификате — «Connect Anyway». OpenConnect GUI
  (Windows, macOS): «New profile» → сервер → «Connect», сверить отпечаток.
- **Успех:** подключено, адрес сменился, `gw sessions` — `ocserv`.
- **Прислать:** какой клиент и версию, ошибку, что показал клиент про сертификат.

### 10. SOCKS5 · Telegram

- **Поставить** (17 → 1 «Протоколы»): SOCKS5, TCP 1080 (UDP — переключатель в карточке SOCKS5, пункт 3). Нужен
  xray: на сервере без «Прокси для API Telegram» установка скачает его сама; не вышло — скажет почему.
- **Выдать:** платформа «iPhone или iPad» или «Android» (SOCKS5 отметьте вручную, см. «Общий порядок», п. 2), вход
  SOCKS5 → «SOCKS5 — прокси для Telegram»: ссылка `tg://socks?server=…&port=…&user=…&pass=…` (для браузера —
  `https://t.me/socks?…`).
- **Подключить:** отправьте ссылку себе в «Избранное» Telegram и нажмите — Telegram покажет окно прокси →
  «Подключить прокси».
- **Успех:** Настройки → Данные и память → Прокси: «подключен»; сообщения и медиа идут; звонок работает
  (нужен UDP). Маршрут устройства действует и здесь: при «пуле» трафик Telegram уходит через выход.
- **Прислать:** версию Telegram и платформу, скриншот статуса прокси, работают ли звонки.

### 11. Маршруты и отказ выхода

Подключите любое устройство, проверяйте адрес на сайте «мой IP». Маршрут устройства: 17 → 2 → 6, общий: 17 → 3.

1. **Пул** (по умолчанию): адрес — одного из выходов пула.
2. **Один выход:** «Только выход «…»» — адрес этого выхода; туннель не рвётся (уже открытые соединения дожидаются
   конца на старом выходе, новые идут по новому).
3. **Напрямую:** адрес узла.
4. **Блок:** интернета нет, страницы не открываются, туннель при этом «подключён».
5. **Отказ выхода, маршрут «пул» или «выход» (при отказе — блок, по умолчанию):** выключите выход для шлюза
   (17 → 3 → 4) и, отдельно, сломайте его по-настоящему (остановите сервер выхода). В течение около 30 секунд
   интернет на устройстве пропадает. **Адрес узла не должен появиться нигде** (ни в «мой IP», ни в других
   сервисах). Включили выход обратно — интернет вернулся.
6. **Несколько выходов:** выключите один — устройство переезжает на другой (адрес сменился), без «напрямую».
7. **«При отказе — напрямую»** (17 → 3 → 2): отказ выхода — адрес узла. Это ожидаемо только в этом режиме;
   верните «блок».
- **Прислать:** на каждом шаге — что показал «мой IP» (адрес выхода, узла или страница не открылась), через
  сколько секунд среагировал отказ; `/opt/kaskad/bin/kaskadctl gw exits`; строки `GW exit` из журнала.

### 12. Пробросы 3.0.1: переезд и возврат

Нужен сервер со старым Kaskad: бесплатный (v1.0/1.1; лучше три правила, два из них на один порт) или PRO 2.x
(лучше 2.13 и 2.3, с ботом, мониторами и «Прокси для API Telegram»); желательно с включённым UFW и Docker с
опубликованным портом. И клиент, который ходит через проброс.

1. **До:** убедитесь, что клиент работает через каждый проброс. Сохраните `iptables -t nat -S` (для отчёта).
2. **Переезд:** поставьте 3.1.0 (см. «Перед началом»). При первом запуске Kaskad показывает план — что
   перенесёт, что нет (и почему), что останется, путь резервной копии в `/var/backups/kaskad/…` — и спрашивает:
   1) Перевести сейчас, 2) Позже, 3) Не спрашивать больше. Скриншот плана — в отчёт. Ответьте «1».
   **Ожидание:** «Пробросы работают через nftables»; клиенты работают, открытые соединения не рвутся; меню 5
   показывает трафик каждого проброса, и он растёт; меню 16 — «таблица kaskad: есть, … совпадает с настройками».
3. **Перезагрузка** узла: пробросы вернулись сами; бот, мониторинг и «Прокси для API Telegram» живы.
4. **Сторож:** `iptables -F` (если iptables есть), `nft flush ruleset`, `ufw reload` — за минуту пробросы
   на месте, в журнале строка `NET repair`.
5. **Бесплатный скрипт поверх** (если есть): команда `gokaskad` вернулась на 3.x, меню предлагает «Забрать сейчас».
6. **Вернуть iptables:** 16 → 2. Прочтите предупреждение (на Debian 12+ и Ubuntu 24.04+ без netfilter-persistent
   пробросы после перезагрузки пропадут) и ответьте «y». **Ожидание:** пробросы в iptables, клиент работает.
   Затем 16 → 1 — снова nftables.
7. **Вернуться на 2.13:** 16 → 4. Шлюз при этом удаляется (Kaskad предупреждает; пользователей и устройства можно
   оставить). На Debian 12+ и Ubuntu 24.04+ Kaskad 2.x при запуске ставит iptables-persistent, а это удаляет UFW —
   меню предупреждает об этом до вопроса. **Ожидание:** `gokaskad` — Kaskad PRO 2.13, пробросы видны в его «Правилах»,
   бот отвечает. Потом снова обновитесь до 3.1.0.
- **Прислать:** систему и версию, что было до (версия Kaskad, число правил, UFW и Docker), скриншот плана,
  результаты пунктов 2–7, `/opt/kaskad/bin/kaskadctl net status`, `/opt/kaskad/bin/kaskadctl migrate backups`,
  последние 50 строк журнала (`MIGRATE`, `ROLLBACK`, `NET`).

## Известные ограничения

- В iOS и macOS нет встроенного SSTP и PPTP; Android 12+ не создаёт L2TP и PPTP — там IKEv2.
- KeeneticOS не умеет AmneziaWG 3.1; в RouterOS AmneziaWG нет (только в контейнере) — для MikroTik берите WireGuard.
- IPv6 клиентам шлюза не выдаётся; DNS шлюза убирает ответы AAAA.
- Устройства шлюза не видят друг друга и частные сети сервера.
- PPTP шифрует слабо: проверять только на старом роутере, который не умеет ничего другого.
