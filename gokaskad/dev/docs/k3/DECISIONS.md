«Решения координатора …», B13, H, I, J), `k3/handoff/DIGEST-2026-10-15-16.md` (DG, хронология владельца),
`k3/handoff/SPEC-todo-coordinator.md` (TODO) и решения, записанные в самих ТЗ.

## Правило

1. **Новое решение — новая строка** с очередным номером `D-NNN` (номера не переиспользуются, строки не удаляются).
   В месте, где решение применено (ТЗ, план, отчёт, комментарий в коде), рядом ставится пометка « (D-NNN)».
   Столбец «Где» — полный список мест. В ТЗ (SE, SG, RN, RF, HY) пометка стоит в каждом разделе, названном в «Где»;
   места вне ТЗ (план, `process/`, память, код) перечислены только в «Где». Разделы истории правок ТЗ и сводные строки
   («по решениям владельца 14.10») не помечаются.
2. **Правка решения** — новая строка «заменяет D-NNN: …»; у старой строки в столбце «Решение» — «**заменено D-MMM**»
   (если меняется часть — «заменено D-MMM в части …»). Расширение без отмены — «дополнено D-MMM» / «дополняет D-NNN».
   Поиск `D-NNN` (`git grep -n "D-NNN"` в репозитории, `grep -rn` в `k3/handoff`) находит все места старого решения —
   их правят вместе с картой зависимостей (правило владельца 15.10, D-064).
3. Пометка « (D-NNN)» не меняет смысла текста. Сверка частей ТЗ с прежним текстом выбрасывает такие пометки
   (`k3/stand/logs/R-s1-docs-parts.py verify`), поэтому формат строгий: пробел, скобка, `D-` и три цифры; несколько —
   через «, ».
4. «Кто»: **владелец** — его слово или ответ; **координатор** — решение координатора (с 15.10 владелец поручил решать
   самому, D-055; где сказано «владелец может поменять» — так и есть); **владелец ← координатор** — предложение
   координатора, которое владелец принял; **владелец; детали — координатор** — слово владельца, подробности дописал
   координатор; **координатор (по вопросу владельца)** — владелец спросил, решил координатор. Выводы координатора
   владельцу не приписываются.

Сокращения в «Где»: SE — `docs/k3/SPEC-stage1-exits.md`, номер части в скобках — файл `SPEC-stage1-exits/NN-…md`
(например, «SE §3.2 (05)»); SG — `SPEC-stage1-exit-groups.md`; RN — `SPEC-stage1-rename.md`; RF —
`SPEC-stage1-rf-mark-builtin.md`; HY — `SPEC-stage1-hy2-inbound.md`; UX — `k3/handoff/UX-FOUNDATION.md`; задачи —
строки таблицы SE §10.1 (13): T1…T15, R1…R7, N1…N7, Q1…Q4, Y1…Y6, F0…F4.
