# Kaskad PRO — гайд для агента (ресурс `kaskad://guide`)

Ты управляешь узлом Kaskad PRO 3.x через MCP-сервер `kaskad-mcp`. Узел — сервер, через который пользователи и их
устройства (телефоны, ноутбуки, роутеры) выходят в интернет по протоколам (WireGuard, AmneziaWG, L2TP, IKEv2 и
другие), а трафик уходит дальше через **выходы** — ключи VLESS и AmneziaWG других серверов. Этот гайд — всё, что
нужно, чтобы делать это безопасно. Прочитай его до первого изменяющего вызова.

## 0. Девять правил

1. **Сначала смотри, потом меняй.** Начинай с `gateway_status` и `scheme`. Не меняй то, чего не видел.
2. **Перед каждым изменением скажи человеку, что именно сделаешь.** Одно действие — одно согласие.
3. **Разрушительные инструменты — только с `confirm`** и только после явного «да» человека на это конкретное действие
   (раздел 5). Никогда не подставляй `confirm` сам «на всякий случай».
4. **Секреты не повторяй.** `device_issue`, `page_url`, `page_on`, `page_rotate`, `page_sub_url`, `page_sub_on`,
   `page_sub_rotate` возвращают ключи, пароли и
   секретные ссылки: отдай их тому, кто попросил, и не пересказывай в других ответах, не сохраняй в заметки.
5. **Ключ выхода — только в `exit_preview` и `exit_add`.** Он уходит на сервер через stdin; в ответах и журналах его
   нет. Не повторяй его в чате.
6. **`force` — только по прямой просьбе человека.** Без него Kaskad отказывает, если порт держит другая программа;
   с ним — забирает порт, и та программа перестаёт работать. У `awg_engine_set` `force` значит другое: смешанный
   режим модуля и программы.
7. **Код 6 (`locked`) — не ошибка.** Узел что-то меняет (меню, панель, бот); подожди 30–60 с и повтори один раз.
8. **Не обещай того, чего нет в ответе.** `usable`, `running`, `ok` — факты; «скорее всего работает» — нет.
9. **Доступ в панель, пароли, ссылки входа, переезд движка, удаление Kaskad — не твоё.** Таких инструментов нет
   намеренно; скажи человеку, где это сделать (SSH-меню `gokaskad`, бот, панель).

## 1. Что это и что под капотом

```
пользователь → устройство → протокол (вход) → правила → маршрут → выход (VLESS / AmneziaWG) → интернет
```

- **Пользователи** (`u-xxxxxxxx`) — владельцы устройств. У пользователя может быть свой маршрут и свой профиль правил.
  «Человек» в этом гайде — тот, с кем ты говоришь (администратор узла), а не пользователь шлюза.
- **Устройства** (`d-xxxxxxxx`, у каждого есть логин) — то, что подключается. Устройству выдают **протоколы**
  (`access`), для каждого создаются свои ключи. Настройки для подключения выдаёт `device_issue`.
- **Протоколы (входы)**: `wg` (WireGuard), `awg1` / `awg2` / `awg3` (AmneziaWG 1.5 / 2.0 / 3.1), `l2tp`
  (L2TP/IPsec), `pptp`, `sstp`, `ikev2`, `openvpn`, `ocserv` (OpenConnect), `socks5`, `vless` (VLESS Reality:
  ссылка `vless://` для v2RayTun, Hiddify, Streisand, v2rayN), `hy2` (Hysteria2 по UDP: ссылка `hysteria2://`). Сначала протокол
  устанавливают на узле (`inbound_install`), потом выдают устройствам.
- **Выходы** (`e-xxxxxxxxxx`) — ключи пула «Прокси для API Telegram»: VLESS и AmneziaWG. Сторож проверяет их каждые
  несколько секунд; `usable: true` — работает. Пул один на узел: его же использует Telegram-бот.
- **Маршрут** (`via`): `pool` — через рабочие выходы пула, `exit:<id>` — через один выход, `group:<gid>` — через
  группу выходов (имя — `group_name`), `direct` — напрямую с этого сервера, `block` — никуда. `fail` — что выбрано у
  самого маршрута, если выходы не работают: `block` (без интернета, зато ничего не утекает мимо выхода) или `direct`.
  **Действует `fail_eff`**: `direct`, если `direct` выбран у маршрута **или у его группы** выходов (у пула — группа
  «Основная», у `exit:<id>` — группа этого выхода); на него и опирайся. Действующий маршрут устройства берётся по
  цепочке: своё → пользователя → по умолчанию узла (`scheme` показывает, откуда он: `from` = device / user / default).
- **Правила** «Россия напрямую»: профиль `ru_direct` — российские адреса и сайты напрямую, остальное через выход;
  `all_exit` — всё через выход. Плюс блокировка рекламы и торрентов (`rules_block`) — для всех сразу.
  **⚠РФ.** Во встроенном списке «всегда через выход» есть ресурсы организаций, признанных экстремистскими в РФ (Meta и
  др.), поэтому `ru_direct` включается только с согласием человека (галочка ⚠РФ) — раздел 5, «Галочка ⚠РФ». На новом узле профиль по умолчанию — `all_exit`.
- **Пробросы портов** (`forward_*`) — старая часть Kaskad: входящий порт сервера → адрес:порт. Работают на движке
  nft; на старом движке (legacy, iptables) — код 5, перевод делает человек (меню 16).
- **Домен и сайт**: домен с сертификатом Let's Encrypt нужен для сайта-маскировки, панели на домене и SSTP/OpenConnect
  на настоящем сертификате.

Под капотом каждый инструмент — команда `kaskadctl … --json` на сервере (та же, что зовут SSH-меню, бот и веб-панель).
Ответ инструмента — её JSON как есть. Изменения ядро делает под замком `state.lock`, применяет и только потом
сохраняет; неудача — ничего не записано.

## 2. Начало сессии — порядок

1. `gateway_status` — шлюз включён? Протоколы работают? Выходы `usable`? Есть `problems`? Проблема `no_exits` —
   у устройств нет интернета: ни один выход не работает, а при отказе стоит «блокировать».
2. `scheme` — кто есть, у кого какие устройства, протоколы, маршруты.
3. По задаче: `exits_list`, `inbounds_list`, `devices_list`, `rules_status`, `site_status`.
4. Шлюз выключен (`enabled: false`) — большинство изменений бессмысленно: скажи человеку. Включает `gateway_enable`
   (нужен движок nft; проверка заранее — `gateway_probe`).

Ресурсы `kaskad://status`, `kaskad://scheme`, `kaskad://exits`, `kaskad://devices`, `kaskad://version` дают те же
данные без вызова инструмента.

## 3. Каталог инструментов по задачам

### 3.1 Обзор и проверка (только чтение)

| Инструмент | Когда |
|---|---|
| `version` | версия Kaskad |
| `gateway_status` | главная сводка узла — всегда первым |
| `scheme` | пользователи → устройства → протоколы → маршруты → выходы, без секретов |
| `gateway_probe` | можно ли вообще включить шлюз на этом сервере |
| `gateway_check` | проблемы шлюза без исправлений (isError — проблемы есть) |
| `net_status`, `net_check` | движок пробросов (nft/legacy) и его проверка |
| `sessions_list` | кто подключён прямо сейчас |
| `gw_activity` | активность одного пользователя или устройства за сутки, 7 или 30 дней: время на связи, «трафик шёл», объём ↓ ↑ — только объём и время, без адресов и сайтов; по всем пользователям сразу — нет |
| `traffic_trace` | «куда пойдёт трафик» устройства или пользователя до домена/адреса |
| `panel_status`, `bot_status`, `bot_proxy` | веб-панель и Telegram-бот (без паролей и токена); `bot_proxy` — как бот ходит в Telegram (через выходы группы, напрямую, нет связи) |
| `update_check` | есть ли новая версия Kaskad |
| `host_health` | здоровье сервера: процессор, память, диск, сеть, часы, сертификаты; светофор и советы (пункт 22 SSH-меню) |
| `host_tariff` (`action`: `show` — по умолчанию, `preview`) | тариф сервера: скорость порта (для правила здоровья «порт») и трафик в месяц (для цены проверок), откуда каждое значение; `preview` — изменение с кодом, ничего не сохраняет |
| `host_score` (`action`: `score` — по умолчанию, `history`, `show`, `schedule`, `price`, `share`) | сервер относительно своей истории (как «Обзор › Проверка сервера» в панели): главное число `summary.rel_total` — 100 как обычно у этого сервера, звенья (сейчас, «обычно», `rel` — от обычного; нет `rel` — история звена меньше 3 дней: «сравнивать пока не с чем: история N из 3 дней», или свежего значения нет), ▲/▼; без балла 0–1000 и выводов; `history` — проверки за 30 дней (до 50; кто запустил: `auto` — повтор после резкого падения; итог, причина пропуска), `show` — одна проверка подробно; `schedule` — расписание проверок: записи с номерами, следующие проверки, цена `cost` (трафик и процессор в сутки и в месяц), `armed`, `retry`; `price` — цена одной проверки до запуска: трафик, процессор, каких программ нет; `share` — что покажет ролик «Поделиться» (собирает браузер в панели; машина, страна, процессор — только флагами `tariff`, `country`, `cpu`; адресов и имён нет) |

### 3.2 Пользователи и устройства

| Инструмент | Тип | Когда |
|---|---|---|
| `users_list`, `devices_list` | чтение | список; `devices_list(user=…)` — устройства одного пользователя |
| `device_offers` | чтение | какие протоколы выдавать устройству этой платформы первыми |
| `user_add` | изменение | новый пользователь (без устройств) |
| `device_add` | изменение | устройство пользователю: `platform`, `access` (протоколы через запятую) |
| `device_grant` | изменение | ещё один протокол устройству |
| `device_issue` | чтение, **секрет** | настройки для подключения: инструкция + записи, QR-коды — картинками |
| `user_route`, `device_route` | изменение | свой маршрут (`inherit` — как уровнем выше) |
| `user_enable` / `user_disable`, `device_enable` / `device_disable` | изменение | выключить, не удаляя (ключи сохраняются) |
| `device_revoke` | **разрушительное** | снять протокол — его ключи стираются |
| `device_reset` | **разрушительное** | новые ключи и пароли — старые настройки перестают работать |
| `device_delete`, `user_delete` | **разрушительное** | удалить навсегда (`with_devices` — вместе с устройствами) |
| `pages_list`, `page_url` | чтение (`page_url` — **секрет**) | личная страница пользователя с настройками его устройств |
| `page_on` / `page_off` | изменение (`page_on` — **секрет**) | включить страницу и получить ссылку / выключить |
| `page_rotate` | **разрушительное**, **секрет** | новая ссылка, старая умирает |
| `page_sub_list`, `page_sub_url` | чтение (`page_sub_url` — **секрет**) | подписка для приложений (v2RayTun, Hiddify, incy): своя ссылка, не страница; в ней ключи VLESS, Hysteria2, AmneziaWG и WireGuard всех устройств пользователя |
| `page_sub_on` / `page_sub_off` | изменение (`page_sub_on` — **секрет**) | включить подписку и получить ссылку / отозвать |
| `page_sub_rotate` | **разрушительное**, **секрет** | новая ссылка подписки, старая умирает — в приложении заменить |

`user`/`device` принимают id, имя (и логин у устройства). Имя неоднозначно — ядро откажет; бери id из `scheme`.

**Переименование** (`person_rename`, `device_rename`, `exit_rename`, `inbound_label`, `exit_sub_rename`,
`forward_rename`, `server_rename`; изменение, без перезапуска и без обрыва): меняется подпись, **id не меняется** —
ключи, логины, ссылки подписок и маршруты работают как раньше; **выданное не переименуется** (файлы `.conf`, QR,
`vless://#…` у пользователя остаются со старым именем — перескажи подсказку `note` из ответа). Имя — 1–40 знаков, без
управляющих и невидимых знаков и без `|`; пусто — сброс (кроме пользователя и устройства). Такое же имя у другого пользователя —
отказ (код 3). У устройства, выхода и прочих — код 3 и `data.need = "confirm_duplicate"` со списком `duplicates`:
спроси человека и повтори с `allow_duplicate=true`. К сущности, чьё имя начинается с `-`, обращайся по id: такую
позиционную ссылку сервер не пропустит. Пример: `device_rename(device="d-1a2b3c4d", name="Телефон Оли")`.

### 3.3 Протоколы (входы)

| Инструмент | Тип | Когда |
|---|---|---|
| `inbounds_list` | чтение | что установлено, работает, порты |
| `inbounds_plan` | чтение | какие порты займёт установка и кто их держит — до установки |
| `inbound_install` | изменение | установить НОВЫЙ протокол; уже установленный — отказ (код 3) |
| `inbound_reinstall` | **разрушительное** | переустановить установленный (порт и ключи сохраняются, где можно) |
| `inbound_enable` / `inbound_disable` | изменение | включить / выключить, не удаляя |
| `inbound_port` | **разрушительное** | сменить порт — выданные настройки со старым портом перестают работать |
| `inbound_option` | изменение | `l2tp` `plain` (L2TP без IPsec), `socks5` `udp` |
| `inbound_label` | изменение | понятная подпись протокола («AmneziaWG 2.0 — для роутеров»); в выданные настройки не попадает |
| `inbound_uninstall` | **разрушительное** | удалить протокол (порт и ключи сервера хранятся до новой установки) |
| `pki_rotate` | **разрушительное** | новый центр сертификации IKEv2 — всем устройствам IKEv2 настройки заново |
| `vless_show` | чтение | VLESS: режим (`security`: `tls` — свой домен и сайт, по умолчанию; `reality` — маскировка под чужой сайт), выбор человека `want`, `reason` и `reason_text` (почему Reality), `forced`, `fix` (что исправить), `recommend` (перейти на TLS и сколько устройств получат ссылки заново), `reality_risks` (текст рисков для показа), `node_domain`, порт, сайт маскировки и его проверка, публичный ключ, shortId; `tls_block` — почему TLS сейчас нельзя |
| `vless_masks` | чтение | сайты маскировки на выбор; `check` — проверить каждый с узла (TLS 1.3, секунды на сайт) |
| `vless_mask` | **разрушительное** | сменить сайт маскировки (`own` — свой сайт узла, `auto` — первый подходящий); ссылки VLESS — заново |
| `vless_rekey` | **разрушительное** | новые ключ узла и shortId VLESS — всем устройствам VLESS ссылки заново |
| `hy2_show` | чтение | Hysteria2: порт и смена портов (`hop`), маскировка Salamander (`obfs`), сертификат (`cert_mode`: `domain` — домена, `self` — самоподписанный, отпечаток `pin` в ссылке), `warnings` (без домена; UDP в мобильных сетях РФ не проверен); без секретов |
| `hy2_option` | **разрушительное** | `hop` = `20000-20099` / `off` — смена портов (до 100 портов, занятый диапазон — отказ со списком), `cert` = `domain` / `self`; ссылки Hysteria2 — заново (`reissue`). Маскировка — `inbound_option hy2 obfs on/off`. Hysteria2 бот не выдаёт: ссылку и QR — панель, страница /p/ или `device_issue` |
| `hy2_rekey` | **разрушительное** | новый самоподписанный сертификат Hysteria2 — ссылки с прежним отпечатком заново |
| `vless_sync` | **разрушительное** | режим VLESS по выбору узла (`want`): без устройств сам переходит на TLS, с устройствами — только рекомендация (и у записи до выбора режима; переход — `vless_mode`); ссылки меняет лишь починка: TLS без сайта → Reality, тогда всем устройствам VLESS ссылки заново |
| `vless_mode` | спросить человека | `tls` (рекомендуем) или `reality`. Reality при домене — **только по прямой просьбе человека** после того, как ему показан текст рисков (`vless_show` → `reality_risks`): в `accept_risks` — фраза, которую он подтвердил, в `risks` и `site` — `reality_risks.ver` и `reality_risks.site`. Цена новых ссылок — отказом ядра (code 3, `data.need = vless_change`, `data.text`): покажите её человеку, `yes: true` — только после его согласия. `data.site_on: false` — сайт на домене выключен и включится вместе с переходом (это сказано в `data.text`) |

### 3.4 Выходы и маршруты

| Инструмент | Тип | Когда |
|---|---|---|
| `exits_list` | чтение | выходы, `usable`, рукопожатие, `text` словами |
| `exit_preview` | чтение | что в ключе: тип, где, есть ли уже в пуле, проблемы — ничего не меняет |
| `exit_add` | изменение | добавить ключ (или несколько) в пул |
| `exit_enable` / `exit_disable` | изменение | включить / выключить выход для шлюза (ключ остаётся) |

| `exit_delete` | **разрушительное** | убрать ключ из пула |

| `exit_sub_restore` | изменение | вернуть исключённые: ключи подписки, удалённые из пула вручную (их обновление не возвращает), приходят снова |

| `default_route_set` | изменение | маршрут по умолчанию узла |
| `exit_groups_list` | чтение | группы выходов: `label` — понятное имя, `role`, выходы по уровням, способ уровня (`method`; `order` = `manual` — по порядку вручную: автовыбор выключен, способ сохранён), уровень сейчас, последний шаг, устройства без выхода, `rev` |
| `exit_policy_get` | чтение | настройки выходов по группам (набор, уровни, условия, частота проверок) — только просмотр |
| `exit_transitions` | чтение | смены состояния выхода с причинами |
| `exit_standby` / `exit_restore` / `exit_maintenance` | изменение | выход в запас, обратно в работу, на обслуживание |
| `exit_accept_country` | изменение | принять новую страну выхода |
| `exit_quota_set` / `exit_quota_clear` | изменение | квота трафика выхода: задать (не заданное остаётся) / снять |
| `exit_move` | изменение | перенести выход в группу той же роли |
| `group_flap_standby_set` | изменение | «нестабильный выход — в запас на 15 мин» у группы |
| `exit_speedtest` | изменение | тест скорости сейчас (тратит лимит тестов; ждёт до 60 с); отказ — сразу, причина в `data.why` |
| `exit_speedtest_force` | **разрушительное** | то же сверх суточного лимита (месячный остаётся) — только по просьбе человека; `confirm` = `id` |
| `exit_tofu_check` | изменение | отпечаток сертификата ключа без своей проверки (идёт к серверу ключа) — показать человеку |
| `exit_add_tofu` | **разрушительное** | добавить ключ, закрепив этот отпечаток; `confirm` = `pin_tofu` — только с согласия человека |
| `exit_policy_reset` | **разрушительное** | сбросить группу к набору (`preset`); `confirm` = `group` |
| `exit_move_role` | **разрушительное** | перенос выхода между ролями (зарубежная ↔ внутренняя); `confirm` = `id` |
| `group_delete` | **разрушительное** | удалить группу; куда выходы и маршруты пользователей — параметрами; `confirm` = `group`; `with_keys` — внутренняя группа вместе с её ключами (+ `confirm_with_keys`) |
| `tz_get` / `tz_set` | чтение / изменение | часовой пояс Kaskad (по нему время в пушах) |
| `gateway_addresses` | чтение | адреса сервера (интерфейсы, внешние адреса облака с NAT, добавленные вручную): какой основной, какой адрес для клиентов; `client_found=false` — адреса для клиентов на сервере нет; `client_primary=false` — он есть, но в интернет сервер выходит с другого (`primary`) |
| `gateway_set_host`, `gateway_detect_host` | **разрушительное** | адрес для клиентов в настройках устройств: задать / определить заново; сменился — все настройки выдать заново. IPv4 — только из `gateway_addresses` (иначе отказ `address_not_here`); `force` — только по прямой просьбе человека |
| `gateway_addresses_in` | **разрушительное** (`confirm` = имя инструмента) | на каких адресах сервера протоколы и свой сайт принимают подключения: `ips` — только на этих (через запятую), `all=true` — снова на всех (возврат, без отказа). Устройства на невыбранных адресах (старые настройки, домен на другом адресе) теряют связь. SSH, пробросы и порт 80 — всегда на всех. Отказы: `client_out` (нет адреса для клиентов), `panel_out` (нет адреса панели и подписок), `address_not_here`; предупреждения — домен, SSH через другой адрес, Hysteria2 с маскировкой и AmneziaWG на движке «программа» отвечают только с основного. |
| `gateway_exit_src` | изменение | с какого адреса сервера выход (`exit`) или все выходы группы (`group`) подключаются к своим серверам; `ip=main` — по маршруту системы. AmneziaWG — SNAT ноги (отказ `route_other`, `same_endpoint`), остальные — `sendThrough`. Адрес пропал — выход временно с основного, выбор остаётся. «Прокси для API Telegram» ходит к выходам VLESS, Hysteria2, Shadowsocks, Trojan и VMess всегда с основного адреса (к AmneziaWG — тоже, пока шлюз выключен). |

Группы выходов (этап 1): маршрут пользователя или устройства может идти через группу — `via` = `group:<id группы>` (только
зарубежная). `fail` = `block` у маршрута через выходы значит «как у группы» (её `fail` — что она делает, когда все её
выходы недоступны), `direct` — напрямую с сервера. Создать группу, переименовать её, настроить уровни и условия — только
человек в панели: инструментов для этого нет, и сырой JSON политики не принимается. Каждая запись политики берёт
`dry=true` («что изменится»: `moves` — какие устройства сменят путь) и `rev` (версия, которую ты прочитал в
`exit_groups_list` или `exit_policy_get`; изменили с тех пор — `conflict`, перечитай и спроси человека снова). Перед
`exit_policy_reset`, `exit_move_role`, `group_delete` покажи человеку `moves` сухого прогона.
Ключ без своей проверки сертификата (allowInsecure, без `pcs`/`pinSHA256`) `exit_add` не добавит: сначала
`exit_tofu_check` — покажи человеку отпечаток и предупреждение, затем, только после его «да», `exit_add_tofu` с этим
`pin_tofu`. Сервер сменил сертификат между показом и согласием — отказ, ничего не закреплено.

`kind` выхода: `awg` | `xray`; протокол выхода через xray — в `proto` (`vless`, `hysteria2`, `shadowsocks`, `trojan`,
`vmess`); в 3.3.5 и раньше было `vless`. `role` — `abroad` | `ru`. Вид **входа** `vless` — другое, он не менялся.
Балансировщик xray-выходов (`balancer` в `traffic_trace`, `highlight.balancer`) — `xray`; в 3.3.5 было `vless`.

### 3.5 Правила

| Инструмент | Тип | Когда |
|---|---|---|
| `rules_status` | чтение | профиль узла, готовы ли списки (`ready`), блокировки |
| `rules_default` | изменение | профиль узла: `ru_direct` / `all_exit` |
| `rules_profile` | изменение | профиль пользователя или устройства (`inherit` — как уровнем выше) |
| `rules_consent` | изменение | подтвердить ⚠РФ без смены профиля (`rf.mode` = `legacy` / `need`, `rf.uncovered`) |
| `rules_ru_via` | **разрушительное** | «Российские сайты» пользователя или устройства: внутренняя группа (`g-…`, `role` = `ru` в `exit_groups_list`), `direct` или `inherit`; `confirm` = `id` |
| `rules_block` | изменение | реклама / торренты: `on` / `off` — для всех сразу |
| `rules_update` | изменение | скачать списки сейчас (таймер делает это раз в сутки) |

Внутренние группы (этап 1, T15): их ключи — домашний роутер или сервер в России (`exit_add` с `group` внутренней
группы — ключ ляжет только во внутренние выходы; саму группу создаёт человек в панели). Через группу идут только
российские сайты и только у тех, кому её выбрали `rules_ru_via`, и только при профиле «Россия напрямую» (согласие ⚠РФ
`rules_ru_via` не даёт и не спрашивает). Российский трафик такого пользователя пойдёт с IP его роутера — провайдер роутера
увидит эти соединения: перед `rules_ru_via` с группой скажи это человеку и спроси. Куда идёт российский сайт сейчас —
`traffic_trace`: поле `ru` (`group`, `name`, `step` — `exit` / `last_direct` / `last_block` / `direct`, `exit`, `tier`,
`since`, `offline` — сервер не достаёт до российских адресов, `chain`).
Последнюю внутреннюю группу с ключами без `with_keys` не удалить (`conflict`, `data.exits` — её ключи): перенести их
некуда. С `with_keys=true` (и `confirm_with_keys="with_keys"`) она уходит вместе с ключами — ключи уйдут с сервера, их
не вернуть; у тех, кто её выбрал, российские сайты — по `reassign` (`direct` — с сервера напрямую). Сначала `dry=true`:
`drop` — ключи, которые удалятся; покажи их человеку и спроси. Подписка группы держит её ключи — сначала удалить её.

## 4. Обязательные порядки операций

### 4.1 Новый пользователь с устройством и QR (подсказка `onboard_person`)

1. `gateway_status` — шлюз включён, нужные протоколы работают.
2. `device_offers(platform)` — что выдавать первым. Не установлен — предложи `inbound_install` (с согласия).
3. `users_list` — пользователь уже есть? Тогда не создавай второго.
4. `user_add(name)` → `device_add(user, name, platform, access="awg2,wg")`.
5. `device_issue(device)` — перескажи `howto` по шагам; QR-коды придут картинками, покажи их. Записи `.conf` и
   ссылки `vpn://` — секрет: не дублируй их текстом без просьбы.
6. `traffic_trace(who=<id устройства>, target="youtube.com")` — путь ведёт через рабочий выход.

Нет программы `qrencode` на сервере — у записи будет `png_error` вместо картинки: скажи человеку
(`apt install qrencode` или SSH-меню → 17), настройки остаются в тексте.

### 4.2 Добавить выход и проверить (подсказка `add_exit`)

1. `exits_list` — что уже есть.
2. `exit_preview(key)` — покажи человеку, что в ключе (тип, где), и нет ли его уже в пуле.
3. `exit_add(key)` — первый ключ AmneziaWG может собирать модуль ядра 1–3 минуты (до 23 минут, если apt занят).
   Предупреди и жди. Код 3 — все ключи уже в пуле.
4. `exits_list` — `usable: true`? Сторожу нужно несколько секунд; `false` — повтори через 30–60 с, потом смотри `text`.
5. `traffic_trace(who="-", target="youtube.com")` — путь через новый выход или пул.

### 4.3 Куда пойдёт трафик (подсказка `where_traffic`)

`scheme` → `traffic_trace(who, target[, inbound])` → `exits_list` → `rules_status`. Вердикт: `exit` (через выход),
`direct` (напрямую), `block`. При `ru_direct` российский адрес идёт напрямую, только если списки загружены
(`rules_status.ready`). Менять маршрут или профиль — только с согласия.

### 4.4 Установить протокол

`inbounds_plan(kinds)` → если порт занят — покажи, кем; `inbound_install(kind[, port])`. Отказ с кодом 3 и
`data.installed` — уже стоит (переустановка — `inbound_reinstall`, разрушительное). Код 5 с `data.needs_key` —
нет ядра AmneziaWG и ключа GitHub: ключ задаёт человек (SSH-меню 8 → 6 или панель). Долго: до 30 минут на пакеты.

### 4.5 Домен, сертификат, сайт

`site_domain_set(name)` (ответ — DNS сразу) → `site_dns(wait=120)` до готовности → `site_email_set` (по желанию) →
`site_cert_issue` → `site_mode(mode="site")` или `site_template_set` → `site_check`. Отказ `site_cert_issue` —
`reason` и `text`: порт 80 занят, DNS не на сервер, лимит Let's Encrypt (`retry_after`).

### 4.6 Сменить движок AmneziaWG

`awg_engine_status` → `awg_engine_check` / `awg_engine_preview(engine)` → согласие (клиенты переподключатся за
15–25 с) → `awg_engine_set(engine)`. Ответ с `rolled_back` — движок не сменён, причина в `reason`/`warnings`.

### 4.7 Обновить Kaskad

`update_check` → `available: true` — назови версии человеку (та же версия при `available: true` — исправление без смены номера) → согласие → `update_run(confirm="update_run")`. Назови и ветку (`branch`): `auto: true` — она выбрана сама (`main` → `test` → `k3`, в `k3` — тестовые сборки); `remembered: true` — ветка `k3` записана в настройки узла, скажи об этом. `partial: true` и `warnings` — файл новый, но не всё перешло на него: перескажи человеку. Бот перезапускается; если новая версия
не поднялась, вернётся прежняя (код 4). После обновления **переподключи MCP-сервер**: каталог инструментов мог
измениться.

### 4.8 Пользователь не может подключиться

`scheme` (включены ли пользователь и устройство, есть ли нужный протокол) → `inbounds_list` (протокол `running`) →
`sessions_list` (подключался ли) → `exits_list` (есть ли рабочий выход; при `fail_eff: block` и мёртвых выходах
интернета нет, при `fail_eff: direct` трафик идёт с адреса сервера) → `traffic_trace`. Крайние меры — `device_reset` (новые ключи) и `device_issue`, только с согласия.

### 4.9 Расписание проверок сервера
1. `host_score(action="schedule")` — что уже есть и сколько стоит (каждая проверка тратит трафик).
2. Только по просьбе человека: `host_bench_schedule(action="add", …)` (или `on`, `off`, `rm` с номером записи
   `entry`; у `rm` ещё `confirm` = тот же номер) **без** `code` — ответ `dry: true`: список после изменения, `cost`,
   `consent`, `errors` и `code`. Ничего не сохранено.
3. Покажи человеку изменение и цену. Согласен — тот же вызов с теми же значениями и `code`. Сервер сверяет код:
   расписание успело измениться или значения другие — отказ `code_mismatch`, начни с шага 1.
4. `consent: true` — трафик в месяц вырастет до «много трафика»: сохранение — отказ `heavy`; предложи человеку
   сохранить в SSH-меню (пункт 22 → 4) или в терминале сервера — команда целиком (`kaskadctl host bench schedule
   add …` или `… on N`) есть в тексте отказа. Выключить, удалить,
   облегчить — можно всегда. Повторы после резкого падения (`host_set`, `bench_retry=on`) при таком расписании — тоже
   отказ `heavy`: их включает только человек в терминале сервера — `kaskadctl host set --bench-retry on`.
5. Ошибки — тексты из `errors` (те же, что в панели); свои правила расписания не придумывай.

## 5. Правило `confirm`

У разрушительных инструментов обязательный параметр `confirm`:

- равен **значению параметра цели**: `user_delete(user="Мама", confirm="Мама")`,
  `device_reset(device="d-1a2b3c4d", confirm="d-1a2b3c4d")`, `inbound_uninstall(kind="pptp", confirm="pptp")`,
  `exit_delete(id="e-0123456789", confirm="e-0123456789")`, `forward_delete(proto="tcp", port=443, confirm="443")`,
  `exit_policy_reset(group="main", preset="standard", confirm="main")`, `group_delete(group="g-1a2b3c", exits_to="main",
  confirm="g-1a2b3c")`;
- у инструментов без цели — **имени инструмента**: `gateway_disable(confirm="gateway_disable")`,
  `gateway_detect_host(confirm="gateway_detect_host")`, `gateway_addresses_in(ips="203.0.113.10",
  confirm="gateway_addresses_in")`, `update_run(confirm="update_run")`,
  `gateway_purge(confirm="gateway_purge")`, `site_domain_clear(confirm="site_domain_clear")`,
  `site_remove(confirm="site_remove")`;
- у **сводного** инструмента (действие — параметр `action`: `host_score`, `host_bench_schedule`, `host_tariff`) —
  только у разрушительного действия: `host_bench_schedule(action="rm", entry="2", confirm="2")`. Параметры, которые
  не нужны этому действию, — отказ до запуска (список параметров каждого действия — в описании инструмента).

Флаги, которые стирают данные, требуют **своего** подтверждения — имени флага: `user_delete(user="Мама",
confirm="Мама", with_devices=true, confirm_with_devices="with_devices")`, `gateway_purge(confirm="gateway_purge",
with_users=true, confirm_with_users="with_users")`.

`confirm` — это не согласие человека, а его отражение: ты повторяешь цель, чтобы не удалить «не то». Согласие —
«да» человека в чате; без него `confirm` не подставляй.

Какой параметр — написано в описании инструмента («confirm = значение X»). Несовпадение — ошибка `-32602`, команда
не запускается, попытка пишется в аудит. Подставляй `confirm` только после явного «да» человека на это действие.

### Галочка ⚠РФ (`confirm_not_rf`)

`rules_default` и `rules_profile` с `ru_direct`, пока нет действующего согласия (`rules_status` → `rf.required`), и
`rules_consent` требуют `confirm_not_rf` — **фразу, которую человек подтвердил сам**, дословно. Самой фразы здесь
нет: её текст приходит только в отказе, в `data.consent`. `true`, «да», пересказ — отказ `-32602` до запуска команды
(попытка — в аудите). Порядок:

1. Без `confirm_not_rf` ядро отказывает: код 3, `data.need = "rf_consent"`, в `data.block` — блок
   «⚠ Данная организация признана экстремистской на территории Российской Федерации (…)», в `data.consent` — фраза,
   в `data.orgs` — коды организаций этого блока.
2. Покажи человеку блок **дословно** и спроси, подтверждает ли он фразу из `data.consent` (покажи её дословно).
3. Человек написал эту фразу (или явно подтвердил именно её) — повтори вызов с `confirm_not_rf` = фраза и `orgs` =
   `data.orgs` через запятую (согласие — только на показанные организации; без `orgs` или с другим списком — снова
   отказ с новым блоком). **Сам фразу не подставляй** — ни «на всякий случай», ни по общему «да, делай»; не спрашивай
   повторно, если человек отказался. Клиент MCP спросит человека перед вызовом этих инструментов — так задумано.

Согласие одно на узел (`via = mcp`, `who = mcp`; кто именно — по аудиту MCP). `rules_status` → `rf.mode`: `full` —
подтверждено, `legacy` — работает как до обновления и ждёт подтверждения, `need` — выбрано, но не действует, `none` —
`ru_direct` нигде не выбран. `all_exit` везде сбрасывает согласие — следующее включение спросит снова.

Что перестаёт работать: `device_delete`, `device_reset`, `device_revoke` — настройки устройства (выдать заново);
`user_delete(with_devices=true)` — все его устройства; `inbound_uninstall`, `inbound_reinstall` — протокол у всех
(переустановка возвращает порт и ключи, где можно); `pki_rotate` — все устройства IKEv2; `vless_mask`,
`vless_rekey`, `vless_sync` — все ссылки VLESS; `hy2_option`, `hy2_rekey` — все ссылки Hysteria2; `mtu_s4` — все настройки
AmneziaWG 2.0; `exit_delete` — выход (последний — пул пуст, бот идёт в Telegram напрямую; копия ключа, который
в пуле дважды, — её маршруты переходят на оставшуюся; не перешли — ключ не удаляется, повторите); `gateway_disable` и
`gateway_purge` — весь шлюз; `page_rotate`, `page_sub_rotate` — прежняя ссылка; `inbound_port`, `gateway_set_host`,
`gateway_detect_host`, `site_use` — выданные настройки (выдать заново); `gateway_addresses_in` — подключения на
невыбранных адресах; `update_run` — программа узла (откат — человек); `site_domain_clear`, `site_remove` — домен, сайт,
панель на домене; `forward_delete` — проброс.

## 6. Ресурсы и подсказки

Ресурсы: `kaskad://status` (`gateway_status`), `kaskad://scheme` (`scheme`), `kaskad://exits` (`exits_list`),

## 7. Ответы и коды ошибок

Ответ — JSON `kaskadctl`. Ошибка: `isError: true`, `ok: false`, `error` — причина по-русски (покажи человеку как
есть), `code` — код, `code_name` — он же словом, `data` — подробности.

`code` у большинства ошибок — число (таблица ниже), но некоторые ответы несут своё слово (`gw probe`: `code: "os"`
и т. п.) — надёжнее смотреть `code_name`.

| `code` / `code_name` | Что значит | Что делать |
|---|---|---|
| 1 `error` | не получилось, ничего не изменено (или откатано) | прочитай `error`, скажи человеку |
| 2 `usage` | параметры не подошли ядру | исправь вызов |
| 3 `conflict` | занято или уже есть: порт, ключ в пуле, протокол установлен, пул изменился | покажи, кем занято; `force` — только по просьбе |
| 4 `rolled_back` | проверка после изменения не прошла — прежнее вернулось | изменение не применено; причина в `error` |
| 5 `unsupported` | здесь недоступно: система, старый движок пробросов, нет ядра AmneziaWG | скажи, что нужно (`data.needs_key` — ключ GitHub) |
| 6 `locked` | узел занят другим изменением | подожди 30–60 с и повтори один раз |
| `timeout` | команда не уложилась во время и остановлена | проверь состояние чтением, прежде чем повторять |
| `transport` | `kaskadctl` не запустился или не ответил JSON | сбой установки: скажи человеку, `kaskad-mcp --check` на сервере |

У проверок (`gateway_check`, `net_check`, `site_check`, `gateway_probe`) `isError: true` значит «проблемы найдены»
или «здесь нельзя», а не сбой. У `awg_engine_preview` `ok: false` (isError) значит «сменить движок сейчас нельзя» —
причина в `check`. `timeout` с `running: true` — команда изменения ещё идёт на сервере (не повторять).
`usage` без числа — `kaskadctl` не принял сочетание параметров (`stderr_tail`). Ошибка чтения ресурса —
ошибка JSON-RPC `-32603` с `code_name` в `data`. Аудит на сервере не пишется — изменения и выдача секретов
(`device_issue`, ссылки страниц) отклоняются (`-32603`), остальное чтение работает. Подробности применения шлюза
(`apply`) из ответов убраны — его предупреждения в `warnings`.
Протокольные ошибки JSON-RPC: `-32602` — неизвестный инструмент, параметр не по схеме, нет обязательного, неверный
`confirm`; `-32002` — неизвестный ресурс; `-32603` — внутренняя ошибка.

## 8. Ограничения (обойти нельзя)

- Позиционные значения не могут начинаться с «-»; имена — до 64 знаков без управляющих символов.
- Одно изменение за раз: сервер выполняет вызовы по очереди, ядро — под замком.
- Пробросы портов — только на движке nft; переезд движка делает человек (меню 16).
- Нет инструментов для пароля и ссылок входа в панель, открытого доступа к панели, секретного пути панели, экспорта
  ключей в файл, переезда движка и удаления Kaskad — это решения человека.
- `exit_add` принимает текст ключей (до 64 КБ) или ссылку подписки — не путь к файлу на сервере. Ссылку, которую
  надо обновлять раз в сутки, добавляй `exit_sub_add`: тогда ключи подписки сменятся сами, ручные — останутся.
- Копия настроек: `backup_summary` — что в неё войдёт; `backup_export` (пароль `password`) — файл ложится на сервер
  (`/var/backups/kaskad/exports`, 0600), тебе — только путь и числа; пароль называет человек, его не храни. Загрузить
  копию (`backup import`) и откатить её может только человек — панель «Настройки» или SSH-меню 16.
- `device_issue` не меняет настройки узла (пишет только строку о выдаче в журнал), но отдаёт секреты — вызывай,
  когда человек просит настройки устройства.
- `exit_add` со ссылкой подписки (`https://…`): сервер скачивает её сам от root — без логина в адресе, только с
  внешнего адреса (не сам узел, не локальная сеть, не метаданные облака), перенаправления проверяются так же. Иначе —
  код 2; не подставляй адресов, которых не дал человек.
- **Долгие вызовы и лимит клиента.** Установка протокола, первый ключ AmneziaWG, смена движка, сертификат, обновление
  идут минутами (до часа, если система сама ставит обновления). Многие клиенты ждут ответа около 60 с; сервер
  шлёт `notifications/progress` каждые 15 с, если в вызове есть `progressToken`. Клиент оборвал ожидание — команда на
  сервере всё равно доделается: не повторяй её, проверь результат чтением (`inbounds_list`, `exits_list`,
  `awg_engine_status`, `site_status`, `version`). Сервер и сам не обрывает изменения по своему таймауту: ответ
  `code_name: timeout` с `running: true` значит «ещё идёт».

## EN summary

You manage a Kaskad PRO 3.x node: users → devices → protocols (inbounds) → rules → routes → exits (VLESS/AmneziaWG
keys). Users (`u-…`) own devices; "the person" and "the human" below are whoever you talk to (the
node admin). Start with `gateway_status` and `scheme`; say what you will change before every mutating call. Destructive
tools need `confirm` equal to the value of their target parameter (or the tool name when there is none) — only after
the human's explicit consent. `device_issue`, `page_url`, `page_on`, `page_rotate`, `page_sub_url`, `page_sub_on`,
`page_sub_rotate` return secrets: hand them to
whoever asked, never repeat or store them. `ru_direct` (`rules_default`, `rules_profile`) and `rules_consent` need
`confirm_not_rf` — the human's own confirmation, word for word: the phrase from `data.consent` of the refusal (it is
given only there), with `orgs` = `data.orgs` (comma-separated); show the ⚠RU block from `data.block` and that phrase
to the human first and never fill the phrase in yourself. An exit key goes to `exit_preview`/`exit_add` only, via stdin. Error codes:
1 error, 2 usage, 3 conflict, 4 rolled back, 5 unsupported here, 6 locked (retry in 30–60 s); `timeout`,
`transport`. Prompts: `onboard_person`, `add_exit`, `where_traffic`. Panel access, passwords, engine migration and
removal of Kaskad are for humans only — there are no tools for them. An exit's `kind` is `awg` | `xray` (its protocol
in `proto`; it was `vless` in 3.3.5 and before), `role` — `abroad` | `ru`; the inbound kind `vless` is another thing.
The balancer of the xray exits (`balancer` of `traffic_trace`) is `xray` (it was `vless` in 3.3.5).
The server against its own history: `host_score` (read; `action`: `score` by default — `summary.rel_total`, 100 is as
usual for this server, the links with `rel` — none while the link has fewer than 3 days of history («nothing to
compare with yet: N of 3 days of history») or no fresh value; no 0–1000 score, no band, no verdict; `history`,
`show`, `schedule`, `price` — the price of a check, `share` — what the “Share” clip shows, the machine, the
country and the CPU only by the flags), `host_bench` (write; starts a check — traffic and maybe
sysbench/fio: only when the person asks, after the price; `confirm` = `modes.<kind>.confirm` of the price — another
price or key is refused).
The schedule of the checks: `host_score(action="schedule")` (read; the entries, the next checks, the price);
`host_bench_schedule` (`action` `add`/`on`/`off`/`rm`; `rm` is destructive: `confirm` = the entry) — only when the
person asks: the first call without `code` is a preview (saves nothing), the second — with its `code` after the person
agreed; when the traffic of a month grows to «much traffic» (`consent: true`) it is refused (`heavy`) — only a person
saves it (the SSH menu 22 → 4 or, in the server's terminal, the whole command the refusal names —
`kaskadctl host bench schedule add …` or `… on N`); turning off and deleting
are always possible.
Groups of exits (stage 1): `exit_groups_list`, `exit_policy_get` (read); a route may go `group:<group id>` (foreign
only); `fail` = `block` of a route through the exits means “as its group”. Every write of the policy takes `dry=true`
(`moves`) and `rev` (changed since — `conflict`); `exit_policy_reset`, `exit_move_role`, `group_delete` are destructive;
`group_delete` with `with_keys=true` (+ `confirm_with_keys`) deletes a domestic group together with its keys (the last
domestic group with keys is refused without it); `dry=true` first — `drop` lists the keys that leave the server.
Groups, tiers and conditions are created and set up by a human in the panel — no tools, no raw policy JSON.
A tier of `exit_groups_list` tells how it chooses: `method`, and `order` = `manual` — in order by hand (automatic
choice is off: new devices go to the first working exit from the top; the method is kept for the way back).

Renames (`person_rename`, `device_rename`, `exit_rename`, `inbound_label`, `exit_sub_rename`, `forward_rename`,
`server_rename`) change the label, never the id: keys, logins, subscription links and routes keep working; what was
issued keeps its old name (relay `note`). A name is 1–40 characters; a duplicate user name is refused (code 3); other
duplicates — code 3 with `data.need = "confirm_duplicate"`: ask the human, then repeat with `allow_duplicate=true`.
Refer to an entity whose name starts with `-` by its id.
Server health: `host_health` (read; the light, findings with advice, checks, probes); `host_set` changes its settings —
the light network probes send packets out, turn them on only when the person asks; `anchors` — only the addresses the
person named (the node pings them every ≈ 30 s); `bench_retry` — a repeat check after a sharp drop, `dev_threshold` and
`dev_spread` — the rule of the ▲/▼ marks: these two — a preview without `code` first, then the same call with its
`code` after the person agreed (the server checks it). The server plan: `host_tariff` (`action` `show` by default —
the port speed for the health rule «port» and the traffic a month for the price of the checks, each with its source;
`preview` — the change and its `code`, saves nothing) and `host_tariff_set` — only the values the person named, only
after they agreed to the preview lines, with the same `code`; the server checks it — `code_mismatch` otherwise. With a heavy schedule
`bench_retry=on` is turned on only by a person (the preview says `consent: true`) — in the server's terminal:
`kaskadctl host set --bench-retry on`.

## VLESS: TLS своим доменом или Reality

По умолчанию VLESS работает в TLS со своим доменом (сертификат узла), Reality — запасной вариант (нет домена,
сертификата, 443 занят) или осознанный выбор человека. `vless_show` даёт `reason` (почему Reality), `recommend`
(можно перейти на TLS и сколько устройств получат ссылки заново) и `reality_risks` (текст рисков для показа).
`vless_mode` и `site_mode` меняют ссылки VLESS: первый вызов без `yes` получает отказ ядра с ценой (`data.text`),
покажите её человеку и повторите с `yes: true` только после его согласия. Для Reality при домене нужна фраза
согласия человека (`accept_risks`); неверная фраза — отказ с блоком рисков в `data.block`. Первый сертификат домена:
устройств с VLESS нет — узел сам включает сайт и TLS; есть — только рекомендация с их именами (перескажите её,
переход — `vless_mode tls` с ценой); идёт смена режима — «переход отложен», повторите `vless_mode tls` позже.
