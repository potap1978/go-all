# Инструкции для AI-ассистентов

## Что это

goDNS Pro поднимает на сервере **шифрованный DNS-резолвер** поверх сертификата,
который уже выпустили goVLESS или goTelegram. Клиентам — DoH на своём порту и
своём секретном пути плюс DoT. Наверх, к публичным резолверам, — тоже только
DoT/DoH. Открытого :53 в схеме нет нигде — кроме **своего** апстрима,
который оператор добавил сам и явно как обычный DNS (см. «Свои апстримы»).

Движок — **dnsdist** (PowerDNS). Выбран не по вкусу: см. «Почему dnsdist».

## Процесс

- **`main` — ветка распространения, `dev` — рабочая.** С 0.32.1 обе
  опубликованы на GitHub, `main` перемотана на `dev` (до этого она была
  локальной, отставала на 82 коммита и несла версию 0.1.0). Установщик по
  умолчанию берёт `main`: `GODNS_REF` в `install.sh` и ветка, названная в
  README, — одно и то же слово, и это слово обязано совпадать с тем, что
  реально опубликовано. Пока умолчанием стоял неопубликованный `main`,
  команда установки из README получала 404 на `tarball/main` и умирала
  сообщением про сеть и токен — то есть посылала человека чинить не то. Ни
  один прогон этого не ловил, потому что все выкатки шли через
  `GODNS_LOCAL_SRC`, а этот путь скачивание не трогает вовсе. Проверяется
  структурно. Отсюда следствие: **правка, доехавшая только до `dev`, до
  пользователей не доехала** — выпуск заканчивается перемоткой `main`.
- **Версию поднимать при КАЖДОМ пуше, а не только в `main`.** Мелкая
  правка — патч-разряд (0.3.0 → 0.3.1), новая возможность — минорный
  (0.3.1 → 0.4.0). Обновление
  поверх сравнивает версии: при равных `godns_update_state` возвращает
  `same`, и установщик считает происходящее переустановкой — не снимает
  копию, не зовёт нормализацию состояния и **не исполняет ступени миграции
  схемы**. Код на сервере обновится, а состояние останется прежним, и
  разъезд всплывёт позже и не там, где его сделали. Проверяется
  `tools/check-version-bumped.py`.
- Версия живёт в `lib/common.sh` (`GODNS_VERSION`). Поднимать её вместе с
  релизом, не забывая про `README.md`.

## Секреты

Токены и пароли **не хранить в репозитории** — ни в коде, ни в документации,
ни в этом файле. Если токен попал в файл — считать его скомпрометированным и
отозвать, а не просто удалить строку: он остаётся в истории git.

## Перед коммитом

```bash
./test_common.sh                    # чистая логика, без root и сети
./test_structure.sh                 # структурные защиты
./test_certs.sh                     # обнаружение сертификатов на фикстурах
./test_engine.sh                    # рендер конфига dnsdist
./test_backup.sh                    # копии, восстановление, обновление поверх
./test_bot.sh                       # Telegram-бот: привязка, маскировка, права
./test_webui.sh                     # веб-панель: 2FA, сессии, Host
./test_menu.sh                      # меню ИСПОЛНЯЕТСЯ: что нажали, то и вызвалось
python3 tools/build-lang.py         # пересобрать lib/lang из .i18n-keys
python3 tools/check-str-parity.py   # ru/en не расходятся по ключам
python3 tools/check-str-usage.py    # нет обращений к несуществующим ключам
python3 tools/check-callgraph.py    # нет вызовов несуществующих функций
python3 tools/check-unreachable.py --strict # нет функций, до которых не дотянуться
python3 tools/check-version-bumped.py # версия поднята вместе с кодом
python3 tools/test-checkers.py      # сами проверки отличают вызов от метки
bash -n godns.sh lib/*.sh lib/engines/*.sh godns-bot/*.sh godns-web/*.sh
python3 -m py_compile lib/bench.py lib/monitor.py tools/*.py \
                     godns-bot/*.py godns-web/server.py
```

**Тесты обязаны глушить системные команды ДО подключения библиотек.**
Песочница по путям (`GODNS_DIR`, `GODNS_BOT_UNIT_DIR`) не закрывает
действия над системой: `godns_bot_remove` и `webui_remove` зовут
настоящие `systemctl disable --now` и `userdel`. Прогон набора на
сервере с установленным goDNS Pro остановил работающего бота и удалил его
пользователя (`auth.log`: `userdel 'godns-bot'`), после чего юнит падал
с `217/USER`. Заглушки не молчат, а ПИШУТ вызовы в файл — иначе они
спрятали бы и настоящую поломку снятия. Проверяется структурно.

Страж такого рода обязан считать, сколько файлов он осмотрел: первая
версия искала `$SCRIPT_DIR` без фигурных скобок, в тестах написано
`${SCRIPT_DIR}`, и проверка зеленела, не проверив ни одного файла.

**Набор прогонять и на цели, не только на macOS.** Секция i18n в
`test_common.sh` требует bash 4.0+ и на macOS (bash 3.2) молча
пропускается: 250 проверок против 287 на Ubuntu. В пропущенных
тридцати семи пряталось две ошибки, и обе — в самих тестах, а не в
коде. Первая: `stat -f` пробовался ПЕРЕД `stat -c`, а на Linux
`stat -f` означает «сведения о файловой системе» и УСПЕШНО печатает
`File: "…"` — запасной вариант не срабатывал, и проверка прав
сравнивала мусор. Вторая: `eq` сравнивал перевод (`t back`) с кодом
языка («ru»). Пока это не запускали на цели, оба места выглядели
зелёными. Помощник `file_mode` в `test_common.sh` уже написан правильно
(GNU первым) — пользоваться им, а не писать `stat` заново.

Утверждения вида «возможности здесь нет» тоже проверять на цели:
`can_doq` был закреплён как «обязан быть no», что верно лишь там, где
dnsdist не установлен. На сервере dnsdist 2.0.8 умеет DoQ, и тест
валился на исправной машине. Проверять согласие с бинарником, а не
константу.

`check-unreachable` ловит третий класс, и самый обидный: функция написана,
отлажена, переведена — и не подключена ни к одному пункту меню. Таких
нашлось тринадцать, включая «проверить доступность снаружи» и слежение за
сертификатом acme.sh. Это не мёртвый код в обычном смысле, а оплаченная
работа, до которой пользователь не может дотянуться. В чек-листе она стоит с `--strict`: без флага
проверка возвращает 0 и на находках, то есть новая недостижимая функция
проезжала ворота с предупреждением, которое никого не останавливало.
Осознанный API модуля вносить в `LIBRARY_API` внутри неё.

`check-str-usage` ловит ровно тот класс ошибок, где пользователь вместо фразы
видит `certs_unusable_pick`.

`check-callgraph` ловит другой: `bash -n` разбирает синтаксис, но про
несуществующую функцию узнаёт только рантайм — и узнаёт в проде, когда
оператор уже нажал пункт меню. Модули писались раздельно, и разъезд имён
(`godns.sh` звал `engine_select`, библиотека определяла `engine_load`) —
самый вероятный способ уронить меню. Проверка обязана иметь отрицательные
тесты: первые две её версии молча пропускали опечатку в `if fn; then`, самой
частой форме вызова в этом проекте.

`test_certs.sh` поднимает мини-CA и выпускает настоящие сертификаты во
временном дереве. Мини-CA обязателен: без него всё выпущенное самоподписано,
путь «годен» недостижим, и тест проходит, ничего не доказав. Отдельно
проверяется CA-подписанный сертификат с ЧУЖИМ ключом — он выглядит годным,
но dnsdist на нём не поднимется.

Чтобы это было вообще возможно, пути соседей в `lib/common.sh` объявлены
через `${VAR:-…}`. Голое присваивание затирало значения, выставленные тестом,
и проверка молча читала настоящий `/etc/letsencrypt`.

**Строки не править в `lib/lang/*.sh`** — они генерируются. Источник истины
`.i18n-keys/*.tsv`, где ru и en лежат в одной строке: так расхождение по
составу ключей структурно невозможно.

## Два железных требования заказчика

**1. Чужие сертификаты не перезаписывать. Никогда.**

goDNS Pro **только читает** `/etc/letsencrypt/live/<домен>/`. Запрещено:
`certbot certonly` для чужого домена, `certbot --expand`, любая правка
`/etc/letsencrypt/renewal/*.conf`, и особенно `acme.sh --install-cert`.

Про `acme.sh` отдельно, потому что это самая разрушительная команда в округе:
`acme.sh --install-cert -d D --reloadcmd X` **без повторной передачи**
`--key-file` / `--fullchain-file` молча записывает в конфиг пустые пути.
`installcert()` вызывает `_savedomainconf` безусловно, а `_save_conf` пишет
значение даже когда оно пустое. То есть пути, настроенные goVLESS, исчезают —
без ошибки, без предупреждения, и поломка всплывает при следующем перевыпуске,
до 60 дней спустя.

Поэтому реакция на перевыпуск сделана **без единой записи в чужое хозяйство**:
- certbot → свой файл в `/etc/letsencrypt/renewal-hooks/deploy/50-godns.sh`.
  Каталог чисто аддитивный: certbot выполняет все файлы в нём, поэтому
  `govless-restart.sh` и хуки goTelegram остаются нетронутыми.
- acme.sh → systemd `.path`-юнит, следящий за mtime файла сертификата.
  Ноль записей в `acme.sh`, ноль риска.

**2. Ubuntu 22.04 / 24.04 / 26.04 и новее.**

`os_gate` в `lib/common.sh` проверяет **до** установки чего бы то ни было:
`rc=0` — 22.04/24.04/26.04; `rc=2` — более новая LTS или промежуточный выпуск
(предупредить и спросить); `rc=1` — старше 22.04, не-Ubuntu, производная
(Mint/Pop через `ID_LIKE`), Debian. Жёсткий список версий не делать: в день
выхода следующей LTS установщик превратится в бомбу.

`/etc/os-release` **не `source`-ить** — файл управляем извне и под `set -u`
затрёт наши переменные. Парсить построчно (`os_release_get`).

## Правила, выведенные из граблей

**bash 4.0+ обязателен.** Таблица строк — ассоциативный массив. На bash 3.2
(штатный в macOS) `I18N[ключ]` молча пишет в индекс 0, и весь интерфейс
превращается в кашу. Проверка живёт в `godns.sh` и `lib/i18n.sh` — там, где
массив и есть. В `lib/common.sh` её намеренно нет: так тесты чистой логики
запускаются на macOS без контейнера.

**Действия меню — только через `run_action`.** Скрипт под `set -euo pipefail`,
а «ненулевой код» здесь — рядовой исход: сертификата нет, соседа нет, DNS не
разошёлся. Голый вызов в ветке `case` при таком исходе убивает **весь скрипт** —
терминал оператора закрывается без единого сообщения. `run_action f` выполняет
`f || true`, а условный контекст отключает `errexit` для всего дерева вызовов
внутри `f`, то есть гасит и мины на несколько уровней вглубь. Проверяется
структурно в `test_structure.sh`.

Следствие: внутри действий меню `errexit` не работает, поэтому каждая функция
обязана сама проверять коды возврата.

**Не присваивать из подстановки команд, которая штатно возвращает 1.**
Писать `x=$(…) || true` и подставлять дефолт.

**Последняя команда функции не должна быть `[ … ] && …`.** При ложном условии
функция вернёт 1. Использовать `if … then … fi` и явный `return 0`.

**`tr … | head -c N` — мина.** `head` закрывает пайп, `tr` умирает по SIGPIPE,
и под `pipefail` подстановка возвращает ненулевой код. В `random_path` это
давало склеенный путь из случайной строки и fallback-хвоста. Использовать
`cut -c1-N`: он вычитывает вход целиком и сигнала не получает.

**`lib/providers.sh` заканчивается `return 0` на уровне файла.** Всё
дописанное ПОСЛЕ этой строки не загружается никогда: `source` доходит до
`return` и останавливается. Ошибка выглядит как «функция определена в файле,
но command not found». Новые функции вставлять ВЫШЕ блока загрузки каталога.

**Свой же процесс — не «занятый порт».** При повторном применении (смена
пути, смена апстримов) порты держит наш работающий dnsdist. Предупреждение
без проверки владельца выдавало «Порт 4443 уже занят» рядом с «Конфигурация
применена», и оператор не понимал, взлетело или нет. Сверять PID с
`systemctl show -p MainPID`.

**Список с галочками: строки готовить заранее.** `prov_render_row` внутри
дёргает `prov_name`, `prov_filter_text`, `_prov_pad` — около шести
подпроцессов на строку. На девятнадцати строках это больше сотни
подпроцессов на КАЖДОЕ нажатие клавиши, и список видимо «перезагружается».
Собирать оба варианта каждой строки один раз, дальше перерисовка — чистый
`printf`. Перерисовывать ВЕСЬ блок от `\033[H`, а не считать номера строк.
Точечная перерисовка через `\033[NA` пробовалась дважды, оба раза расчёт
врал на единицу и затирал соседнюю строку: с экрана пропадал заголовок
группы, а пункты задваивались. Арифметика по строкам ломается от любой
правки раскладки — и ломается молча. Полный repaint без `clear` не мерцает
(экран не гасится, а переписывается поверх), `\033[K` гасит хвост каждой
строки, `tput lines` решает только, хватает ли окна для `\033[H` или нужен
`clear`.

**Выравнивание колонок: `printf '%-12s'` считает БАЙТЫ.** Кириллическая
подпись (2 байта на букву) разъезжается ровно на свою длину. Дополнять
пробелами вручную по `${#s}` (символы при UTF-8-локали) и обязательно
обрезать слишком длинное — иначе одно длинное имя сдвигает всю строку.

**jq в системе нет.** На Ubuntu 22.04 (standard) и на всех minimal-образах
`jq` отсутствует, а конфиги соседей нужно прочитать **до** права что-то
устанавливать. JSON читать и писать через `python3` (`json_get` / `config_set`).

**Логи пишутся в stderr.** Иначе попадают в `$(...)` вместе с полезным
значением и ломают вызывающий код.

**Секреты не передавать аргументами curl.** `/proc/<pid>/cmdline` читается
любым локальным пользователем.

**Меню — в стиле goVLESS.** Подменю: `print_header "$(t menu_*)"`, пункты
`echo -e "  ${CYAN}N)${NC} $(t key)"`, ввод
`read -rp "  ▸ " choice || { echo ""; return; }`, неверный ввод →
`log_warning; sleep 1; continue` (остаёмся в подменю), в конце цикла —
`echo -ne "  $(t press_enter_return) "; read -r`. Хелпер `pause()` не заводить.

**Глубина меню — ровно два уровня.** Пять разделов: подключиться,
наблюдение и отладка, настройки DNS, настройки goDNS Pro, удалённое
управление. Третьего уровня нет нигде, и заводить его нельзя: до
переработки самое частое действие (дать человеку адрес) лежало на третьем
уровне — глубже, чем «удалить goDNS Pro». Длинный раздел режется
подзаголовками `── $(t *_grp_*) ──`, а не выносится в отдельный экран.

Состояние показывать прямо в строке пункта (`[По кругу]`, `[включён :853]`,
`[off]`): иначе оператор заходит внутрь только чтобы посмотреть.

Опасное — на `99`, далеко от рабочих цифр. Промах на одну клавишу не
должен сносить продукт.

**Инструкция без пути назад — незаконченная инструкция.** Даём команду,
меняющую систему человека (`netsh`, `opkg`, `/ip dns set`) — рядом даём
обратную. Проверяется структурно: каждая функция сниппетов печатает
`$(t snip_undo)`.

**Enter и Ctrl-D — разные ответы.** Везде было написано `read -r x || x=""`,
то есть конец ввода приравнивался к «просто Enter». На экране «Изменить
порты» это значило, что привычный жест выхода ПРОХОДИЛ мастер до конца на
умолчаниях и перезапускал службу; соседний пункт на том же Ctrl-D честно
отменял — две семантики в соседних строках меню. Читать через
`godns_read_line`: код 0 и пустая строка — это Enter (умолчание), код 1 при
пустой переменной — отмена. Код 1 с НЕПУСТОЙ переменной — тоже ответ:
строка без завершающего перевода (`printf yes | godns`) приходит именно так.

**Отмена не должна оставлять полработы.** Следствие предыдущего: пока
`config_set` стоял между вопросами, отказ на втором вопросе оставлял
записанным первый. Все записи — одной группой в конце функции.

**«Шаг 4 из 5» врёт, если пришли не из мастера.** Один экран открывается
двумя дорогами; заголовок обязан зависеть от дороги (`_wiz_header`), иначе
человек, зашедший сменить одну настройку, ждёт продолжения мастера.

**«Ничего не изменилось» — не повод применять.** `reconfigure` применял
конфигурацию всегда, когда шаг вернул 0, а шаг возвращает 0 и при отказе
оператора: под словом «Отменено» печаталось «Изменения применены», и
клиенты роняли соединения на ровном месте. Сверять отпечаток до и после,
но применять при дрейфе — пункт меню обязан оставаться способом всё
вправить.

**Loopback — не утечка.** Пакет `127.0.0.1 > 127.0.0.53.53` машину не
покидает: это система разговаривает со своей заглушкой systemd-resolved,
то есть штатная Ubuntu из коробки. Аудит ловил его и печатал ✗
«разберитесь, кто ходит на :53» на исправном сервере — самое частое ложное
«сломано» на самой частой конфигурации. Считать отдельно то, что реально
ушло с машины (`oifname != "lo"`, фильтр tcpdump без 127.0.0.0/8), а
объяснялке — делать следующий шаг: только loopback в resolv.conf ⇒ виновник
resolved, и назвать его апстримы из `resolvectl`.

**Ключ консоли dnsdist на экран не выводить.** Панель и демон бота его
чистили, SSH-пункт «Показать конфигурацию» печатал конфиг как есть — и
ключ уезжал в запись терминала и в скриншот для поддержки. Обратная ссылка
`\1` в ERE здесь не годится: это расширение GNU, BSD sed на macOS молча
не применяет её, и «чистка» ничего не чистит.

**Лимит запросов — поштучный, не бан; свой адрес не считать.** До 0.32.0
стоял `dynBlockRulesGroup():setQueryRate(80, 10, …, 60)`: больше 800
запросов за 10 с с одного адреса — и адрес выключался целиком на минуту, а
бан продлевался, пока клиент продолжал слать. «Порог щедрый» считался из
расчёта «один адрес — одна квартира». Роутер на OpenWrt с Forkop/Podkop
собирает DNS всей квартиры в один поток (кэш dnsmasq у него выключен под
FakeIP), а с включённым «DNS через прокси» все такие роутеры приходят с
адреса самого VPS — и у людей «пропадал YouTube» до выключения goDNS Pro.
Keenetic под порог не попадал, поэтому жаловались только на Forkop.
Воспроизведено на dnsdist 2.1.1 из Homebrew: DoH получал HTTP 403, DoT —
разрыв, UDP — тишину; при 100 qps бан не снимался вовсе. Теперь
`MaxQPSIPRule` (token bucket по адресу, лишнее отбрасывается в ту же
секунду), свои адреса и loopback исключены через `NotRule` ПЕРВЫМ в
`AndRule` (он останавливается на первом ложном), лимит виден в «Состоянии»
и меняется в «Настройках DNS». Урок шире: утверждение «обычный клиент в
порог не упирается» проверять на клиенте, который АГРЕГИРУЕТ — роутер,
туннель, CGNAT, — а не на одном телефоне. Что видит клиент на лишний
запрос, по транспортам разное: DoH — HTTP 403 на него одного, DoT — dnsdist
на Drop закрывает всё соединение (`terminateClientConnection`), клиент
переподключается; писать «отбрасывается только лишнее» без этой оговорки
нельзя. Число из config.json перед арифметикой нормализовать (`10#`,
длина ≤ 6): «08» валил `$((08 * 2))` в рендере на каждом применении, а
двадцать знаков ломали `-gt` и молча выключали лимит. И: конфиг движка
теперь перерисовывается новым кодом на каждом обновлении
(`godns_update_reapply`), но служба перезапускается только если строки Lua
реально отличаются (`dnsdist_config_is_current`): раньше исправление
рендера доезжало только до тех, кто что-то менял в меню, а рестарт ради
правки README рвал бы соединения клиентов. В логе dnsdist бан ищется по
`Inserting dynamic block` (2.0.x) или `Inserting dynamic rule` (2.1.x) в
`/var/log/godns/dnsdist.log`; надёжнее `showDynBlocks()`.

## Стражи: чему научил мутационный прогон

56 мутаций на замороженной копии. 25 поймано, остальное — дыры, и почти
все одного вида: **страж узнавал шаблон, а не смысл**.

- **Диспетчер целиком без `run_action`.** Признак «в этом `case` уже есть
  хоть один run_action» слеп к худшей форме: подменю, написанное без
  обёртки ВСЁ, диспетчером не считалось. Меню узнавать по имени
  (`main_menu`, `submenu_*`), а не по содержимому.
- **`trap f EXIT`.** Аргумент trap — это позиция команды, просто
  отложенная. Опечатка там проходила `bash -n`, граф вызовов и все наборы,
  а у оператора случалась на каждом выходе из меню.
- **Граница процессов транзитивна.** Проверка читала только строки
  `actions.sh`/`bridge.sh`; вызов функции из `godns.sh`, вставленный в
  `lib/engine.sh`, был невидим. Расширение до замыкания по `source` тут же
  нашло два настоящих бага: ни бот, ни панель не подключали `update.sh`
  (миграция при восстановлении копии молча не выполнялась), а панель звала
  `godns_bot_installed`, которой у неё нет, — `command not found` под `!`
  читается как «не установлен», и панель ВСЕГДА сообщала «бот пропал».
- **Имя стража — не проверка.** «iOS-профиль без ServerAddresses» этого
  поля не искал вовсе, а порт стерёгся в диапазоне, который не включал
  строку, где адрес собирается.
- **«Отличается» ≠ «поднята».** `check-version-bumped` засчитывал
  понижение 0.25.0 → 0.1.0 как успех.
- **Шесть стражей зеленели, не осмотрев ничего.** Счётчик осмотренного
  обязателен КАЖДОМУ, а не только тому, кого уже ловили.
- **Комментарий — не код.** Структурная проверка грепала тело функции
  вместе с комментариями: удаление строки ловилось, отладочный `#` — нет.
- **Совпадающий исход прячет разную причину.** У «чужой wildcard» и «весь
  loopback занят» итог один (`none`), и снос ветки wildcard оставался
  зелёным. Проверять и названную причину — проект сам этого требует.
- **Отрицательные тесты — не только у первой проверки.** Они были у
  `call_names` и больше ни у кого; обе слепоты выше прожили именно поэтому.
  `tools/test-checkers.py` теперь ломает копию дерева и требует, чтобы
  каждый инструмент покраснел.
- **`godns.sh` не исполнял ни один тест.** Две тысячи строк — мастер,
  дашборд, семь подменю — держались на грепе. Перепутанные местами пункты
  меню прошли ВЕСЬ набор зелёными. `test_menu.sh` меню запускает: жмёт
  каждую клавишу и сверяет, что вызвалось. Два разных утверждения:
  закреплённая руками таблица «нажатие → действие» (она нарочно повторяет
  код — без второй записи перестановку нечем заметить) и выводимая из
  самого экрана сверка «что напечатано, то и принимается» — ею ловятся
  мёртвый пункт и дубль номера, оба в этом меню уже случавшиеся.
- **Опись функций для стража строить по БОЕВЫМ файлам.** Тесты глушат
  системные команды одноимёнными функциями (`sleep() { :; }`), и с ними в
  описи `sleep 1` в ветке `case` читался как вызов функции проекта.
- **Строки бота были единственной поверхностью без инструмента.** `t()` при
  промахе возвращает САМ КЛЮЧ: опечатка доезжает до пользователя Telegram
  как `claim_hintt`. Паритет ru/en её не ловит — ключа нет ни там, ни там.

## Почему dnsdist, а не dnsproxy

Проверено прогоном настоящего бинарника dnsproxy v0.84.1:

- **Настоящего round-robin у dnsproxy нет.** `--upstream-mode` принимает ровно
  `load_balance` (по умолчанию), `parallel`, `fastest_addr`. `load_balance` —
  взвешенно-случайная выборка с весом 1/RTT: замер дал 37/23 на 60 запросах к
  двум одинаковым апстримам. Требование «по кругу ротировать каждый запрос»
  этим не закрывается. `--all-servers` и `--fastest-addr` удалены в v0.72.0 —
  теперь это ошибка разбора, а не устаревший синоним.
- **`-p 0` не выключает открытый DNS**, вопреки `--help`. Он биндит случайный
  эфемерный порт, и это полноценный работающий резолвер. PR #457 висит
  с 2025-05-27.
- **SIGHUP его убивает** (exit 129). Перевыпуск сертификата требует рестарта.
- Путь DoH по умолчанию **любой**; enforcement включается только
  `--doh-routes "GET /путь" --doh-routes "POST /путь"`.

dnsdist закрывает всё это: `setServerPolicy(roundrobin)` — настоящая ротация,
`addDOHLocal(…, {'/путь'})` сверяет путь точно (404 на любой другой),
`reloadAllCertificates()` перечитывает сертификат без разрыва соединений.

**Пакет дистрибутива годится не всегда — спрашивать apt, а не гадать.** jammy
даёт 1.6.1 (исходящих DoT/DoH не существовало до 1.7.0), noble — 1.8.3,
собранный без libh2o. А вот **26.04 (resolute) даёт 2.0.2 с `dns-over-https`
и `dns-over-tls`** — он подходит целиком, и третья сторона там не нужна.
Правило «пакет дистрибутива не годится никогда» было верным два выпуска и
перестало быть верным: на 26.04 ветки `resolute` в `repo.powerdns.com` ещё
нет, установщик деградировал до `noble`, пакет не вставал по несовместимым
зависимостям — и падал на машине, где всё нужное лежало рядом.

Поэтому порядок такой: спросить `apt-cache policy dnsdist`; если кандидат
1.9 или новее — поставить его и принять **только** после разбора
`dnsdist --version` («Enabled features:» должен содержать `dns-over-https` и
`dns-over-tls`). Одной версии мало: noble 1.8.3 проходит по номеру, но собран
без нужного. Не подошёл — `repo.powerdns.com`, линия `dnsdist-20`.

**Причину отказа называть своим именем.** Запасной путь печатал
«repo.powerdns.com недоступен» на ЛЮБОМ провале, в том числе когда индекс
репозитория только что успешно прочитали. Оператор шёл проверять сеть вместо
настоящей причины. У каждого выхода — свой ключ; проверяется в `test_engine.sh`.

## Соседи: чего не трогать

**Порт 443 занят у обоих.** goVLESS Pro отдаёт :443 xray (nginx живёт на :80),
причём установка Pro убивает любой не-xray слушатель на 443. goTelegram Pro
ставит на :443 nginx `stream` + `ssl_preread` — SNI-диспетчер, который
раскидывает telemt на :7443 и сайт на :8443. Поэтому свой порт — не прихоть.

**Занятые порты, которые надо обходить:** 80, 443, 7443, 8443, 9090, 9091,
1984, 9443, панель 3X-UI и sub-сервер (оба случайные, читать из `x-ui.db`
`webPort`/`subPort`). 853 не занят никем — это наш порт по умолчанию для DoT.

**nginx.** Ни goVLESS, ни goTelegram не читают и не удаляют ничего в
`/etc/nginx/conf.d/`. Свой файл класть только туда. `sites-available/govless`
и `sites-available/gotelegram` переписываются целиком из heredoc.

**Своё состояние — только в `/etc/godns` и `/opt/godns`.** Удаление goVLESS
делает `rm -rf /opt/govless /etc/govless /var/www/html` без проверки владельца
и сносит весь lineage Let's Encrypt своего домена.

**Формат `/root/.govless_credentials` менялся:** 1.3.1 писал
`USERNAME`/`PASSWORD`/`PORT`/`WEB_PATH`, более ранние — `XUI_USER`/`XUI_PASS`/
`XUI_PORT`/`XUI_WEB_PATH`. Файл **не `source`-ить**: значение с литеральным `$`
(bcrypt-пароль `$2a$…`) будет раскрыто шелом и под `set -u` уронит скрипт.

## Сертификат и права

`/etc/letsencrypt/{live,archive}` — `0700 root:root`, а файлы в `live/` —
симлинки в `archive/`. Поэтому `chmod` на одном `privkey.pem` бесполезен:
непривилегированный процесс не пройдёт даже по каталогу.

dnsdist с версии 1.5.0 не работает от root. Правильный способ — штатная для
дистрибутива группа `ssl-cert`: certbot сохраняет владельца-группу и режим при
перевыпуске, поэтому настраивается один раз и живёт. Копировать сертификаты
**не надо** — это вторая копия приватного ключа, которая расходится с
оригиналом и требует пере-chown при каждом перевыпуске.

После настройки прав — **доказать**:
`runuser -u _dnsdist -g ssl-cert -- test -r <privkey>`.

## Про замер задержки до резолверов

Это **не ping**. ICMP идёт другим путём, до другого порта, и многие endpoint'ы
его режут. Меряется реальный транспорт: TLS-рукопожатие плюс запрос на уже
установленном соединении.

- **DoT** — чистый python3 (`socket` + `ssl`), RFC 7858, двухбайтовый префикс
  длины, с настоящей проверкой сертификата: провал проверки на цензурируемой
  сети — это и есть полезный сигнал, глушить его нельзя.
- **DoH** — через `curl --http2`. `http.client` в python3 умеет только
  HTTP/1.1, а Quad9 отвечает на HTTP/1.1 DoH кодом 505, Mullvad же просто
  рвёт соединение после TLS. Замер на stdlib был бы измерением несуществующего.
- Показывать **два** числа: `cold` (соединение + TLS + первый ответ) и `warm`
  (**медиана** запросов 2..N по тому же соединению). Сортировать по warm.
  Одно только cold делает всех медленнее в пять раз.
- Медиана, не среднее: один таймаут в 4000 мс сдвигает среднее из пяти проб
  на +780 мс.
- Отказ показывать **причиной**, а не числом: таймаут / TLS / HTTP 505 / 403.
- base64url в `?dns=` — **без padding**. Padded `?dns=…%3D` даёт у Quad9 403.

**kdig без `+keepopen` меряет не то.** Каждое имя открывает новую TLS-сессию, и
в «задержку» попадает рукопожатие: замерено 263 мс против 61 мс на прогретом
соединении.

## Живое наблюдение: что консоль dnsdist отдаёт на самом деле

Всё ниже снято с работающего dnsdist 2.1.1 с тремя DoT/DoH-апстримами, а не
взято из документации. Четыре факта контринтуитивны, и каждый из них тихо
ломает наблюдение, если его не знать.

**Поштучные запросы dnsdist в лог не пишет — но они есть в кольцах.**
`grepq` читает кольцевые буферы (по умолчанию 10000 записей), которые
включены ВСЕГДА и не зависят от `setVerbose`. В строке ответа лежит всё, что
нужно оператору: клиент, имя, тип, АДРЕС АПСТРИМА, ЗАДЕРЖКА в мс и rcode.
Поэтому живой экран не требует подробного логирования.

**Селектор `grepq` — пустая строка.** Очевидное
`grepq({'0.0.0.0/0','::/0'}, 8)` печатает заголовок и НИ ОДНОЙ строки;
`grepq('', 8)` отдаёт восемь. Замерено обеими командами подряд на одном
и том же кольце. Лимит применяется к КАЖДОМУ кольцу отдельно, так что
`grepq('', N)` — это до 2N строк: N запросов и N ответов.

**Команды консоли не батчатся.** `-e 'showVersion();showSecurityStatus()'`
возвращает вывод только ПОСЛЕДНЕЙ: буфер вывода перезаписывается, а не
копится. Отсюда три отдельных вызова на кадр (~30 мс каждый), а не один.
Возвращаемое значение приходит, только если это строка: `getVerbose()` даёт
«Command returned an object we can't print», а `tostring(getVerbose())` —
честные `true`/`false`.

**Колонка `Lat` в `showServers()` у goDNS Pro всегда «-».** Она считает только
UDP-ответы, а все наши апстримы — DoT/DoH, то есть TCP; число живёт в
колонке `TCP`. Разбор обязан падать на `TCP`, иначе экран показывает
«задержки нет» при исправных апстримах.

**Колонки `grepq` фиксированной ширины, и переполнение сдвигает всё
правее себя.** Имя `nonexistent-zzz-qqq.example.` (28 символов при ширине
25) двигает `Type` со 114-й позиции на 117-ю. При этом у строк-ЗАПРОСОВ
колонка `Server` пустая. Значит, не годится ни разбор по пробелам (съезжает
на пустой колонке), ни разбор по жёстким смещениям (ломается на
переполнении): нужен обход колонок с переносом сдвига — `split_fixed`
в `lib/monitor.py`.

**Чего dnsdist не даёт вовсе.** Отдельного «времени апстрима» он не
записывает. Задержка в кольце — это время от прихода запроса клиента до
прихода ответа апстрима, то есть НАШЕ время ответа, в котором апстрим —
почти всё. Разделить поштучно «сколько думали мы» и «сколько думал
апстрим» нельзя. Зато видно главное: ответ из кэша (`Cache` в колонке
сервера, ~0 мс, наверх не ходили) против похода к апстриму.

**Два числа задержки на экране означают разное, и это надо подписывать.**
В ленте — весь обмен, включая TLS-рукопожатие, если готового соединения не
было: замерено 250–400 мс. В таблице апстримов — скользящее среднее по
прогретому соединению: 10–20 мс до тех же адресов в тот же момент. Без
подписи это выглядит как ошибка в одном из двух чисел.

**Подробный лог запросов — режим с таймером, а не переключатель.**
`setVerbose(true)` через консоль включается на лету и живёт только до
перезапуска службы (в конфиг `setVerbose(false)` записан явно). Формат в
dnsdist 2.x структурированный: `backend.name`, `dns.question.name`,
`dns.response.latency_us`, `dns.response.rcode`. Две строки на КАЖДЫЙ
запрос, ~550 байт каждая — при 50 зап/с это около 200 МБ в час, то есть
ровно тот сценарий, ради которого написан `lib/logs.sh`. Поэтому режим
обязан: показывать оценку объёма ДО включения, иметь выключатель рядом с
включателем и сам гаснуть по транзитному таймеру `systemd-run --on-active`.

**Ловушку EXIT в живом экране не подменять.** На ней висит
`cleanup_temp_files` из `godns.sh`; `trap … EXIT` внутри функции её затрёт,
а `trap - EXIT` не вернёт. Ctrl-C ловится своим `trap … INT`, который
ставит флаг и выводит в меню, — это и безопаснее, и лучше по UX.

**Цвета из `lib/common.sh` — литеральные строки `'\033[2m'`, а не
управляющие последовательности.** Весь проект печатает их через `echo -e`.
Тому, кто получает их иначе (например `printf` в python3-помощника),
разворачивать надо самому: `printf '%b'`, и только для цветов — для
подписей `%b` съел бы обратный слэш внутри перевода.

## Свои апстримы

Оператор добавляет свой резолвер: DoT, DoH или обычный DNS. Как устроено и
почему именно так:

- **Хранение** — `custom_upstreams` в config.json, записи через `;`:
  `id|proto|ip|port|sni|path|name`, id всегда `custom-<slug>`. Формат тот же,
  что у записей движка `upstreams`, схему поднимать не пришлось.
- **Вливаются в ТУ ЖЕ таблицу `PROVIDERS`** с полями `custom=yes` и `proto`,
  а не живут отдельной веткой. Поэтому `prov_exists` (валидация панели),
  список с галочками, отчёт, замер и `engine_upstreams_store` работают без
  правок; свои — третьей группой `── Свои ──`. Второй путь для «своих»
  разошёлся бы с первым, как уже расходились помощники межсетевого экрана.
- **Протокол — у записи.** `engine_upstreams_store` раньше звал
  `engine_upstream_record "$id" dot` жёстко для всех: каталог в бою ходил
  наверх ТОЛЬКО DoT, а `doh_url` каталога не использовался нигде. Теперь
  протокол читается из записи; каталог по-прежнему DoT (он есть у всех и им
  же меряется), свой приносит свой. Исходящий DoH впервые включён
  по-настоящему — проверен на живом бинарнике (2.0.2, nghttp2): 23 мс,
  чужой `subjectName` честно помечается `down`.
- **Адрес — только IP-литерал.** Контракт разбора это требовал, а регэксп
  пропускал имя; каталог всегда давал IP, и граница спала. Имя разрешается
  при добавлении (`godns_resolve_host`, getaddrinfo системы), в запись
  кладётся адрес, `dnsdist_upstreams_parse` проверяет `valid_ip`.
- **Кандидат пробуется ДО записи** (`bench_probe_line`): задержка или
  причина отказа. Иначе человек добавит мёртвый адрес и узнает об этом из
  жалоб клиентов.
- **Проверка сертификата у своих DoT/DoH всегда включена.** Самоподписанный
  не заведётся — намеренно; IP вместо имени в SNI отвергается на границе.
- **Обычный DNS разрешён, цена названа сразу:** приватный адрес — «внутри
  вашей сети», публичный — предупреждение и подтверждение с умолчанием
  «нет». Аудит утечки знает адреса своих plain-апстримов (accept раньше
  счётчиков nftables, `not host` в tcpdump) и называет их ожидаемыми —
  иначе он красил бы осознанный выбор оператора ✗.
- **`$(prov_custom_add …)` — подоболочка.** Config на диске записан, а
  таблица перечитана только там; у вызывающего каталог остаётся старым, и
  движок отвечает «нет адреса IPv4» на только что добавленное. Поэтому
  дубли сверяются по ДИСКУ, id отдаётся ещё и через
  `PROV_CUSTOM_LAST_ID`, а меню зовёт функцию напрямую.
- **В манифест копии — только id апстримов.** Запись несёт путь DoH, а у
  своего апстрима он может быть чужим секретом (второй goDNS Pro как апстрим).
- **`--check-config` слеп к неизвестному ключу `newServer`.** На dnsdist
  2.0.2 он печатает «Unknown key … ignored» и заканчивает «OK!» с кодом 0.
  Опечатка в `validateCertificates` проходила ворота и молча выключала
  проверку сертификата апстрима. `dnsdist_check_config` читает вывод, а не
  только код; проба ленивого health-check — тоже.
- **Из мастера — клавишей `+`** в списке с галочками (оба варианта:
  стрелочный и числовой). Селектор возвращает код 2, `wizard_upstreams`
  открывает `custom_upstream_add --no-enable` и возвращает в список с новой
  записью уже отмеченной. Иначе человек, у которого свой резолвер и есть
  главный, был бы обязан сначала выбрать чужой и идти менять.
- **Тестовые драйверы и pty: type-ahead теряется на смене режима.**
  Стрелочный список читает `read -rsn1` (raw), экран добавления —
  построчно (canonical), потом снова raw. Если весь ввод подан в pty
  разом (`printf … | script -qec godns`), второе сырое чтение получает
  `\004` вместо Enter — проверено экспериментом на Linux; при вводе с
  паузами, как у человека, всё доходит. Это артефакт драйвера, не
  продукта: интерактивные экраны в живых прогонах кормить с паузами
  (`printf; sleep; printf`), а `test_menu.sh` идёт не через tty — там
  числовой селектор.
- **Панель и бот — та же логика, не второй путь.** Неинтерактивная часть
  экрана SSH вынесена в `lib/webui.sh`: `webui_custom_probe` (rc 0 ответил /
  3 не ответил / 4 plain к публичному адресу без подтверждения — проба НЕ
  выполнялась / 1 негодно), `webui_custom_add`, `webui_custom_remove`,
  `webui_custom_list_tsv`. Мост панели (`bridge.sh`) и фасад бота
  (`actions.sh`) зовут ровно их; порядок шагов один: разрешение имени →
  цена plain до пробы → проба → запись → включение.
- **Путь DoH не ездит в argv.** `/proc/<pid>/cmdline` читает любой
  локальный пользователь, а путь чужого резолвера может быть чужим
  секретом. Мост и демон бота передают его переменной окружения
  `GODNS_CUSTOM_PATH` (`/proc/<pid>/environ` — только владельцу); у демона
  окружение действия — allowlist `ACTION_ENV` с регэкспом на значение,
  в аудит идут только имена ключей. Страж в `test_structure.sh` считает
  четыре файла (bridge.sh, actions.sh, server.py, bot.py).
- **Регэкспы границ панели и демона тождественны** и закреплены таблицей в
  `test_bot.sh` (AST-извлечение из `server.py` и `botd.py`). Валидатор
  демона — `fullmatch`, не `match`: у `$` в Python поблажка на завершающий
  `\n`, и `"dns.google\n"` прошёл бы. Порт вне диапазона — отказ, не
  прижатие (`_int_range` прижимает — для порта не годится).
- **Бот ждёт свободный текст через `_CU_DRAFT`** — по образцу
  `_PENDING_TYPED`: TTL `CONFIRM_TTL`, чистка в `_sweep_confirms`, сброс
  любой не-`cu:*` навигацией и `/start`. `ConversationHandler` не заводить.
  Кнопки `cu:*` строятся в коде, не в `MENUS`, поэтому контрактный тест
  «у каждого действия есть кнопка» читает `CUSTOM_FLOW_ACTIONS`.
- **Слепое пятно `check-callgraph`, закрытое: однострочник `f() { g; }`.**
  Вызов узнаётся по первому токену фрагмента, а `{` границей команды не
  был — в `bot_act_upstream_report() { engine_upstream_report; }` вызов
  оставался невидимым (нашёл исполнитель бота). Теперь `{` и `}` режут
  фрагменты, но `{` только НЕ после `$`: у `${var}` скобка — часть
  подстановки, и `${st_good}` читался бы как вызов. Отрицательные тесты в
  `tools/test-checkers.py` держат обе стороны.

## Провайдеры

Таблица в `lib/providers.sh` — проверена живыми запросами. Что важно помнить:

- **dns0.eu мёртв** — закрыт в октябре 2025. Не возвращать. Европейский слот
  занимает DNS4EU (`unfiltered.joindns4.eu`).
- **LibreDNS с блокировкой рекламы — нестандартный порт `dot.libredns.gr:854`.**
- **Провайдеров, требующих учётной записи, в таблице нет.** NextDNS был
  единственным: его адрес — шаблон `{id}.dns.nextdns.io`, без профиля апстрим
  не собирается, а в списке замера он выглядел «— ошибка», то есть сломанным,
  а не ненастроенным. Заказчик решил его не поддерживать, и вместе с ним ушёл
  весь механизм: `prov_requires_account`, `prov_needs_input`,
  `prov_set_nextdns_id`, подстановка `{id}`, опрос профиля в мастере и колонка
  `needs_account` в мосте панели. Инвариант проверяется структурно: НИ ОДНА
  строка каталога не содержит `{…}` — такая запись доехала бы до конфига
  dnsdist и уронила службу «недопустимым именем сертификата».
- По умолчанию предлагать **нефильтрующие** варианты: фильтрующий апстрим молча
  отдаёт NXDOMAIN на домены, которые запросили клиенты туннеля, и это выглядит
  как сломанный туннель, а не как фильтр.

## Копии и обновление поверх

Опыт снят с goTelegram (`lib/backup.sh`, `install.sh` ветки 2.10.9) и
адаптирован. Что перенесено дословно и что пришлось изменить:

**Сравнение версий — `sort -V`.** `godns_version_lt A B`. Не путается на
`0.9.0` против `0.10.0`, чего не умеет ни строковое сравнение, ни наивный
разбор по точкам. Запасной почленный разбор есть, потому что «не смог
сравнить» иначе молча означало бы «не старее», то есть пропущенную миграцию.

**`GODNS_MIGRATED_FROM` + гейт по версии.** Миграции пишутся как
`if godns_migrated_from_before "0.4.0"; then …`. Но **нормализация состояния
идёт на КАЖДОМ обновлении, без гейта**: в goTelegram гейт `< 2.7.4` отсёк
ровно всех живых пользователей, потому что все они были новее, и конфиг
молча уезжал на несуществующий профиль. Гейт по версии — только для правок,
осмысленных ровно для одной старой версии (например «что нового»).

**Признак «уже установлено» — НЕ существование config.json.** У goTelegram
config.json пишется в самом конце установки, поэтому там такой гейт годится.
У нас файл создаёт уже `save_language` при первом запуске меню: язык
выбирают до того, как что-либо установлено. Гейт — `godns_state_present`:
выбранный домен, либо `applied_fingerprint`, либо `godns_version`. Иначе
человек на чистой машине получает отчёт об обновлении и лишний архив.

**Версию установленного читать только из config.json.** Соблазн взять её из
старого `lib/common.sh` на диске выглядит бесплатным и врёт: `finish`
запускается уже ПОСЛЕ подмены каталога программы, и там лежит НОВАЯ версия.
Такой «запасной источник» отменял бы миграцию ровно тем, кому она нужна.

**Нет копии — нет миграции.** `godns_update_finish` отказывается мигрировать,
если копию снять не удалось. `install.sh` при этом установку не отменяет:
подмена программы состояния не касается, и запрет должен стоять там, где
конфиг действительно переписывается.

**Порты и секретный путь — в глобальные переменные ДО первой записи**
(`godns_preserve_existing`), сверка ПОСЛЕ (`godns_restore_preserved`). Не
через `$( )`: в goTelegram эта же функция однажды исполнялась в подоболочке,
присваивания гибли вместе с ней, и «сохранение» не сохраняло ничего. Смена
пути DoH отваливает всех клиентов разом и без сообщения.

**Молчаливый no-op обязателен.** Та же версия и первая установка — ни строки
на экране, ни файла на диске. В goTelegram чистая установка не ставила
маркер, и человек при каждом запуске видел «Миграция состояния…», вопрос
«продолжить обновление?» и получал лишний архив.

**Распаковка — только `--no-same-owner --no-same-permissions`.** Архив может
быть чужим («вот мой бекап, разверни»), а разворачиваем мы его от root.

**Из архива не восстанавливается ничего исполняемого.** `dnsdist.conf` —
это Lua, который исполнит служба. В архив он кладётся для диагностики, на
место — никогда: настоящий рождается заново из `config.json` через
`engine_apply`, а архивный остаётся рядом как `…conf.from-backup`. Тот же
урок, из-за которого goTelegram не восстанавливает `server.py` и `i18n.py`.

**Сертификаты в архив не кладём вовсе.** goTelegram кладёт — у него они
свои. У нас они чужие, и копия чужого приватного ключа была бы вторым
местом, где он лежит, и первым, про которое забудут.

**Секретов нет в манифесте.** Манифест читают, чтобы РЕШИТЬ, разворачивать ли
архив; ни пути DoH, ни ключа консоли там быть не должно — они и так внутри,
в `config.json`.

**Шифрование — есть, но по умолчанию выключено.** На сервере архив лежит
0600 в каталоге 0700, то есть защищён ровно как оригиналы. Шифрование даёт
ровно одно: защиту после того, как архив уехал с сервера. Пароль — через
файл, не через argv (`/proc/<pid>/cmdline` читает любой локальный
пользователь).

**`[ -s ]` после каждой записи.** И `tar`, и `cat >` при нехватке места
завершаются успешно, оставляя пустой или обрезанный файл. Без проверки
уверенность «откат возможен» ложная.

**Сортировка копий — по mtime, не по имени.** В имени первой идёт версия, и
лексически `godns-0.10.0-…` оказывается «старше» `godns-0.9.0-…`.
`find -printf` и `stat -c` — GNU-only, поэтому python3.

## Телефоны: две чужие платформы со своими правилами

Оба факта ниже стоили работающего продукта у живого пользователя, и оба
невидимы из кода — их пришлось добывать снаружи.

**iOS и macOS ИГНОРИРУЮТ порт в `ServerURL`** пейлоада
`com.apple.dnsSettings.managed` и всегда идут на `<хост>:443`. Профиль с
`https://домен:4443/путь` ставится без единой ошибки, `plutil -lint`
считает его валидным, а система стучится на 443 — и если там сосед,
резолвер для телефона просто мёртв. Диагностики Apple не даёт никакой.

Отсюда правило: **DoH в профиль — только когда DoH на 443**. Иначе
профиль строится как DoT (`DNSProtocol=TLS`, `ServerName`): у Apple порт
DoT не настраивается вовсе — всегда 853 по RFC 7858. Ни того, ни другого
нет — генератор возвращает rc 2 и объясняет, а не отдаёт нерабочий файл.
`PayloadScope=System` обязателен, иначе macOS ставит профиль
пользовательским. Проверяется структурно.

Отдельно: `ServerAddresses` при `HTTPS` **законен** (эталонный профиль
Cloudflare его содержит) — первая версия комментария в коде обвиняла это
поле, и обвиняла зря. Настоящей причиной был порт.

**Android «Частный DNS» — это ТОЛЬКО DoT**, только имя хоста, только порт
853. Проверено по исходникам AOSP: `kDotPort = 853` — константа в
резолвере, а поле в настройках отбрасывает `host:port` ещё в UI
(`InternetDomainName.isValid` не пропускает двоеточие). DoH в системных
настройках не появился ни в 13, ни в 16; автоматический переход на DoH3
работает только для жёсткого списка (Google, Cloudflare) — чужой домен
туда не попадёт никогда.

Значит: при выключенном DoT системный путь Android закрыт в принципе, и
экран обязан говорить это прямо, а не показывать бесполезный QR. DoH на
Android — только приложением (RethinkDNS, AdGuard, Intra), там наш
нестандартный порт и секретный путь работают.

Путь в настройках у производителей РАЗНЫЙ (Pixel, Samsung, Xiaomi) — даём
все три и совет искать поиском. И предупреждаем: «Частный DNS» вместе с
VPN-приложением либо уводит DNS мимо туннеля, либо ломает всё.

**DDR (RFC 9462) не внедрять.** Android его ещё не включил, а когда
включит — потребует ALPN h3, порт 443 и путь ровно `/dns-query{?dns}`
(порт из SVCB резолвер выбрасывает). С секретным путём несовместимо по
построению.

## Тестирование: что можно доказать, а что нельзя

- «`ss` показывает LISTEN» и «до нас достучались из интернета» — **разные
  утверждения**. С самого сервера доказуемо только первое. Внешняя проверка —
  либо с ноутбука оператора, либо через сторонний сервис, и тогда честно
  сказать, что host:port уходит третьей стороне (секретный путь — не уходит).
- **DNSSEC валидирует апстрим, не goDNS Pro.** Писать «goDNS Pro проверяет DNSSEC»
  нельзя. Проверка `www.dnssec-failed.org` → SERVFAIL обязана идти в паре с
  контрольным прогоном `+cd` → NOERROR: без контроля полностью мёртвый
  резолвер тоже «проходит» тест.
- `dig +short` для этого **не годится**: он ничего не печатает и возвращает 0.
  Разбирать `status:`.
- **Ротацию апстримов видно только на уникальных именах.** С включённым
  packet cache запросы 2..N вообще не доходят до апстрима, и тест «проходит»
  по одной строке лога. Использовать случайную метку в каждом запросе.
- **«Открытый DNS с этой машины» и «goDNS Pro выпускает запросы клиентов
  открытыми» — РАЗНЫЕ утверждения.** Пока `/etc/resolv.conf` сервера
  смотрит на внешний резолвер, счётчик и tcpdump будут ловить пакеты на
  :53 — это ходит сама операционная система, а не клиенты. Красить это
  провалом нельзя: оператор на исправном сервере читает ✗ как «резолвер
  сломан». Объяснённая утечка — наблюдение (rc 3) с названным
  виновником; необъяснённая — провал. Направлять resolv.conf на себя —
  осознанный выбор со своей ценой: остановка dnsdist оставит сервер
  вообще без DNS, поэтому решение за оператором, а не за установщиком.
- **Проверка «секрет не в argv» через `/proc/*/cmdline` — шаблон только из
  файла (`grep -f`).** Строка поиска в argv самого `grep` находит его же:
  первый замер дал «41 попадание» на исправленном коде. Рядом обязателен
  положительный контроль — `curl` с канарейкой в argv тем же грепером
  ловится, иначе ноль ничего не доказывает.
- **Мост из копии дерева подключает библиотеки из `/opt`.** `bridge.sh`
  берёт `GODNS_PROGRAM_DIR` (по умолчанию `/opt/godns-installer`), поэтому
  `bash /tmp/godns-src/godns-web/bridge.sh …` исполняет СТАРЫЙ `lib/*` и
  `bench.py`, а не то, что только что синхронизировали. Живой контроль
  правки — только после выкатки в `/opt` (или с явным
  `GODNS_PROGRAM_DIR=/tmp/godns-src`).
- **Замер DoH: URL — не в argv curl** (`bench.py`, конфиг через `-K -`).
  Путь своего DoH-апстрима может быть чужим секретом, а `/proc/<pid>/cmdline`
  читает любой; мост и демон берегли путь в окружении, замер — нет. Страж 6
  читает bash-строки `curl` и python не видел — для `bench.py` свой страж
  (`argv` без `url`/`get_url`) и функциональный тест с поддельным curl.
- Утверждать «утечки открытого DNS нет» можно по счётчику nftables в output-хуке
  (`policy accept`, только считает). Но это ничего не говорит о том, что делает
  апстрим после получения запроса — так и писать.
