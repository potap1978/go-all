# Зелёный терминал — дизайн-система (`iwtsy-ds`)

Навык для раскатки единого вида на все панели и мини-приложения семьи
`iwtsy.com` / antenka. Один общий вид: тёмный терминальный фон, зелёный
акцент, моноширинный шрифт, смысловые цвета состояний. Продукт узнаётся как
часть семьи с первого экрана.

**Применять, когда просят:** админку, дашборд, панель управления скриптом,
Telegram WebApp / мини-апп, «сделай как на iwtsy», «в том же стиле»,
«натяни нашу тему», «оформи страницу статистики», «панель для бота».

**Стек, под который написано:** статика — HTML + CSS + нативные ES-модули.
Никакой сборки: деплой это `rsync`/`scp` файлов на сервер. Отдаётся любым
сервером (nginx, FastAPI `StaticFiles`, `python -m http.server`).

---

## 1. Три инварианта вида

Их нарушение сразу читается как «это другой продукт»:

1. **Тёмный терминальный фон и моноширинный шрифт.** JetBrains Mono, 400/500/700/800.
   Фон — почти чёрный с зелёным подтоном (`#080b0a`), не серый и не синий.
2. **Один зелёный акцент.** `#3fb950`. Залитая зелёным кнопка на экране одна —
   главное действие. Ссылки и вторичные акценты — циан `#56d4dd`.
3. **Смысловая шкала состояний зафиксирована:** зелёный → салатовый → жёлтый →
   оранжевый → красный. Пользователь её выучил на сайте, в админке и в
   документации API. Новое состояние вешается на существующую ступень, а не
   заводит шестой цвет.

Всё остальное — поверхности, ритм, тени, скругления, иконки, ховеры — рабочая
зона, менять можно.

## 3. Раскатка на новый скрипт — шесть шагов

**1. Скопировать ассеты** в статику проекта:

```bash
mkdir -p /opt/myapp/static/{sections,}
cp iwtsy-ds/assets/{theme.css,ui.css,ui.js,shell.js,api.js,tg-webapp.js,index.html,app.js} /opt/myapp/static/
cp iwtsy-ds/assets/sections/example.js /opt/myapp/static/sections/overview.js
```

**2. Отдать статику.** FastAPI:

```python
from fastapi.staticfiles import StaticFiles
app.mount("/panel", StaticFiles(directory="static", html=True), name="panel")
```

nginx (панель закрыта паролем, статика кешируется, `index.html` — нет):

```nginx
location /panel/ {
    auth_basic "panel";
    auth_basic_user_file /etc/nginx/.htpasswd;
    root /opt/myapp;
    try_files $uri $uri/ /panel/index.html;
}
location ~* ^/panel/.+\.(css|js)$ { root /opt/myapp; expires 7d; }
```

**3. Переписать `app.js`** — это единственный продуктовый файл:

```js
import { mountShell } from './shell.js';
import * as api from './api.js';

mountShell({
  sections: [
    { id: 'overview', title: 'Обзор',  icon: '◉', short: 'обзор',  load: () => import('./sections/overview.js') },
    { id: 'keys',     title: 'Ключи',  icon: '⌸', short: 'ключи',  load: () => import('./sections/keys.js') },
    { id: 'log',      title: 'Журнал', icon: '☰', short: 'журнал', load: () => import('./sections/log.js') },
  ],
  periods: [{ v: 1, label: '24ч' }, { v: 7, label: '7д' }, { v: 30, label: '30д' }],
  api, storageKey: 'myapp', titleSuffix: 'панель',
});
```

Значки — символы Unicode (`◉ ◈ ⧗ ⇄ ⌸ ≡ ☰ ⚑ ⚙ ⌁ ⎋ ▣`), не иконочный пакет:
внешних ресурсов в системе нет, а моноширинный шрифт ставит их по сетке.

**4. Написать разделы** по контракту (копировать `sections/example.js`):

```js
export default {
  title: 'Обзор',
  interval: 20000,                    // такт опроса; убрать — раздел статичный
  note: (d) => `за ${d.days} дн.`,    // примечание в шапке
  async load({ api, days }) { … },    // только запросы, никакой разметки
  render(el, data, ctx) { … },        // только разметка, никаких запросов
};
```

**5. Сервер отдаёт данные готовыми к показу.** Считать проценты, средние и
подписи на клиенте — значит держать логику в двух местах. Раздел получает
`{ totals, bars, recent, labels }` и раскладывает по компонентам.

**6. Проверить по чек-листу** (раздел 12) на 1440, 820 и 375 px.

## 4. Токены

Правится только `theme.css`. Поверхности и текст:

| роль | переменная | значение |
|---|---|---|
| фон страницы | `--bg` | `#080b0a` |
| карточки и блоки | `--panel` | `#0e1512` |
| вложенные поверхности, поля ввода | `--panel-2` | `#0a100d` |
| границы | `--line` | `#1c2a24` |
| границы активных элементов | `--line-2` | `#2a4033` |
| основной текст | `--fg` | `#c9d6cf` |
| заголовки и числа | `--hi` | `#eaf3ee` |
| подписи | `--dim` | `#8b9f94` |
| третьестепенное | `--faint` | `#71857a` |

Смысловая шкала — **не менять**:

| смысл | переменная | значение |
|---|---|---|
| всё хорошо | `--ok` | `#3fb950` |
| работает с потерями | `--lossy` | `#a8d65c` |
| сложности | `--warn` | `#f4c752` |
| почти не работает | `--warn2` | `#ff9e64` |
| не работает, ошибка | `--bad` | `#ff5f56` |
| закрыто, отключено | `--closed` | `#d8b84a` |
| ссылки, вторичный акцент | `--cyan` | `#56d4dd` |
| главное действие | `--accent` = `--ok`, текст на нём `--accent-ink` `#05130a` |

Геометрия и ритм: `--r: 12px` (карточки), `--r-sm: 8px` (кнопки и поля),
`--gap: 12px`, `--pad: 16px` → `22px`/`14px` от 1160 px и `12px`/`10px` на
телефоне, `--nav-w: 224px`, `--head-h: 56px`, `--speed: .16s`.

Типографика: `--fs: 14px` основной, `--fs-sm: 12.5px` таблицы и поля,
`--fs-xs: 11px` подписи, `--fs-2xs: 10.5px` бейджи и шапки таблиц,
`--fs-h: 15px` заголовки разделов, KPI-число `26px/800`. Числа всегда
`font-variant-numeric: tabular-nums` — колонки не пляшут при обновлении.

Светлая тема живёт заделом: `:root[data-theme="light"]` в `theme.css`,
включается атрибутом на `<html>`, разметка её уже поддерживает. Доводить
только по отдельной просьбе.

## 5. Компоненты

Всё из `ui.js`, вызывается внутри `h``:

| компонент | сигнатура | когда |
|---|---|---|
| `kpi` | `kpi([{value, label, hint?, color?, title?}])` | 3–6 чисел, за которыми смотрят каждый день. Больше шести — уже таблица |
| `table` | `table(cols, rows, {empty?, rowAttr?})`, `cols = [{key, title, cell?, num?, wide?}]` | любой список. На телефоне сам становится карточками |
| `badge` | `badge(text, kind)`, kind → класс `b-*` | состояние строки, источник, тип |
| `bar` | `bar(value, max, color)` | одна доля рядом с числом |
| `mixbar` | `mixbar({open: 20, timeout: 5}, colors)` | состав из состояний одной строкой |
| `spark` | `spark(values, {color})` | тренд без осей, внутри карточки |
| `stackedBars` | `stackedBars([{label, mix}], colors, {order, labels})` | «по дням» с разбивкой; своя подсказка со значениями |
| `heatmap` | `heatmap(rows, cols, get)` | матрица «что × где», витрина уникальных данных |
| `seg` | `seg(name, value, [{v, label}])` | срез данных: период, источник, тип. Один вид во всех разделах |
| `legendOf` | `legendOf(mix, colors, labels)` | подписи к цветам под графиком — обязательны |
| `section` | `section(title, body, note?)` | блок раздела с заголовком и примечанием |
| `toast` | `toast(text, 'ok'\|'bad')` | итог действия. Не для ошибок загрузки — те идут в `#stale` |

Форматтеры: `num` (`18 432`), `short` (`4,1к`), `pct`, `ago` (`5 мин назад`),
`hms`, `plural`, `dateLabel`, `okColor(percent)` — цвет по доле удачных.

Классы-обёртки: `.card`, `.block`, `.row` (флекс с `gap`), `.kpi`, `.tbl`,
`.legend`, `.badge`, `.seg`, `.btn`, `.loading`, `.empty`, `.err`, `#stale`.

## 6. Кнопки: иерархия действий

```html
<button class="btn ok">ПРОВЕРИТЬ ▶</button>   <!-- главное: залито акцентом, ОДНО на форму -->
<button class="btn">править</button>          <!-- обычное: тихий призрак, оживает под курсором -->
<button class="btn no">удалить</button>        <!-- опасное: красный призрак, наливается под курсором -->
<button class="btn" disabled>недоступно</button>
```

В строках таблиц `.btn` ужимается автоматически (`td .btn`) — ряд действий не
перевешивает данные. Исключение делается вручную для решений вида
«пустить / отклонить»: они должны быть крупными.

Опасное действие всегда требует подтверждения текстом того, что удаляется, —
не «вы уверены?», а «удалить партнёра `acme` и все его ключи?».

## 7. Четыре состояния данных

Обязательны у каждого раздела, иначе панель врёт:

1. **Загрузка** — `<div class="loading">загружаю…</div>`, точка-спиннер уже в CSS.
2. **Пусто** — `<div class="empty">…</div>`: пунктирный слот с объяснением,
   почему пусто и когда наполнится. Пустая база — нормальное состояние первого
   дня, «нет данных» тут недостаточно.
3. **Ошибка** — `<div class="err">…</div>`, когда рисовать нечего.
4. **Устарело** — полоса `#stale` над разделом, когда данные на экране есть, а
   очередной такт опроса не удался. Экран и наполовину заполненную форму рвать
   нельзя. Это делает `shell.js` сам.

Отдельно: **чего не смогли узнать — называть прямо.** `0 ждут модерации` при
недоступном источнике — не ноль, а незнание: показывать прочерк и подпись
«не удалось получить». Пропавший сигнал читается как «всё спокойно», а это
не одно и то же.

## 8. Оболочка и адаптив

Три ширины, все три обязательны к проверке:

* **ПК (> 1000 px)** — боковое меню `--nav-w`, прилипшая шапка с блюром,
  контент в `#view` с `--pad`.
* **Планшет (≤ 1000 px)** — меню уезжает наверх строкой и переносится, а не
  прячется за горизонтальную прокрутку: это рабочий инструмент.
* **Телефон (≤ 700 px)** — меню фиксируется снизу под большой палец, иконка
  над короткой подписью (`short`), счётчики становятся точками-значками;
  таблицы превращаются в карточки, подпись колонки берётся из `td[data-l]`
  через `::before`.

Ни одной горизонтальной прокрутки страницы. Внутри широких таблиц и тепловой
матрицы — можно и нужно.

## 9. Telegram WebApp

Мини-апп — это тот же экран, что панель на телефоне, плюс мост в клиент.
Подключение:

```html
<script src="https://telegram.org/js/telegram-web-app.js"></script>
```

```js
import { initTelegram } from './tg-webapp.js';

const tg = initTelegram({ onBack: () => { location.hash = '#/overview'; } });

tg.main.set({ text: 'ПРОВЕРИТЬ', onClick: run });   // главное действие — родная кнопка
tg.main.progress(true);                              // на время запроса
tg.haptic('ok');                                     // итог операции
tg.back(true);                                       // вложенный экран
tg.guardClose(true);                                 // в форме есть несохранённое
```

Правила:

* **Тему клиента не подхватываем.** Вид один на всех площадках: светлый
  Telegram не должен выбеливать панель. Из клиента берём только высоту окна,
  безопасную зону, родные кнопки и вибрацию.
* **Высота — из `viewportStableHeight`**, не `100vh`: иначе при открытой
  клавиатуре нижнее меню то уезжает под край, то прыгает на каждый символ.
  `tg-webapp.js` кладёт её в `--tg-vh`.
* **Главное действие — родная MainButton**, а не кнопка в вёрстке. Вёрстанный
  дублёр помечается `data-tg-main` — `ui.css` прячет его внутри Telegram,
  чтобы на экране не было двух главных кнопок.
* **«Назад» — родная BackButton**, своя стрелка в интерфейсе не рисуется:
  `#burger` внутри Telegram скрыт, заголовок раздела рисует сам клиент.
* **Вертикальный свайп отключается** (`disableVerticalSwipes`): иначе жест
  закрывает мини-апп посреди заполненной формы.
* **Вибрация на каждое решение** — без неё мини-апп ощущается веб-страницей.
* **Данные не доверять клиенту.** `initData` проверяется на сервере HMAC-подписью
  токена бота; без проверки любой может подставить свой `user.id`.

## 10. Безопасность разметки

Правило без исключений: **данные попадают в HTML только через `` h` ` `` или
`esc()`**. Тег-шаблон экранирует каждую подстановку сам; готовую разметку
оборачивают в `raw()`.

```js
el.innerHTML = String(h`<div class="card">цель: ${target}</div>`);   // так
el.innerHTML = '<div>цель: ' + target + '</div>';                    // никогда
```

Прямой `innerHTML` с данными, конкатенация строк с данными, `eval` —
запрещены. Это не стиль, а защита от XSS по построению: в панель попадают
строки, которые прислали посторонние — адреса целей, имена операторов,
пользовательские метки.

## 11. Грабли (проверено на живом продукте)

1. **Обработчики не навешивать поэлементно.** Раздел перерисовывается по
   таймеру — слушатели копились бы с каждым тактом. Один `el.onclick` на
   контейнер, поиск цели через `e.target.closest('[data-act]')`.
2. **Гонки запросов.** Пока идёт медленный запрос, успевают переключить
   раздел — ответ придёт последним и перетрёт свежие данные. `shell.js`
   нумерует запросы и выбрасывает устаревшие; в своём коде делать так же.
3. **Ячейка-карточка на телефоне — flex-строка.** Её содержимому нужен
   `flex: 0 0 auto`, иначе браузер рвёт подписи посреди слова: «ДОСТУ П ЕСТЬ».
4. **Полосам `.mixbar` / `.bar` внутри карточки нужна явная ширина**
   (`flex: 1 1 90px`), иначе схлопываются в ноль и строка выглядит пустой.
5. **`.side` на телефоне** фиксируется снизу — сбросить унаследованные
   `top: 0` и `height: 100vh`, иначе панель растянется на весь экран и
   закроет раздел своим фоном.
6. **Два атрибута `class` браузер не склеивает** — второй молча пропадает.
   Класс собирать одной строкой.
7. **`letter-spacing` в пикселях не сжимается** при масштабировании текста —
   строка вылезает за контейнер. На командах и длинных строках обнулять.
8. **Скрытая вкладка сервер не дёргает.** Опрос останавливается по
   `document.hidden` — на телефоне это заметная разница по батарее и трафику.
9. **`min-width: 0` и `minmax(0, 1fr)`** на колонках сетки: без них широкая
   таблица растягивает всю страницу вбок вместо прокрутки внутри себя.
10. **Свои подсказки вместо `title`** там, где под курсором единственное
    место с цифрами: браузерная всплывашка появляется через секунду,
    системным шрифтом и без цвета состояния.
11. **`prefers-reduced-motion` уважается** одним правилом в конце `ui.css` —
    не потерять при правках.
12. **Фиксированные панели съедают низ страницы.** Под нижнее меню и виджеты
    добавляется `padding-bottom`, иначе последние строки недоскроллить.

## 13. Чего в системе нет — осознанно

Сборки и npm. CSS-фреймворков. Иконочных пакетов и картинок с чужих доменов.
Библиотек графиков — `spark`, `stackedBars`, `heatmap` рисуются инлайновым SVG
и `div`-ами, этого хватает. Модальных окон — опасное подтверждение делается
текстом в строке, а не диалогом. Анимаций ради анимаций: движение только там,
где показывает изменение данных.

Если чего-то из этого просят — сначала сказать, что система обходится без
этого и почему, и только потом добавлять.
