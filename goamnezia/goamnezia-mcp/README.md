# goamnezia-mcp — MCP-сервер goAmnezia pro

`goamnezia-mcp` — четвёртый интерфейс к серверу goAmnezia после SSH-меню, Telegram-бота и
панели: он предназначен не для человека, а для ИИ-агента. Claude Code, Claude Desktop, Cursor и
любой другой клиент [Model Context Protocol](https://modelcontextprotocol.io/) видят набор
**типизированных инструментов** («создать пользователя», «выдать ключ», «обновить ядро») с
описанием и JSON-схемой параметров — и работают с сервером как с API, а не разбирают экраны
меню. Фраза «добавь пользователя Анна с лимитом 50 ГБ и пришли QR для awg2» превращается в два
вызова инструментов, а QR приходит в чат картинкой.

Сервер — один файл `server.py` на чистой стандартной библиотеке Python (≥ 3.8, без `pip`),
транспорт stdio (через SSH) или Streamable HTTP по секретному пути (см. [Подключение по
HTTP](#подключение-по-http)), протокол MCP `2025-06-18` (совместим с клиентами `2025-03-26` и
`2024-11-05`).
Он **ничего не делает сам**: каждый вызов инструмента превращается в штатный мост
`install.sh --action=<имя> --json --k=v …`, а последняя JSON-строка его stdout становится
результатом. Тот же мост используют бот и панель, тот же замок `config.lock`, те же проверки
входа — MCP лишь добавляет к ним свою валидацию, подтверждение `confirm` и аудит.

```
Claude Code / Claude Desktop / Cursor / любой MCP-клиент
        │  stdio: JSON-RPC 2.0, по одному сообщению на строку
        ▼
ssh root@HOST goamnezia-mcp  ──►  /opt/goamnezia-mcp/server.py
        аутентификация — ключ SSH        │  install.sh --action=user-add --json --name=anna --quota-gb=50
        никаких открытых портов          ▼
                                   /opt/goamnezia/install.sh (мост)  →  config.json · users.json · docker
                                         stdout: {"status":"success",…}   stderr: UI и логи
```

Единственный источник правды для набора инструментов — `lib/actions.json`. Из него строятся
`tools/list` (имена, схемы, флаги «только чтение» / «разрушительное», описания RU/EN), ресурсы и
подсказки. В `server.py` нет ни одного имени действия, поэтому переходник переносится в другие
скрипты серии без переписывания (см. [Перенос](#перенос-в-другой-продукт-серии)).

## Быстрый старт

1. На сервере (ставится вместе с goAmnezia: `/opt/goamnezia-mcp/server.py`, команда
   `/usr/local/bin/goamnezia-mcp`) убедитесь, что переходник видит каталог действий и мост:

   ```bash
   goamnezia-mcp --check
   # actions.json : /opt/goamnezia/lib/actions.json
   # action bin   : /opt/goamnezia/install.sh
   # tools        : 65 (чтение 21, изменение 31, разрушительных 13); скрыто (mcp: null): 24
   # resources    : 6 (действий 5, файлов 1), prompts: 3
   # http         : выключен (127.0.0.1:1986 за nginx); agents.json /opt/goamnezia/agents.json (нет файла) — доступов 0 …
   # OK
   ```

2. На своей машине подключите сервер к Claude Code (нужен рабочий вход по ключу
   `ssh root@HOST`):

   ```bash
   claude mcp add goamnezia -- ssh root@HOST goamnezia-mcp
   claude mcp list        # goamnezia: … - ✓ Connected
   ```

3. В сессии Claude Code наберите `/mcp` — сервер `goamnezia` покажет все инструменты (сейчас 65), 6 ресурсов
   (пять сводок сервера и гайд для агента `goamnezia://guide`) и 3 подсказки. Попросите: «покажи
   состояние сервера и список пользователей» — агент вызовет `server_status` и `users_list`.
   Инструкции сервера просят модель прочитать гайд до первого изменяющего вызова; подключить его
   к контексту можно и вручную: `@goamnezia:goamnezia://guide` (см. [Документация для агента](#документация-для-агента)).
   Разрушительные действия агент выполнит только после вашего подтверждения в клиенте **и** с
   параметром `confirm` (см. [Модель безопасности](#модель-безопасности)).

## Подключение

Во всех клиентах команда одна и та же: `ssh root@HOST goamnezia-mcp`. Клиент запускает её как
подпроцесс и общается с сервером через stdin/stdout — ни портов, ни токенов, ни веб-хуков.
Полезные ключи `ssh`:

| Ключ | Зачем |
|---|---|
| `-o BatchMode=yes` | не задавать вопросы (пароль, «добавить host key?») — у процесса нет терминала, вопрос повесит сессию |
| `-o ServerAliveInterval=30` | держать соединение живым во время долгих действий (`profile_install`, `upstream_update`) |
| `-i ~/.ssh/goamnezia_mcp` | отдельный ключ только для агента (см. ниже про `authorized_keys`) |

Первый раз подключитесь к серверу обычным `ssh root@HOST` вручную, чтобы host key попал в
`known_hosts`, иначе `BatchMode` откажет.

### Claude Code

```bash
# только для текущего проекта (по умолчанию)
claude mcp add goamnezia -- ssh -o BatchMode=yes -o ServerAliveInterval=30 root@HOST goamnezia-mcp

# для всех проектов на этой машине
claude mcp add --scope user goamnezia -- ssh -o BatchMode=yes root@HOST goamnezia-mcp

# то же в виде JSON
claude mcp add-json goamnezia '{"command":"ssh","args":["-o","BatchMode=yes","root@HOST","goamnezia-mcp"]}'

# язык подсказок и сообщений об ошибках — переменной окружения на стороне сервера
claude mcp add goamnezia -- ssh root@HOST "GOAMNEZIA_LANG=en goamnezia-mcp"
```

Проверка: `claude mcp list` (состояние подключения), `claude mcp get goamnezia` (конфигурация),
в сессии — `/mcp`. Инструменты видны модели как `mcp__goamnezia__<имя>`, например
`mcp__goamnezia__user_add`. Ресурсы подключаются через `@goamnezia:goamnezia://status`,
подсказки — как команды `/mcp__goamnezia__onboard_user`.

Долгие действия: Claude Code ждёт ответа инструмента ограниченное время (переменная
`MCP_TOOL_TIMEOUT`, миллисекунды). Установка профиля или обновление ядра могут идти несколько
минут — при необходимости поднимите этот лимит; сервер со своей стороны ждёт мост
`GOAMNEZIA_MCP_TIMEOUT` секунд (по умолчанию 300).

### Claude Desktop

Файл конфигурации: macOS — `~/Library/Application Support/Claude/claude_desktop_config.json`,
Windows — `%APPDATA%\Claude\claude_desktop_config.json`. Добавьте сервер в `mcpServers` и
перезапустите приложение:

```json
{
  "mcpServers": {
    "goamnezia": {
      "command": "/usr/bin/ssh",
      "args": ["-o", "BatchMode=yes", "-o", "ServerAliveInterval=30",
               "-i", "/Users/USER/.ssh/goamnezia_mcp", "root@HOST", "goamnezia-mcp"]
    }
  }
}
```

Особенности настольного приложения: оно запускает команду с минимальным окружением, поэтому
путь к `ssh` лучше указывать абсолютным (`/usr/bin/ssh` на macOS,
`C:\\Windows\\System32\\OpenSSH\\ssh.exe` на Windows), а SSH-агент может быть недоступен —
используйте ключ без парольной фразы, указанный через `-i`, или алиас в `~/.ssh/config`
(`Host goamnezia` с `HostName`, `User`, `IdentityFile`), тогда в `args` остаётся
`["goamnezia", "goamnezia-mcp"]`. Логи подключения: `~/Library/Logs/Claude/mcp-server-goamnezia.log`.

### Cursor

Глобально — `~/.cursor/mcp.json`, для проекта — `.cursor/mcp.json`; формат тот же, что у
Claude Desktop:

```json
{
  "mcpServers": {
    "goamnezia": {
      "command": "ssh",
      "args": ["-o", "BatchMode=yes", "root@HOST", "goamnezia-mcp"]
    }
  }
}
```

После сохранения сервер появится в Settings → MCP; инструменты включаются там же. Cursor
показывает подтверждение на каждый вызов инструмента, если не включён авто-режим — для
сервера с root-доступом авто-режим лучше не включать.

### Другие клиенты

Подойдёт любой клиент со stdio-транспортом: команда `ssh`, аргументы
`root@HOST goamnezia-mcp`. Сервер отвечает на `initialize`, `ping`, `tools/list`, `tools/call`,
`resources/list`, `resources/read`, `resources/templates/list`, `prompts/list`, `prompts/get`;
уведомление `notifications/initialized` принимает молча. Агентам, которые не умеют запускать
`ssh` (облачные сессии, Claude Code в браузере), нужен HTTP-транспорт — следующий раздел.

## Подключение по HTTP

Тот же сервер умеет Streamable HTTP (`server.py --http`, PLAN §6.10): агент подключается **без
SSH** по адресу вида `https://…/a-<секрет>/mcp`. У каждого агента свой адрес («доступ»), у
доступа — уровень, срок, список адресов; любой доступ выключается, перевыпускается и удаляется
мгновенно.

**Доказательств два, и это принципиально.** Секретный путь — 32 случайных байта (43 символа
base64url), подобрать его нельзя. Но адрес — то, что *видно*, и утекает он буднично: снимок
экрана со ссылкой, пересылка в мессенджере, история браузера, журнал промежуточного прокси,
конфиг агента на чужой машине, резервная копия этого конфига. Поэтому у доступа есть второй
секрет — **токен**, который передаётся не адресом, а заголовком:

```
Authorization: Bearer <токен>
```

Заголовок в перечисленные места не попадает: браузер его не запоминает, прокси пишет в лог метод
и URL, на снимке экрана со ссылкой его нет. Утёкший адрес сам по себе бесполезен.

**Отказ выглядит как «нет такого пути».** Запрос по верному адресу без верного токена получает
тот же `404` с телом nginx, что и любой чужой путь. Не `401`: `401` подтвердил бы, что путь
существует и нужен лишь пароль — тот, кто нашёл адрес, узнал бы, что нашёл живой сервер, и
занялся бы токеном. `404` не отличим от ответа сайта-маскировки, и подобравший адрес не понимает,
что подобрал.

**Старые доступы не сломались.** У выданных до появления токена в записи нет `require_token`
(умолчание — `false`), они работают по одному адресу и помечены в списках как «слабый доступ,
только путь». Выдать такому доступу токен — `agent-harden` («Выдать токен» в меню, боте и
панели); после этого агенту нужно прописать заголовок, иначе он получит `404`.

### Одноразовый ключ: `mode: rolling`

Токен закрывает утечку ссылки. Он не закрывает — и не может закрыть — **копирование доступа
целиком**: файл конфигурации агента унесли на другую машину, и там он работает точно так же.
Скопированный секрет обезвредить программно нельзя: любая проверка живёт на той же машине, что и
секрет, и копируется вместе с ним. Поэтому цель другая — не предотвратить кражу, а
**гарантированно её заметить**.

Доступ с `mode: "rolling"` выдаёт вместе с адресом и токеном **одноразовый ключ**. Каждый успешный
запрос сжигает пришедший ключ и возвращает следующий заголовком ответа:

```
   запрос:  X-Ga-Key: <текущий ключ>      X-Ga-Nonce: <номер этой попытки>
   ответ:   X-Ga-Next-Key: <следующий ключ>
```

Ключ едет **заголовком**, а не в теле: тело ответа клиенты MCP пишут в свои отладочные журналы
целиком, и ключ уезжал бы туда при каждом вызове.

Сервер помнит текущий ключ, предыдущий и отпечатки полусотни уже выданных. Дальше решает таблица:

| Что пришло | Вывод | Ответ |
|---|---|---|
| Текущий ключ | законный запрос | результат и следующий ключ |
| Предыдущий **с тем же номером** | ответ не доехал, агент повторил дословно | тот же самый сохранённый ответ и тот же следующий ключ; действие **не** выполняется заново |
| Предыдущий с другим номером, но запрос пришёл **раньше, чем ушёл ответ** с новым ключом | одновременность: отправитель следующего ключа знать не мог | выполняется и получает **тот же** новый ключ; цепочка не вращается |
| Ключ **из истории выданных** (или предыдущий, пришедший уже после ухода ответа) | клон: у настоящего агента такого ключа уже нет | доступ **замораживается**, владельцу уходит сообщение |
| Что угодно ещё | обычный неверный ключ | тот же `404`, что у чужого пути, плюс счётчик неудач |

Последние две строки различаются намеренно. Ключ, которого сервер никогда не выдавал, ничего не
доказывает: считай его клоном — и всякий, кто узнал адрес, гасил бы чужого агента одним мусорным
запросом.

**Гарантия одной строкой:** клон не может сделать больше одного запроса, оставшись незамеченным.
Молчал вор — он придёт со старым ключом; пришёл вор первым — со старым ключом придёт настоящий
агент. Исход один и тот же.

**Обнаружение замораживает, а не удаляет.** Доступ перестаёт впускать вообще всех, а владелец
получает карточку с двумя временами и двумя адресами: когда и откуда пришёл чужой ключ и когда и
откуда работал доступ в последний раз. В событии есть признак `frozen`: если заморозить не удалось
(реестр не пишется), доступ **жив**, и сообщение владельцу говорит это прямо, а не «заморожен». Решений два: «это был я, перевыпустить» (`agent-rotate` —
новая цепочка ключей, заморозка снята) и «отозвать совсем» (`agent-del`). Так и должно быть:
восстановление машины агента из вчерашней резервной копии выглядит ровно как кража.

> **Один доступ — один клиент.** Два запроса разом от ОДНОГО клиента сервер пропускает: тот, что
> пришёл раньше ответа с новым ключом, знать этого ключа не мог, и это не копия. А вот два
> РАЗНЫХ клиента вращают одну цепочку, и второй приходит с уже сожжённым ключом много позже —
> сервер честно объявит это клоном и заморозит доступ. Каждому клиенту выдавайте свой доступ.
>
> **Файл ключа нельзя держать в синхронизируемой папке.** iCloud, Dropbox, OneDrive и им подобные
> размножат его на вторую машину и устроят ту же ложную тревогу.

**Свой клиент.** Обычный клиент MCP менять заголовок между запросами не умеет, поэтому `rolling` —
**явный выбор** при выдаче (умолчание остаётся `static`), и подключается он клиентом, который умеет
положить `X-Ga-Key` и `X-Ga-Nonce` в запрос и прочитать `X-Ga-Next-Key` из ответа. Одноразовый ключ
показывается **один раз** — при выдаче и при перевыпуске; на сервере остаётся только его отпечаток.
Для обычного клиента есть переходник — вид `connect`, ниже.

### Переходник: `mode: connect`

Тот же одноразовый ключ, но хранит и вращает его **`goamnezia-connect`** — один файл на Python 3.8+
без сторонних пакетов, который клиент MCP запускает как обычный stdio-сервер. В конфигурации клиента
нет ни адреса, ни токена, ни ключа — при пересылке нести нечего:

```json
{"mcpServers": {"goamnezia": {"command": "/usr/bin/python3",
  "args": ["/Users/you/bin/goamnezia-connect", "--grant", "a-b285", "--dir", "/Users/you/.config/goamnezia-connect"]}}}
```

Интерпретатор, скрипт и каталог настроек — полными путями: клиент с окнами (Claude Desktop и прочие) не
видит ни PATH, ни XDG_CONFIG_HOME оболочки, а первая строка скрипта ищет `python3` именно через PATH. Готовую строку печатает сам переходник — при
привязке и командой `~/bin/goamnezia-connect status --grant a-b285`. Работает на macOS и Linux.

1. **Выдача.** `agent-add --mode=connect` (или вид доступа «connect» в меню, боте и панели) печатает
   одноразовый **код привязки** `GA-XXXXX-XXXXX-XXXXX-XXXXX`, годный 10 минут, и команды:

   ```bash
   mkdir -p ~/bin && scp root@<IP сервера>:/opt/goamnezia/goamnezia-mcp/connect.py ~/bin/goamnezia-connect && chmod +x ~/bin/goamnezia-connect
   ~/bin/goamnezia-connect enroll GA-XXXXX-XXXXX-XXXXX-XXXXX --server https://vpn.example.com
   ```

   С самоподписанным сертификатом в команде есть ещё `--fingerprint <SHA-256>`: переходник сверяет
   сертификат с ним и рвёт соединение при расхождении.
2. **Привязка.** Код по сети не едет — переходник шлёт его отпечаток путём. Сервер создаёт токен,
   первый ключ и зерно плавающего пути и отдаёт их один раз; код сгорает. Владельцу приходит
   уведомление с адресом привязки: чужая привязка — повод перевыпустить доступ сразу.
3. **Работа.** Путь меняется каждую минуту (`/r-<HMAC>/mcp`); постоянный `/a-…/mcp` такой доступ не
   принимает. Часы переходник сверяет с сервером по заголовку `Date`, так что NTP ни на одной стороне
   не нужен. Ключ лежит в **TPM** через `systemd-creds`, где он есть (копия файла на другой машине
   не расшифровывается), иначе — файлом `0600`; что выбрано, видно в карточке доступа. Второй
   экземпляр переходника на том же доступе не запустится, а в синхронизируемой папке (iCloud,
   Dropbox, OneDrive…) переходник жить отказывается.
4. **Перевыпуск** — новая привязка: прежние токен, ключ и зерно умирают разом, выдаётся новый код. Если
   клиент MCP в это время ещё открыт и держит прежний переходник, привязка не теряется: она ляжет
   рядом и включится при следующем запуске переходника — закройте и откройте клиент.

`goamnezia-connect status --grant a-b285` показывает состояние привязки без секретов. Настройки —
в `~/.config/goamnezia-connect` (`--dir`, если нужен другой каталог). Подробности и отступления от
замысла — docs/MCP_ROTATION.md §12.6.

**Привязка к адресу** (`pin_ip`, по умолчанию выключена, предлагается при выдаче) — третья,
необязательная линия: доступ запоминает адрес, с которого им воспользовались впервые, и дальше
принимает только его. Страховка на случай, когда утекли и адрес, и токен. Снимается
`agent-pin --id=a-xxxx --state=off` (или кнопкой в карточке).

**Срок по умолчанию — 30 дней.** Бессрочный доступ (`--days=0`) остаётся возможным, но это явный
выбор с предупреждением: он живёт ровно столько, сколько живёт утечка, о которой никто не узнал.

**Владельцу приходит уведомление** (в бота): при первом использовании доступа, при вызове с
нового адреса и при запросе по верному адресу без верного токена — последнее означает, что адрес
где-то утёк и им уже пробуют воспользоваться.

**Где живёт адрес.** Решает не название режима, а то, чем сайт отдаётся **сейчас**: сайт в
`lite_site` и в `pro` один и тот же (домен, Let's Encrypt, TCP/443), а самоподписанный
сертификат на IP — запасной путь любого из них, пока домена нет или его A-запись ещё не
указывает сюда. Поэтому `ga_agents_endpoint` и `mcp-http-status` спрашивают готовность домена
(`ga_site_domain_ready`), а не режим:

| Состояние сайта | Адрес | Сертификат |
|---|---|---|
| Сайт на домене с Let's Encrypt (оба режима с сайтом) | `https://<домен>/a-<секрет>/mcp` — nginx проксирует в `127.0.0.1:1986` | Let's Encrypt, ничего доверять не надо |
| Сайт на запасном самоподписанном (домена ещё нет) | `https://<IP>/a-<секрет>/mcp` — тот же nginx на IP | самоподписанный сертификат сайта: клиенту нужно доверить его по отпечатку (ниже) |
| `lite` — сайта нет | `https://<IP>:<порт>/a-<секрет>/mcp` — свой TLS-слушатель на отдельном порту (`mcp-http-on --port=N`, случайный 30000–49999 из меню) или персональный порт доступа (`agent-add --port=N`) | тот же самоподписанный |

Проверка по режиму была бы неверной: в `lite_site` с готовым доменом она выдавала бы адрес по IP
с отпечатком запасного сертификата — ссылку, по которой доверия не будет.

Без сайта и без порта в Lite транспорт включить нельзя (`needs_site`) — SSH-транспорт при этом
работает всегда.

**Включить и выдать доступ** — из любого человеческого интерфейса (агент сделать этого не может,
действия `agent-*`/`mcp-http-*` для него скрыты):

- SSH-меню: `goamnezia` → Настройки → «Доступы агентов (MCP по HTTP)»: включить транспорт,
  «Добавить доступ» (название, уровень, срок, привязка к адресу, адреса) → адрес, токен, готовая
  команда подключения и QR адреса (в QR только адрес — иначе снимок экрана снова стал бы полным
  ключом);
- бот: Настройки → «🤖 Доступы агентов» (адрес и токен приходят отдельным сообщением — его можно
  удалить сразу после копирования); панель: страница «Агенты»;
- мост: `goamnezia --action=mcp-http-on --json` (в Lite — `--port=40000`),
  `goamnezia --action=agent-add --json --label="Claude Code" --scope=read --days=30 --allow-ips=203.0.113.0/24 --pin-ip=on`
  (`--scope` можно не писать: умолчание — `read`)
  → в ответе `url`, `token`, `connect` (готовая команда), `cert_fingerprint_sha256` (если
  сертификат самоподписанный) и `hint`. С `--mode=connect` адреса и токена нет: вместо них
  `enroll_code` (один раз), `enroll_expires` и `connector_hint`.

**Claude Code:**

```bash
claude mcp add --transport http goamnezia https://vpn.example.com/a-<секрет>/mcp \
  --header "Authorization: Bearer <токен>"
claude mcp list        # goamnezia: https://… (HTTP) - ✓ Connected
```

`--header` (короткая форма `-H`) можно повторять. То же в файле конфигурации (`.mcp.json`,
`~/.claude.json`):

```json
{"mcpServers": {"goamnezia": {"type": "http", "url": "https://vpn.example.com/a-<секрет>/mcp",
  "headers": {"Authorization": "Bearer <токен>"}}}}
```

Cursor (`~/.cursor/mcp.json`) — тот же блок без `type`, с подстановкой из окружения, чтобы токен
не лежал в файле проекта:

```json
{"mcpServers": {"goamnezia": {"url": "https://vpn.example.com/a-<секрет>/mcp",
  "headers": {"Authorization": "Bearer ${env:GOAMNEZIA_MCP_TOKEN}"}}}}
```

Claude Desktop: в его окне «Коннекторы / Custom integrations» произвольные заголовки задать
нельзя (там только OAuth), поэтому доступ подключается через прокси `mcp-remote` в
`claude_desktop_config.json`:

```json
{"mcpServers": {"goamnezia": {"command": "npx",
  "args": ["-y", "mcp-remote", "https://vpn.example.com/a-<секрет>/mcp", "--header", "Authorization:${AUTH}"],
  "env": {"AUTH": "Bearer <токен>"}}}}
```

Пробел внутри `args` часть клиентов (Claude Desktop на Windows, Cursor) не экранирует, поэтому
значение с пробелом выносится в переменную окружения — заголовок в `args` пишется без пробела
после двоеточия.

`Origin`, если клиент его шлёт, должен совпадать с `Host` (защита от DNS-rebinding; исключения —
`mcp.allowed_origins` в `config.json`). Заголовок `Authorization` nginx передаёт наверх как есть —
он не в числе тех, что проксирование съедает (`Connection`, `Proxy-Authorization`, `Upgrade`…), и
в `location` доступов его никто не переопределяет.

**Запасной самоподписанный сертификат (сайт на IP, пока нет домена; Lite со своим портом).** Клиент откажется от TLS-соединения с
неизвестным сертификатом. Скачайте сертификат сайта и подсуньте его клиенту как доверенный корень:

```bash
scp root@HOST:/opt/goamnezia/tls/site.crt ~/.goamnezia-site.crt
openssl x509 -noout -fingerprint -sha256 -in ~/.goamnezia-site.crt   # сверьте с отпечатком из меню / ответа agent-add
NODE_EXTRA_CA_CERTS=~/.goamnezia-site.crt claude                     # Claude Code (Node.js) — для каждой сессии
```

Отпечаток SHA-256 показывают `mcp-http-on`, `agent-add`, `agent-show`, `status`
(`site.cert_fingerprint_sha256`) и экран «Режим и сайт». Он не меняется, пока жив сертификат
(10 лет; перевыпуск — только при смене IP или вручную «Перевыпустить сертификат»), поэтому
доверенный файл не устаревает. Для Cursor и Claude Desktop (Electron) — добавьте `site.crt` в
системное хранилище доверенных сертификатов ОС или доведите сайт до домена с Let's Encrypt —
режим для этого менять не нужно, настоящий сертификат выпускается в любом из двух режимов с сайтом.

**Уровни доступа** (`scope`, по умолчанию `read`). Все три интерфейса при выдаче печатают
**состав** уровня, а не одно его свойство — иначе владелец выбирал бы по одной строке, которая
о главном молчит:

| Уровень | Что получает |
|---|---|
| `read` | Смотреть: состояние, люди, профили, трафик, журналы. Приватных ключей клиентов **не** выдаёт (`user_get_key` скрыт) и ничего не меняет. Журналы сужены: `logs_tail component=system` не даётся вовсе, `component=mcp` отдаёт только строки аудита этого же доступа |
| `write` | Всё из `read`, плюс: **выдача приватного ключа любого клиента** (одним запросом украденного доступа уносят чужой рабочий конфиг); заведение и правка людей и профилей; и — **без единого подтверждения** — `mode_set`, то есть снос сайта-маскировки, панели на домене и всего транспорта агентов, включая собственный (агент, переключивший сервер в `lite`, отрезает сам себя); `site_set_template` (сайт заменяется целиком), `panel_domain_disable`, `backup_schedule off` |
| `admin` | Всё из `write`, плюс разрушительное: удалить человека, профиль или доступ, восстановить из копии, обновить ядро — каждое с `confirm` |

Умолчание `read` — это наименьшие права: украденный доступ успевает один запрос, и этим запросом
не должен быть чужой рабочий конфиг. Выше `read` уровень выдаётся явным выбором.
Инструменты вне уровня агент **не видит** в `tools/list`
(подсказки — только те, все шаги которых доступны); вызов по имени → JSON-RPC `-32003` `forbidden`.
`initialize.instructions` сообщают агенту его уровень.

**Отзыв и учёт.** Сервер читает `/opt/goamnezia/agents.json` при каждом запросе (по mtime), поэтому
«Выключить», «Удалить», «Перевыпустить» и «Выдать токен» действуют на следующий же вызов агента —
без перезапуска службы и nginx. Выключенный, истёкший (`--days`), пришедший не из `allow_ips` или
не с закреплённого адреса, с неверным токеном или просто неизвестный адрес получают один и тот же
`404` с телом nginx; 20 неудач с одного IP за 10 минут — бан IP на 10 минут (тоже `404`); тело
больше 1 МБ — `413`; `GET` — `405`. **Бан не бьёт по своему:** отказ по состоянию доступа
(выключен, истёк, заморожен) счётчик подбора не трогает, а перевыпуск снимает бан с адресов
доступа — иначе честный агент после заморозки за двадцать своих же вызовов банил собственный
адрес, и новый ключ не работал ещё десять минут. **Предел частоты** — 120 удачных вызовов на
доступ за минуту; сверх него честный `429` с `Retry-After` (не `404`: ключ уже сошёлся, и прятать
нечего) и событие владельцу. **Замок занят:** первое закрепление адреса (`pin_ip`) пишется под
`config.lock`, а его минутами держит каждое пишущее действие моста (установка профиля,
восстановление); не дождался замка — `503` с `Retry-After`, ничего не выполнено, повторить тем же
ключом. Уже закреплённый адрес замка не ждёт вовсе. **Истечение не молчит:** владелец получает уведомление за три дня
до конца и в момент первого отказа, а продлить срок можно `agent-extend`, не трогая ни адрес, ни
токен — агента перенастраивать не придётся. После каждого успешного вызова обновляются `last_used`,
`last_ip` (из `X-Real-IP` только за nginx), `calls` и `known_ips` (последние 10 адресов) — их
видно в списке доступов. В аудит-лог попадает `agent=<id>`; ни секрет, ни токен не пишутся ни в
один лог (путь в логах сервера маскируется до `/a-***`, заголовок не логируется вовсе).

**Если адрес всё-таки утёк.** Перевыпуск (`agent-rotate`) меняет и секрет, и токен сразу:
компрометация одного фактора ничего не говорит о втором. Старый адрес умирает на следующем же
запросе.

**Служба.** `goamnezia-mcp-http.service` (`Restart=always`, `User=root`) —
`server.py --http --bind 127.0.0.1 --port 1986` за nginx или `--bind 0.0.0.0 --port <N> --tls
site.crt,site.key` в Lite; персональные порты доступов открываются автоматически
(`--extra-ports auto`). Состояние: `goamnezia --action=mcp-http-status --json`, логи —
`journalctl -u goamnezia-mcp-http` (пункт «Логи службы» в меню). Выключение (`mcp-http-off`)
снимает маршрут и службу, доступы остаются в файле.

Ответ `mcp-http-status` различает «включено», «записано» и «здесь этого не бывает» — три разных
состояния, которые раньше сливались в одно поле: `enabled` — транспорт **работает**;
`configured` — он включён в `config.json` (флаг переживает смену режима, и в `lite` от него
остаётся след, за которым ничего нет); `available` — транспорту есть где слушать; `reason`
(`no_site`) и `hint` — чего не хватает и что сделать. Рядом — `listen` (`nginx` |
`public_port` | `grant_ports` | `none`), `base_url`, `via` (`domain` | `ip` | `port`),
`cert_fingerprint_sha256` на запасном сертификате, `nginx_location`, `unit_state`, `reachable`
(мёртвый юнит за живой nginx-локацией — это 502, а не работающий транспорт) и счётчики доступов,
включая `agents_weak` (живут на одном лишь адресе) и `agents_compromised` (заморожены по
подозрению на клон).

## Модель безопасности

**Аутентификация — ключ SSH, портов нет.** MCP-сервер живёт ровно столько, сколько SSH-сессия
клиента, и запускается от root — как и `install.sh`, которому он передаёт вызовы. Никаких
слушающих сокетов, токенов в конфигах клиентов и веб-хуков.

**Поверхность — только `actions.json`.** Агент не получает shell: сервер знает только действия из каталога (сейчас 65 публикуемых из 89) с
жёсткими схемами, любой параметр вне схемы (лишний ключ, символ не из регекса, число вне границ,
перевод строки в значении) отклоняется ошибкой `-32602` до запуска моста; мост проверяет те же
регексы второй раз. Значения уходят в `argv`, а не в командную строку shell — подстановок нет.

**`confirm` поверх подтверждения клиента.** Четырнадцать инструментов необратимы: `profile_remove`, `profile_regen`, `profile_set_param`, `profile_set_subnet`, `user_delete`, `users_del_bulk`, `user_remove_profile`, `user_reissue_key`, `backup_restore`, `upstream_update`, `upstream_rollback`, `core_update`, `page_revoke_all`, `mirror_remove`. Каждому нужен обязательный параметр `confirm`, равный значению первого
параметра (`user_delete(name="anna", confirm="anna")`; у `page_revoke_all` без `name` — имя инструмента); при несовпадении — `-32602`, мост не
запускается, попытка пишется в аудит со статусом `rejected`. У `users_del_bulk` `confirm` свой — число людей из
`users_del_bulk_preview` (`users_del_bulk(state="expired", confirm="3")`): он объявлен в каталоге, уходит мосту, и
сверяет его ядро в момент удаления под замком — выбор задевает другое число, и отказ `confirm_mismatch` до изменений. Клиент и так спрашивает у человека
разрешение на вызов, но (а) не все клиенты и не во всех режимах спрашивают (авто-режимы,
`--dangerously-skip-permissions`, скрипты поверх MCP), (б) подтверждение клиента защищает от
вызова *вообще*, а `confirm` — от вызова *не с той целью*: модель обязана осознанно повторить
имя удаляемого объекта. Инструкции сервера (`initialize.instructions`) прямо говорят модели
подставлять `confirm` только после явного согласия человека на конкретное действие и отсылают к
гайду `goamnezia://guide`, где для каждого разрушительного инструмента расписано, что именно
перестанет работать.

**Не всё из каталога — инструмент.** Действия с `"mcp": null` в `actions.json` (выдача, продление
и отзыв доступов агентов `agent-*`, включение HTTP-транспорта `mcp-http-*`, временные ссылки на скачивание
файла `share-*`, служебные таймеры `*-tick`) сервер не публикует:
их нет в `tools/list`, вызов по имени отвечает `-32602` как неизвестный инструмент, в подсказки и
инструкции они не попадают. Агент не должен уметь выдать доступ себе или другому агенту — это
делает человек из SSH-меню, бота или панели. `--check` показывает число скрытых действий.

**Аудит.** Каждый `tools/call` и `resources/read` — строка в `/var/log/goamnezia-audit.log`
(`GOAMNEZIA_AUDIT_LOG`), файл создаётся с правами 0600:

```
2026-09-08T09:08:56Z mcp call tool=user_delete action=user-del args={"confirm":"anna","name":"anna"} status=success code=- ms=13 client=claude-code/1.0.0 from=<ip клиента ssh>
2026-09-08T09:09:01Z mcp call tool=user_delete action=user-del args={"name":"bob"} status=rejected code=invalid_params ms=0 client=claude-code/1.0.0 from=<ip клиента ssh>
```

В аудит попадают параметры вызова и статус, но никогда — ответ моста (там могут быть ключи).
Значения параметров с именами вида `token`, `secret`, `pass*`, `privkey`, `psk` маскируются на
случай, если такие появятся в `actions.json`. Мосту передаётся `GOAMNEZIA_CALLER=mcp`, чтобы его
собственный аудит тоже помечал источник.

**Секреты.** Приватные ключи возвращает только `user_get_key`; QR-коды приходят клиенту
отдельными `image`-блоками, а в текстовой копии ответа заменяются заглушкой
`<PNG N байт: см. изображение №k>` — модель не тащит килобайты base64 в контекст.
Полный ответ моста (с base64) остаётся в `structuredContent` для программных клиентов.

**Замок и таймауты.** Мост берёт тот же `/run/goamnezia/config.lock`, что бот и панель, поэтому
сервер обрабатывает запросы строго последовательно — параллелизм ничего бы не дал. Действие,
не уложившееся в `GOAMNEZIA_MCP_TIMEOUT` (300 с), получает `SIGTERM`, через 3 с — `SIGKILL`
всей группе процессов (мост и всё, что он породил), а инструмент отвечает
`{"status":"error","code":"timeout"}` без обрыва сессии.

**Рекомендация: отдельный ключ с принудительной командой.** Заведите для агента свой ключ и
ограничьте его в `/root/.ssh/authorized_keys` на сервере — тогда этим ключом нельзя получить
ничего, кроме MCP-сервера, даже если машина с клиентом скомпрометирована:

```
restrict,command="/usr/local/bin/goamnezia-mcp" ssh-ed25519 AAAA… claude-mcp
```

Команда клиента при этом не меняется (`ssh -i ~/.ssh/goamnezia_mcp root@HOST goamnezia-mcp` —
переданная команда игнорируется, всегда запускается MCP). Язык в таком режиме задаётся не через
окружение, а полем `lang` в `/opt/goamnezia/config.json` — сервер читает его как запасной вариант.

**Что сервер не делает.** Не открывает порты, не хранит состояние, не пишет в stdout ничего, кроме
протокола (логи — только в stderr, их можно смотреть через `ssh … goamnezia-mcp 2>лог`), не
подставляет значения по умолчанию за клиента (умолчания применяет мост), не выполняет
`resources/read` для изменяющих действий (такие ресурсы отбрасываются при загрузке каталога),
не публикует действия с `mcp: null`.

## Документация для агента

Документация живёт в двух слоях (контракт §5). Этот README — для человека. Агенту всё нужное
доступно по протоколу, без доступа к репозиторию:

1. **`instructions` в ответе `initialize`** — десяток строк RU/EN: что за сервер, где полный гайд,
   с чего начать (`server_status`, `profiles_list`, …), какие инструменты разрушительны и правило
   `confirm`, какие есть подсказки-сценарии, что ключи возвращают только инструменты выдачи ключей.
   Все списки собираются из `actions.json` — в коде сервера имён инструментов нет.
2. **Описания и схемы инструментов** в `tools/list`, **подсказки-сценарии** в `prompts/get`.
3. **Ресурс `goamnezia://guide`** (`text/markdown`) — полный гайд `AGENT_GUIDE.md`, лежит рядом с
   `server.py` (`/opt/goamnezia-mcp/AGENT_GUIDE.md`). Инструкции просят модель прочитать его до
   первого изменяющего вызова. Внутри: что под капотом (три интерфейса для людей и мост
   `--action`), договор о режимах (`lite_site` и `pro` — один и тот же сайт на домене, разница
   только в месте AmneziaWG; самоподписанный сертификат — запасной путь обоих, и именно `cert` с
   `domain`, а не название режима, решают, что сейчас доступно), обязательный порядок начала
   сессии, каталог инструментов по задачам с «когда
   применять / когда нельзя», порядки операций для типовых задач (новый пользователь и ключ нужной
   линейки, «не подключается», смена порта/подсети/параметра с предупреждением о перевыпуске
   ключей, безопасное обновление ядра, бэкап и восстановление, импорт существующей установки, ключ на
   другой адрес сервера, когда адрес замолчал),
   правило `confirm`, коды ошибок моста и что с ними делать, ограничения продукта, примеры вызовов
   в JSON и краткая EN-сводка. Тест `tests/test_mcp.py` проверяет, что каждый публикуемый
   инструмент, ресурс и подсказка упомянуты в гайде.

В Claude Code гайд подключается к контексту как `@goamnezia:goamnezia://guide`. Файл читается
при каждом запросе, без кэша: правка `AGENT_GUIDE.md` на сервере видна следующей сессии без
перезапуска. Отсутствие файла — ошибка упаковки, а не пустой документ: `resources/read` отвечает
`-32002` с путём, `--check` печатает `ПРОБЛЕМА` и возвращает 1.

Файловые ресурсы описываются в `actions.json` записью
`{"uri": …, "file": "<путь относительно каталога server.py>", "mimeType": …, "name": …}`;
текстовый файл отдаётся полем `text`, нетекстовый (PNG, архив) — полем `blob` в base64. Ресурсы с
полем `action` — обёртки над действиями только для чтения (`application/json`), см. [Ресурсы](#ресурсы).

### Ключ на другой адрес сервера

У машины бывает несколько внешних адресов и домен. `user_get_key` с необязательным параметром
`endpoint` (мосту — `--endpoint=<хост>`) выдаёт **тот же ключ** — та же пара ключей, тот же порт
профиля — с другим адресом сервера внутри, разово: за пользователем ничего не сохраняется. Без
`endpoint` или с пустой строкой ключ байт в байт прежний. Замысел — docs/EDGEIPS.md §3.4 «Разовый
ключ на адрес»; порядок действий для агента — гайд, §4.9.

- **Что принимается.** Схема (тип `key_endpoint`) пропускает домен или IPv4, но мост берёт только
  хосты этого сервера: домены — заданный `endpoint_set`, домен сервера в режиме Pro, домен сайта с
  Let's Encrypt; затем IPv4 — заданный `endpoint_set`, `server_ip` из `config.json`, внешние адреса
  машины. Ключ на чужой адрес не соединился бы, а выглядел бы настоящим, поэтому остальное —
  отказ: `address_not_here` (такого адреса или домена у сервера нет; в `message` перечислены
  допустимые), `addresses_unknown` (спрошен IP, а машина своих внешних адресов не видит — NAT, нет
  команды `ip` — и этого IP не знает), `invalid_ip` (не IPv4 и не домен или `0.0.0.0`).
- **Ответ `user_get_key`** — прежние поля (`conf`, `vpn`, `qr_conf_png_b64`, `qr_vpn_png_b64`,
  `line`, `min_client`, `disabled`) и всегда три новых: `key_host` — адрес сервера в этом ключе
  (разовый, если задан, иначе обычный — с закреплённым адресом пользователя; пусто — неизвестен),
  `key_endpoint` — `<key_host>:<порт профиля>` (пусто, если неизвестен адрес или порт),
  `key_host_override` — `true`, если выдан разовый адрес. QR, как всегда, приходят картинками и
  несут тот же адрес. Запись `vpn://` в приложении Amnezia называется
  «<подпись> · AmneziaWG <линейка> · <адрес>» — две записи одного человека различаются.
- **Где взять варианты.** `edge_status` — `keys_host` (общий адрес в ключах как обычно) и
  `key_choices[]{host, kind, default, verdict, users, in_dns}` — ровно те хосты, что примет
  `endpoint`: первым адрес как обычно (`default: true`), затем домены (`kind: domain`), затем
  адреса, замолчавшие (`verdict: dark`) — в конце; `verdict` и `users` — только при двух и более
  адресах, иначе `null`. `server_status` — `key_hosts` (тот же список хостов, без похода в сеть).
  `user_show` — `key_host` (адрес в обычных ключах этого человека, с закреплённым) и
  `key_host_gone` (`true` — закреплённого адреса на машине больше нет: обычная выдача ответит
  `address_gone`, разовая работает).
- **Границы.** Сторож адресов (`edge_status`: пользователи на адресе, тревога `dark`) считает людей
  по адресу их обычных ключей — закреплённому, иначе общему, доменных — по A-записям — и разовых
  ключей не видит: чтобы человек остался на новом адресе и считался там, адрес закрепляют
  (`user_set_address`). Одна пара ключей — один пир: тот же ключ одновременно с двух адресов или
  устройств «прыгает», одновременным устройствам нужны отдельные пользователи. Ссылка на скачивание
  файлом с разовым адресом есть только у людей (SSH-меню, бот, панель), агенту она не публикуется.

### Ресурсы

Ресурсы двух видов: те же действия только для чтения в виде документов `application/json`
(клиент подключает их к контексту без вызова инструмента; в Claude Code — `@goamnezia:<uri>`)
и файлы рядом с сервером — гайд для агента. Таблица — вторая часть вывода `--tools-md`:

| Ресурс | Источник | MIME | Что внутри |
|---|---|---|---|
| `goamnezia://status` | действие `status` | `application/json` | Состояние сервера / Server status |
| `goamnezia://profiles` | действие `profiles-status` | `application/json` | Профили / Profiles |
| `goamnezia://users` | действие `user-list` | `application/json` | Пользователи / Users |
| `goamnezia://traffic` | действие `traffic` | `application/json` | Трафик / Traffic |
| `goamnezia://diagnose` | действие `quality` | `application/json` | Диагностика / Diagnostics |
| `goamnezia://guide` | файл `AGENT_GUIDE.md` | `text/markdown` | Гайд для агента / Agent guide |

Ресурс-действие при чтении вызывает мост (без замка — только `readonly`-действия); ошибка моста —
JSON-RPC ошибка `-32603` с ответом моста в `data`. Файловый ресурс мост не трогает; отсутствие
файла на сервере — `-32002` с путём. Неизвестный URI — тоже `-32002`. Чтение любого ресурса
пишется в аудит. Шаблонов ресурсов (`resources/templates/list`) в этой версии нет.

### Подсказки

Подсказки (`prompts`) — готовые сценарии для человека: в Claude Code они появляются как
команды, в Claude Desktop — в меню «+». Текст подсказки на языке `GOAMNEZIA_LANG` перечисляет,
какие инструменты вызвать и в каком порядке, и напоминает про `confirm`:

| Подсказка | Аргументы | Сценарий |
|---|---|---|
| `onboard_user` | `name`*, `profiles` | `profiles_list` → `users_list` → `user_add` → `user_get_key` по каждому профилю → `user_show` |
| `diagnose_user` | `name`* | `user_show` → `traffic_report` → `profiles_list` → `diagnose` → `logs_tail`, затем типовые причины и что с ними делать |
| `safe_core_update` | `profile`* | `upstream_check` (`profiles[].current_tag → available_tag`, `unsupported[]`) → `profiles_list` → `traffic_report` → `backup_create` → `upstream_update` (бэкап, скрипты релиза, образ по дайджесту, пересоздание из копии состояния, проверка, автооткат) → проверка → при неудаче `upstream_rollback`; сломанный контейнер без смены образа — `core_update` |

Список подсказок и их аргументы берутся из `actions.json`; порядок шагов сейчас описан в
`server.py` (`PROMPT_RECIPES`). Если добавить подсказке в `actions.json` поле
`"steps": [{"tool": "…", "ru": "…", "en": "…"}]` (и при желании `intro` / `outro`), сервер
возьмёт шаги оттуда — так подсказки можно целиком держать в JSON.

## Формат ответов и ошибок

Результат `tools/call`:

```json
{
  "content": [
    {"type": "text", "text": "{\n  \"status\": \"success\",\n  \"message\": \"ok\",\n  …\n}"},
    {"type": "image", "data": "<base64 PNG>", "mimeType": "image/png"}
  ],
  "structuredContent": {"status": "success", "message": "ok", "…": "…"},
  "isError": false
}
```

- `structuredContent` — ответ моста как есть; `content[0].text` — он же, отформатированный,
  но с заглушками вместо полей `*_png_b64`; `image`-блоки — по одному на каждый PNG
  (`qr_conf_png_b64` и элементы `qr_vpn_png_b64` у `user_get_key`).
- `isError: true` — при любом `status`, отличном от `success`: ошибка самого действия
  (`code` из моста, например `not_found`, `lock_timeout`), сбой запуска или отсутствие JSON в
  выводе (`code: "transport"`, с хвостами stdout/stderr) или таймаут (`code: "timeout"`).

Полный разбор кодов моста — в гайде для агента (`AGENT_GUIDE.md` §7). Четыре из них стоит знать и
человеку, потому что по ним видно, нужен ли он сам:

| `code` | Что значит |
|---|---|
| `update_failed` | обновление ядра не прошло проверку, но **откат сделан**: состояние прежнее, вмешательства не требуется |
| `update_failed_no_rollback` | обновление не прошло, и **откат не сделан**: контейнер снесён и не поднят, профиль лежит — нужен человек по SSH (`backup_restore` из бэкапа, который сделало обновление) |
| `no_profiles_picked` | в `user_add` пришёл пустой `profiles`. Отсутствующий параметр значит «во все установленные профили», а пустой — «ни одного»: молча понять его как «во все» значило бы завести ключи в линейках, которых никто не просил |
| `not_pro` | несмотря на имя, речь о **сертификате, а не о режиме**: действию нужен домен с доверенным Let's Encrypt, поэтому оно работает в обоих режимах с сайтом и отказывает в `lite` и на запасном самоподписанном. В ответе `mode`, `cert`, `domain` и `reason` (`no_site` \| `no_domain` \| `untrusted_cert`) |

Ошибки протокола (JSON-RPC `error`, вызов до моста не доходит):

| Код | Когда |
|---|---|
| `-32700` | строка не является JSON |
| `-32600` | не объект, нет `method`, `jsonrpc` не `"2.0"`, пустой пакет |
| `-32601` | неизвестный метод |
| `-32602` | неизвестный инструмент или подсказка, параметр не по схеме, нет обязательного, неверный `confirm`, `params` не объект |
| `-32603` | внутренняя ошибка сервера или ошибка моста при `resources/read` ресурса-действия |
| `-32002` | неизвестный URI ресурса; файл файлового ресурса (гайд) отсутствует на сервере |

```bash
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"users_list","arguments":{}}}' \
  | GOAMNEZIA_MCP_LOG=debug goamnezia-mcp
```

На сервере то же самое через `ssh root@HOST goamnezia-mcp`. `GOAMNEZIA_MCP_LOG=debug` печатает
в stderr каждое сообщение протокола, командную строку моста и хвост его stderr. В Claude Code
состояние сервера показывает `/mcp`, в Claude Desktop — логи `mcp-server-goamnezia.log`.

Тесты запускают сервер подпроцессом с заглушкой моста `tests/fixtures/fake_action.sh` (она
шумит в stderr, печатает мусор в stdout перед JSON, умеет спать, падать без JSON и отвечать
`status=error` — всё через переменные `FAKE_ACTION_*`):

```bash
python3 -m unittest tests/test_mcp.py tests/test_mcp_http.py
GOAMNEZIA_ACTION_BIN=tests/fixtures/fake_action.sh python3 goamnezia-mcp/server.py --check
/opt/homebrew/bin/bash tests/test_agents_dryrun.sh      # lib/agents.sh + живой server.py --http на выданном agents.json
```

`tests/test_mcp_http.py` поднимает сервер в режиме `--http` на петле с временным `agents.json`
(в том числе второй фактор, привязка к адресу и уведомления):
уровни в `tools/list`, `-32003` вне уровня, одинаковый `404` для выключенного/истёкшего/чужого
IP/неверного секрета, `403` на чужой `Origin`, бан после 21 неудачи, правка `agents.json` видна
следующим запросом, рост `last_used`/`calls`, `GET` → `405`, персональный порт, TLS-слушатель,
аудит с `agent=<id>`. `tests/test_agents_dryrun.sh` делает то же с настоящим `lib/agents.sh`:
выдаёт доступ, стартует сервер на этом `agents.json` и проверяет отзыв (`disable` → `404`),
перевыпуск (старый `404`, новый `200`) и учёт вызовов.

Ключи командной строки `server.py`: без аргументов — MCP-сервер по stdio; `--http [--bind ADDR]
[--port N] [--tls cert.pem,key.pem] [--extra-ports auto|none|P1,P2] [--extra-bind ADDR]
[--extra-tls cert.pem,key.pem]` — Streamable HTTP (слушатель вне петли обязан быть с `--tls`);
`--check` — сводка настроек, каталога и HTTP-транспорта (код возврата 0/1, для
`install.sh --selftest`; отсутствующий файл ресурса — проблема); `--tools-md` — таблицы
инструментов и ресурсов для этого README; `--version`.

## Перенос в другой продукт серии

Переходник параметризован только `actions.json` и окружением, поэтому для goTelegram, goDNS и
других скриптов серии его не надо переписывать:

1. Скопировать `server.py` и заменить блок «умолчания продукта» в начале файла
   (`PRODUCT`, `ENV_PREFIX`, `DEFAULT_DIR`, `DEFAULT_AUDIT_LOG`) — или задать переменные окружения.
2. Описать действия в `lib/actions.json` того же формата: `param_types` (тип, `pattern` /
   `enum` / `minimum` / `maximum`, описание RU/EN), `actions` (`mcp`, `readonly`, `destructive`,
   `params` со ссылками `ref` / `required` / `default`, описание; `"mcp": null` — действие есть у
   моста, но агенту не публикуется), `resources` (на действия `readonly` — или на файл рядом с
   сервером: `file` + `mimeType`), `prompts` (при желании — с `steps`).
3. Мост должен соблюдать контракт: `--action=<имя> --json --k=v`, весь UI в stderr, последняя
   строка stdout — JSON с полем `status`; поле `*_png_b64` в ответе автоматически станет
   `image`-контентом.
4. Переписать `AGENT_GUIDE.md` под продукт: каталог инструментов, порядки операций, коды ошибок
   моста, ограничения. Тест полноты гайда подскажет, какие инструменты ещё не описаны.
5. Скопировать `tests/test_mcp.py` и заглушку — они тоже читают `actions.json`, менять придётся
   только имена инструментов в нескольких проверках.
