## Выпуск 0.4.5 — 2026-09-25 (вечер): перехват установки приложения Amnezia

- **K1 (критично, из плана перехвата)**: `profile-install` сносил `amnezia-awg2` приложения как «остаток» —
  вместе с ключами всех людей. Теперь страж `foreign_container`: контейнер с именем профиля, которого нет в
  `config.json`, с `[Peer]` в конфиге — отказ до ключей и сборки и ещё раз после подъёма Docker;
  остановленный контейнер читается через `docker cp`. Остаток без людей сносится, как раньше.
- **Мастер** сам находит контейнеры приложения с людьми (`import_scan`) и спрашивает «Подхватить?»; отказ от
  awg2 — мастер стоит, ничего не удалив; необязательный профиль снимается с установки.
- **Снимок перед подхватом** (`import-snapshots/<контейнер>-<время>/`, 700/600, вне `backups/`).
- **«Привязать старый ключ»** (`user-attach-key`, ключ только через stdin; SSH, бот, панель, MCP
  `user_attach_key`): приложение ключи людей не хранит (проверено по исходникам AmneziaVPN:
  `generateConnectionConfig` кладёт приватный ключ только в выданную ссылку, `appendClient` пишет на
  сервер открытый ключ и имя; в бэкап приложения ключи людей не попадают) — вернуть ключ можно только из
  ссылки `vpn://` или `.conf`, что отправляли человеку. Проверка по открытому ключу пира; чужой ключ назван
  по имени владельца.
- **Без недосказанности** про ключ, которого нет на сервере: карточка, выдача ключа/ссылки/страницы,
  перевыпуск, страница подключения (вместо 404 — пояснение).
- **Вживую, сервер B**: контейнер «как у приложения» (`amnezia-awg1`, флаги `run_container.sh`, 1.5, один
  человек «Телефон Маши»): клиент с A подключается → `profile-install awg1` отказал (и на остановленном) →
  `import-scan` видит → `import-adopt` со снимком → клиент подключается → `user-key` объясняет → привязка
  `.conf` через stdin → выдаётся тот же ключ (sha256 совпал) → новый человек на подхваченном контейнере
  подключается, Маша — тоже; в `clientsTable` оба имени. Потом профиль снят, B как был.
- **Вживую, все три последние версии контейнеров приложения** (сервер B, настоящие `server_scripts`
  приложения из ветки dev: `build_container.sh` → `run_container.sh` → `configure_container.sh` в контейнере →
  `start.sh`; человек — как у приложения: общий PSK сервера, `clientsTable`, `syncconf`; клиенты — с A):
  `amnezia-awg` (AmneziaWG 1.x, образ `amnezia-wg`, `wg0.conf`) → awg1; `amnezia-awg2` с параметрами 2.0 и
  `amnezia-awg2` с параметрами 3.1 (HeaderProtectionKey, RandomTrailers…) → awg2. В каждой: клиент до подхвата
  подключается → страж (для `amnezia-awg2` — и на остановленном) → поиск и подхват со снимком → клиент
  подключается → привязка `.conf` через stdin → тот же ключ → новый человек и прежний — оба подключаются, в
  `clientsTable` оба имени → уборка. 12 из 12 подключений. Наш awg2 на B снимался и вернулся на порт 7141.
- Кириллические имена из приложения — транслитом в идентификаторе («Телефон Маши» → `Telefon_Mashi`; раньше
  `client-xxxx`, три имени из четырёх в живом прогоне), `label` — как было.
- Осталось: полный перевод подхваченного контейнера на наш закреплённый образ с сохранением ключей.

## Состояние на 2026-09-24 — версия 0.4.3 (в рабочем дереве, в `dev` не выложена)

0.4.3 по просьбе владельца:
- **Порты в мастере у каждого профиля.** Раньше спрашивался только порт awg2, а awg3 и awg1 молча получали
  случайные. Теперь один экран-сводка: Enter — принять случайные из 1024–9999, 1 — задать свои по очереди,
  0 — назад к галочкам (порты сохраняются). Все порты разные; UDP/443 — не больше чем у одного профиля: в
  «Сайт и VPN на 443» ровно один (по умолчанию awg2, можно отдать любому), в «VPN и сайт» 443 не даётся,
  третий режим без 443 мастер предлагает сменить на второй. Бот научился ставить профиль на свой порт.
- **Исправлены два дефекта мастера:** «0 — назад» на вопросе порта продолжал установку на другом случайном
  порту; случайный порт awg3 выбирался без оглядки на порт awg2 и при совпадении обрывал установку.
- **Домен с несколькими A-записями** (как в goTelegram: адрес на каждый интерфейс). Все проверки — мастер,
  «Домен», включение сайта, «Проверка сайта снаружи», «Адрес сервера в ключах» — сравнивают набор A-записей
  с набором адресов машины, а не первую запись с одним адресом (раньше домен с двумя адресами этого же
  сервера в половине случаев уводил мастер на самоподписанный сертификат). Вердикт `dns_partial`, поля
  `dns_ips` / `dns_foreign` / `dns_state`. В таблице «Адреса сервера» — колонка DNS, под ней — чужие адреса
  из A-записей; строка в шапке, если адрес один или чужая запись у домена сайта. Сторож адресов считает
  доменных пользователей только на адресах из A-записей — адрес без записи больше не «замолкает» ложно.
- **Неточности:** хвост пояснений под галочками падал на край окна; устаревшие названия режимов («Lite +
  сайт», «Pro-режим включён» для «VPN и сайт»); подсказка «нажмите r» вместо номера пункта; бот обещал порт
  «из 30000–49999»; «Endpoint» в сообщениях; список «что нового» не менялся с 0.1; свои и доменные
  пользователи адреса затирали друг друга в счёте сторожа.
