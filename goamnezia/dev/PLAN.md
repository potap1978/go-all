## 0. Одним абзацем

`goAmnezia pro` — установщик и панель управления серверной частью AmneziaVPN в стиле серии
`go*`: одна команда под root на чистом Ubuntu/Debian поднимает официальные Docker-контейнеры
Amnezia, одновременно поддерживает три линейки AmneziaWG (1.x, 2.0, 3.1) как отдельные
профили на своих UDP-портах, выдаёт ключи в форматах приложения Amnezia (`vpn://`),
AmneziaWG-клиентов (`.conf`, QR) и роутеров, а управляется из трёх интерфейсов, которые ходят к
одному коду: SSH-меню `goamnezia`, Telegram-бот, веб-панель. Сервер, поднятый goAmnezia, остаётся
совместимым с официальным приложением Amnezia (его можно добавить в приложение по SSH) и с
goWARP PRO (который подключает такие контейнеры к сети Cloudflare как прокладку поверх).

## 1. Цели, рамки, не-цели

### Главная задача

Перестать ставить серверную часть Amnezia через установщик из приложения (клиент ходит на VPS по
SSH и сам собирает контейнеры) и делать то же самое **своим скриптом на сервере**, но гибче:
выбор линеек AmneziaWG, Telegram-бот и веб-панель, домен и
сайт-маскировка на 443, обновление контейнеров из официального репозитория Amnezia без
участия приложения. Приложение при этом остаётся совместимым клиентом и запасным пультом.

### Цели (что должно получиться)

1. **Один клик.** `bootstrap.sh` → `install.sh` → через несколько минут работающий сервер с
   профилем AWG по умолчанию и первым ключом на экране (QR + ссылка).
2. **Все версии AmneziaWG сразу.** Три профиля, каждый в своём контейнере и на своём порту:
   1.x (роутеры Keenetic/MikroTik, старые приложения), 2.0 (приложения 4.8.12+), 3.1
   (приложения 5.0.1.5+). Любой из профилей можно не ставить.
3. **Три интерфейса, одно ядро.** SSH-меню, бот, панель показывают одно и то же состояние и
   ходят через один контракт `install.sh --action=… --json` (как в goTelegram).
4. **Совместимость с приложением Amnezia.** Официальные имена контейнеров, пути, `clientsTable`,
   форматы ключей. Приложение видит наши контейнеры и пользователей; goAmnezia умеет подхватить
   контейнеры, поставленные приложением («импорт существующей установки»).
5. **Совместимость с goWARP PRO.** WARP в goAmnezia не реализуем: goWARP PRO подключает
   контейнеры `amnezia-awg*` к Cloudflare сам. Наша задача — не мешать (см. §7.4).
6. **Pro-режим серии.** Домен, Let's Encrypt, сайт-маскировка из библиотеки 33 467 шаблонов
   (навык `site-templates-library`, база берётся как есть), панель на домене по секретному пути,
   вход кодом из бота.
7. **Качество серии.** RU/EN, бэкапы, бюджет логов, миграции, статические и живые тесты,
   `AUDIT.md`, ветки `dev`/`main`.

### Не-цели (сознательно вне рамок)

- Своя реализация протокола или свои сборки `amneziawg-go`: только официальные образы Docker.
- WARP/WARP+, платные ключи Cloudflare — это goWARP PRO.
- Прокси для API Telegram (egress бота через VLESS/AWG) — сервер Amnezia стоит за рубежом,
  бот достаёт `api.telegram.org` напрямую. Модуль из goVLESS/goKaskad можно подключить позже.
- Cloak и Shadowsocks (классический) — приложение Amnezia пометило их как неподдерживаемые.
- **Xray / VLESS Reality: не делаем** — решение владельца от 09.09.2026 («мы работаем с
  Амнезией, а не с VLESS-ключами; нам не нужно ядро xray»). goAmnezia — продукт только про
  AmneziaWG (профили `awg1`/`awg2`/`awg3`); для VLESS в серии есть отдельный продукт goVLESS.
  Контейнер `amnezia-xray` приложения Amnezia мы не ставим, а при импорте помечаем как
  неподдерживаемый.
- Биллинг, подписки, многосерверность — отдельные продукты.

## 2. Что известно о серверной стороне Amnezia (факты, на которых стоит план)

Источники: репозиторий `amnezia-vpn/amnezia-client` (ветка `dev`, каталог `client/server_scripts`
и `client/core/*`), `amnezia-vpn/amneziawg-go` (тег `v3.1.20260828`), отчёты приёмки goWARP PRO
2.4 от 05.09.2026 (живой стенд с AWG 1, 2 и 3.1).

### 2.1 Контейнеры официального клиента

| Контейнер (имя Docker) | Тип | Образ | Конфиг внутри | Инструменты |
|---|---|---|---|---|
| `amnezia-awg` | AmneziaWG 1.x (legacy) | `amneziavpn/amnezia-wg:latest` | `/opt/amnezia/awg/wg0.conf`, iface `wg0` | `wg`, `wg-quick` |
| `amnezia-awg2` | AmneziaWG 2.0 / 3.x | `amneziavpn/amneziawg-go:latest` (= `3.1.20260828`) | `/opt/amnezia/awg/awg0.conf`, iface `awg0` | `awg`, `awg-quick` |
| `amnezia-xray` | VLESS + Reality (XTLS-Vision) | Alpine 3.15 + Xray `v26.7.28` | `/opt/amnezia/xray/server.json`, ключи `xray_*.key` | `xray` |
| `amnezia-wireguard` | WireGuard | — | `/opt/amnezia/wireguard/wg0.conf` | `wg` |
| `amnezia-openvpn`, `amnezia-ipsec`, `amnezia-ssxray` | другие VPN | — | — | — |
| `amnezia-telemt`, `amnezia-mtproxy`, `amnezia-tproxy`, `amnezia-dns`, `amnezia-sftp`, `amnezia-socks5proxy`, `amnezia-torwebsite` | сервисы (не VPN) | — | — | — |

Поправки из исходников клиента 5.0.2.x, которые меняют картину:

- **`amnezia-awg` (legacy) приложение больше не устанавливает** — только подхватывает на уже
  существующем сервере (`isInstallationAllowed` исключает `Awg`). Образ `amnezia-wg:latest`
  заморожен с 2023-10-03 и умеет только AWG 1.0.
- **Единственный AWG-контейнер, который приложение ставит сегодня, — `amnezia-awg2`**, и линейка
  внутри него — это просто набор строк в `awg0.conf`: демон `amneziawg-go` 3.1 принимает конфиг
  1.0, 1.5, 2.0 и 3.x, все параметры необязательны. Отсюда наш выбор образа (решение D2).
- Порт при установке приложением — **случайный из 30000–49999**; `55424` лишь запасная константа.
- Официальные образы `amneziavpn/amneziawg-go` и `amnezia-wg` собраны **только под `linux/amd64`**;
  arm64 (Oracle Ampere, Hetzner CAX) без своей сборки не работает.
- `amnezia-xray` публикует порт и по TCP, и по UDP, `dest` по умолчанию — чужой сайт
  `www.googletagmanager.com:443`; `server.json` пишет приложение, скрипт делает только ключи.
  **Мы этот контейнер не ставим** (§1 «Не-цели»): таблица выше — описание чужого продукта.
  Если он уже стоит на сервере, `import-scan` покажет его с пометкой «не поддерживается».
- Требования Amnezia к серверу: Ubuntu 22.04/24.04, Debian 12/13 официально; KVM (не
  OpenVZ/LXC); публичный IPv4, IPv6 не поддерживается; Docker из репозитория дистрибутива,
  **podman отвергается**; ядро 4.14+ для AWG 2.0.

Общее для всех: `ENTRYPOINT dumb-init /opt/amnezia/start.sh`, `clientsTable` по пути
`/opt/amnezia/<тип>/clientsTable` (для обоих AWG — `/opt/amnezia/awg/clientsTable`),
запуск `docker run --privileged --cap-add=NET_ADMIN --cap-add=SYS_MODULE -p PORT:PORT/udp
-v /lib/modules:/lib/modules --sysctl net.ipv4.conf.all.src_valid_mark=1 --restart always
--log-driver none`, сеть `amnezia-dns-net` (bridge `amn0`, `172.29.172.0/24`).
**Данные лежат в файловой системе контейнера, томов нет** — `docker rm` теряет ключи сервера и
всех пользователей. Это главная эксплуатационная слабость официальной схемы, и goAmnezia её
закрывает (см. §3, решение D6).

### 2.2 Линейки AmneziaWG и совместимость

| Линейка | Параметры, которые её отличают | Где живёт | Клиенты |
|---|---|---|---|
| 1.0 | `Jc Jmin Jmax S1 S2 H1–H4` (одиночные значения) | `amnezia-awg` | приложения Amnezia 4.x, AmneziaWG-клиенты, роутеры Keenetic/MikroTik, ядерный модуль |
| 1.5 | + `I1–I5` сигнатурные пакеты (шлёт только клиент; сервер 1.x их отбрасывает как junk) | тот же `amnezia-awg` | Amnezia 4.8.8.3+ (10.07.2025; 4.8.8.1 и 4.8.8.2 — предварительные) |
| 2.0 | + `S3 S4`, `H1–H4` как диапазоны `a-b`, `I1–I5` | `amnezia-awg2` (образ 3.1 без 3.x-параметров ведёт себя как 2.0) | Amnezia 4.8.12.9+ (27.01.2026; 4.8.12.7 и 4.8.12.8 — предварительные) |
| 3.0 / 3.1 | + `HeaderProtectionKey` (обязательное совпадение), `ContentPaddingAddition`, `RandomTrailers`, `DisableCookies` (3.1), тайминги `RekeyAfterTime RekeyTimeout RejectAfterTime KeepaliveTimeout MaxHandshakeAttempts`, диапазон `PersistentKeepalive` | `amnezia-awg2` | Amnezia 5.0.1.5+ (21.08.2026); текущая 5.0.2.1 |

Минимальные версии клиента в таблице — те, что отдаёт `ga_export_min_client` (`lib/export.sh`) и
показывает `user-key` в поле `min_client`. Для 1.5 это **4.8.8.3**: ключи `I1–I5`
(`specialJunk1..5`, `setI1` в андроидном `WireguardConfig.kt`) появились в диапазоне
`4.8.7.2 … 4.8.8.1` — сверено по `git compare` официального `amnezia-vpn/amnezia-client`;
4.8.7.x (май 2025) их ещё не знает. Но 4.8.8.1 (07.07.2025) и 4.8.8.2 — предварительные выпуски
(prerelease на GitHub), первый стабильный с `I1–I5` — **4.8.8.3** (10.07.2025). Так же для 2.0:
4.8.12.7 и 4.8.12.8 — предварительные, первый стабильный — **4.8.12.9** (27.01.2026). Человеку называем
стабильный выпуск — его ставят из магазинов и с сайта (A-15 критика 16.10, как в `lib/clients.json`).

Версию клиент определяет по содержимому конфига: есть любой 3.x-параметр → 3.1; есть `S3/S4`
или дефис в `H` → 2; есть `I1–I5` → 1.5; иначе 1.0. **Линейки между собой несовместимы**
(официальная запись: «предыдущие версии протокола несовместимы с AmneziaWG 2.0»; в 3.x
несовпадение `HeaderProtectionKey` рвёт рукопожатие). Отсюда главное архитектурное следствие:
**один контейнер = один набор параметров = одна линейка**, поэтому «все версии» = несколько
контейнеров на разных портах.

Матрица реализаций (что какой демон принимает): `amneziawg-go` 0.2.13–0.2.19 — `S3/S4` и
`I1–I5`, но `H` только одиночные; 3.0 (июль 2026) — диапазоны `H`, защита заголовков, тайминги;
3.1 (август 2026) — `RandomTrailers`/`DisableCookies`. Ядерный модуль и `amneziawg-tools` идут
теми же ступенями (`v3.1.20260812`+). Сторонние клиенты и роутеры (Keenetic, OpenWrt, wg-easy)
живут на 1.0/1.5 — для них нужен профиль «совместимость».

Ограничения на параметры, которые зашиваем в валидатор: `H1–H4` попарно различны; итоговые
размеры `148+S1`, `92+S2`, `64+S3`, `32+S4` попарно различны; `S1, S2 ≤ 150`, `S3 ≤ 64`, все
`S ≥ 12` при включённой защите заголовков; для ядерного модуля 1.0 — `1 ≤ Jc ≤ 128`,
`Jmax ≤ 1280`, `S1 ≤ 1132`, `S2 ≤ 1188`, `S1 + 56 ≠ S2`; `Jmax` меньше MTU пути.

Значения по умолчанию официального клиента 5.0.2 (`protocolConstants.h`, `awgInstaller.cpp`):
порт случайный 30000–49999, подсеть `10.8.1.0/24` (адрес сервера — сам `10.8.1.0`, первый
клиент `.1`), `Jc` случайно 4–6, `Jmin 10`, `Jmax 50`, `S1–S4 = 12`, `H1–H4 = 1,2,3,4`
(в 3.x заголовки защищены ключом, поэтому магические значения больше не рандомизируют),
`I1` — фальшивый DNS-ответ (`<r 2><b 0x8580…>`), `HeaderProtectionKey` — свежий X25519,
`ContentPaddingAddition 10-100`, `RekeyAfterTime 100-120`, `RekeyTimeout 3-7`,
`RejectAfterTime 150-180`, `KeepaliveTimeout 5-15`, `MaxHandshakeAttempts 15-20`,
`PersistentKeepalive 25-35`, `RandomTrailers on`, `DisableCookies on`, MTU `1280` (мобильные)
/ `1376`. Для 1.x/2.0 приложение раньше генерировало случайные `H1–H4`; goAmnezia будет делать
то же (случайные непересекающиеся значения, для 2.0 — диапазоны).

### 2.3 Как приложение ставит контейнер (мы повторяем этот порядок)

1. `check_user_in_sudo` → 2. `check_server_is_busy` (ждёт dpkg) → 3. `install_docker`
(+ `install_conntrack` для telemt/mtproxy/tproxy) → 4. проверка порта через `lsof` →
5. `prepare_host` (`mkdir /opt/amnezia/<container>`, сеть `amnezia-dns-net`) →
6. `remove_container` старого → 7. загрузка `Dockerfile` в `/opt/amnezia/<container>/` и
`docker build --no-cache --pull -t <container> <folder>` → 8. `run_container` →
9. `configure_container` (генерация ключей `genkey/pubkey/genpsk`, запись `wg0.conf`/`awg0.conf`,
пустые параметры вычищаются `sed`) → 10. `setup_host_firewall` (ip_forward, правила
DOCKER-USER/FORWARD, тюнинг conntrack; **официально ещё и DROP на ICMP echo** — у нас это
будет опцией, по умолчанию выключенной) → 11. загрузка `start.sh` и запуск
(`awg-quick up`, iptables FORWARD/MASQUERADE, `tail -f /dev/null`).

Обнаружение уже стоящих контейнеров: `docker ps --format '{{.Names}} {{.Ports}}'` и регулярка
`(amnezia[-a-z0-9]*).*?:([0-9]*)->[0-9]*/(udp|tcp)`; конфиг читается обратно из контейнера.
**Вывод для нас:** любой контейнер, в имени которого есть `amnezia`, приложение попытается
разобрать. Дополнительные контейнеры goAmnezia, которых приложение не знает, называем без
этой подстроки.

### 2.4 Пользователи

- Ключи клиента приложение генерирует у себя (X25519 через OpenSSL), сервер получает только
  `[Peer]` (`PublicKey`, `PresharedKey`, `AllowedIPs = <ip>/32`), дописанный в конец конфига, и
  команду `awg syncconf awg0 <(awg-quick strip /opt/amnezia/awg/awg0.conf)` (для legacy —
  `wg`/`wg0`). IP — последний `AllowedIPs` + 1, освободившиеся адреса не переиспользуются.
  **Приватный ключ клиента на сервере не хранится** — повторно выдать тот же конфиг приложение
  не может. **PSK один на всех** (`wireguard_psk.key`). Дописывание файла и `syncconf` не
  защищены замком — два одновременных «выдать ключ» ломают конфиг.
- Что делаем иначе (совместимость не страдает): свой аллокатор IP с переиспользованием и
  подсетью на профиль; PSK на каждого клиента (приложение свои пиры по-прежнему заводит с
  общим PSK из файла — обе схемы живут в одном конфиге); приватные ключи в `users.json`;
  один замок на три интерфейса. Адрес сервера в подсети — как у Amnezia (`.0`), чтобы
  аллокация приложения не столкнулась с нашей.
- `I1–I5` в серверном конфиге лежат закомментированными (`# I1 = …`) — при чтении конфига
  обратно их надо разбирать тоже. Официальный `start.sh` при каждом старте добавляет правила
  iptables заново — в нашей копии делаем идемпотентно (`-C … || -A …`).
- `clientsTable` — JSON-массив `[{ "clientId": "<PublicKey>", "userData": { "clientName",
  "creationDate", "latestHandshake", "dataReceived", "dataSent", "allowedIps" } }]`.
  Переименование меняет `userData.clientName`; удаление вырезает блок `[Peer]`, делает
  `syncconf` и убирает запись.
- Xray (справка о чужом продукте, мы его не ставим — §1 «Не-цели»): `clientId` = UUID из
  `inbounds[0].settings.clients[]`, удаление — правка `server.json` и `docker restart`.

### 2.5 Форматы ключей

- **`vpn://`** (приложение Amnezia): `base64url` без `=` от `qCompress(JSON, 8)` — 4 байта
  длины big-endian + zlib. JSON `{ "containers": [ { "awg": { …параметры…,
  "last_config": "<JSON-строка с полем config = текст .conf>", "transport_proto": "udp",
  "port" }, "container": "amnezia-awg2" } ], "defaultContainer", "description", "dns1",
  "dns2", "hostName" }`. «Полный доступ» несёт все контейнеры и SSH-учётку, «подключение» —
  один контейнер без учётки. Мы выдаём только второй вариант.
- **`.conf` AmneziaWG** — `[Interface]` с `Address, DNS, PrivateKey, MTU` и параметрами линейки,
  `[Peer]` с `PublicKey, PresharedKey, AllowedIPs = 0.0.0.0/0, ::/0, Endpoint, PersistentKeepalive`.
  Для 1.0 — без `I`, `S3/S4` и 3.x-строк, иначе клиент/роутер не примет файл.
- **QR** для AmneziaWG-клиентов — тот же `.conf` в PNG. (VLESS-ссылку из той же семьи форматов
  мы не выдаём: ядра Xray в продукте нет — §1 «Не-цели».)
  **QR приложения Amnezia — не строка `vpn://`**: сжатые байты режутся по 850, каждый чанк
  = `magic 1984 (int16) + число чанков + индекс + данные` в base64url, приложение собирает их
  при сканировании. Делаем оба варианта: ссылку `vpn://` (открывается приложением как deep link)
  и QR в чанковом формате; приём обычного `vpn://` в QR приложением — проверить на стенде.
- Готовый разбор/сборка `vpn://` и `.conf` уже написан и проверен в серии
  (`egress_parse.py` навыка `telegram-api-egress-vless-awg`) — переиспользуем декодер, добавляем
  кодер.

## 3. Ключевые решения

| № | Решение | Почему | Альтернатива и почему нет |
|---|---|---|---|
| D1 | **Docker и официальные образы/раскладка Amnezia**, ничего своего в контейнерах | совместимость с приложением и с goWARP PRO, официальные `Dockerfile` — источник правды; пользователи «контейнеров для Amnezia» это и просили | нативный `amneziawg-go` под systemd легче, но приложение и goWARP его не увидят; можно добавить позже как «Lite-ядро» |

### 4.3 Режимы (три; договор уточнён владельцем 10.09.2026)

Редакция от 2026-09-08 («`lite_site` — второй режим БЕЗ домена, на самоподписанном
сертификате») **отменена**. Нормативный текст — [docs/CONTRACT.md](docs/CONTRACT.md) §3.1;
здесь — та же таблица.

| Режим | `mode` | Домен | AWG | TCP/443 и 80 | Панель | Для кого |
|---|---|---|---|---|---|---|
| **Lite** | `lite` | нет | случайный UDP-порт из **1024–9999** | закрыты | только SSH-туннель | обычная Amnezia без домена, ставится без вопросов |
| **Lite + сайт** | `lite_site` | **да** | случайный UDP-порт из 1024–9999 | nginx с сайтом-заглушкой из библиотеки шаблонов и **настоящим сертификатом Let's Encrypt** на домене | по секретному пути на домене | нужен сайт-маскировка и панель, но UDP/443 занят или не нужен |
| **Pro** | `pro` | да | профиль по умолчанию на **UDP/443**, остальные случайные | тот же nginx, тот же сертификат, тот же сайт | по секретному пути на домене с кодом из бота, мини-апп в Telegram | максимальная маскировка: домен, валидный сертификат, сайт и VPN на одном 443 |

Два режима с сайтом отличаются **только местом AmneziaWG**: домен, сертификат, сайт, панель и
маршрут агентов у них общие. Поэтому переход `pro ↔ lite_site` — одна запись `mode`
(`website_switch_site_mode`): ни nginx, ни сертификат, ни домен не трогаются, двигается только
порт профиля, и то отдельным действием с подтверждением.

**Самоподписанный сертификат — запасной путь, а не режим.** Он включается в ЛЮБОМ из двух
режимов с сайтом ровно в двух случаях: домена ещё нет или его A-запись ещё не указывает на
сервер (`website_enable_site_selfsigned`). Как только домен готов, сервер выходит на основной
путь. Вид сертификата хранится в `config.json` (`site.cert`) и **не выводится из названия
режима** — его спрашивают `ga_site_cert_kind` и `ga_site_domain_ready`.

Общее: профили и ключи во всех режимах одни и те же; переходы `lite → lite_site → pro` и обратно
не пересоздают контейнеры и не перевыпускают ключи (меняется только `Endpoint`, если включён
домен вместо IP).

### 4.3.1 Предполётная проверка портов при выборе режима (решение владельца)

Режимы с сайтом (`lite_site`, `pro`) нельзя выбрать, если TCP/80 или TCP/443 заняты или
закрыты. Проверка выполняется **до показа меню режимов** и повторяется при каждом переключении
режима из любого интерфейса. Модуль `lib/preflight.sh`.

Что проверяем и как:

| Проверка | Как | Результат |
|---|---|---|
| Занятость TCP/80, TCP/443, UDP/443 | `ss -ltnp` / `ss -lunp` → PID и имя процесса; юнит systemd через `/proc/<pid>/cgroup` (как в goInstaller); если это `docker-proxy` — имя контейнера через `docker ps --format` по порту | `free` / `busy {pid, process, unit, container, product}` |
| Чей это процесс | сопоставление с известными соседями серии: `telemt`/`nginx` из `/etc/nginx/sites-enabled/gotelegram` → goTelegram Pro; `xray`/`x-ui` → goVLESS/3x-ui; `dnsdist` → goDNS; `amnezia-*` контейнеры → Amnezia/goAmnezia (своё — не препятствие, это обновление) | `product` для человеческого сообщения |
| Локальный файрвол | `ufw status` (active и нет правила на 80/443), `iptables -S INPUT`/`nft list ruleset` с DROP/REJECT на эти порты | `closed_local` — мы умеем открыть сами (спросим) |
| Внешняя достижимость | проверить изнутри честно нельзя: соединение на собственный публичный IP не проходит через файрвол хостинга. Поэтому: после установки сайта `site-check` пробует адрес снаружи через публичный сервис проверки портов (`GOAMNEZIA_PORTPROBE_URL`, по умолчанию выключено — внешний сервис видит наш IP) и всегда показывает подсказку про файрвол хостинга (security group, панель провайдера) | `unknown` до установки, `open`/`closed_external` после `site-check` |

UX в мастере и в экране «Режим и сайт»:

```
Режим установки

  1) Lite         AmneziaWG на случайном порту, без домена и сайта            ✓ доступен
  2) Lite + сайт  то же + сайт-заглушка на 80/443 по IP                        ✗ недоступен
  3) Pro          домен, сайт и VPN на 443, панель и MCP на домене              ✗ недоступен

  ✗ TCP/443 занят: nginx (PID 812, юнит nginx.service) — похоже, goTelegram Pro
  ✗ TCP/80  занят: nginx (PID 812)
  ⚠ UDP/443 занят: x-ui — профиль по умолчанию получит случайный порт (не мешает)

  Освободите порт (например: systemctl disable --now nginx) или используйте чистый сервер.
  Повторить проверку — r, выбрать доступный режим — цифра, выйти — 0.
```

- Недоступный режим показывается, но при выборе цифры выводится то же объяснение и предложение
  повторить проверку после освобождения порта; выбрать его нельзя.
- Занятый **UDP/443** режим не блокирует: профиль по умолчанию просто не получит 443
  (предупреждение), «занять UDP/443» появится позже, когда порт освободится.
- Если порт занят **нашим** старым nginx/контейнером goAmnezia — это не препятствие: мастер
  переходит в режим обновления/переустановки без сообщения о конфликте.
- В боте, панели и MCP `change-mode` на занятый порт отвечает кодом `port_busy` с теми же
  полями (`port`, `proto`, `pid`, `process`, `unit`, `container`, `product`) и человеческим
  сообщением; бот показывает «Освободите порт или используйте чистый сервер».
- Локально закрытый порт (`ufw`) — предложение «Открыть 80/443 в ufw? [y/N]» прямо в мастере;
  без согласия режим недоступен с пометкой `closed_local`.
- `quality` (диагностика) включает ту же таблицу портов; `status` показывает `ports` для профилей.

### 4.4 Порт 443: сайт и AmneziaWG вместе

Вопрос владельца: можно ли пустить трафик Amnezia (особенно 2.0 и 3.1) через 443 вместе с
сайтом, чтобы браузер получал сайт, а клиент Amnezia — контейнер. Ответ: да, и проще, чем в
goTelegram, потому что делить ничего не надо.

- HTTPS-сайт живёт на **TCP/443**, AmneziaWG — на **UDP/443**. Это два независимых сокета:
  nginx слушает `0.0.0.0:443/tcp`, контейнер профиля публикуется как `-p 443:443/udp`.
  Никакого разделителя по содержимому первого пакета не требуется.
- Для внешнего наблюдателя картина: домен с валидным сертификатом, обычный сайт по TCP/443 и
  UDP-поток на тот же 443 — так выглядит HTTP/3 (QUIC). Сигнатурный пакет `I1` профиля 3.1
  подбирается под QUIC Initial (у Amnezia по умолчанию — DNS-ответ; пресет «QUIC» делаем
  своим), защита заголовков 3.x убирает узнаваемые WireGuard-байты.
- **UDP/443 может держать только один профиль** — по умолчанию профиль по умолчанию, то есть
  `awg2` (2.0, решение владельца §10 п.1). Остальные профили получают свои порты: случайные из
  **1024–9999** (решение владельца 10.09.2026: номера выше десяти тысяч у части провайдеров и
  корпоративных сетей режутся целым блоком, и человек получал ключ, который у него же не
  открывается; прежние 30000–49999, как выбирает само приложение Amnezia, остались запасным
  диапазоном на случай, когда весь низкий занят). Переключатель «занять UDP/443» переносит
  порт на любой другой профиль.
  В меню «Протоколы → Порт» переключатель «занять UDP/443» переводит порт между профилями с
  перевыпуском только `Endpoint` в ключах (сами ключи не меняются, но `.conf` надо переслать).
- Опция «объявлять HTTP/3»: nginx отдаёт `Alt-Svc: h3=":443"`. Делает картину ещё
  правдоподобнее, но настоящие браузеры попробуют QUIC на UDP/443, упрутся в AWG и откатятся
  на TCP с задержкой в секунду-две. По умолчанию выключено; включать сознательно.
- **Lite-режим** тоже может использовать UDP/443 (сайта нет, но порт «нормальный» для DPI).
- TCP/443 в Pro всегда наш nginx: TCP-протоколов, которым понадобился бы этот порт, у продукта
  нет (§1 «Не-цели»), и уводить сайт на localhost не для кого.
- На одном сервере с goTelegram Pro (тоже TCP/443): решается через его shared-443, описать в
  `NEIGHBOURS.md`; UDP/443 goTelegram не использует.

Итог для DPI-картинки в Pro: `A example.com → VPS`, TCP/443 — сайт с сертификатом Let's
Encrypt, UDP/443 — «QUIC» (на деле AWG 3.1). Это и есть «максимально похоже на сайт».

## 5. Интерфейсы

Главные экраны бота и SSH-меню совпадают до буквы с первого дня (в goTelegram это осталось
открытым пунктом). Разделы собраны по частоте обращения.

### 5.1 Дерево (бот = SSH, отличия помечены)

```
1) Пользователи   → список (● активен / ○ выключен / ⏳ срок / ▮ лимит) · Добавить · карточка:
                    ключи по профилям (QR · .conf · vpn://) · Лимит · Срок ·
                    Выключить/Включить · Переименовать · Удалить (typed-confirm)
2) Состояние      → Статус (контейнеры, интерфейсы, порты, версии ядра) · Трафик (по профилям и
                    пользователям, онлайн по handshake < 3 мин) · Логи · Адреса сервера
3) Протоколы      → карточка каждого профиля: AWG 1.x · AWG 2.0 · AWG 3.1
                    → Установить/Удалить · Порт (в т.ч. «занять UDP/443») · Подсеть · MTU ·
                    Параметры (показать · изменить любой по отдельности, как в приложении Amnezia ·
                    пресет · перегенерировать — с предупреждением, какие ключи придётся перевыпустить) ·
                    Перезапуск · версия ядра
                    Глобально (в Настройках): DNS клиентов · хост Endpoint (домен или IP)
4) Обслуживание   → Перезапуск всего · Бекап · Восстановить · Обновления Amnezia (проверить ·
                    обновить профиль · откатить) · Импорт существующей Amnezia ·
                    Обновить goAmnezia (SSH) · Диагностика (порты, ip_forward, docker, MTU)
5) Настройки      → Режим и сайт (Lite/Pro · домен · шаблон · SSL) · DNS для клиентов ·
                    Панель (мини-апп · панель на домене · веб-админка) · Админы · Язык ·
                    О программе · Промо · Удалить (последним, отдельной строкой)
6) Telegram-бот   (только SSH) → Установить · Статус · Логи · Перезапуск · .env · Удалить
0) Выход / Закрыть
```

Глубина не больше двух уровней, третий — конечная карточка. Разрушительное — только с
подтверждением (в SSH `confirm()` из `/dev/tty`, в боте typed-confirm с TTL 60 с).

### 5.2 Веб-панель

Страницы: Обзор (профили, онлайн, трафик за сутки, здоровье служб) · Пользователи (таблица с
поиском, QR/скачать `.conf`/скопировать `vpn://`, лимиты, сроки, вкл/выкл) · Протоколы (карточки
профилей, параметры, порты) · Трафик · Бэкапы · Логи · Настройки. Слой входа — как в goTelegram:
SSH-туннель без второго фактора, домен по секретному пути с кодом из бота, подпись WebApp для
мини-аппа, токен-файл как аварийный путь без поля ввода, сессия 15 минут + минута на продление.

### 5.3 Контракт `--action=` (первый набор)

```
status · profiles-status · quality
profile-install  --profile=awg1|awg2|awg3 [--port=N]            profile-remove --profile=…
profile-restart  --profile=…     profile-params --profile=…       profile-regen --profile=… [--preset=…]
profile-port     --profile=… --port=N                            core-update --profile=…
user-add   --name=… [--profiles=awg1,awg3] [--quota-gb=N] [--days=N]
user-del   --name=…     user-list     user-show --name=…     user-rename --name=… --new=…
user-key   --name=… --profile=… --format=conf|vpn|qr            user-enable/user-disable --name=…
user-quota --name=… --gb=N     user-expiry --name=… --days=N
traffic · logs-status · logs-enforce · backup-create · backup-list · backup-restore --file=…
import-scan · import-adopt --container=…
upstream-check · upstream-update --profile=… [--tag=…] · upstream-rollback --profile=…

```

Формат ответа — последней строкой stdout `{"status":"success|error","message":…,"code":…}`, весь

валидируются регексами до любого `docker exec` (`^[A-Za-z0-9_-]{1,32}$` для имени пользователя,
`^[0-9]{2,5}$` для порта, белый список профилей).

## 6. Как устроены ключевые сценарии

### 6.1 Установка профиля

1. Проверка порта (`ss -lun`), свободной подсети (`10.8.<n>.0/24` — по подсети на профиль),
   Docker и сети `amnezia-dns-net`.
2. `docker build` из официального `Dockerfile` папки `awg` (вендорен в `lib/upstream/awg/`,
   базовый образ — по закреплённому дайджесту, D8); один образ на все три профиля.
3. `docker run` с официальными флагами, имя контейнера по профилю.
4. `configure_container`: ключи сервера, конфиг с параметрами линейки из `lib/awg_params.sh`,
   `start.sh`, запуск, проверка `awg show`.
5. Синхронизация в `state/<container>/`, запись профиля в `config.json`, пункт файрвола.
6. Для каждого существующего пользователя — создать peer в новом профиле (спросить).

### 6.2 Добавление пользователя

Ключи клиента генерируем на хосте (`awg genkey`/`wg genkey` из пакета `amneziawg-tools` или
`wireguard-tools`; при отсутствии — внутри контейнера), IP из свободных в подсети профиля,
`[Peer]` в конфиг контейнера через `docker exec … tee -a`, `syncconf`, запись в `clientsTable`
в официальном формате и в `users.json`, синхронизация в `state/`. Приватный ключ клиента
хранится в `users.json` (0600) — иначе повторная выдача `.conf`/QR невозможна; приложение
Amnezia делает так же, храня его у себя.

### 6.3 Выдача ключа

`user-key --format=conf` собирает `[Interface]`/`[Peer]` по линейке профиля; `--format=vpn`
оборачивает тот же `.conf` в JSON приложения и кодирует `qCompress+base64url`; `qr` — PNG во
временный файл (`mktemp`), бот отправляет и удаляет в `finally`. Для 1.x дополнительно
«вариант для роутера» (без `DNS` и без `PersistentKeepalive`-диапазона).

### 6.4 Лимиты и сроки

`goamnezia-quota.timer` раз в 5 минут читает `awg show <iface> transfer` из каждого контейнера,
накапливает в `users.json` (счётчики контейнера обнуляются при перезапуске — храним дельты),
при превышении лимита или истечении срока вырезает `[Peer]` и делает `syncconf`, помечает
пользователя, шлёт уведомление в бота. Включение — обратная операция.

### 6.5 Импорт существующей установки

`import-scan` повторяет регулярку приложения по `docker ps`, читает конфиги и `clientsTable`
из найденных контейнеров, показывает таблицу «что нашли». `import-adopt` записывает профили и
пользователей (без приватных ключей — их у нас нет, для таких пользователей доступна только
ротация ключа) и делает копию в `state/`. Контейнеры не пересоздаются.

### 6.6 Обновление ядра

`core-update`: pull нового дайджеста, `docker rm` старого, `run` нового, восстановление
`/opt/amnezia/<тип>/` из `state/`, запуск, проверка `awg show` и handshake-теста, при провале —
откат на прежний образ. Ключи пользователей не меняются.

### 6.7 Бэкап и восстановление

Архив: `config.json`, `users.json`, `state/*`, `.env` бота, nginx-конфиг и Let's Encrypt
(перенос между VPS), `user_langs.json`. Восстановление на чистом сервере поднимает контейнеры
из `state/` — это и есть сценарий переезда без перевыпуска ключей.

### 6.8 Обновления из официального репозитория Amnezia

Задача: когда Amnezia выпускает новую версию (ядро `amneziawg-go`, образ, серверные скрипты),
обновить контейнеры из бота или из SSH-меню, не трогая приложение и не теряя пользователей.

**Откуда берём.** Два источника, оба официальные:

| Что | Источник | Как узнаём «новое» |
|---|---|---|
| серверные скрипты контейнера: `Dockerfile`, `configure_container.sh`, `run_container.sh`, `start.sh`, `template.conf` | GitHub `amnezia-vpn/amnezia-client`, каталог `client/server_scripts/awg/`, **по тегу последнего релиза клиента** (API `releases/latest`), не по ветке `dev` | хеш файлов против вендоренных копий в `lib/upstream/awg/` |
| образы ядра: `amneziavpn/amneziawg-go` (2.0/3.x), `amneziavpn/amnezia-wg` (1.x) | Docker Hub API `v2/repositories/amneziavpn/<image>/tags` → теги и дайджесты | дайджест в `config.json` профиля против дайджеста тега `latest`/новейшего версионного тега |

**Как устроено.** Модуль `lib/upstream.sh` + действия:

- `upstream-check` — сравнивает скрипты и дайджесты, отвечает JSON `{ "awg": { "image":
  "3.1.20260828 → 3.2.…", "scripts": "changed: configure_container.sh" }, … }`. Ничего не
  меняет. Тот же вызов делает `goamnezia-upstream.timer` раз в сутки и шлёт в бота
  «Доступно обновление Amnezia» (без автообновления — оно всегда по кнопке).
- `upstream-update --profile=awg3 [--tag=…]` — скачивает новые скрипты в
  `lib/upstream/awg/<тег>/`, показывает краткий diff (какие плейсхолдеры добавились или
  исчезли), делает бэкап, затем `core-update` из §6.6: новый образ → пересоздание контейнера
  → восстановление конфига и `clientsTable` из `state/` → проверка `awg show` и рукопожатия
  тестовым клиентом → при провале откат на прежний образ и скрипты. Ключи пользователей не
  меняются; линейка профиля не меняется (параметры берутся из нашего конфига, а не из upstream).
- `upstream-rollback --profile=…` — вернуть предыдущий образ и скрипты (храним один шаг назад).
- Новые плейсхолдеры в `template.conf` (например, появится параметр 3.2) не подставляются
  молча: `upstream-check` помечает их как «новый параметр, не поддержан», а поддержку добавляем
  релизом goAmnezia (генератор в `lib/awg_params.sh`). Так обновление ядра не ломает клиентов
  старой линейки.
- Сеть: GitHub и Docker Hub могут быть недоступны с части хостингов — в `upstream-check`
  отдельный код `unreachable` с советом, без падения меню.

**В интерфейсах.** Бот и SSH: «Обслуживание → Обновления Amnezia» — экран с таблицей профилей
(текущая версия ядра · доступная · дата) и кнопками «Обновить профиль» с подтверждением и
«Откатить». Панель — карточка на странице «Протоколы». В статусе профиля всегда видно версию
ядра и дайджест.

**Проверка совместимости при обновлении** (в тестах): образ 3.1 обслуживает конфиг 2.0 без
3.x-параметров и конфиг 1.x — это нужно подтвердить на стенде до того, как разрешать обновление
ядра для профилей `awg2`/`awg1`; если не подтвердится, эти профили остаются на закреплённых
образах (`0.2.19`, `amnezia-wg`), а обновляется только `awg3`.

### 6.9 MCP-сервер: управление сервером агентами

Что такое MCP. Model Context Protocol — открытый протокол, по которому ИИ-агенты (Claude Code,
Claude Desktop, Cursor и другие клиенты) подключают внешние «серверы инструментов». Сервер
объявляет набор инструментов с описанием и JSON-схемой параметров, ресурсы для чтения и
готовые подсказки; клиент показывает их модели, модель вызывает инструмент, клиент спрашивает
у человека разрешение на опасные вызовы. Обмен — JSON-RPC 2.0, транспорт — stdio (клиент
запускает процесс сервера и общается через stdin/stdout) или Streamable HTTP.

Зачем здесь. Бот, панель и SSH-меню сделаны для людей. Агенту нужен типизированный доступ:
«добавь пользователя Анна с лимитом 50 ГБ и пришли ключ 2.0» — одна команда, а не разбор
экрана меню. У goAmnezia уже есть контракт `--action=… --json`; MCP-сервер — тонкий
переходник над ним, четвёртый интерфейс к тому же ядру.

**Устройство.**

- `goamnezia-mcp/server.py` — stdlib Python (без `pip`, как панель): JSON-RPC 2.0 по stdio,
  методы `initialize`, `tools/list`, `tools/call`, `resources/list`, `resources/read`,
  `prompts/list`, `prompts/get`, `ping`; версия протокола `2025-06-18`. Каждый вызов инструмента
  → `install.sh --action=<имя> --json …` → ответ JSON как результат инструмента. Команда
  `/usr/local/bin/goamnezia-mcp`.
- **Единое описание действий `lib/actions.json`**: имя, параметры с типами и регексами, флаг
  «разрушительное», описание RU/EN, что возвращает. Из него MCP строит `tools/list`
  (`inputSchema`), статические тесты сверяют его с диспетчером `install.sh` и с кнопками бота.
  Один источник правды на четыре интерфейса.
- **Инструменты** (первый набор): `server_status`, `profiles_list`, `profile_install`,
  `profile_remove`, `profile_set_port`, `profile_restart`, `users_list`, `user_add`,
  `user_delete`, `user_enable`, `user_disable`, `user_set_quota`, `user_set_expiry`,
  `user_get_key` (возвращает `.conf`, `vpn://` и QR как image-контент MCP), `traffic_report`,
  `logs_tail`, `backup_create`, `backup_list`, `backup_restore`, `upstream_check`,
  `upstream_update`, `upstream_rollback`, `site_set_template`, `diagnose`.
- **Ресурсы**: `goamnezia://status`, `goamnezia://profiles`, `goamnezia://users`,
  `goamnezia://users/<имя>`, `goamnezia://logs/<компонент>`, `goamnezia://neighbours`.
- **Подсказки**: «подключить нового пользователя», «диагностика: пользователь не подключается»,
  «обновить ядро безопасно».
- **Безопасность.** Транспорт по умолчанию — stdio через SSH: в клиенте агента команда
  `ssh root@host goamnezia-mcp`; портов не открываем, аутентификация — ключ SSH. Разрушительные
  инструменты (`user_delete`, `profile_remove`, `backup_restore`, `upstream_update`,
  `profile_regen`) требуют параметр `confirm` со значением, повторяющим имя цели — вторая
  линия после подтверждения клиентом. Приватные ключи выдаёт только `user_get_key`; всё
  пишется в аудит-лог с пометкой `mcp`. Тот же замок `config.lock`, что у бота и панели.
- **HTTP-транспорт (этап 2):** Streamable HTTP на `127.0.0.1:1986` с bearer-токеном
  (`/opt/goamnezia-mcp/token`, 0600) — через SSH-туннель или по секретному пути домена в
  Pro, для агентов, которые не могут запускать SSH (облачные сессии). Включается пунктом
  «Настройки → MCP», по умолчанию выключен.
- **Проверки.** `tests/test_mcp.py`: запуск сервера как подпроцесса, `initialize` →
  `tools/list` → `tools/call` на заглушке моста (`GOAMNEZIA_ACTION_BIN` указывает на тестовый
  скрипт), сверка `tools/list` с `lib/actions.json`. Ручная приёмка: `claude mcp add goamnezia
  -- ssh root@host goamnezia-mcp` и сценарий «добавь пользователя и покажи QR».
- **Переносимость.** Переходник параметризован только `actions.json` и путём к `install.sh`,
  поэтому после goAmnezia его можно поставить в goTelegram и goDNS без переписывания.

### 6.10 Доступы агентов по HTTP: секретный путь как ключ, отзыв из скрипта

Задача владельца: агент подключается к серверу без SSH, по секретному порту и пути, которые
работают как ключ; у каждого агента свой ключ; все ключи видны в скрипте и отзываются.

**Модель.** «Доступ агента» (grant) — запись в `/opt/goamnezia/agents.json` (0600):

```json
{"id": "a-7f3c", "label": "Claude Code на ноутбуке", "secret": "<43 символа base64url = 32 случайных байта>",
 "scope": "write", "enabled": true, "created": "…", "expires": "", "port": 0,
 "allow_ips": [], "last_used": "", "last_ip": "", "calls": 0}
```

- **Ключ = секретный путь.** Адрес агента: `https://<домен>/a-<secret>/mcp` (Pro) или
  `https://<IP>:<порт>/a-<secret>/mcp` (Lite). Секрет 32 байта — перебор невозможен, поэтому
  дополнительный заголовок не нужен; путь одинаково умеют все MCP-клиенты
  (`claude mcp add --transport http goamnezia https://…/a-…/mcp`).
- **Уровни доступа (`scope`).** `read` — только инструменты с `readOnlyHint`, **кроме тех, что
  возвращают секреты** (`user_get_key`; в `actions.json` такие помечены `"secret": true`);
  `write` — всё, кроме разрушительных, включая выдачу ключей; `admin` — всё, включая
  разрушительные (с `confirm`). Сервер не просто отклоняет чужие
  вызовы, а **не показывает** агенту инструменты вне его уровня в `tools/list`.
- **Отзыв мгновенный.** Сервер читает `agents.json` при каждом запросе (файл маленький), так
  что «Выключить» или «Удалить» в SSH-меню действует на следующий же вызов. «Перевыпустить»
  меняет секрет — старый адрес умирает, агенту выдаётся новый.
- **Срок и адреса.** Необязательные `expires` (дни) и `allow_ips` (список IP/подсетей) на
  каждый доступ. Истёкший — как выключенный.
- **Учёт.** `last_used`, `last_ip`, `calls` обновляются сервером; каждая операция пишется в
  аудит-лог с меткой доступа (`agent=a-7f3c`). В SSH-меню, боте и панели видно: кто, с какого
  адреса, когда последний раз, сколько вызовов.
- **Управление доступами — не через MCP.** Действия `agent-*` помечены `mcp: null`: агент не
  может выдать доступ другому агенту или продлить себя. Только SSH-меню, бот, панель.

**Транспорт.** Streamable HTTP по спецификации MCP `2025-06-18`: `POST /a-<secret>/mcp` с
JSON-RPC, ответ `application/json`; `GET` на тот же адрес → `405` (поток сервер→клиент нам не
нужен); проверка `Origin` (защита от DNS-rebinding); заголовок `MCP-Protocol-Version`.
Тот же `server.py`, режим `--http`, слушает `127.0.0.1:1986`.

**Как адрес попадает в интернет.**

| Режим | Как | Почему так |
|---|---|---|
| Pro | nginx на домене, адрес `https://<домен>/a-<secret>/mcp`: `location ~ ^/a-[A-Za-z0-9_-]{43}/ { proxy_pass http://127.0.0.1:1986; access_log off; }` | секрет не попадает в логи nginx; форма пути столь специфична, что с сайтом не пересекается; новый доступ не требует перезагрузки nginx; для всех прочих путей — сайт-маскировка, чужой перебор получает обычные 404 сайта |
| Lite + сайт | тот же nginx, та же location и тот же адрес на домене: сайт у двух режимов один и тот же (§4.3), различать их здесь нечего | место AmneziaWG на маршрут агентов не влияет |
| Запасной путь (в любом режиме с сайтом) | пока домена нет или A-запись не разошлась — `https://<IP>/a-<secret>/mcp` на **самоподписанном** сертификате сайта, отпечаток SHA-256 показывается рядом с адресом | клиенту нужно доверить сертификат по отпечатку (`NODE_EXTRA_CA_CERTS`), иначе — SSH-транспорт; адрес выбирается по готовности сайта (`ga_site_domain_ready`), а не по названию режима |
| Lite | HTTP-транспорта нет по умолчанию; по желанию — отдельный TCP-порт (случайный из **1024–9999**, §4.3) с TLS на том же самоподписанном сертификате | без nginx открывать нечего; SSH-транспорт работает всегда |

**Свой порт на агента** — необязательная опция для Lite (`port` в записи): сервер поднимает
дополнительный слушатель и принимает на нём только этот доступ. По умолчанию выключено:
каждый открытый порт — лишний сигнал сканерам, а стойкость даёт путь, не порт. Порт стоит
включать, когда нужно физически развести агентов (например, ограничить один из них файрволом
хостинга).

**Защита от подбора и шума.** Неизвестный путь → `404` с телом как у nginx по умолчанию, без
подсказок; счётчик неудач по IP с временным баном (как корзины кодов у панели); ограничение
размера тела (1 МБ) и частоты вызовов на доступ; секреты никогда не пишутся в обычный лог,
в аудите — только `id`.

**Интерфейсы.** «Настройки → Доступы агентов (MCP)»: список · добавить (название, уровень,
срок, адреса, порт) → экран с адресом и QR адреса · показать адрес снова · перевыпустить ·
выключить/включить · удалить (с подтверждением). В боте — то же, с предупреждением, что адрес
в чате равносилен ключу. В панели — страница «Агенты». Включение самого HTTP-транспорта —
отдельный переключатель (`mcp.http_enabled`), по умолчанию выключен; SSH-транспорт остаётся
всегда.

**Действия:** `agent-list`, `agent-add`, `agent-show`, `agent-rotate`, `agent-enable`,
`agent-disable`, `agent-del`, `mcp-http-status`, `mcp-http-on`, `mcp-http-off`.

## 7. Безопасность и соседство

### 7.1 Безопасность

- Как в goTelegram: всё от root, компенсации — `0600` на конфиги и `.env`, `0700` на каталоги
  панели/бэкапов/state, `mktemp`, валидация входа регексами `[[ =~ ]]`, окно первого админа
  с одноразовым маркером, пустой allowlist = никого не пускать, панель только на loopback,
  защита от DNS-rebinding, раздельные корзины лимитов на код.
- Новое для этого продукта: **приватные ключи пользователей** в `users.json` — маскируются в
  выводе (`SENSITIVE_KEYS`), не попадают в логи и в `--action` ответы, кроме `user-key`.
- `--privileged` у контейнеров — официальный флаг; в MVP оставляем ради паритета, отдельный
  пункт этапа упрочнения — попробовать `NET_ADMIN` + нужные sysctl без `--privileged` и
  замерить, что ломается.
- Бот отдаёт ключи только админам; выдача ключа записывается в аудит-лог (`/var/log/goamnezia-audit.log`).

### 7.2 Соседство (будущий `NEIGHBOURS.md`)

- Не занимаем: 1984 (goTelegram), 40000 (goWARP SOCKS), 5199/853/4443 (goDNS), 10808/10851
  (egress goVLESS/goKaskad), таблицы маршрутов 256–356 (goKaskad) и 7788 (goTelegram WARP).
- goInstaller: добавить запись `goamnezia` в таблицу продуктов и портов (отдельная задача в
  том репозитории).
- goTelegram Pro на том же сервере: оба хотят 443 в Pro-режиме — в `NEIGHBOURS.md` описать
  порядок (shared-443 у goTelegram, либо goAmnezia в Lite).

### 7.3 Совместимость с приложением Amnezia

Приложение, добавив сервер по SSH, увидит `amnezia-awg` и `amnezia-awg2`, прочитает их конфиги
и `clientsTable`, сможет добавлять и удалять пользователей. Двойное управление допускаем, но
объявляем правило: после действий из приложения goAmnezia при следующем запуске сверяет
`clientsTable` и конфиг с `users.json` и предлагает «подхватить изменения». Контейнеры `gawg1`
и `gawg2` приложение не видит намеренно.

### 7.4 Совместимость с goWARP PRO

goWARP PRO работает с контейнерами `^amnezia-awg[0-9]*$`: поднимает внутри интерфейс `warp`,
ставит свои инструменты в `/opt/warp-tools`, хранит `/opt/warp/{warp.conf,clients.list,disabled}`,
меняет правила маршрутизации выбранных клиентов. Наши обязательства: не трогать эти файлы и
интерфейс; при `syncconf` и пересоздании контейнера из `state/` сохранять их (в `state/`
копируем и `/opt/warp/`); не перезапускать контейнер без нужды; в `NEIGHBOURS.md` описать, что
после `core-update` goWARP нужно запустить «восстановление» (у него есть сторож
`gowarp-awg-watch`). Контейнеры `gawg1` и `gawg2` для goWARP невидимы (он ищет
`^amnezia-awg[0-9]*$`) — это ограничение записываем; WARP-прокладка доступна профилю 3.1.

## 10. Решения владельца от 2026-09-08 (принято, план ниже им подчинён)

1. **По умолчанию при первой установке выдаётся конфигурация AmneziaWG 2.0.** Профиль `awg2`
   живёт в контейнере `amnezia-awg2` — единственном, который видит официальное приложение.
2. **Раскладка контейнеров:** `amnezia-awg2` = 2.0 (по умолчанию), `amnezia-awg3` = 3.1,
   `amnezia-awg1` = 1.0/1.5. Приложение незнакомые имена с подстрокой `amnezia` молча
   пропускает (проверено по `getAlreadyInstalledContainers`), goWARP PRO по своей маске
   `^amnezia-awg[0-9]*$` видит все три. Все три из одного официального образа.
3. **Пользователь может иметь несколько конфигураций** — по одной на профиль (2.0, 3.1, 1.x);
   карточка пользователя показывает их рядом.
4. **Lite** — случайный порт из 1024–9999, без домена. **Pro** — домен, TCP/443 сайт,
   UDP/443 профиль по умолчанию, «Amnezia и домен на одном порту» (§4.4).
5. **QR и ключи в двух стилях** везде (SSH, бот, панель): классический `.conf` + его QR и
   «стиль Amnezia» — копируемый ключ `vpn://` + QR в формате приложения.
6. **Вход в панель** — секретный путь на домене или секретный порт через туннель, второй
   фактор через Telegram-бота, как в goTelegram.
7. **MCP-сервер** как штатный компонент (§6.9): агенты управляют сервером через MCP, а не
   через сырой API. Первый продукт серии с MCP.
8. Разработку вести с распределением задач между субагентами; продукт делать «крутым».
10. **Три режима** (§4.3, договор уточнён владельцем 10.09.2026): Lite — случайный порт без
   домена и без сайта; Lite + сайт — домен, сайт-заглушка и панель на TCP/443 с настоящим
   сертификатом Let's Encrypt, AmneziaWG на своём порту; Pro — то же самое, но AmneziaWG на
   UDP/443 рядом с сайтом. Мастер установки предлагает их первым шагом.
9. **Настройки как в официальном приложении.** У профиля редактируются порт, подсеть (с
   перенумерацией пиров), MTU и каждый параметр маскировки по отдельности с проверкой по
   правилам линейки, а не только пресеты; глобально — DNS клиентов и хост `Endpoint`. Действия
   `profile-set-param`, `profile-subnet`, `profile-mtu`, `endpoint-set` в `lib/actions.json`.
   Серверные параметры (`S1–S4`, `H1–H4`, `HeaderProtectionKey`, `RandomTrailers`,
   `DisableCookies`) после смены требуют перевыпуска ключей — интерфейсы предупреждают об этом
   до подтверждения; клиентские действуют на новые выдачи.
