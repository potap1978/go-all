# Режимы установки: Ленивый Pro, Pro, Semi-Pro, Lite (0.6.0)

Запрос владельца 27.09.2026. Заморожено 27.09; **разморожено 28.09 (решение владельца): Ленивый Pro + 4 режима — в 0.6.0**
(дизайн iteration3: F-1 Ленивый Pro, F-2 названия режимов, F-3 выбор линии на UDP 443). **Сертификат на IP (F-4, раздел ниже) —
по-прежнему заморожен**, в 0.6.0 не входит: Lite остаётся с самоподписанным сертификатом, как сейчас.

## Договор 0.6.0 для панели, бота и мини-аппа (мост)

Внутренние id режимов не меняются (`pro`, `lite_site`, `lite`); Ленивый Pro — сценарий, его итог — `pro` (или `lite_site`, если
UDP 443 занят). Названия для людей — из словарей по id, одинаковые во всех интерфейсах:

| id | RU | EN |
|---|---|---|
| (сценарий) lazy | Ленивый Pro — только домен, остальное сделаю сам | Lazy Pro — just a domain, I do the rest |
| `pro` | Pro — сайт и VPN на 443 | Pro — site and VPN on 443 |
| `lite_site` | Semi-Pro — VPN и сайт | Semi-Pro — VPN and site |
| `lite` | Lite — только VPN | Lite — VPN only |

Действия моста (`lib/actions.json`, `install.sh --action=… --json`; в MCP не публикуются — как `agent-*`):

- `lazy-check --domain=<d>` (read, без изменений): `{domain (punycode), domain_display, points_here, a:[], aaaa:[], server_ips:[],
  cloudflare_proxied, ports:{tcp80:{free,by}, tcp443:{free,by}, udp443:{free,by}}, app_containers:[{name,line,port}],
  plan: "pro"|"semi_pro"|"blocked", reasons:[код…]}`. `semi_pro` — UDP 443 занят (сайт на 443, профили на случайных портах);
  `blocked` — TCP 80/443 заняты чужим или домен смотрит не сюда (в `reasons` — почему; чужое не останавливаем).
- `lazy-setup --domain=<d> [--keys=1..20, по умолчанию 5]` (write, разрушительное: меняет режим; `confirm`): весь сценарий без
  вопросов, долгий — занятость как у прочих долгих действий. Ответ: `{mode, domain, udp443:{profile,line}|null,
  profiles:[{id,line,port}], site:{template}, panel_on_domain, keys:[{name,label,page}], warnings:[код…]}`. Ссылки страниц и панели —
  как у существующих действий (панели — по её правилам доступа).
- `pro-line --profile=<id>` (write, разрушительное; `confirm`): в режиме `pro` ставит выбранную линию на UDP 443, прежнюю — на
  свободный случайный порт; подхваченный у приложения профиль — только с явным `--adopted-confirm=<profile>` (ACC-2).
- Установка без терминала (goInstaller): `install.sh --lazy --domain=<d> [--keys=N]`; конец ввода — отмена.

Уточнения договора (28.09, по итогам панели; ядро, бот и панель следуют им):
- Первым параметром `lazy-setup` идёт `--domain` (подтверждение берётся по первому параметру), затем `--keys`. Домен в мост —
  латиницей (punycode); панель и бот чистят ввод сами (https://, путь, точка в конце), ядро повторяет ту же чистку.
- Коды `reasons` (`lazy-check`): `dns_none`, `dns_elsewhere`, `dns_partial`, `aaaa_foreign`, `cloudflare_proxied`, `tcp80_busy`,
  `tcp443_busy`, `tcp443_app` (контейнер приложения на TCP 443), `udp443_busy`. Коды `warnings` (`lazy-setup`): `template_fallback`,
  `cert_fallback`, `adopted`, `keys_partial`, `panel_off`, плюс все коды `reasons`, которые сценарий обошёл. Незнакомый код клиенты
  показывают как есть.
- `lazy-setup`: `panel_on_domain` — `true`/`false` (адрес панели — существующим действием по её правилам доступа); `keys[].page` —
  полный адрес страницы подключения или `null`.
- `lazy-setup` (1.0.6, L-26): сайт встал на запасном сертификате из-за отказа Let's Encrypt — рядом с `cert_fallback` поля
  `cert_cause` (`dns` | `net` | `limit`) и `cert_retry_after` («2026-09-27 10:00» UTC или пусто); отказ `cert_failed` (сайт жил на
  домене с настоящим сертификатом) несёт те же поля. Причина неизвестна — полей нет (docs/CONTRACT.md, режимы с сайтом).
- `pro-line`: ответ `{mode:"pro", udp443:{profile,line}, profiles:[{id,line,port}]}`; отказ подхваченного профиля — как у
  `profile-port`: код `adopted_keyless`, имя профиля в `profile`; повтор с `--adopted-confirm=<profile>`.
- Время ожидания в клиентах: `lazy-check` 120 с, `lazy-setup` 1800 с, `pro-line` 600 с.
- `lazy-check`: `ports.<порт>.by` — строка для человека, кто держит порт («nginx», «контейнер amnezia-xray», «процесс xray»), или `null`,
  если свободен.
- По итогам ядра (28.09): `by` — полная формулировка предполётной проверки (может быть длинной). Дополнительные коды `reasons`:
  `no_line_for_443` (обе линии уже стоят на своих портах — частый случай «Lite → Ленивый Pro»: итог Semi-Pro, перенос линии на 443 —
  отдельно через `pro-line`, ключи этой линии придётся обновить), `dns_unknown` (DNS не ответил), `awg2_container_busy` (место 2.0
  занял контейнер приложения с людьми — план `blocked`). Редкие `warnings`: `adopt_failed`, `firewall_open_failed`, `line_skipped`,
  `profile_failed`, `site_failed`, `timers_failed`, `subnet_overlap` (SUBNET-01, 06.10: контейнеры приложения подхвачены на одной
  подсети — приложение ставит их все на 10.8.1.0/24; раньше второй отказывал, и сценарий падал `adopt_failed`; сценарий их не
  переносит — выход в карточке профиля, недостающая линия встаёт на свободную подсеть). Отказ `lazy-setup` до изменений несёт `plan` и `reasons`. `lazy-check` отдаёт
  `udp443_line` — какая линия встанет на UDP 443 (`"2.0"`, `"3.1"` или `null`). Страницы Ленивого Pro живут 30 дней.
- По итогам живой проверки (28.09, LZ-02…05): линия — по версии контейнера, а не по месту профиля (приложение держит 3.1 и в
  `amnezia-awg2`): на UDP 443 встаёт недостающая 2.0, при занятом месте awg2 — контейнером `amnezia-awg3` с линией 2.0; `profiles[]` и
  `udp443` в ответах — с настоящими линиями. `lazy-check`: `ports.<порт>.ours` — `true`, если порт держим мы сами (наш nginx, наш
  профиль; для сценария он свободен, `free: true`), клиенты пишут «занят нами»; необязательный `--keys=1..20` (по умолчанию 5) и в
  ответе `keys_have` (живые ключи прошлых заходов — засчитываются) и `keys_new` (сколько ключей будет заведено на самом деле, для
  другого числа — `max(0, keys − keys_have)`). За прокси Cloudflare его IPv6 в AAAA — не `aaaa_foreign`; `message` моста говорит, что
  ключи ведут на IP сервера.

## Порядок в мастере (первый экран режима) и в «Настройки → Режим и сайт»

| № | Название | Внутренний id | Что занимает | Суть |
|---|---|---|---|---|
| 1 | Ленивый Pro | сценарий установки → итог `pro` | TCP 80/443, UDP 443 | вводится только домен, остальное делает скрипт |
| 2 | Pro | `pro` | TCP 80/443, UDP 443 | сайт на TCP 443 + AmneziaWG на UDP 443; **человек выбирает, какая линия (2.0/3.1) сидит на 443** |
| 3 | Semi-Pro | `lite_site` (нынешний «VPN и сайт») | TCP 80/443, UDP случайные | сайт на 443, профили на случайных портах или на выбранных вручную |
| 4 | Lite | `lite` (нынешний «Только VPN») | UDP случайные; TCP 80 — на секунды при выпуске/продлении сертификата | сайта нет; попытка получить доверенный сертификат **на IP** (Let's Encrypt, профиль shortlived, ~6 дней) с автопродлением, как в 3x-ui; не вышло — самоподписанный, как сейчас |

Внутренние id **не меняются**: на них опираются существующие установки (config.json), мост, бот, панель, MCP и goInstaller
(`prod_modes 'pro lite_site lite'`). Меняются только названия, порядок и описания.

## Ленивый Pro

1. Домен — в цикле с подсказками: `https://`, путь и точка в конце отрезаются, кириллица объясняется (или переводится в
   punycode), `0` — назад. Никаких тупиков (урок goVLESS pro, U-03).
2. Проверки без вопросов: домен указывает на этот сервер (если нет — показать, куда указывает, и перепроверять раз в 15 с
   до 5 минут); TCP 80/443 и UDP 443 свободны (занято — назвать кем, чужое не останавливать); домен за прокси Cloudflare —
   ключи ведут на IP.
3. Подстраивается под сервер: UDP 443 занят → Semi-Pro (сайт на 443, профили на случайных портах) с объяснением; TCP 80/443
   заняты → остановиться, назвать, кто держит, и предложить обычные режимы (в Lite сам не уходит — ленивый только с доменом).
4. Ставит: сертификат Let's Encrypt; случайный шаблон сайта (до 3 попыток, потом встроенная заглушка); AWG 2.0 и 3.1
   (**на UDP 443 — 2.0, решение владельца 27.09**, с предупреждением на экране: почему 2.0 — шире всего поддержка клиентов,
   включая роутеры Keenetic; 3.1 — на случайном порту; поменять — «Протоколы → порт»);
   панель на домене; **5 ключей** (оба профиля у каждого) и страницу подключения на каждый; имена ключей — раздел «Имена».
5. Итог: сайт; ссылка на панель и её пароль один раз; 5 ссылок на страницы и QR по номеру; «Привязать Telegram-бота?» —
   токен скрытым вводом → установка бота → **привязка сообщением с подтверждением в SSH** (раздел ниже); `0` — позже.
6. Сервер с контейнерами приложения Amnezia: подхват без вопроса; **порты подхваченных не трогать** (ACC-2); недостающую
   линию (2.0 или 3.1) поставить новым профилем на UDP 443; случайный сайт; 5 новых ключей к существующим людям; TCP 443
   занят контейнером приложения (Xray/Cloak) — остановиться и объяснить, людей молча не ломать.
7. Без терминала (goInstaller): `install.sh --lazy --domain=…` (+ число ключей); конец ввода — отмена.
8. Только при первой установке; на установленном сервере — пункт «Режим и сайт» (повторный запуск ничего не ломает).
9. Ленивого режима без домена нет (решение владельца 27.09): Enter без домена — повтор вопроса с подсказкой и `0 — назад`.

## Имена ключей (решение владельца 27.09)

- Случайные «прилагательное + столица мира», связанные по смыслу: «Туманный Лондон», «Солнечная Манила», «Снежная Оттава».
  Набор — 500 пар (по 2–3 прилагательных на столицу), русский с согласованием рода и числа («Солнечные Афины»), английский
  («Foggy London»), идентификатор латиницей из английского (`foggy_london`, `^[A-Za-z0-9_-]{1,32}$`).
- Прилагательные нейтральные и добрые: погода, природа, архитектура, цвет, культура; без стереотипов о бедности и войне;
  спорные и конфликтные столицы — не включать (решение владельца, если захочет иначе).
- Подпись короткая (до ~18 символов) — бот показывает людей по двое в ряд.
- Выбор: 5 разных, не совпадающих с уже заведёнными людьми; язык подписи — язык установки.
- Данные — отдельным файлом (`lib/names_capitals.json`) с проверкой в тестах: 500 записей, уникальность, длина, латиница в id,
  пары ru/en; функция выбора — в `lib/users.sh`.
- **«🎲 Случайное имя» — решение владельца 27.09, делаем везде, где добавляют человека:** SSH (в поле имени пустой Enter или `?`
  → предложить имя, `🎲` ещё раз — другое), бот (кнопка под вопросом об имени, повторное нажатие меняет вариант в том же
  сообщении), панель (кнопка у поля имени), мост/MCP (действие `name-suggest` или параметр `random_name` у `user-add`).
  Предложенное можно отредактировать; подпись — по языку интерфейса, id — латиницей. В дизайн (стадия 2) — кнопка в формах.

## Привязка администратора бота — сообщением + подтверждение в SSH (решение владельца 27.09)

Вместо копирования одноразового кода: человек просто пишет боту, а доверие даёт SSH-сессия, в которой идёт установка.

1. После установки бота SSH показывает: «Напишите боту @имя_бота любое сообщение» и ждёт (живой статус, до 10 минут).
2. Бот в окне привязки записывает каждого написавшего в кандидаты (`/opt/goamnezia-bot/.admin_candidates.json`, 0600: id,
   @username, имя, время) и отвечает ему: «Запрос на управление сервером получен. Вернитесь в SSH-терминал и подтвердите
   привязку». Вне окна чужим — как сейчас (молчание/ограничение ответов).
3. SSH показывает кандидата: «Написал @username (Имя, id …, 14:52). Это вы? [y/N]»; если написавших несколько — список и выбор
   номером; подтверждение — только в SSH (у постороннего SSH нет, поэтому «первый написавший» админом сам не станет).
4. После подтверждения: ALLOWED_IDS/OWNER_ID атомарно (0600), бот перечитывает настройки, пишет подтверждённому
   «✓ Вы администратор сервера …» и показывает меню; SSH — «✓ администратор: @username».
5. `0 — позже` и пункт «Telegram-бот → Администраторы → Привязать по сообщению» запускают то же окно в любой момент.
6. Без терминала (goInstaller) — `ALLOWED_IDS` в окружении, как сейчас; одноразовый код остаётся запасным путём только для
   таких установок (закрывает и SEC46-07: код не живёт вечно — только пока открыто окно).
7. Тесты: pty-тест мастера с поддельным ботом (кандидат появился → подтверждение → запись .env), тест бота на окно
   кандидатов и на отказ вне окна; живая проверка на стенде.

## Сертификат на IP (Lite, а также Semi-Pro без домена) — ЗАМОРОЖЕНО (не входит в 0.6.0)

- Let's Encrypt выдаёт сертификаты на IP только коротким профилем (~6 дней): выпуск и продление каждые ~3 дня.
- Проверка HTTP-01 на TCP 80 (или TLS-ALPN-01 на 443): в Lite порт 80 нужен на секунды при выпуске/продлении; занят соседом →
  самоподписанный с объяснением; чужие webroot и конфиги не трогать.
- certbot из apt (Ubuntu 22.04/24.04) слишком стар для IP; вероятно — acme.sh в собственном каталоге продукта (правило серии:
  не трогать чужие `acme.sh`/`/etc/letsencrypt/renewal`). Проверить вживую выпуск с адресов Aeza.
- Таймер продления + тревога в бот/панель при сбое продления (6 дней — истекает быстро); после N неудач — самоподписанный.
- Что выигрываем: страницы подключения, временные ссылки, панель и MCP в Lite без предупреждения браузера.
