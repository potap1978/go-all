# goAmnezia pro — несколько адресов сервера (DEFECTS §2.3)

Замысел перенесён из goTelegram (`lib/edgeips.sh`) и приспособлен к AmneziaWG. Статус на 13.09.2026:
**сделано по образцу goTelegram**: учёт и сторож (`lib/edgeips.sh`) в тике сторожа контейнеров — раз в
две минуты и только когда у машины два адреса и больше; таблица «Адреса сервера» (пакеты за 15 минут,
час и сутки, пользователи, вердикт) в шапке SSH-меню, на экране «Состояние → Адреса сервера», в боте и в
панели. С 25.09.2026 в шапке она всегда, и с одним адресом: колонка «A-запись» (✓ / ✗ / ? / —) — ведёт ли
A-запись домена (из ключей, иначе домена сайта) на адрес; счётчики и вердикт — только при двух адресах и больше; действие моста `edge-status` (MCP `edge_status`); свой адрес сервера в ключе пользователя
(`user-set-address`). При доменном Endpoint (несколько A-записей) пользователи считаются на каждом
адресе, как в goTelegram. Не сделано: пересадка всех пользователей с адреса на адрес.

**0.4.3, 24.09.2026 — домен с несколькими A-записями.** A-записи домена из ключей теперь известны
продукту (`ga_site_dns_state`: набор A-записей против набора адресов машины, кэш две минуты): доменные
пользователи считаются только на адресах, которые есть в A-записях, — адрес без записи простаивает
честно («на адрес не смотрит ни один ключ»), а не поднимает ложную тревогу «замолчал» (в goTelegram так
и было до 2.10.30). DNS не ответил — по последнему удачному ответу из кэша (иначе адрес, снятый из DNS, на тике со сбоем снова ждал бы трафика и давал ложную тревогу), а если удачного не было — по-старому, на каждом. Домен ведёт только на чужие адреса или без записей — доменных пользователей нет ни на одном адресе. Свой адрес пользователя и доменные теперь
складываются: раньше доменные затирали счёт адреса, вписанного в ключ. В таблице — колонка DNS (✓ адрес
в A-записях, — нет), под таблицей — чужие адреса из A-записей; на машине с одним адресом чужой адрес
в A-записях — строка в шапке. `edge-status` отдаёт `dns {domain, state, a, foreign}` и `in_dns` у адреса;
бот и панель показывают то же. Проверки сайта (мастер, «Домен», «Проверка сайта снаружи», включение
сайта, «Адрес сервера в ключах») сравнивают все A-записи со всеми адресами машины — раньше только первую
с одним адресом сервера, и домен с двумя адресами этого же сервера в половине случаев уводил мастер на
самоподписанный сертификат.

**0.4.3, 25.09.2026 — ключ на другой адрес сервера (разово).** Тот же ключ человека (та же пара ключей,
тот же порт профиля) можно выдать с другим адресом этой машины или её доменом внутри, не меняя ничего
за пользователем: `user-key --endpoint=<хост>` и `share-create --endpoint=<хост>`, пункт «Ключ на другой
адрес сервера (разово)» в SSH, кнопка «🌐 Ключ на другой адрес» в боте, выбор «Адрес сервера в ключе» в
панели, параметр `endpoint` у MCP `user_get_key`. Подробности и границы — §3.4.

## 1. Зачем

У машины бывает несколько внешних IPv4: хостер выдаёт дополнительные адреса. Блокировка
провайдером обычно бьёт по одному адресу, а не по серверу целиком. Если все ключи смотрят на
один адрес, падают все пользователи разом. Если ключи разложены по адресам, падает часть, и её
можно пересадить на живой адрес, не трогая остальных.

Для доменов это не нужно: при домене, вписанном в `endpoint_host`, адрес в ключе выбирает DNS, а не
сервер. Поэтому всё ниже действует, когда Endpoint в ключах — IP или домен сервера по умолчанию (режим
Pro): свой адрес пользователю владелец задаёт сам, и он важнее домена,
который никто не выбирал.

## 2. Что уже есть и работает

* Порт профиля публикуется на все адреса машины (`-p порт:порт/udp` в
  `lib/upstream/awg/run_container.sh`). Второй адрес принимает клиентов без изменений в
  контейнере. Обратные пакеты уходят с того адреса, на который пришли: это делает conntrack
  при DNAT Docker.
* Endpoint в ключе собирает одна функция — `ga_export_endpoint_host` (`lib/export.sh`), её зовут
  `export_conf` и `export_vpn`.
* Сторож `goamnezia-watch.timer` ходит каждые две минуты и уже раз в час проверяет, не
  сменился ли адрес сервера.

## 3. Что добавить

### 3.1. Адрес в ключе у пользователя

* `users.json`: необязательное поле `endpoint_ip` у пользователя. Пусто или нет поля — общий
  адрес (`endpoint_host`, иначе домен сервера в Pro, иначе `server_ip`), как сейчас.
* `ga_export_endpoint_host [имя]`: если общий Endpoint — IP или домен сервера по умолчанию и у
  пользователя задан `endpoint_ip`, берётся он. Домен, вписанный в `endpoint_host`, побеждает всегда (§1).
* Задать можно только адрес, который есть на машине сейчас (`ga_edge_list`). Машина своих внешних
  адресов не видит (облако за NAT, нет команды `ip`) — отказ `addresses_unknown`: проверить адрес
  нечем, а общий вернуть можно всегда. Адрес, который
  пропал с машины, при выдаче ключа — отказ `address_gone` со словами, а не ключ, который не
  соединится.
* Смена адреса **не перевыпускает ключи**: пара ключей та же, меняется только строка Endpoint.
  Уже поставленный клиенту конфиг продолжает смотреть на прежний адрес — человеку прямо
  говорится, что конфиг надо отправить заново.

### 3.2. Учёт трафика по адресам

Сделано 13.09.2026 (`lib/edgeips.sh`, проверка — `tests/test_edgeips_dryrun.sh`); подключено к тику
сторожа: `amnezia_watch_tick` (`lib/amnezia.sh`) зовёт `ga_edge_tick`.

* `ga_edge_list` — глобальные IPv4 машины: без петли, частных сетей, link-local и CGNAT.
* Счётчики — правила без действия в своей цепочке `GOAMNEZIA_EDGE`, в которую ровно одним переходом
  ведёт `mangle PREROUTING`: `-d <адрес> -p udp --dport <порт профиля> -m conntrack --ctstate
  ESTABLISHED`, по одному на пару «адрес, порт». `mangle PREROUTING` стоит **до** DNAT Docker,
  поэтому адрес назначения ещё настоящий. Считаются **пакеты установленных соединений**, а не байты:
  сканер остаётся в `NEW` (AmneziaWG ему не отвечает), а подключённый клиент, даже спящий, шлёт
  keepalive в установленном соединении. По байтам спящий клиент от сканера не отличался.
* Правила идемпотентны: пропавшие адреса, сменённые порты, правила чужого вида, копии правил и
  лишние переходы снимаются — копия перехода считала бы пакеты дважды. Все вызовы `iptables` ждут
  замок xtables (`-w 5`); занятый и после ожидания замок — отказ без изменений до следующего тика.
* Снимок — тик сторожа (две минуты), история — `state/edge_ips.csv`, строка на пару «адрес, порт»:
  `timestamp,ip,port,packets`. Приросты считаются по паре, поэтому снятое правило одного порта не
  выглядит обнулением всего адреса. Хранение 15 суток (тот же день недели две недели назад), срез — не чаще раза в сутки.
* Вердикт по каждому адресу машины; снятые с машины адреса не учитываются нигде, в том числе как
  «живой сосед»:
  * `unused` — на адрес не смотрит ни один ключ включённого пользователя с пиром во включённом
    профиле. Когда общий Endpoint —
    домен, в ключах у всех домен, и пользователи ни одному адресу не приписываются — даже те, кому
    задан свой адрес;
  * `quiet` — адрес ни разу не принимал, или тишина есть, но в это время он обычно и молчит;
  * `ok` — трафик идёт или тишина короче 20 минут, пока соседний адрес принимает;
  * `quiet-all` — в последний тик не принимал ни один адрес: ночь или сервер без клиентов, не тревога. Вердикт
    один у всех молчащих адресов, как бы давно каждый ни замолчал (1.0.6, NC6-10: адрес, замолчавший 6 минут
    назад, раньше оставался «принимает» рядом с «тихо у всех адресов», хотя за 15 минут у всех был ноль);
  * `dark` — на адрес смотрят **не меньше двух пользователей** (у адреса с одним пользователем отгул
    человека от блокировки по счётчикам не отличить), 20 минут подряд ни пакета **без разрывов в
    наблюдении**, у соседнего адреса в последний тик пакеты были, а **в это время суток адрес обычно
    занят**: в окне ±90 минут вокруг того же времени живы 90% тиков — не меньше чем в 70% из 7 прошлых
    дней с историей (и таких дней не меньше двух) или и неделю, и две недели назад в тот же день недели.
    Тишина в тот же день недели неделю назад тревогу снимает, если только две недели назад в это время
    не было занято: суббота после рабочей недели — не тревога, а разовый праздник неделю назад
    настоящую блокировку не глушит. Окно стоит на текущем времени суток, а не на начале тишины: блокировку, начавшуюся
    ночью, видно утром, а конец обычного дня тревогой не выглядит. Дни, чьё окно заходит в нынешнюю
    тишину, не в счёт — блокировка дольше суток остаётся `dark`. Край дня (пришли на час позже, ушли
    на час раньше, перевод часов у клиентов), суббота после рабочей недели, пользователь «через день»
    и один день истории тревоги не дают. Цена — утреннюю блокировку видно примерно через час с
    небольшим после обычного начала трафика.
* Событие владельцу `edge_ip_dark` (адрес, пользователей на нём, с какого времени тишина, UTC) — на
  переход в `dark`, но по одному адресу не чаще раза в сутки: эпизод мигающего адреса внутри суток
  записывается молча и объявляется, если тянется дольше; напоминание о всё ещё тёмном — раз в сутки.
  `edge_ip_back` — после трёх живых тиков подряд и только об объявленном эпизоде. Адрес, с которого
  всех пересадили, тревогу снимает молча. Память тревог — `state/edge_alerts.json`: пишется до
  отправки (не записалась — не шлём), пустой или битый файл читается как пустая память, записи о
  снятых с машины адресах стираются.

### 3.4. Разовый ключ на адрес

Сделано 25.09.2026 (0.4.3). Задача — отдать человеку, у которого не открывается домен или молчит его
адрес, **тот же ключ** на другой адрес этой машины, ничего не меняя за ним. Пара ключей, порт профиля,
параметры маскировки — прежние; в `.conf` и `vpn://` меняется только хост в Endpoint. Без адреса выдача
байт в байт прежняя (с закреплённым адресом человека, если он есть).

* **Какие хосты принимаются** — `ga_export_key_hosts` (`lib/export.sh`, без похода в сеть): сначала
  домены — `endpoint_host`, если там домен, домен Pro и домен сайта, если на нём Let's Encrypt
  (`ga_site_domain_ready`); затем IPv4 — `endpoint_host`, если там IP, `server_ip` из `config.json` и
  внешние адреса машины (`ga_edge_list`). Регистр и точка на конце не важны, `0.0.0.0` не бывает.
  Произвольный хост не принимается: ключ на чужой адрес выглядел бы настоящим, но не соединился бы.
* **Проверка** — `ga_export_key_host_check` (её же зовут `export_conf`, `export_vpn`, `export_bundle` и
  `share_create` до открытия порта). Отказы с кодом 2: `invalid_ip` — негодный IPv4, `0.0.0.0` или не
  хост вовсе; `address_not_here` — такого адреса или домена у сервера нет (в сообщении — какие есть);
  `addresses_unknown` — спросили IP, которого нет среди известных, а своих внешних адресов машина не
  видит (NAT, нет `ip`).
* **За пользователем ничего не сохраняется.** Чтобы и следующие ключи шли на этот адрес, а сторож
  считал человека на нём, — закрепить адрес (§3.1: «Адрес сервера в ключе», `user-set-address`).
  Разовый адрес действует и тогда, когда в `endpoint_host` вписан домен: он заменяет хост только
  этого ключа.

| Где | Что |
|---|---|
| Мост | `user-key --endpoint=<хост>` (MCP `user_get_key`, параметр `endpoint`, тип `key_endpoint` в `lib/actions.json`): в ответе `key_host` (хост в этом ключе), `key_endpoint` (`хост:порт`), `key_host_override` (`true` — выдан разовый); `share-create --endpoint=<хост>` (агентам не дано): имя файла то же, что без адреса (`anna-2_0.<расширение>`: имя туннеля ≤15 знаков, П-2), `endpoint` в `meta.json`, в ответе, в `share-list` и в строке аудита. Для выбора: `edge-status` — `keys_host` (адрес в ключах как обычно) и `key_choices [{host, kind, default, verdict, users, in_dns}]` — ровно то, что примет `--endpoint` (`export_key_choices_json`: «как обычно» первым, затем домены, затем адреса, замолчавшие — в конце); `user-show` — `key_host`, `key_host_gone`; `status` — `key_hosts` |
| Подпись `vpn://` | с разовым адресом — «имя · AmneziaWG 2.0 · хост»: записи одного человека на разные адреса в приложении Amnezia не сливаются |
| SSH-меню | карточка → «Ключ: QR, файл, ссылка» → «Ключ на другой адрес сервера (разово)» (`_pick_key_address`; пункт есть, когда у человека есть приватный ключ и у сервера есть хост, отличный от его адреса): «как обычно», домены, адреса с вердиктом сторожа и пометкой «нет в A-записях — запасной»; выбранный адрес держится, пока открыт экран ключей (строка «Выдача на адрес … — разово, пока открыт этот экран»), и его берут пункты 1–5; замолчавший адрес выбирается с предупреждением; после выдачи — подсказка, как закрепить |
| Бот | карточка → «🌐 Ключ на другой адрес» → адреса → по профилю: QR .conf, .conf файлом, ключ Amnezia, QR Amnezia, «Скачать файлом по ссылке»; адрес — в подписи ключа и в сообщении раздачи |
| Панель | карточка пользователя → ключ профиля → выбор «Адрес сервера в ключе» (варианты из `key_choices`, слова вердиктов как на Обзоре); смена адреса убирает показанный ключ; скачанный `.conf` — с адресом в имени файла, раздача ссылкой берёт тот же адрес |
| Проверки | `tests/test_actions_dryrun.sh` §7б, `tests/test_wizard_pty.py` (экран ключей), `tests/test_bot_features.py`, `tests/test_admin_features.py` (`KeyEndpointServerTests`, `FrontendKeyAddressTests`), `tests/test_admin_http.py` (`KeyEndpointRoutesTests`) |

Границы, о которых говорить прямо:

* **Сторож разовых ключей не видит.** Людей по адресам он считает только по закреплённому адресу
  (`endpoint_ip`) и по A-записям домена (`ga_edge_users_map`). Пакеты разовых ключей в счётчики адреса
  попадают, а люди — нет: адрес, на который смотрят только разовые ключи, в таблице остаётся «на адрес
  не смотрит ни один ключ» (`unused`), и тревоги `dark` по нему не будет. Кого нужно сторожить на этом
  адресе — закрепить.
* **Одна пара ключей — один пир.** Тот же ключ, включённый одновременно на двух адресах (два устройства
  или две записи в приложении), будет «прыгать»: у пира WireGuard один Endpoint, и сервер отвечает туда,
  откуда пришёл последний пакет. Для двух одновременных устройств — отдельные пользователи.
* **Живьём проверено 25.09.2026** на сервере с тремя IPv4 (почасовой сервер Aeza, «Сайт и VPN на 443»,
  домен с двумя A-записями): ключи на каждый адрес и на домен выданы, клиенты AmneziaWG 2.0 и 3.1
  подключились.

На стенде test1 один адрес. Путь с несколькими адресами проверяется сквозными прогонами с поддельным
