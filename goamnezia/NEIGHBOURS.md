# Соседи по серверу: что goAmnezia pro занимает и что обещает

По образцу `NEIGHBOURS.md` из goDNS; первая версия — 08.09.2026, сверено с кодом 0.5.x 28.09.2026, модуль ядра и MSS — 08.10.2026 (1.0.13, ветка dev). Режимы
называются, как в меню: «Только VPN» (`lite` в `config.json`), «VPN и сайт» (`lite_site`), «Сайт и VPN на 443»
(`pro`); два последних — режимы с сайтом.

## Что занимает goAmnezia

| Ресурс | Значение | Примечание |
|---|---|---|
| UDP-порты | по одному на профиль AmneziaWG: случайный из **1024–9999** (общеизвестные порты пропускаются) или свой; весь низкий диапазон занят — запасной 30000–49999, и меню говорит об этом вслух. В «Сайт и VPN на 443» один профиль (по умолчанию `awg2`) — на **UDP/443** | свободен ли порт, проверяется до установки (предполётная проверка, `docker`, `ss`); занятый порт → предложить другой. UDP/443 держит не больше одного профиля |
| TCP/443 | режимы с сайтом: nginx — сайт-маскировка на домене с Let's Encrypt; пока домена нет или A-запись не разошлась — запасной путь: тот же сайт на IP с самоподписанным сертификатом (`server_name _`, без `default_server`). «Только VPN» — не занят | конфликт с goTelegram Pro и goVLESS Pro на одном сервере — см. ниже |
| TCP/80 | режимы с сайтом: Let's Encrypt HTTP-01 и редирект на HTTPS; на запасном самоподписанном — тот же сайт по HTTP без редиректа | |
| TCP 30000–49999 (случайный) | временная ссылка на файл (`lib/share.sh`): свой HTTPS-слушатель на раздачу, по умолчанию 5 минут, не больше 10 раздач сразу; закрывает порт локальный файрвол — он открывается на время раздачи и закрывается после | в любом режиме; файрвол панели хостера продукт не видит |
| `/opt/goamnezia/tls/` | запасной самоподписанный ключ и сертификат режимов с сайтом (`site.key`, `site.crt`, 0700/0600) | наш каталог, соседи его не читают |
| `127.0.0.1:1985` | веб-панель (`goamnezia-admin.service`); мастер ставит её в любом режиме, в режимах с сайтом — ещё и за nginx на домене по секретному пути | 1984 занят goTelegram |
| `127.0.0.1:1986` | MCP по HTTP (`goamnezia-mcp-http.service`, включается `mcp-http-on`, по умолчанию выключен); в режимах с сайтом — за nginx | |
| `127.0.0.1:1987` | страницы подключения (`goamnezia-pages.service`, `pages.port`) за nginx на `/p-<секрет>/` — только в режимах с сайтом на домене; служба и location появляются с первой страницей и снимаются с последней | |
| TCP `mcp.public_port` и персональные порты доступов | собственный TLS-слушатель MCP на самоподписанном сертификате: публичный порт — только в «Только VPN» (`mcp-http-on --port=N`, по умолчанию прежний или случайный из 1024–9999), персональные порты (`agent-add --port=N`) — в любом режиме; открываются в ufw/iptables модулем | по умолчанию нет |
| `/opt/goamnezia/agents.json` | доступы агентов (секретные пути), 0600 | наш файл |
| Docker | контейнеры `amnezia-awg1`, `amnezia-awg2`, `amnezia-awg3`; сеть `amnezia-dns-net` (`amn0`, `172.29.172.0/24`) | это официальный неймспейс Amnezia, разделяемый с приложением Amnezia и goWARP PRO |
| Каталоги | `/opt/goamnezia*`, `/var/www/goamnezia-site`, `/var/www/goamnezia-acme` (проверки Let's Encrypt), `/run/goamnezia`, `/var/log/goamnezia*`; `/var/lib/goamnezia-netdeps` — только между «Удалить всё» и новой установкой, если в сети профилей жили чужие контейнеры (WRP-06) | |
| systemd | `goamnezia-*`: службы панели, бота, страниц, MCP по HTTP и таймеры; `goamnezia-cert-renew.timer` — только если в системе нет `certbot.timer` | |
| nginx | `sites-available/goamnezia`; хук `/etc/letsencrypt/renewal-hooks/deploy/goamnezia-nginx-reload.sh` | |
| sysctl | `net.ipv4.ip_forward=1` закреплён в `/etc/sysctl.d/99-goamnezia.conf`; `nf_conntrack_max` и сетевые буферы — `sysctl -w` без записи в файл (как в официальном `setup_host_firewall.sh`) | |
| iptables | правила `DOCKER-USER`/`FORWARD` официального скрипта; **DROP ICMP echo не ставим** (опция `drop_icmp`) | |
| iptables в контейнере профиля | изоляция клиентов `FORWARD -i awg0 -o awg0 -j DROP`; с 1.0.13 — подгонка TCP MSS: `mangle FORWARD` по TCP SYN, из туннеля `--set-mss` (MTU − 40, у ip6tables − 60), в туннель `--clamp-mss-to-pmtu` | внутри нашего сетевого пространства; таблицы хоста не трогаются |
| Модуль ядра `amneziawg` (только по выбору человека, с 1.0.13) | DKMS-модуль `amneziawg/3.1.20260906` с меткой `+kaskad-k31.1`: исходники `/usr/src/amneziawg-3.1.20260906/` (метка `.goamnezia`), хуки `/etc/kernel/postinst.d/zz-goamnezia-amneziawg` и `/etc/kernel/header_postinst.d/zz-goamnezia-amneziawg` (журнал `/var/log/goamnezia-kmod-hook.log`), `/etc/modules-load.d/amneziawg.conf` — только если файла не было; пакеты `dkms gcc make patch gcc-NN linux-headers-<ядро>` (список — в `state/kmod.json`). В `dkms.conf` нет `AUTOINSTALL` и `REMAKE_INITRD` | по умолчанию ничего этого нет: профили работают программой `amneziawg-go`. «Удалить модуль» и «Удалить всё» убирают модуль, исходники и хуки; пакеты — командой, которую называет продукт |

## Что goAmnezia обещает не трогать

- Порты соседей: 1984 (goTelegram), 40000 (goWARP SOCKS), 5199/853/4443 (goDNS), 10808/10851
  (egress goVLESS/goKaskad), 2053/54321 (панель 3x-ui), 22.
- Таблицы маршрутов и fwmark соседей: 256–356 (goKaskad), 7788 (goTelegram WARP); интерфейсы
  `gtwarp`, `kawg*`, `warp`.
- Внутри контейнеров `amnezia-awg*`: интерфейс `warp`, каталоги `/opt/warp/` и `/opt/warp-tools/`
  goWARP PRO и его блок `# --- WARP-MANAGER BEGIN/END ---` в `start.sh`. Мы их не пишем, а переносим
  через пересоздание контейнера (с 29.09.2026, WRP-01): перед сносом `/opt/warp/` и `/opt/warp-tools/usr/`
  снимаются из самого контейнера в `state/` (там свежий ключ WARP), после подъёма возвращаются
  (инструменты — исполняемыми), блок переезжает и в `start.sh` нового релиза при `upstream-update`, а
  затем зовётся сторож самого goWARP `gowarp-awg-watch --once`. MTU = 1280 интерфейса `warp` живёт в
  `/opt/warp/warp.conf` — его мы не трогаем; строку MTU в `awg0.conf` пишем из настроек профиля.
- Контейнеры в сети профиля (`docker run --network container:amnezia-awgN …`, например `warp-socks` с
  прокси на 1080): после пересоздания контейнера профиля пересоздаём их из их же `docker inspect` с той же
  конфигурацией и сетью нового контейнера, после его перезапуска — перезапускаем (Docker хранит в
  `NetworkMode` ID хозяина, а сеть хозяина создаётся заново при каждом старте). Удаление профиля называет
  соседей, которые остаются без сети; сами их не удаляем. «Удалить всё» сохраняет запись о них в
  `/var/lib/goamnezia-netdeps`, и новая установка goAmnezia возвращает их в сеть нового контейнера профиля
  сама (с 03.10.2026, WRP-06). Сосед в сети пропавшего контейнера, о котором записи нет (снос версией до
  этого, `docker rm` руками), не трогаем: о нём говорят конец установки, «Диагностика» и сторож (один раз).
- WARP goWARP PRO живёт внутри наших контейнеров, поэтому «Удалить всё» уносит и его; новая установка его не
  восстанавливает (ключ мог быть перевыпущен), а в конце говорит: goWARP стоит, WARP в новых контейнерах нет —
  `gowarp` → пункт 1 «Установить / переустановить WARP».
- Контейнеры, которых нет в нашем `config.json` (например, `amnezia-awg` legacy, поставленный
  приложением) — только читаем при `import-scan`, меняем только после `import-adopt`.
- Чужие логи в `/var/log`: бюджет логов чистит только по маске `goamnezia*`.
- Модуль ядра соседа Kaskad (`amneziawg` с меткой `+kaskad-k31` или `+goamnezia-k31`): берём как есть, не пересобираем и не выгружаем; его исходники в `/usr/src` и записи DKMS не трогаем (чужие исходники без нашей метки — отказ `kmod_foreign_src`). «Удалить модуль» и «Удалить всё», пока Kaskad им пользуется (`awg-kmod.json` или интерфейсы `kgw-awg*`, `kawg*`), модуль оставляют и убирают только наши хуки. Правило modprobe.d `install amneziawg /bin/false` не пишем никогда — оно сломало бы Kaskad.
- Модуль ядра, которого мы не ставили и который без исправлений (стоковый `amneziawg` из пакета или руками): не трогаем и не перезаписываем — говорим о нём (`status.kmod.warn`, шапка меню, бот, панель), а установка отвечает `kmod_foreign`.

## Правила именования контейнеров

- Приложение Amnezia разбирает любой контейнер, в имени которого есть подстрока `amnezia`,
  и **молча пропускает незнакомые имена**; goWARP PRO работает с `^amnezia-awg[0-9]*$`.
- Поэтому наши AWG-контейнеры называются `amnezia-awg<линейка>`: приложение видит только
  `amnezia-awg2`, goWARP видит все три. Другие продукты серии не должны создавать контейнеры
  с подстрокой `amnezia` в имени.

## Сосуществование с продуктами серии

| Сосед | Что делать |
|---|---|
| goTelegram Pro (TCP/443 у telemt, nginx на 8443) | ставить goAmnezia в «Только VPN»; сайт для домена goAmnezia на том же 443 требует shared-443 у goTelegram — отдельная задача |
| goVLESS Pro (TCP/443 занят) | goAmnezia в «Только VPN»: TCP/443 занят соседом, а UDP/443 свободен и может быть у `awg2` |
| goWARP PRO | ставится до или после; находит наши `amnezia-awg1/2/3` по маске и их `awg0.conf`. Пересоздание профиля (смена порта, линия на 443, «Поднять заново», `core-update`, `upstream-update`, восстановление из копии) переносит его WARP и соседей в сети профиля сами — ручное восстановление goWARP не нужно. Правки на стороне goWARP — в отчёте совместимости 29.09.2026 |
| goDNS | конфликтов нет; можно указать его как DNS клиентов (`dns-set`) |
| goKaskad (Kaskad Pro) | модуль ядра AmneziaWG общий: годный модуль Kaskad (метка `+kaskad-k31`) goAmnezia берёт как есть, наш (`+kaskad-k31.1` — тот же набор исправлений) годится Kaskad. Кто поставил — тот и пересобирает (`state/kmod.json` → `owner`); удаляя, goAmnezia оставляет модуль, пока им пользуется Kaskad |
| goInstaller | знает goAmnezia (id `goamnezia`, режимы `lite` / `lite_site` / `pro`, версия из `lib/common.sh`); его таблица портов должна совпадать с этим файлом |
