# Подписка: постоянная ссылка на человека (договор)

Решение владельца 03.10.2026: «приём ссылки vpn://, чтобы работало и для 1.5, и для 2, и для 3.1, формат — как
забирает mihomo». Исследование — `.claude/work/subscription/RESEARCH.md`. Код: `lib/subs.sh` (ядро),
`lib/pages_server.py` (отдаёт), `lib/awgkeys.py` (профиль mihomo), `lib/website.sh` (локация nginx).

## 1. Адрес и суффиксы

```
https://<домен>/s-<секрет>/<суффикс>
```

- Секрет — 32 случайных байта, 43 знака base64url (256 бит), один на человека на все линии и форматы.
- Подписка создаётся по просьбе («Создать подписку») и вместе со страницей подключения (решение владельца
  04.10.2026: `page-create` заводит её, если её ещё нет и сайт на домене с доверенным сертификатом; существующим людям
  без новой страницы сама не появляется), живёт, пока жив человек. Новый адрес — только «Перевыпустить подписку»;
  перевыпуск ключа, смена порта, параметров, MTU и адреса сервера меняют тело, не адрес. На странице подключения
  подписка — вкладкой «Подписка» (docs/CLIENTS.md §7): адрес — `POST sub.json` по первому нажатию «QR-код» или
  «Скопировать».
- Суффикс — `<какие линии>.<формат>` (§2), белый список (его же держит локация nginx, служба проверяет ещё раз):

| Суффикс | Тело | Для кого |
|---|---|---|
| `all.yaml` | профиль mihomo со всеми ключами человека (§3; с 1.0.13 — и на двух профилях одной линии, имена уникальны: «AmneziaWG 3.1 · порт 6714», DUP-LINE-01) | Clash Verge Rev, FlClash, Mihomo Party, Clash Meta for Android; OpenClash/nikki |
| `awg10.conf`, `awg15.conf`, `awg20.conf`, `awg31.conf` | `.conf` линии — ровно `user-key --format=conf` | роутер (Keenetic 5.2 `wireguard import`, OpenWrt), WG Tunnel, INCY, AmneziaWG; AWG Manager — текстом (страница: «Скопировать» кладёт сам `.conf`) |
| `awg10.vpn` … `awg31.vpn` | одна строка `vpn://` линии (кодек ядра не меняется) | приложение Amnezia — открыть и скопировать; страница подключения — «Скопировать» кладёт сам ключ (AmneziaVPN, DefaultVPN, AWG Manager, §9) |
| `all.vpn` | строки `vpn://` всех линий, 3.1 → 2.0 → 1.5 → 1.0 | импорт пула в egress серии |
| `all.txt` | подписка incy: по строке на ключ (с 1.0.13 — все ключи, и две 3.1 тоже; имя такой линии — с портом), 3.1 → 2.0 → 1.5 → 1.0, `amneziawg://<base64url .conf линии без «=»>#<имя>` — .conf байт в байт как у `awgNN.conf`, имя «AmneziaWG 3.1» в процентной кодировке UTF-8 (docs.incy.cc, «Multiple AmneziaWG servers in one subscription») | incy (iPhone и iPad, Android, Android TV, Apple TV, macOS — с пометками каталога); добавить — `incy://add/<адрес>`, адрес как есть, или голый адрес сканером внутри incy; AWG Manager — «Подписка по URL» (поддержку добавляет разработчик) |
| `mihomo.yaml` | прежнее имя `all.yaml` — тот же ответ (уже выдано людям; в списках не показывается) | — |
| `awgv15.*`, `awgv2.*`, `awgv3.*` | синонимы владельца для `awg15`, `awg20`, `awg31` (`.conf` и `.vpn`) | — |

Суффикс выбирает **линию**, а не профиль: у человека берётся первый установленный профиль этой линии в порядке
продукта (awg3 → awg2 → awg1) с ключом на сервере; линия — `ga_profile_line`, та же, что подписывает ключ в
`user-key`. Ключ из приложения Amnezia (`has_key: false`) и выключенный пир не отдаются; такой линии нет — 404.
Голый `/s-<секрет>/` и любой другой путь под `/s-<43>` — 404 сайта без строки в журнале (§6).

## 2. Каталог форматов

Имя адреса — `<какие линии>.<формат>`: `all` — все линии человека, `awg31`, `awg20`, `awg15`, `awg10` — одна линия.

| Формат | Что внутри | Все линии | Одна линия | Кто берёт | Обновляется сам |
|---|---|---|---|---|---|
| `.yaml` | профиль Clash (mihomo) с группой «Auto» | `all.yaml` | — | FlClash, Clash Meta, Clash Verge Rev, Clash Party | да |
| `.txt` | ссылки `amneziawg://` | `all.txt` | — | incy; AWG Manager | да |
| `.vpn` | ключи Amnezia `vpn://` | `all.vpn` | `awgNN.vpn` | AmneziaVPN, DefaultVPN, AWG Manager (вручную); goVLESS, Kaskad, goTelegram (импорт) | нет |
| `.conf` | файл AmneziaWG | — | `awgNN.conf` | Keenetic 5.2, WG Tunnel, AmneziaWG, AWG Manager | нет, разово |

Синонимы рабочие, но нигде не показываются — ни в `urls` и `clients` ответа моста, ни на странице: `mihomo.yaml` —
прежнее имя `all.yaml` (уже выдано людям, ответ тот же байт в байт), `awgv15`, `awgv2`, `awgv3` — синонимы владельца
для `awg15`, `awg20`, `awg31` (`.conf` и `.vpn`).

**Поле `clients`** — в ответах `sub-create`, `sub-show` и `sub-rotate` рядом с `base_url` и `urls`: кто какой адрес
берёт. По нему адреса показывают панель, мини-апп, бот и SSH — форму менять только вместе с ними. Источник — поле
`subscription` каталога `lib/clients.json` (docs/CLIENTS.md §2) и запись продуктов серии (`GA_SUBS_EGRESS` в
`lib/subs.sh`); собирает список `ga_subs_clients_json`.

```
"clients": [
  {"id": "flclash",                      // у многоформатного — <app>-<формат>: awgm-txt, awgm-vpn, awgm-conf
   "app": "flclash",                     // id приложения — для группировки (у одноформатных = id)
   "name": "FlClash", "name_en": "",
   "variant": "",                        // подпись формата у многоформатного («Все линии .txt», «Ключ vpn://», …)
   "group": "auto",                      // auto — «Обновляется сам», once — «Разово»
   "format": "yaml",                     // yaml | txt | vpn | conf
   "platforms": ["android", "windows", "macos", "linux"],   // ключи платформ каталога
   "update_hours": 24,                   // у auto: 0 — интервал из заголовка сервера; у once — 0
   "official": false, "recommended": true,
   "hint": {"ru": "…", "en": "…"},       // {minutes} уже подставлен
   "items": [
     {"line": "",                        // "" — все линии; иначе "3.1" | "2.0" | "1.5" | "1.0"
      "suffix": "all.yaml", "url": "https://<домен>/s-<секрет>/all.yaml",
      "deeplink": "flclash://install-config?url=https%3A%2F%2F…",   // готовая ссылка или ""
      "command": "",                     // готовая команда (роутер) или ""
      "copy": "url",                     // что копирует «Скопировать»: url | key (сам ключ линии) | command
      "qr": "url",                       // что кодировать в QR: url | deeplink | key (ключ этой линии) | ""
      "qr_alt": "",                      // второй QR рядом: url (голый адрес) | ""
      "key_format": ""}                  // vpn | conf — при qr = key или copy = key
   ]}
]
```

Поле `short_url` в items зарезервировано под короткую ссылку (отдельная задача) и пока не заполняется.

- FlClash, Clash Meta for Android, Clash Verge Rev, Clash Party — auto, `yaml`, item `all.yaml`; QR — адрес у
  FlClash, у остальных нет (у Clash Meta сканера нет, десктопным он не нужен); «Открыть в …» — install-config, как на
  странице (адрес и подпись в процентной кодировке, `{minutes}` — интервал сервера в минутах);
- incy — auto, `txt`, item `all.txt`, QR — ссылка `incy://add/<адрес>` (адрес как есть; её читает обычная камера
  телефона), `qr_alt: url` — второй QR с голым адресом (его берёт сканер внутри incy);
- AWG Manager — три записи с `app: awgm` (решение владельца 04.10.2026): `awgm-txt` — auto, `txt`, `all.txt`
  («Подписка по URL»); `awgm-vpn` — once, `vpn`, items по линиям, `copy: key` (сам ключ `vpn://`); `awgm-conf` — once,
  `conf`, items по линиям, `copy: key`, `key_format: conf` (текст `.conf`); QR нет — роутеру он не нужен;
- AmneziaVPN, DefaultVPN — once, `vpn`, items `awgNN.vpn` по линиям, которые приложение берёт, 3.1 → 2.0 → 1.5 → 1.0;
  QR — ключ, `copy: key`, `key_format: vpn`;
- AmneziaWG — once, `conf`, items `awgNN.conf` по линиям; QR — ключ, `key_format: conf`;
- Keenetic — once, `conf`, items только линий каталога (2.0, 1.5, 1.0); QR нет; `command` —
  `interface Wireguard9 wireguard import <адрес>` (номер интерфейса — как на странице), `copy: command`;
- WG Tunnel — once, `conf`, items по линиям; QR — ключ, `key_format: conf`; `deeplink` — `wg://<хост>/<путь>`
  (WG Tunnel скачивает с `https://<хост>/<путь>`);
- продукты серии — `id: egress`, «goVLESS, Kaskad, goTelegram», once, `vpn`, item `all.vpn`, QR нет, последними.

Платформы клиента — устройства вкладки «Подписка» страницы (все устройства: iPhone и iPad, Android, Android TV, Apple
TV, Windows, macOS, Linux, роутер; AmneziaVPN и AmneziaWG — без телевизоров, ключ из буфера там не вставить), на
которых приложение берёт хоть одну линию человека. У разового
items — линии из `subscription.lines` каталога, которые у человека есть (ключ на сервере) и которые приложение хоть на
одной своей платформе не помечает `no`. `recommended` — приложение «рекомендуем» хоть на одной своей платформе (поле
`subscription.recommended` каталога: iPhone, Android TV и Apple TV — incy, Android — FlClash, компьютеры — Clash Verge
Rev, роутер — Keenetic). Порядок — сначала auto, потом once (`.yaml`, `.txt`, `.vpn`, `.conf`; внутри — как в каталоге,
варианты одного приложения — в порядке каталога), продукты серии — последними. Клиента без items для линий человека в списке нет; без домена (пауза) или без ключей —
`clients: []`. Адрес с секретом идёт в jq окружением, не аргументом (SEC46-02).

## 3. all.yaml — профиль mihomo

`awgkeys.mihomo_proxy(line, data, name)` — из тех же данных, что `render_conf`; служба строит его из `.conf` линии,
полученного у моста (`awgkeys.conf_client_data`), — второго пути к ключам нет. YAML пишется без библиотек
(`mihomo_profile`): строки в двойных кавычках с экранированием, управляющие из подписи выброшены.

```yaml
mixed-port: 7890            # клиенты-оболочки ставят свои; голому ядру — локальный порт
allow-lan: false
mode: rule
log-level: warning
proxies:
  - name: "<подпись> · AmneziaWG 3.1"
    type: "wireguard"
    server: "<домен или IP из Endpoint>"
    port: <порт профиля>
    ip: "<адрес человека>"
    private-key / public-key / pre-shared-key
    allowed-ips: [...]
    udp: true
    mtu: <MTU профиля>
    persistent-keepalive: <целое; у 3.1 — нижняя граница диапазона>
    remote-dns-resolve: true    # только когда DNS — голые IP
    dns: [...]
    amnezia-wg-option: {...}
proxy-groups:
  - {name: "goAmnezia", type: select, proxies: ["Auto", все линии]}
  - {name: "Auto", type: fallback, url: "http://1.1.1.1/cdn-cgi/trace", interval: 300, proxies: [все линии]}
rules:
  - "MATCH,goAmnezia"
```

«Auto» (с 04.10.2026, линий больше одной) — приложение выбирает линию само: первая живая в порядке 3.1 → 2.0 → 1.5 →
1.0 (проверка доступности через саму линию раз в 5 минут — по голому IP, без DNS: первый DNS-запрос через только что
поднятый туннель 3.1 теряется, и проверка по имени сразу после запуска уводила «Auto» на 2.0; ответ годится любой, 1.1.1.1
по http отвечает 301). Ядро, которое 3.1 ещё не умеет, уходит на 2.0 само; руками
линию по-прежнему можно выбрать в группе goAmnezia. У профиля из одной линии группы «Auto» нет.

Поля `amnezia-wg-option` по линиям (wiki.metacubex.one `config/proxies/wg`, `adapter/outbound/wireguard.go`; образец —
3X-UI `buildAmneziaWGProxy`):

| Линия | Поля | mihomo |
|---|---|---|
| 1.0 | `jc`, `jmin`, `jmax`, `s1`, `s2` (целые), `h1`–`h4` (строки) | ≥ 1.18.9 |
| 1.5 | + `i1`–`i5` | ≥ 1.19.13 |
| 2.0 | + `s3`, `s4`, диапазоны в `h1`–`h4` | ≥ 1.19.14 (≥ 1.19.28 — без падения на большом `s4`) |
| 3.1 | `version: 3` + `header-protection-key` (base64), `content-padding-addition`, `rekey-after-time`, `rekey-timeout`, `reject-after-time`, `keepalive-timeout`, `max-handshake-attempts` (строки, диапазоны), `random-trailers`, `disable-cookies` (да/нет) | ≥ 1.19.31 (3.x с 1.19.30, исправления — 1.19.31) |

`version: 3` — только у линии 3.1: без поля mihomo берёт реализацию 1.x/2.0.

## 4. Заголовки ответа 200

- `Content-Type`: `text/yaml; charset=utf-8` (mihomo), `text/plain; charset=utf-8` (остальное).
- `Content-Disposition`: `.conf` — `attachment; filename="anna-2_0.conf"` (Keenetic берёт только `.conf`; имя — по
  `ga_key_file_base`, как у страницы и `user-key`: не длиннее 15 знаков до расширения, Н-2);
  `.vpn` — `inline; filename="anna-2_0.txt"`; `all.txt` — `inline; filename="<имя>-all.txt"`, `all.vpn` — `inline; filename="<имя>-all-vpn.txt"`; mihomo —
  `attachment; filename="<имя>.yaml"; filename*=UTF-8''<подпись>.yaml` (Clash Verge Rev берёт имя профиля из
  `filename*`). Имя человека — только здесь, не в пути. Браузеру (`Accept: text/html`) по короткой ссылке (§11.2)
  профиль mihomo — текстом: `text/plain; charset=utf-8` и `inline` с тем же именем файла; тело то же, приложениям и
  полному адресу — как выше.
- `Profile-Title: base64:<подпись>` (у линии — «<подпись> · AmneziaWG 2.0»), `Profile-Update-Interval: 12`
  (`subs.update_interval` в config.json, 1–168).
- `Subscription-Userinfo: upload=<rx>; download=<tx>; total=<лимит или 0>; expire=<срок в секундах или 0>` — из users.json.
- Защитные: `Cache-Control: no-store, no-cache, must-revalidate, private`, `Pragma: no-cache`, `X-Content-Type-Options:
  nosniff`, `X-Frame-Options: DENY`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`,
  `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; sandbox`, `Server: nginx`; HSTS — nginx.

## 5. Состояния

| Событие | Адрес | Ответ |
|---|---|---|
| Перевыпуск ключа, смена порта, параметров, MTU, адреса | тот же | новое тело |
| Человек выключен (руками, лимит, срок) | тот же | 404 по всем суффиксам — клиент и роутер оставят прежний конфиг; включили — снова 200 |
| Удалён (и массово) | секрет стёрт под тем же замком (`_users_del_locked` → `_subs_revoke_locked`) | 404; тёзка ключей не получит |
| Владельца нет (удалён прежней версией, тёзка) | сторож тика снимает (`owner_gone`) | 404 сразу (метка `user_created`) |
| «Перевыпустить подписку» | новый | прежний — 404 сразу, новый — 200 сразу |
| «Отозвать страницу» с галочкой «Перевыпустить и подписку» (`page-revoke --sub on`; галочка есть, если у пользователя подписка есть сейчас — страница отдаёт её адрес на лету; включена, если подписку завела эта страница — `subscription: created` в её `meta.json`; агентам MCP `sub` не публикуется) | новый | как у «Перевыпустить подписку»: страница отдавала и адрес подписки (B2-2/A2-4, 16.10) |
| «Отозвать страницу» без галочки | тот же | 200: отзыв страницы подписку не трогает |
| «Отозвать подписку» | нет | 404 |
| Смена домена | хост — нынешний домен, путь тот же | — |
| Сайт ушёл с домена (Lite, самоподписанный) | пауза: маршрут снят, секреты хранятся | 404; вернулся домен — тот же адрес ожил (тик) |
| Без домена создать | — | `subs_need_domain` |
| Робот превью мессенджера (Telegram, WhatsApp, VK…) | — | 404, забором не считается |
| Мост занят | — | 503 с `Retry-After` |

## 6. Безопасность

- nginx: локация с белым списком, глушилка `^/s-<43>` для всего остального, `access_log off` и
  `error_log /dev/null crit` во всех блоках, 404/502/504 → `@ga_subs_down` (заголовки 404 сайта),
  `limit_req zone=goamnezia_subs` (1 r/s, burst 10), `limit_conn 4`, отказы — 404. Маршрут к службе — только вариант
  vhost на Let's Encrypt. Глушилка секретных путей (одна на `/p-`, `/s-`, `/a-`, `/r-`, `/d-` и путь панели,
  `_ga_site_secret_paths_block`) стоит в vhost всегда, в обоих вариантах и без единой подписки: на 443 — 404 сайта,
  на 80 — тот же ответ, что у любого пути там (в Pro — 301 на HTTPS, в Lite + сайт — 404). Так адрес не ложится в
  журнал ни после отзыва последней подписки, ни на паузе, ни набранным в роутере как `http://…`. Новый суффикс
  белого списка (`all.txt`) доезжает до поставленных серверов сам: vhost из шаблона пересобирает шаг миграции
  `_migrate_site_vhost` — при обновлении версии (1.0.8 → 1.0.9) и при новом коде той же версии по отпечатку (UP-7).
- Служба: секрет ищется по sha256 в памяти и сверяется `compare_digest`, затем с файлом (перевыпуск и отзыв — сразу);
  промахи — тот же бан, что у страниц (10 за 5 минут → 15 минут 404); путь в журнал не пишется (маска `s-***`).
- Учёт без адреса: `state.json` подписки — `fetches`, `last_fetch`, `last_suffix`, `last_client` (семейство по
  User-Agent одним словом); перевыпуск счёт обнуляет, а сколько раз и когда последний раз забирали прежний адрес,
  оставляет в `meta.json` — `prev_fetches`, `prev_last_fetch` (Н-1: след утечки в карточке; прежний адрес не
  забирали ни разу — след прошлого перевыпуска остаётся, второй перевыпуск подряд не затирает его нулём, П-4; поэтому в панели, боте и SSH строка «Прежний адрес
  забирали: N · когда» — это последний адрес до перевыпуска, который успели забрать; в панели это сказано в подсказке, П-6-2); `sub-fetch` в аудит раз в час. `auto_fetches` (R-1, 15.10) — заборы подписки, которая
  обновляется сама: `all.yaml`/`mihomo.yaml`/`all.txt` приложением — не браузером (и не «Показать содержимое»
  короткой ссылки), не curl/wget; ключ одной линии `awgNN.*` не в счёт (после смены линии он 404), `all.vpn` — тоже:
  это разовый импорт пула продуктом серии, сам он не обновляется (N-1, 15.10). По нему ядро решает,
  кому после смены параметров «обновится сама» (`ga_amn_s4_audience`); у `state.json` прежней службы — по последнему забору.
- Перевыпуск (`sub-rotate`, A3-2, 17.10) начинает счёт заново: `state.json` — `{"fetches": 0, "auto_fetches": 0}`
  без `last_*` (прежний адрес мёртв, его приложению — 404, «обновится сама» про него — неправда). Забор прежнего адреса,
  закончившийся уже после перевыпуска, служба не записывает (секрет на диске сменился). Карточка в панели — «перевыпущена
  <когда>» рядом с датой, бот и SSH — строкой «Перевыпущена».
- Секрет — 0600 в каталоге 0700, в аудит и `sub-list` не попадает; адрес идёт в jq окружением (SEC46-02).
- ИИ-агентам адресов нет: у `sub-create`, `sub-show`, `sub-rotate`, `sub-revoke` `"mcp": null`, агенту — `sub_list`.

## 7. Хранение и бэкап

`<GOAMNEZIA_DIR>/subs/<имя>/{meta.json, secret, state.json, state.lock}`; `meta.json` — `user`, `user_created`, `created`, `rotated`,
`generation`, после перевыпуска с заборами — `prev_fetches`, `prev_last_fetch` (§6). `state.lock` (0600, пустой) — замок
заборов `flock` (Н-5, 17.10): служба берёт его на проверку секрета и запись забора (`_state_lock` в `lib/pages_server.py`),
ядро — на перевыпуск (`_ga_subs_with_state_lock` в `lib/subs.sh`), чтобы счёт прежнего адреса не лёг поверх обнулённого;
права 0600 ставятся при каждом взятии (П-5-2), файла нет — его создаёт первый, кто берёт замок. Каталог `subs/` уходит в бэкап; восстановление кладёт его только на сервер, где подписок ещё не было
(переезд) — поверх действующих копия не возвращает перевыпущенный или отозванный адрес (`kept_current: subs`).
Служба — общая со страницами (`goamnezia-pages`), снимается, когда нет ни маршрута страниц, ни маршрута подписок;
флаг маршрута — `site.subs_location`; обвязку по факту чинит `watch-tick` (блок `subs` в ответе).

## 11. Короткие ссылки (2FA через Telegram-бота)

Решения владельца 04.10.2026 (`.claude/work/short-links/SPEC.md`). **Короткие ссылки работают только с 2FA через
Telegram-бота**: бот не настроен (в `.env` бота нет токена или ни одного администратора — то же правило, что
`_bot_has_admins`) — кнопки «Короткая ссылка» нет нигде, `short-ensure` отвечает `short_need_bot`, а `/<КОД>` — 404.
Код: `lib/shortlinks.py` (одна логика у службы и моста), обёртки `short-*` в `lib/subs.sh`, маршрут и страница
подтверждения — `lib/pages_server.py`, локация — `lib/website.sh`.

### 11.1. Код

- Адрес — `https://<домен>/<КОД>`: 8 знаков из алфавита в 32 знака — `0–9` и `A–Z` без `I`, `L`, `O`, `U`, и в
  коде всегда **не меньше двух цифр и не меньше двух букв**. Вариантов — **843 227 123 200** (сумма C(8, d)·10^d·22^(8−d)
  по числу цифр d = 2…6; 76,7 % от 32⁸, около 39,6 бита). Генератор — `secrets.randbelow(32)`: криптостойкий и без
  смещения по модулю; код не по правилу отбрасывается и тянется заново, поэтому каждый допустимый код равновероятен.
- При показе в коде 1–3 тире в случайных промежутках (`NV43-9BKX`); показ хранится и одинаков везде. При вводе тире,
  пробелы и регистр не важны, `O` читается как `0`, `I` и `L` — как `1`.
- **Что считается кодом.** Только путь, где после нормализации ровно 8 знаков алфавита и хотя бы одна цифра набрана
  цифрой (`NV43-9BKX`, `nv43 9bkx`); даты и номера, где букв меньше двух (`/2024-10-01`, `/12345678`; `O`, `I`, `L`,
  ставшие цифрами, — не буквы), — тоже не код, а честный ввод выданного кода (в нём всегда ≥2 букв) это не задевает. Замены `O → 0`, `I`/`L → 1` тут не в счёт: путь из одних букв — слово сайта, а не
  код, даже если после замены в нём появились цифры (`/download` → `D0WN10AD`, `/contacts`, `/wp-admin`,
  `/phpmyadmin`). Такой путь и путь не из алфавита (`U`, точка, другая длина) — обычный 404 сайта: без балла, без
  тревоги и без строки в журнале службы; сканеры по словам ничего не набирают.
- Код — на пару «подписка + суффикс» (`all.yaml`, `all.txt`, `all.vpn`, `awgNN.vpn`, `awgNN.conf`; синонимов нет),
  создаётся при первом показе (кнопка страницы, панель, бот, SSH — `short-ensure`) и живёт, пока его не заменят.
  Перевыпуск и отзыв подписки, удаление человека (и массовое) гасят все её коды: они уходят в кладбище на 30 дней, а
  ждущие по ним запросы закрываются истёкшими. Код прежнего поколения подписки мёртв и без погашения.
- Хранение: `subs/<имя>/short.json` (0600) — суффикс → `{code, display, created, generation}`;
  `subs/.short/state.json` (0600, каталог 0700, запись под `flock` на `subs/.short/.lock`) — кладбище, баны и
  баллы, заморозки, доверенные адреса, запросы и счёт промахов; всё переживает перезапуск службы и уходит в бэкап
  вместе с `subs/`.

### 11.2. Вход — как у Google

1. Запрос `/<КОД>` с адреса, которому этот код ещё не доверен: **браузеру** (`Accept: text/html`) — страница
   подтверждения: двузначное число 10–99, «Назовите администратору число», ожидание 5 минут с опросом статуса;
   **приложению** — 404 (заберёт подписку после подтверждения из браузера той же сети).
2. Всем администраторам — событие `short_confirm` (бот: «Вход по короткой ссылке» — подпись человека, устройство по
   User-Agent, IP, город и страна, если на сервере есть GeoIP: `mmdblookup` с базой GeoLite2/DB-IP или
   `geoiplookup`), 12 кнопок: две строки по 5 чисел (верное и 9 случайных разных, перемешаны), «Это не я» и
   «↻ Заменить ссылку».
3. **Верное число** — адрес (IPv4 целиком, у IPv6 — подсеть /64) открыт для этого кода на 15 минут; первый успешный
   забор делает его доверенным на 30 дней, окно сдвигается с каждым забором. Доверенный забор отдаёт то же, что полный
   адрес этого суффикса: тело, заголовки подписки, учёт заборов.
   **После «Вход подтверждён» страница выдаёт этому устройству полную ссылку подписки** (SHORT-03, владелец 05.10):
   телефон ходит между сетями, а доверие короткой ссылки привязано к адресу сети, — приложение с полной ссылкой
   обновляется из любой сети без подтверждений. Сама страница никуда не переходит (автопереход SHORT-02 отменён): итог —
   «Добавьте в приложение полную ссылку — она работает из любой сети без подтверждения», строка «Телевизору и роутеру
   можно оставить короткую: добавьте её в течение 15 минут — дальше из этой сети она продлевается с каждым обновлением»
   и кнопка «Показать полную ссылку». По нажатию человека (не из скрипта) — блок полной ссылки: адрес и «Скопировать»,
   QR адреса для телефона, «Открыть в …» — приложения каталога с подпиской этого формата, которые стоят на устройстве
   браузера (по User-Agent) и открываются по deeplink (`all.txt` — incy, `all.yaml` — FlClash, Clash Meta, Clash Verge
   Rev, Clash Party, `.conf` — WG Tunnel), и команда роутера (Keenetic) — всегда: у роутера браузера нет. `awgNN.vpn` —
   сам ключ `vpn://` с «Скопировать ключ» и его QR (AmneziaVPN по ссылке не обновляется), адреса нет; `.conf` — ещё
   «Скачать файл». «Показать содержимое» — тот же короткий адрес с меткой `?go=<запрос>`, только по нажатию: открытый
   или доверенный адрес получает то же, что приложение (`all.yaml` и `all.txt` — текстом (§4), `.conf` — файлом,
   `.vpn` — текстом), и это первый забор — адрес становится доверенным на 30 дней.
   **Окно выдачи** — 15 минут после решения (`FULL_TTL`, как окно первого забора): человек берёт ссылку сразу, а
   забытая открытой вкладка (общий компьютер, телевизор) секрет больше не отдаст. Ссылку получает только страница,
   начавшая вход: номер подтверждённого запроса и одноразовое значение её отрисовки (§11.7); адрес сети при выдаче не
   проверяется — телефон, сменивший сеть после подтверждения, свою ссылку получит. Перезагрузка (адрес вкладки после
   итога — `?r=<запрос>`) показывает тот же итог; вкладка без своего значения (адрес страницы открыли на другом
   устройстве или в другой сети) и нажатие после окна — «Нужна новая проверка», без нового запроса в бот. Без
   JavaScript полной ссылки нет — страница пишет об этом; «Показать содержимое» работает и без него.
   **Без петель:** по метке `?go=` служба нового запроса в бот не создаёт: адрес, который не открыт и не доверен
   (браузер сменил IPv4 ↔ IPv6, другая сеть, время вышло), получает «Нужна новая проверка» и кнопку «Новый запрос» —
   обычный адрес без метки, новое число — только по нажатию. Метка в счёт, только если это подтверждённый вход по этому
   самому коду (номер запроса знает лишь его страница; решённый запрос помнится час): выдуманная, чужая или забытая
   метка ничего не меняет — живой код не проверить молча, мимо запроса в бот.
4. **Неверное число** — запрос отклонён. Три неверных числа подряд по коду — код заморожен на сутки, следующие три — на
   месяц: новых входов нет, доверенные адреса забирают как прежде, замена разрешена. Верное число серию обнуляет.
5. **«Это не я»** — запрос отклонён, адрес закрыт для коротких ссылок по лестнице банов (§11.4).
6. **«↻ Заменить ссылку»** — запрос отклонён, старый код — в кладбище на 30 дней, выдаётся новый (администратору — в
   ответе `short-decide`; странице входа — нет: её мог открыть чужой).
7. Решает первый нажавший; остальным — `short_decided {request, status, by}`, сообщение обновляется.
8. На код одновременно не больше одного ожидающего запроса и не больше 5 новых в час; истечение пяти минут отказом не
   считается (событие `short_decided` со статусом `expired`).

Адрес клиента — `X-Real-IP` от nginx, и только с `127.0.0.1`.

### 11.3. Замена — кнопка ↻

Кнопка стоит рядом с короткой ссылкой на странице человека (вкладка «Подписка»), в панели и в SSH. Любая замена идёт
через бот: у просящего на экране число, в боте «Замена короткой ссылки» — 11 кнопок (10 чисел и «Это не я»). Верное
число выдаёт новый код, старый — в кладбище на 30 дней. «Это не я» у замены со страницы закрывает её адрес по
лестнице банов; у замены из панели, SSH и бота адреса нет. Ожидающий запрос по этому коду — чужой вход или прежняя
замена — администратору не помеха: замена из панели, SSH или бота закрывает его как «заменён» (`short_decided`,
`swapped`, `by` — кто заменил; страница прежней замены просит обновиться после подтверждения) и идёт дальше; со
страницы — ждать, пока запрос решат или он истечёт (`short_pending`).

### 11.4. Баны за подбор

- **Неверный код** — путь, который считается кодом (§11.1), но такого кода нет и он не в кладбище. **Балл** — один
  новый неверный код с адреса; повтор того же кода (в любом виде), стук по кладбищу, слова сайта, даты и номера балла
  не дают — старый клиент и сканер не банятся.
- **Лестница:** три балла подряд без верного кода между ними — бан адреса на сутки; следующие три — на месяц, дальше
  снова на месяц. Адрес — IPv4 целиком, у IPv6 — подсеть /64.
- Бан закрывает **только короткие ссылки**: полные ссылки, страницы и VPN работают. **Свой клиент** — код, который с
  этого адреса уже успешно забирали, работает и во время бана (соседи за общим IP оператора).
- Снять бан и заморозку — в боте, панели и SSH (`short-unban`: адрес, его подсеть /64 или код); лестница начинается
  заново.
- **Тревога** в бот (`short_alarm {misses_hour}` в обычной очереди) — если неверных кодов со всех адресов больше 100
  за час; не чаще раза в час.

### 11.5. Риск

- С одного адреса выходит около **39 попыток** подобрать код в год: 3 кода, бан на сутки, 3 кода, бан на месяц, дальше
  по 3 в месяц.
- 10 живых ссылок и 100 000 адресов у атакующего — шанс подобрать хоть один код **0,0046 % за год**:
  1 − exp(−10 · 39 · 100 000 / 843 227 123 200) ≈ 4,63·10⁻⁵. Правило «не меньше двух цифр и двух букв» сужает выбор с
  32⁸ = 1 099 511 627 776 до 843 227 123 200 вариантов, и шанс растёт в 1,30 раза (было 0,0035 %). Для 100 ссылок и
  100 000 адресов — 0,046 %, для 1000 ссылок — 0,46 % за год.
- Даже подобранный код ничего не даёт без нажатия администратора: атакующий увидит у себя число, а на чужой запрос —
  «Это не я». Полная ссылка (43 знака) не подбирается вовсе, но при утечке работает без подтверждения.

### 11.6. Сеть

nginx (только вариант vhost на Let's Encrypt, вместе с маршрутом подписок): регулярная локация
`GA_SITE_SHORT_PATH_RE` (`lib/website.sh`) — 8–14 знаков (пробел — `%20`, если его набрали вместо тире), хотя бы одна
цифра и не меньше двух букв без `O`, `I`, `L`, `U` (у кода тех и других не меньше двух), можно с косой в конце; слова
(`/download`), даты и номера (`/2024-10-01`) сюда не попадают и уходят в `location /` сайта. Обрамление копирования
из мессенджера и разметки (`GA_SITE_SHORT_FRAME` = `shortlinks.FRAME`: до 3 знаков в начале и до 6 в конце из
`( ) [ ] { } < > « » " ' “ ” ‘ ’ „ * _ ~ + : ; , . ! ? – — • …`, обратного апострофа, таба, пробела и неразрывного
пробела — `/(КОД)`, `/«КОД»`, `/*КОД*`, `/КОД.`, `/КОД%20`) — та же локация: без строки в журнале, а служба снимает
его при нормализации; `/.КОД` — своя локация `GA_SITE_SHORT_DOT_RE` с `rewrite`, снимающим точки (без 403 сайта и
строки в error.log). Сначала файлы сайта-маскировки (`try_files $uri $uri/ @ga_short`), затем служба страниц;
`access_log off` и `error_log /dev/null crit` во всех локациях коротких ссылок, роботам превью — 404 сразу (карта
`$ga_short_bot` на уровне http, правило — `PREVIEW_RE` службы), 404/502/504 службы → 404 сайта (`@ga_short_down`),
свой предел запросов (`goamnezia_short`, 2 r/s, burst 20). На 80 — тот же путь редиректом на HTTPS без строки в
журнале. Обновление бесшовное: vhost пересобирает шаг миграции `_migrate_site_vhost` и при новой версии, и при новом
коде той же версии (отпечаток `lib/*.sh`, `lib/nginx/*`); служба перезапускается и при правке `lib/shortlinks.py`.

### 11.7. Мост и события (договор с ботом, панелью и SSH)

| Действие | Параметры | Ответ |
|---|---|---|
| `short-ensure` | `name`, `suffix` | `{code, display, url, created, suffix, new}`; бот не настроен — `short_need_bot`, линии нет — `short_no_line` |
| `short-list` | `name` | `{codes: [{suffix, code, display, url, created}], short_available}` — только созданные |
| `short-replace-request` | `name`, `suffix`, `who` | `{request, number, expires, left}`; уже ждёт — `short_pending` (ожидающий вход или замена при `who` не `page` закрываются: `short_decided` `swapped`), 5 в час — `short_limit` |
| `short-decide` | `request`, `answer` (`NN`, `deny`, `swap`), `who` (кто нажал) | `{decision: ok\|wrong\|denied\|swapped\|expired\|frozen, display?, url?, already?, by?}` — новый код рядом, в `display` и `url` |
| `short-status` | `request` | `{decision: pending\|ok\|wrong\|denied\|swapped\|expired\|frozen, kind, suffix, expires, left, display?, url?}` |
| `short-pending` | — | `{requests: [{request, kind, name, label, suffix, device, ip, geo, options, who, created, expires, left}]}` — без верного числа |
| `short-bans` | — | `{bans: [{kind: ip\|code, target, level, until, reason: misses\|denied\|wrong}]}` (у кода — ещё `name`, `label`, `suffix`) |
| `short-unban` | `target` | `{unbanned: true\|false, kind: ip\|code}` |

Все — `"secret": true`, в MCP их нет (`"mcp": null`); `readonly: true` — у `short-list`, `short-status`, `short-pending`,
`short-bans`. Итог решения и опроса — поле `decision` (а не `status`: `status` корня — конверт моста `success|error`),
снятия бана — `unbanned`. `who` — `page`, `panel`, `ssh`, `bot` или `bot:<числовой id>` (бот); у решения он же — `by` в
`short_decided`. Номер запроса — `[A-Za-z0-9_-]{1,48}` (ядро выдаёт 16 знаков). Причины бана: `misses` — три новых
неверных кода, `denied` — «Это не я», `wrong` — заморозка кода за неверные числа. `short-decide` идёт **без общего
замка моста** и без миграции (`_action_own_lock` в install.sh): только замок состояния `subs/.short/.lock`, — нажатие
в боте не ждёт до 30 с за долгой операцией; `short-status` и `short-pending` — чтения, общего замка тоже не берут. В
ответах `sub-create`, `sub-show` и `sub-rotate` — `items[].short_url` (адрес, если код уже создан и бот настроен, иначе
`""`) и `short_available`.

События — файлами в формате `ga_notify` (`{ts, event, …}`, каталог 0700, файл 0600):
`${GOAMNEZIA_LOCK_DIR:-/run/goamnezia}/short-confirm/` (стенды — `GOAMNEZIA_SHORT_CONFIRM_DIR`; служба страниц знает
каталог из юнита) — `short_confirm {request, kind: login|replace, name, label, suffix, device, ip, geo, options, who,
created, expires, left}` и `short_decided {request, status, by}` — и для решений из бота, `by` = `who` (бот смотрит
очередь раз в секунду); `short_alarm {misses_hour}` — в обычную очередь `notify`. Верного числа нет ни в событиях, ни в
`short-pending`: бот передаёт нажатое число в `short-decide`. Кнопки бота — `sc~<request>~<NN|deny|swap>`.

Страница подключения: `sub.short` в данных страницы (бот настроен) и своё одноразовое значение `reveal_short` — каждый
ответ `POST short.json {nonce, suffix}` (код пары; создаётся, если нет) и `POST short-replace.json {nonce, suffix}`
(число и номер запроса) несёт следующее (`next`); опрос замены — `GET short-status.json?r=<запрос>` (`decision`). Поле `short` в
ответе `sub.json` — в той же форме, что адреса (`{mihomo, txt, vpn: {линия}, conf: {линия}}`), только уже созданные
коды. Страница подтверждения `/<КОД>` — опрос `?r=<запрос>` (JSON `{decision, left}`, у `ok` — ещё `open_left` и
`full_left`; без кода и числа), скрипт — внутри страницы и разрешён своим хешем в CSP, без JavaScript — обновление
каждые 5 секунд. После итога `ok` страница сама никуда не переходит (SHORT-03): адрес вкладки — `?r=<запрос>`
(`history.replaceState`), браузеру по нему — тот же итог, а когда окно выдачи вышло (`full_left` = 0), — `moved`.

**Полная ссылка** (SHORT-03) — `POST /<КОД> {request, nonce}`: номер подтверждённого (`ok`) входа по этому самому коду
и одноразовое значение (`data-n` в разметке; `RevealNonces`, как SEC50-05), которое служба выдаёт только отрисовке с
адреса, начинавшего вход (страница ожидания или `?r=` с того же адреса). Скрипт хранит значение в `sessionStorage`
вкладки, а не в адресе, и шлёт POST только по нажатию человека (`isTrusted`); каждый ответ несёт следующее (`next`).
Ответ (`no-store`) — `{suffix, kind, url?, qr?, key?, key_qr, apps, commands, html, next}`: `kind` — `link` (`all.yaml`,
`all.txt`, `all.vpn`), `file` (`awgNN.conf`) или `key` (`awgNN.vpn`: `key` — сам ключ `vpn://`, `key_qr` — его QR от
моста по страницам, `url` нет); `qr` — PNG адреса (base64); `apps` — `[{id, name, name_en, href}]` по deeplink каталога
для устройства по User-Agent (`Catalog.sub_actions`), `commands` — `[{id, name, name_en, text}]` роутеров; `html` —
готовый экранированный блок, скрипт вставляет его как есть. Не код, бот не настроен, робот превью, чужой, выдуманный
или забытый номер, вход не подтверждён, код погашен — 404 как у nginx и без баллов (`ShortLinks.confirmed` — только
чтение); окно выдачи (`FULL_TTL`, 15 минут после решения) вышло — 409 `{error: expired}`; значение чужое или
повторное — 409 `{error: reveal}`; мост занят — 503 с `next`. QR — картинками `data:` внутри ответа (CSP страницы —
`img-src 'self' data:`): своего адреса, который можно открыть мимо подтверждения, у них нет. «Показать содержимое» —
`/<КОД>?go=<запрос>` по нажатию: открытый или доверенный адрес получает подписку, иначе — `moved` («Нужна новая
проверка») без запроса в бот (§11.2). Полного адреса подписки (`/s-…`) и ключей в HTML страницы нет — они только в
ответе POST после «Вход подтверждён»; страница, «Нужна новая проверка», ответ POST и ответ с подпиской —
`Cache-Control: no-store`. Метка `?go=` (как и `?r=`) — только в строке запроса: классификацию кода не трогает, nginx
пропускает её в ту же локацию (POST — тоже: файла с таким именем нет, `try_files` передаёт его службе), в журнал
службы путь не пишется (маска `/***`).

Кодов, числа и адресов нет ни в журнале службы, ни в аудите: там `short-ensure`, `short-request`, `short-decide`,
`short-trust`, `short-full` (полная ссылка выдана странице подтверждения), `short-ban`, `short-freeze`, `short-replace`,
`short-kill`, `short-unban`, `short-alarm` — имя, суффикс, итог и уровень; полного адреса, ключа и одноразовых значений —
тоже.
