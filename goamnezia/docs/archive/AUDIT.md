## 1. Что это

Установщик и панель управления серверной частью AmneziaVPN. Одна команда под
`root` поднимает официальные Docker-контейнеры AmneziaWG, выдаёт ключи для
приложения Amnezia и для сторонних AmneziaWG-клиентов, и даёт четыре интерфейса
к одному и тому же коду.

Ключевое отличие от goTelegram: три линейки протокола AmneziaWG **несовместимы
между собой**, поэтому один контейнер = одна линейка = один порт. Человек с
телефоном и роутером ходит под одним именем, но с разными ключами.

```
                     ┌──────────────────────────────────────┐
  приложение Amnezia │  amnezia-awg2  UDP/443 или случайный  │ 2.0  ← по умолчанию
  AmneziaWG-клиенты  │  amnezia-awg3  UDP случайный          │ 3.1
  роутер AWG 1.x     │  amnezia-awg1  UDP случайный          │ 1.0/1.5
                     └──────────────────────────────────────┘
                            сеть amnezia-dns-net (172.29.172.0/24)

  браузер / сканер ──► nginx TCP/80,443 ──┬─ сайт-маскировка (шаблон из каталога)
                       (режимы с сайтом)   ├─ /<app-xxxx>/ ──► панель 127.0.0.1:1985
                                           └─ /a-<secret>/mcp ► MCP-HTTP 127.0.0.1:1986
```

### Четыре интерфейса, одно ядро

| интерфейс | где живёт | как разговаривает с ядром |
|---|---|---|
| SSH-меню | `install.sh` | вызывает функции `lib/*.sh` напрямую |
| Telegram-бот | `goamnezia-bot/bot.py` | `install.sh --action=… --json` |
| Веб-панель | `admin-web/server.py` | `install.sh --action=… --json` + чтение `config.json` белым списком |
| MCP-сервер | `goamnezia-mcp/server.py` | то же, инструменты строятся из `lib/actions.json` |

Контракт `--action=`: неинтерактивный, **последняя строка stdout — JSON**, весь
UI — в stderr. Действия с `readonly: true` замок не берут: их дёргают по таймеру
и на каждое открытие экрана.

## 3. Действия моста `--action=` (63)

Единый каталог — `lib/actions.json`: имя, флаги `readonly` / `destructive` /
`secret`, имя инструмента MCP, схема параметров (29 типов в `param_types`),
описания RU и EN. Из него строятся диспетчер (сверяется тестом), инструменты
MCP, проверки ввода в панели.

| группа | действия |
|---|---|
| состояние | `status` `profiles-status` `quality` `traffic` `logs-tail` `logs-status` `preflight` |
| профили | `profile-install` `profile-remove` `profile-restart` `profile-port` `profile-params` `profile-regen` `profile-set-param` `profile-subnet` `profile-mtu` `endpoint-set` |
| пользователи | `user-add` `user-del` `user-list` `user-show` `user-key` `user-rename` `user-enable` `user-disable` `user-quota` `user-expiry` `user-add-peer` `user-del-peer` |
| бэкапы | `backup-create` `backup-list` `backup-restore` |
| импорт | `import-scan` `import-adopt` `import-reconcile` |
| обновления | `upstream-check` `upstream-update` `upstream-rollback` `core-update` |
| режим и сайт | `change-mode` `change-template` `site-check` `site-alt-svc` `dns-set` |
| панель на домене | `miniapp-status` `miniapp-on` `miniapp-off` `miniapp-rotate` |
| доступы агентов | `agent-list` `agent-add` `agent-show` `agent-rotate` `agent-enable` `agent-disable` `agent-del` |
| транспорт MCP | `mcp-http-status` `mcp-http-on` `mcp-http-off` |
| тики таймеров | `quota-tick` `watch-tick` `stats-tick` `upstream-tick` |
| прочее | `lang-set` |

Из 63: **19 `readonly`** (без замка), **12 `destructive`** (в MCP и в панели
требуют `confirm` со значением первого параметра), **4 `secret`** — их ответ
содержит ключ или секретный адрес (`user-key`, `miniapp-on`, `miniapp-rotate`,
`agent-show`).

**15 действий помечены `"mcp": null` и агенту не публикуются:** четыре тика
таймеров, `lang-set`, все семь `agent-*` и три `mcp-http-*`. Смысл жёсткий: агент
не должен уметь выдать себе или продлить себе доступ. Публикуется 48
инструментов (16 на чтение, 22 на изменение, 10 разрушительных).

Три правила диспетчера, на которых стоят все интерфейсы:

1. **Пустой аргумент ≠ отсутствующий.** `--value=` у `profile-set-param` значит
   «убрать параметр», `--host=` у `endpoint-set` — «вернуть IP сервера».
   `missing_arg` — только когда обязательного нет вовсе.
2. **Код ошибки модуля доходит до вызывающего.** Функции зовутся через
   `_action_run` без подоболочки (`ga_capture`), поэтому в ответ попадают
   `port_busy`, `user_not_found`, `params_invalid`, `subnet_overlap`,
   `needs_site`, `not_pro`, `unreachable`, а не обобщённое `*_failed`.
3. **Заглушек `not_implemented` в диспетчере не осталось.**

## 4. systemd

Службы: `goamnezia-bot.service`, `goamnezia-admin.service`,
`goamnezia-mcp-http.service` (только когда включён HTTP-транспорт MCP).

Таймеры и что они дёргают:

| таймер | период | действие | зачем |
|---|---|---|---|
| `goamnezia-quota` | 5 мин (первый через 3) | `quota-tick` | лимиты трафика и сроки → выключение + событие боту |
| `goamnezia-watch` | 2 мин | `watch-tick` | сторож: `exited` → `docker start`; `awg show` молчит → `restart`; событие не чаще раза в час на одно и то же |
| `goamnezia-stats` | 10 мин | `stats-tick` | трафик по суткам, 30 дней |
| `goamnezia-upstream` | раз в сутки 05:10 ±1 ч | `upstream-tick` | «есть новая версия» — **только уведомление, автообновления нет** |
| `goamnezia-backup` | по расписанию (`daily` по умолчанию) | `create_backup` | 30 архивов |
| `goamnezia-logbudget` | 15 мин | сторож бюджета логов | реальные байты, а не «объявленный» потолок |
| `goamnezia-logrotate` | 1 ч | `logrotate` наших конфигов | logrotate сам ходит раз в сутки — для ротации по размеру этого мало |

Все четыре продуктовых таймера идут **через мост**, а не сорсят модули в
`ExecStart`: так у них тот же замок, тот же JSON в журнале и те же коды ошибок,
что видят бот и MCP. `timers_install` идемпотентен — юнит переписывается только
при изменении текста.

## 6. Три режима

| режим | `mode` | домен | AWG | TCP/80 и 443 | панель на домене | сертификат |
|---|---|---|---|---|---|---|
| **Lite** | `lite` | нет | случайный UDP 30000–49999 | закрыты | нет | — |
| **Lite + сайт** | `lite_site` | нет | случайный UDP | nginx на IP: сайт по HTTP и HTTPS | нет | самоподписанный, 10 лет |
| **Pro** | `pro` | да | `awg2` на **UDP/443**, остальные случайные | nginx на домене | да | Let's Encrypt |

Переходы — полный граф из шести направлений, каждый со своим объяснением и
подтверждением. **Ни один переход не пересоздаёт контейнеры и не перевыпускает
ключи**: меняются только конфиг nginx, сертификат и `mode`/`site.cert` в
`config.json` (проверяется тестом отдельно).

Почему `lite_site` устроен именно так:

- **сайт и по 80, и по 443, без редиректа** — обычный веб-сервер на голом IP
  отдаёт страницу по HTTP как есть; редирект на `https://<IP>/` вёл бы прямо в
  предупреждение браузера о самоподписанном сертификате, то есть был бы лишним
  сигналом. ACME-локации нет: домена нет, проверять нечего. HSTS не отдаём — на
  недоверенном сертификате браузер его игнорирует, а «строгий HTTPS без
  доверия» для наблюдателя противоречие;
- **`server_name _` без `default_server`** — отвечаем на любой Host и по IP, но
  не перехватываем умолчание у соседей по nginx;
- **сертификат — наш секрет, а не системный**: `/opt/goamnezia/tls` (0700), EC
  P-256, CN и SAN = IP, 10 лет. **Живой сертификат не перевыпускается**: его
  отпечаток SHA-256 — то единственное, по чему агент MCP отличает наш сервер от
  подменённого. Перевыпуск — только при смене IP, истечении или явной команде.

## 7. Профили и линейки AmneziaWG

| id | линейка | контейнер | подсеть | порт по умолчанию | интерфейс |
|---|---|---|---|---|---|
| `awg2` | 2.0 (**ставится всегда**) | `amnezia-awg2` | `10.8.2.0/24` | Lite: случайный; Pro: 443 | `awg0` |
| `awg3` | 3.1 | `amnezia-awg3` | `10.8.3.0/24` | случайный | `awg0` |
| `awg1` | 1.0/1.5 | `amnezia-awg1` | `10.8.1.0/24` | случайный | `awg0` |

Все три собираются из одного официального `Dockerfile` на образе
`amneziavpn/amneziawg-go` **по закреплённому дайджесту**, а не по `latest`.

Имена выбраны не произвольно: официальное приложение Amnezia разбирает любой
контейнер с подстрокой `amnezia` в имени и **молча пропускает незнакомые** — оно
видит только `amnezia-awg2` и считает сервер своим; goWARP PRO по своей маске
`^amnezia-awg[0-9]*$` видит все три.

### Линейка → минимальная версия клиента

| линейка | что её отличает | минимальная версия приложения Amnezia | кто ещё умеет |
|---|---|---|---|
| 1.0 | `Jc Jmin Jmax S1 S2 H1–H4` одиночными значениями | 4.0.0 | AmneziaWG-клиенты, Keenetic, MikroTik, OpenWrt, ядерный модуль |
| 1.5 | + `I1–I5` (шлёт только клиент) | 4.8.8.1 | Amnezia 4.8.8.1+ |
| 2.0 | + `S3 S4`, `H1–H4` диапазонами `a-b` | 4.8.12.7 | Amnezia 4.8.12.7+ |
| 3.1 | + `HeaderProtectionKey`, тайминги, `RandomTrailers`, `DisableCookies` | 5.0.1.5 | Amnezia 5.0.1.5+ |

Значение отдаётся вместе с ключом (`min_client` в ответе `user-key`) — чтобы
человек не получил ключ, который его приложение не откроет.

**Линейки между собой несовместимы.** В 3.x несовпадение `HeaderProtectionKey`
рвёт рукопожатие. Отсюда «один контейнер = одна линейка».

Параметры профиля правятся как в настройках приложения: порт, подсеть (с
перенумерацией пиров), MTU и **каждый параметр маскировки по отдельности**.
Параметры делятся на две стороны:

- **серверные** (`S1–S4`, `H1–H4`, `HeaderProtectionKey`, `RandomTrailers`,
  `DisableCookies`) — переписывается конфиг, контейнер перезапускается (только
  рестарт перечитывает `[Interface]`), в ответе `reissue_required=true`:
  выданные ключи надо раздать заново;
- **клиентские** (`Jc`, `Jmin`, `Jmax`, `I1–I5`, `MTU`, `PersistentKeepalive`,
  тайминги) — применяются `syncconf` без разрыва сессий, `reissue_required=false`.

Значение проверяется по правилам **базовой** линейки профиля (`awg1` → 1.5,
`awg2` → 2.0, `awg3` → 3.1), а фактическая линейка определяется по содержимому
(`detect-line`). Так `awg1` свободно ходит между 1.0 и 1.5, добавляя или убирая
`I1`, но `S3/S4` и 3.x-поля в него не пройдут. Следствие — см. §15 п. 6.

## 8. Пользователи и ключи

Пользователь — одна запись в `users.json`, у неё пир в каждом профиле: один
человек ходит с телефона (3.1) и с роутера (1.0) под одним именем.

Что мы делаем иначе, чем приложение Amnezia (совместимость не страдает):

| у нас | у приложения | почему |
|---|---|---|
| PSK на каждого пира | один общий из `wireguard_psk.key` | компрометация одного ключа не тянет остальных; пиры приложения с общим PSK живут в том же конфиге |
| приватный ключ клиента хранится в `users.json` (0600) | хранится в приложении | иначе повторно выдать тот же `.conf` и QR нельзя |
| свой аллокатор IP с переиспользованием освободившихся | последовательный | после удалений подсеть не выедается |
| выключение = убрать `[Peer]` + `syncconf`, запись остаётся | — | лимит и срок должны уметь вернуть человека |

Каждая мутация **целиком переписывает** серверный конфиг и `clientsTable` из
`users.json` — без дописываний «в хвост», чтобы конфиг не расходился с
источником правды.

### Два стиля ключа, везде

| стиль | что это | кто читает |
|---|---|---|
| классический | текст `.conf` + QR обычной строкой | AmneziaWG-клиенты, роутеры |
| «стиль Amnezia» | ссылка `vpn://…` + **серия QR** | официальное приложение Amnezia |

`vpn://` — это Qt `qCompress` (4 байта big-endian длины исходных данных + zlib
уровень 8) в base64url без `=`. Без четырёхбайтового префикса `qUncompress` в
приложении возвращает пустой массив — это первое, обо что тут спотыкаются.
QR приложения — не картинка со строкой: сжатые байты режутся по 850 байт, каждый
чанк упакован как `QDataStream` (`qint16` magic **1984**, `quint8` число чанков,
`quint8` индекс, `quint32` длина + данные) и отдаётся отдельным PNG. Их
сканируют по порядку.

### Подхваченные пользователи

Пользователь, пришедший из контейнера приложения (`import-adopt`,
`import-reconcile`), помечен `imported: true` и **не имеет приватного ключа** —
его хранит приложение, у сервера его никогда не было. `user-key` такому отвечает
`no_private_key`; новый `.conf` можно получить только перевыпуском пира
(`user-del-peer` + `user-add-peer`). Это видно во всех интерфейсах.

## 9. Панель: доступ и сессии

Слой входа перенесён из goTelegram Pro без изменений в логике (`goTelegram
AUDIT.md` §7). Порт **1985** — 1984 занят goTelegram.

### Два входа

1. **SSH-туннель** — `ssh -L 1985:127.0.0.1:1985 root@SERVER`, работает всегда,
   не зависит ни от домена, ни от бота.
2. **С домена по секретному пути** (`app-<hex12>`) — только режим Pro: allowlist
   `Host` и код входа из бота рассчитаны на домен.

### Как пускает внутрь

| способ | чем доказывает | где работает |
|---|---|---|
| петля без второго фактора | ни одного из `X-Forwarded-Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto` **и** петлевой адрес сокета | только туннель; `GOAMNEZIA_TRUST_TUNNEL=0` отключает |
| код 2FA | приходит в Telegram-бота, живёт 5 минут, 5 попыток | браузер, оба пути |
| подпись Telegram | HMAC `WebAppData` от админа бота, не старше суток | мини-апп |
| токен панели | `/opt/goamnezia-admin/token`, 0600 | только `?token=…` в адресе; поля ввода в интерфейсе нет |

**Размен, который надо держать в голове:** на `127.0.0.1:1985` может постучаться
любой процесс той же машины, в том числе `www-data` под nginx. Раньше от него
защищал root-only файл токена, при `trust_tunnel` не защищает ничто.

Сессия живёт **15 минут**, затем **60 секунд** на продление кодом (в это окно
данные не отдаются). Cookie переживает сессию (+6 ч) — доступа не даёт, нужна
лишь чтобы сервер сказал «сессия закончена», а не «нужен токен». Состояние — в
памяти процесса: рестарт панели разлогинивает всех.

Корзины лимита на код раздельные, чтобы долбёжка из интернета не заперла вход
администратору: публичная 5/час, туннельная по IP 30/час, продление 12/час,
общий кулдаун 30 с. Код уходит **только по нажатию кнопки**.

Панель **не пишет** `config.json` и `users.json` и не читает `users.json`
напрямую: пользователи — через `user-list`, ключи — только через `user-key`.
CSP без внешних источников: подпись мини-аппа читается из `#tgWebAppData` в
адресе, а не из скрипта с telegram.org — у аудитории он часто заблокирован.

## 10. MCP: сервер для ИИ-агентов

Первый продукт серии с MCP. `server.py` — один файл на stdlib, протокол
`2025-06-18` (принимает клиентов `2025-03-26` и `2024-11-05`). В нём **нет ни
одного имени действия**: инструменты, ресурсы и подсказки строятся из
`lib/actions.json`, поэтому переходник переносится в другой продукт серии без
переписывания.

48 инструментов, 6 ресурсов (5 действий + файл `AGENT_GUIDE.md` по адресу
`goamnezia://guide`), 3 подсказки-сценария.

### Два транспорта

| транспорт | адрес | аутентификация |
|---|---|---|
| **stdio** | `ssh root@HOST goamnezia-mcp` | ключ SSH; открытых портов нет |
| **HTTP** | `POST https://…/a-<secret>/mcp` | секрет в пути = ключ |

Где живёт HTTP по режимам: `pro` — nginx на домене; `lite_site` — тот же nginx
на самоподписанном сертификате, адрес по IP, рядом отдаётся отпечаток SHA-256;
`lite` — nginx нет, поэтому `mcp-http-on` без `--port` отвечает `needs_site`, а с
`--port=N` поднимает собственный TLS-слушатель.

### Доступы агентов

Доступ — запись в `agents.json` (0600): `id` (`a-<hex>`), метка, секрет (32
случайных байта → 43 символа base64url), уровень, срок, список разрешённых IP,
персональный порт, счётчики.

| уровень | что видит |
|---|---|
| `read` | инструменты с `readonly: true` |
| `write` | всё с `destructive: false` |
| `admin` | всё |

Вызов вне уровня → JSON-RPC `-32003 forbidden`. Выключенный, истёкший, не
прошедший `allow_ips` доступ и неизвестный секрет → **одинаковый 404** с телом
как у nginx по умолчанию: ответ не подтверждает существование пути. 20 неудач с
одного IP за 10 минут → бан на 10 минут, и тоже 404, а не 429.

`agents.json` перечитывается по mtime **при каждом запросе**, поэтому «Выключить»,
«Удалить» и «Перевыпустить» действуют на следующий же вызов — ни nginx, ни юнит
перезапускать не нужно. Исключение — персональные порты: слушатели открываются
при старте, и смена набора портов перезапускает юнит.

Адрес доступа = ключ. Он показывается только по явной кнопке, всегда с
предупреждением, и **никогда не пишется в аудит и в логи** — туда уходит только
`id`.

## 11. Обновления из upstream и импорт

### Обновления

Два официальных источника: GitHub `amnezia-vpn/amnezia-client` (серверные
скрипты контейнеров) и Docker Hub (образы ядра). `upstream-check` сравнивает,
`upstream-update` обновляет один профиль, `upstream-rollback` возвращает
предыдущий, `core-update` пересоздаёт контейнер на уже закреплённом образе.
**Автообновления нет намеренно** — только по кнопке человека; таймер лишь
сообщает, что вышло новое.

Три места, где легко ошибиться, и как это решено:

- тег релиза берётся из **списка** релизов (первый не-draft), а не из
  `releases/latest`: тот эндпоинт по правилам GitHub пропускает пре-релизы, а
  текущий `5.0.2.1` помечен пре-релизом;
- образ — новейший **версионный** тег Docker Hub (`sort -V`); `latest` — только
  справка. У legacy-образа `amnezia-wg` версионных тегов нет, там сравнивается
  дайджест `latest`;
- **новый плейсхолдер `$…`** в `template.conf` или `configure_container.sh` — это
  новый параметр протокола, которого наш генератор не знает. Он попадает в отчёт
  как «не поддержан», и обновление его не подставляет. Молча подставить пусто
  нельзя: так ломается совместимость линейки.

Обновление идёт с бэкапом и откатом в одном действии: `state_sync` живого →
сборка нового образа → `docker rm/run` с прежним портом → `state_restore` →
проверка `awg show` и порта. Ключи сервера и пиров не меняются.

### Импорт

Сервер уже могли поставить официальным приложением. `import-scan` повторяет
поиск приложения (`docker ps` + регулярка), читает конфиг и `clientsTable`
каждого контейнера и отдаёт таблицу **без единого секрета**. `import-adopt`
записывает контейнер профилем, пользователей — в `users.json` без приватных
ключей, копирует конфиг и ключи в `state/`; **контейнер не пересоздаётся**, люди
продолжают ходить теми же ключами.

`import-reconcile` — сверка после старта: приложение могло добавить или удалить
пира прямо в контейнере, минуя нас. Новые подхватываются как импортированные,
исчезнувшие получают `active=false` (запись остаётся). SSH-меню предлагает эту
сверку при каждом интерактивном запуске, если есть расхождение.

Контейнер `amnezia-xray`, поставленный приложением, помечается `unsupported` и
не подхватывается: goAmnezia — продукт только про AmneziaWG.

## 12. Предполётная проверка портов

Режимы с сайтом нельзя выбрать, если TCP/80 или 443 заняты или закрыты. Проверка
идёт **до показа меню режимов** и повторяется при каждом переключении из любого
интерфейса.

| что | как | результат |
|---|---|---|
| кто слушает | `ss -ltnp` / `-lunp`; юнит — через `/proc/<pid>/cgroup`, а не по имени процесса | `free` / `busy {pid, process, unit, container, product}` |
| контейнер за `docker-proxy` | `docker ps --format '{{.Names}} {{.Ports}}'` по опубликованному порту; тот же список нужен при `userland-proxy=false`, когда порт держит правило DNAT и в `ss` его не видно | имя контейнера |
| чей это продукт | по юниту, процессу, контейнеру и vhost'ам nginx | `gotelegram` `govless` `godns` `amnezia` `goamnezia` `xui` `unknown` |
| локальный файрвол | `ufw status`, `iptables -S INPUT`, `nft list ruleset` | `closed_local` — мы умеем открыть сами, спросив |

Юнит по `cgroup` — не педантизм: у `telemt`, `dnsdist` и `xray` процесс
называется как угодно (`x-ui` запускает `xray-linux-amd64`), а cgroup всегда
указывает на юнит, который надо остановить.

Подсказка про освобождение порта предлагает **`docker stop <контейнер>`, а не
`systemctl disable --now docker.service`**: у `docker-proxy` юнит —
`docker.service`, и его остановка убила бы и наши контейнеры.

Свой nginx и свои контейнеры (`ours`) не блокируют. Занятый UDP/443 — только
предупреждение: профиль обойдётся случайным портом. Сомнение в разборе файрвола
даёт `unknown` (режим доступен, но с ⚠), а не `closed`: без `ss` честнее сказать
«не проверено», чем «свободно».

Внешний файрвол хостинга изнутри не проверяется — соединение на собственный
публичный IP через него не проходит. Это работа `site-check` и подсказки про
security group.

## 13. Бэкапы и логи

**Бэкап** содержит: `config.json`, `users.json`, `state/<container>/` (серверные
приватные ключи и `clientsTable`), `.language`, `.env` и `user_langs.json` бота,
nginx-конфиг, Let's Encrypt `live/archive/renewal` домена, `tls/`
(самоподписанный сертификат), `metadata.json`. Смысл состава: восстановление на
**чистом** сервере обязано поднять те же контейнеры с теми же ключами, без
перевыпуска ни одного клиентского ключа. Глубина хранения — 30 архивов, одна на
все интерфейсы. Архив содержит приватные ключи и токен бота.

**Логи** — потолок 300 МБ на компонент (`journal`, `nginx`, `goamnezia*` в
`/var/log`, docker), из них половина живого слоя. Это не гигиена, а
доступность: на боевом сервере goTelegram `/var/log` разросся до 552 МБ, и когда
раздел забивается, nginx и sshd встают на записи в лог — принимают TCP и молчат.
Снаружи выглядит как «VPN жив, а сервер недоступен», и по SSH уже не зайти.

Слоя «резать в источнике» здесь нет по-хорошему: контейнеры запускаются с
`--log-driver none`, источник вырезан до появления файла. Предохранитель из
goTelegram сохранён: в общем каталоге (`/var/log`, `/var/log/nginx`) сторож
трогает **только своё по маске** — иначе бюджет сносил бы чужие `syslog.1`.
