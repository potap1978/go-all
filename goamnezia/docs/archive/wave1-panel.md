## Что нужно от ядра / моста / других

1. **edge-status — DNS домена сайта** (паритет с SSH): когда ключи на IP или на другом домене, SSH берёт A-записи
   домена сайта (`_edge_table`, ветка без `.dns`, и `_site_dns_warn_header`), а мост их не отдаёт — панель и бот
   не могут показать ни колонку A-записи, ни строку «домен сайта указывает ещё и на чужой адрес». Нужно поле
   вроде `site_dns{domain, state, a, foreign}` в ответе `edge-status` (тот же кэш на 120 с).
2. **`user-del-peer` снимает страницы**, у которых не осталось ни одного профиля с ключом (как `user-del`), —
   ядерная часть UI-4 (lib/users.sh `_users_del_peer_locked`).
3. **PUI-25 в SSH**: `_panel_show_access` и хвост мастера печатают `root@<server_ip>`; на машине, где основной адрес
   только исходящий (сервер A), команда не подключается. Логика панели (`tunnel_host`): основной, если его
   вердикт у сторожа `ok`, иначе первый адрес с `ok`. `install_admin.sh` при установке данных сторожа ещё не имеет.
4. **Сбои DNS не кэшируются в ядре** (критик 24.09, п.2): `edge-status` теперь зовут и `/api/settings` (адрес туннеля),
   и Обзор, и карточка пользователя; панель кэширует только удачный ответ на 30 с. При лежащем DNS каждый такой
   запрос ждёт таймауты `dig`.
5. **Слой входа (решение владельца)**: ответы `/api/auth/verify` и `/api/auth/request` — только по-русски, у `verify`
   нет `code` — новый экран входа не сможет их перевести. Предложение: `code` (`expired`, `too_many`, `wrong` + `left`)
   в отказе `verify`. Не трогал — слой входа.
6. Язык ответов сервера панели берётся из `config.json`, а язык интерфейса — из браузера: EN-панель на RU-сервере
   получает отказы сервера по-русски. Для редизайна — передавать язык интерфейса заголовком и выбирать по нему
   `PANEL_STRINGS`.
