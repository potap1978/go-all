План для владельца. Собран из пунктов «что проверять вживую», разбросанных по
`docs/PRO.md` §5, `docs/PREFLIGHT.md` §8, `docs/PANEL.md` §8, шапкам модулей
`lib/*.sh`, `PLAN.md` §11 (риски) и `SPRINTS.md`, — сгруппированных по темам и

без сервера, но **ни одна его строка ни разу не выполнялась на машине с

## 0.0 Доставка кода на стенд, пока нет репозитория

`bootstrap.sh` берёт файлы с GitHub. Пока репозитория нет, дерево копируют напрямую, и здесь
есть ловушка, на которой уже один раз потеряли состояние стенда.

**`rsync -a --delete` из репозитория сносит рабочее состояние сервера.** В репозитории нет
`config.json`, `users.json`, `agents.json`, `state/`, `backups/`, а на сервере это и есть весь
продукт: конфигурация, пользователи, ключи серверов, копии контейнеров. Плюс
`lib/upstream/images.json` на сервере — рабочая копия, куда пишет `upstream-update`.

Правильная команда:

```bash
rsync -a --delete \
  --exclude .git --exclude __pycache__ \
  --exclude config.json --exclude users.json --exclude agents.json \
  --exclude state/ --exclude backups/ --exclude tls/ \
  --exclude lib/upstream/images.json \
  "<локальное дерево>/" root@<сервер>:/opt/goamnezia/
```

После копирования: `chmod +x` установщикам и `server.py`, симлинки `/usr/local/bin/goamnezia`
и `/usr/local/bin/goamnezia-mcp`, каталог `/run/goamnezia`.

## 0. Что подготовить

| Что | Зачем | Требования |
|---|---|---|
| **VPS-1** (Lite) | основной стенд | Ubuntu 24.04, x86-64, KVM, публичный IPv4, чистый — без чужих сервисов на 80/443 |
| **VPS-2** (Pro) | домен, Let's Encrypt, панель на домене, переезд | то же |
| **Домен** | Pro-режим | A-запись на IP VPS-2, **отвечающая до установки**; не тот домен, что у боевых серверов |
| **Токен бота** | отдельный, тестовый | один токен = один сервер; боевого бота не трогать |
| **Telegram ID** | админ бота | свой |
| **Устройство с приложением Amnezia 5.0.2** | приёмка ключей `vpn://` и серии QR | телефон или десктоп |
| **Роутер с AWG 1.x** | приёмка линейки 1 | Keenetic, MikroTik или OpenWrt с AmneziaWG |
| **Клиент AmneziaWG** | приёмка `.conf` | десктопный или мобильный |
| **VPS-3 или снапшот VPS-1** *(желательно)* | восстановление из бэкапа и переезд | одноразовый |

Правила стенда:

- **сертификат Let's Encrypt выпускается один раз.** Повторные эксперименты —
  только `GOAMNEZIA_LE_STAGING=1`. Такой сертификат браузер и `site-check` не
  примут (`https_ok=false`) — это ожидаемо, а не провал;
- боевые серверы и серверы соседних продуктов серии не трогаем;
- второй экземпляр бота с боевым токеном не запускаем.

Перед каждым большим блоком снимайте состояние:

```bash
cp /opt/goamnezia/config.json /root/config.$(date +%H%M).json
docker ps --format '{{.Names}} {{.CreatedAt}} {{.Status}} {{.Ports}}'
```

### 7.6 Рассогласование версий Docker (пакет обновлён, демон не перезапускался)

Сценарий не выдуманный: ровно это сделал `unattended-upgrades` в ночь на
10.09.2026 — обновил `docker.io` 24.0.7 → 29.1.3 и, как всегда, не тронул демон.
Клиент стал просить API 1.52, живой демон понимает 1.43, каждая команда `docker`
падает, а контейнеры при этом работают.

Как воспроизвести, если природа не помогла: обновить пакет (`apt-get install
--only-upgrade docker.io`) и **не** перезапускать `docker.service`. Проверить,
что рассогласование живо:

```bash
docker ps                                   # ошибка «client version … is too new»
DOCKER_API_VERSION=1.43 docker ps           # контейнеры Up
systemctl show docker -p ActiveEnterTimestamp   # демон стартовал ДО обновления пакета
```

- [ ] **7.6.1** `goamnezia --action=profiles-status --json` — у всех профилей
      `state: "running"`, **не** `missing`.
- [ ] **7.6.2** `goamnezia --action=quality --json | jq .quality.docker_info` —

## 15. Чего мы не сможем проверить даже на стенде

Честно, чтобы не считать приёмку полной там, где она не полна.

| Что | Почему |
|---|---|
| **Работа под настоящей DPI-блокировкой** | нужен канал в стране блокировки и время наблюдения; стенд показывает только «подключается» |
| **Эффективность маскировки** | что сканер или DPI действительно принимает сервер за веб-сервер — проверяется статистикой на живом трафике, а не одним `nmap` |
| **Долгая стабильность** | утечки памяти, распухание конфигов, поведение через месяц — за одну приёмку не видны |
| **Все 33 467 шаблонов сайта** | проверяется выборка по источнику; библиотека взята из навыка как есть |
| **Все версии роутеров и клиентов AmneziaWG** | приёмка на том, что есть под рукой; капризность к параметрам 1.x — известный риск |
| **Все хостинги** | доступность Docker Hub и GitHub, поведение файрвола провайдера, KVM-особенности различаются |
| **Все версии iproute2/nftables** | разбор `ss` и `nft` писался под сохранённые образцы; на другой версии формат может отличаться (проверяется п. 5.1) |
| **Одновременная работа четырёх интерфейсов под нагрузкой** | гонки между SSH, ботом, панелью и агентом ловятся не сценарием, а нагрузочным прогоном |
| **Восстановление после порчи данных** | битый `config.json`, оборванная запись, забитый диск — отдельная работа, за рамками приёмки |
| **`lite_site` на IPv6-only сервере** | продукт рассчитан на публичный IPv4 |
| **RHEL-семейство** | Docker и официальные скрипты Amnezia там не проверялись; установка предупреждает, но не блокирует |

## Выкладка кода на стенд — только с исключениями состояния (11.09.2026)

`rsync -a --delete ./ root@стенд:/opt/goamnezia/` снёс живое состояние: `config.json`,
`users.json`, `agents.json`, `state/` с приватными ключами сервера и все архивы в
`backups/`. В исходниках этих файлов нет, а `--delete` удаляет всё, чего нет у источника.

Правильная команда:

```
rsync -a --delete \
  --exclude '.git' --exclude '.venv' --exclude '__pycache__' \
  --exclude 'config.json' --exclude 'users.json' --exclude 'agents.json' \
  --exclude 'state' --exclude 'backups' --exclude 'admin' --exclude 'stats.json' \
  ./ root@СТЕНД:/opt/goamnezia/
```

Перед выкладкой — `bash install.sh --action=backup-create --json`. Если состояние всё же
потеряно, а контейнеры живы, его возвращает собственный импорт продукта: `import-scan`
покажет контейнеры, `import-adopt --container=amnezia-awgN` подхватит профиль вместе с
пользователями из `clientsTable` и прежними ключами. Не вернутся: доступы агентов, пароль
панели, архивы копий и заданные людьми имена пользователей (придут как `client-xxxxxx`).
