# Зависимости установщика

Перед проверкой запуска нового кода и его раскладкой `bootstrap.sh` вызывает
`deps_install_missing --yes core` из скачанного выпуска. Запуск установленного
продукта проверяет тот же профиль. Наличие команды, минимальная версия и нужные
возможности проверяются отдельно; несовместимая команда попадает в список пакетов
для установки или обновления.

Полная проверка `core` стоит 0,2–0,3 CPU-с, а мост зовут панель на каждом обновлении
экрана и таймеры раз в несколько минут (CPU-аудит 03.10.2026). Поэтому удачная полная
проверка оставляет отметку `/run/goamnezia/deps-core.ok` с отпечатком проверенного:
версия продукта, путь каждой команды по `PATH`, inode, ctime и размер этих файлов,
сертификатов CA, базы пакетов (`/var/lib/dpkg/status`) и самого `lib/deps.sh`.
Верят отметке только **читающие действия моста и тики таймеров** — и только пока
отпечаток тот же и не прошли сутки: обновили или откатили пакет, подложили другую
команду раньше в `PATH`, заменили файл — проверка снова полная. Меню, установка и
любые изменения из интерфейсов проверяют полностью всегда, так что несовместимый
пакет ловится до установки, как и прежде. `/run` — tmpfs: перезагрузка снимает отметку
сама. Без `stat` GNU (macOS) отпечатка нет — проверка всегда полная.

| Компонент | Поддерживаемый минимум / проверка |
|---|---|
| Bash | 4.3: массивы и nameref |
| jq | 1.6: JSON, переменные окружения; фильтры совместимы с Ubuntu 22.04 |
| curl | 7.55.0 и протокол HTTPS: заголовки из stdin, сокет Docker |
| Python | 3.8 для ядра/MCP, 3.9 для бота (PTB 21); модули ssl, json, hashlib, zlib, subprocess, http.server |
| OpenSSL | 1.1.1 и рабочее шифрование AES-256-CBC с PBKDF2 |
| tar | параметры извлечения --no-same-owner и --no-same-permissions |
| Docker CLI | 20.10; Podman не заменяет Docker; демон проверяется модулем Docker |
| nginx | 1.18; конфигурация дополнительно проверяется nginx -t |
| Certbot | 1.0 |
| qrencode | 3.4 |
| Git | 2.20; нужен для сайта из собственного репозитория |

В `core` также входят ip/ss (iproute2), iptables, systemctl, gzip, awk, sed,
grep, find/xargs, cmp, sysctl, hostname, getent, nsenter, основные команды
coreutils, сертификаты CA и dig. Для окружения бота отдельно проверяются
`venv` и `ensurepip` (`python3-venv`). Docker, QR, сайт, сертификат, бот и
собственный шаблон получают свои профили перед установкой компонента.

При необходимости apt сначала обновляет индекс, затем устанавливает или
обновляет только пакеты из выбранного профиля с `--no-remove`. Общего `apt upgrade`
нет. После операции выполняется повторная проверка. Если репозиторий ОС не
даёт нужной версии, команда из другого каталога перекрывает установленный пакет
или критическая возможность по-прежнему недоступна, установка останавливается
и показывает компонент, установленную и требуемую версии. Подмены `/usr/bin/jq`
скачанным бинарником нет. `GOAMNEZIA_DRY_RUN=1` не вызывает apt.

Диагностика без установки:

```bash
bash lib/deps.sh all
bash -c 'source /opt/goamnezia/lib/deps.sh; deps_report_json all'
```

`deps_report_json` сохраняет поля `ok`, `profiles`, `crit`, `warn`, `opt`,
`missing`, `openssl`; поле `checks` добавляет `name`, `installed`, `required`
и `reason` (`ok`, `missing`, `version`, `capability`). Пустой `required` означает,
что проверяется наличие или возможность, а числовой минимум не задаётся.

Регрессии: `tests/test_dependencies.py` использует подставные apt/jq/id и проверяет
старую установленную версию, порядок update → install, идемпотентность, повторный
отказ, перепроверку и dry-run. `tests/test_core_cpu.py` — отметку «уже проверено»: пока
ничего не менялось, чтение не повторяет проверку, а замена файла команды, другая команда
раньше в `PATH`, чужой или испорченный файл отметки и прошедшие сутки возвращают полную
проверку. `tests/test_jq_compat.py` проверяет аргументы фильтров
и восстановление отсутствующего/пустого состояния тревог. Сквозные наборы нужно
запускать также с настоящим jq 1.6 первым в PATH, не заменяя пакет машины.
