Версия ветки `dev`: **2.10.27**. Документ описывает то, что есть в коде сейчас.
`DOCS_AI.md` и `DOCS_HUMAN.md` — исторические (до 2.7.0 и 2.6.0), при расхождении
верить коду и этому файлу.

---

## 1. Что это

Установщик MTProxy на ядре `telemt` (Rust) с маскировкой под обычный HTTPS-сайт.
Один VPS, один домен, один порт 443: Telegram-клиенты получают прокси, браузеры —
сайт. Управление тремя интерфейсами, которые ходят к одному и тому же коду.

```
                        ┌─────────────────────────────┐
   Telegram-клиент ───► │  telemt  :443 (fake-TLS)     │
                        │    └─ не-прокси TCP ─────────┼──► nginx 127.0.0.1:8443
   браузер        ───►  └─────────────────────────────┘         ├─ сайт-маскировка
                                                                └─ /app-xxxx/ ──► панель
                                                                      127.0.0.1:1984
```

### Три интерфейса, одно ядро

| интерфейс | где живёт | как разговаривает с ядром |
|---|---|---|
| SSH-меню | `install.sh` | вызывает функции `lib/*.sh` напрямую |
| Telegram-бот | `gotelegram-bot/bot.py` | `install.sh --action=… --json` |
| Веб-панель | `admin-web/server.py` | `install.sh --action=… --json` + прямое чтение конфигов |

Контракт `--action=`: неинтерактивный, вывод JSON, меню не показывает. Действия
вида `*-status|*-probe|quality` не тянут миграцию конфига — их дёргают по таймеру.

Глубина: максимум два уровня, третий — конечный экран. Разделы собраны по
частоте обращения, не по темам.

### SSH-меню

```
1) Прокси      → Режим работы · Установить · Статус · Ссылка · Поделиться ·
                 Перезапуск · Логи · Сменить режим/шаблон · Ключи
2) Статистика  (свой цикл авто-обновления)
3) Управление  → Бекап · Восстановить · Обновить telemt · Сайт/SSL · Удалить ·
                 Язык · WARP-egress · Панель на домене · Веб-админка
4) Telegram-бот → Статус · Логи · Перезапуск/Запуск · Остановить · .env · Удалить
5) О программе → Версия · Промо
```

> **Известное расхождение.** Главные экраны бота и SSH **не совпадают**: в боте
> пять разделов по частоте, в SSH — прежние пять по темам. Перекрой SSH-меню под
> бота (этап 3) не выполнен: `install.sh` идёт на боевые серверы, и владелец не
> давал на это согласия отдельно. Внутри разделов пункты и формулировки уже
> сведены. Это открытый пункт, а не недосмотр.

## 4. Режимы работы

**Lite** — без домена. `telemt` с `tls_emulation` под чужой SNI, клиент идёт на
`IP:443`. Сайта нет.

**Pro** — свой домен с валидным сертификатом. `telemt` занимает `0.0.0.0:443`,
не-прокси TCP отдаёт на `nginx 127.0.0.1:8443` (`mask_port` в конфиге).
Следствие, важное для аудита: **реального адреса клиента за nginx не
существует** — для него клиент всегда `127.0.0.1`.

## 5. Анти-DPI

Две независимые вещи, которые легко перепутать:

- **Пресеты** (`preset_id`, значения 1/2/4) — параметры ядра, применяются
  `preset-apply`. Пункты меню `p1`/`p2`/`p4`.
- **Внешний фикс** (`mekofix`, значения `v3`/`v4`) — SYN-фикс на файрволе,
  применяется `mekofix-apply`. Пункты меню `v3free`/`v3lim`/`v4`.

Выбор пресета **намеренно снимает внешний фикс** (иначе остался бы от прошлого
выбора). V4 помечен экспериментальным и требует подтверждения в обоих
интерфейсах.

## 6. WARP-egress

Исходящий трафик к дата-центрам Telegram уходит через Cloudflare; клиенты на
`:443` остаются на вашем IP. Схема: `wgcf` + `wg-quick` интерфейс `gtwarp`
(`Table=off`) + policy-routing таблица 7788, pref 100 — только подсети Telegram.

**Fail-open**: `gotelegram-warp-egress.service` при старте проверяет
достижимость ME-эндпоинта и **снимает маршруты**, если не проходит.
`gotelegram-warp-watch.timer` тикает и следит дальше.

Проверено вживую и опровергнуто прежнее утверждение из 2.10.4: **Cloudflare
пропускает порт 8888**, на котором висит большинство ME-эндпоинтов. Проба
`_warp_endpoint_responds` действительно шлёт байты и читает ответ — прежняя
проба судила по `time_connect > 0` и не отличала живой эндпоинт от TEST-NET.

## 7. Панель: доступ и сессии

### Два входа

1. **SSH-туннель** — `ssh -L 1984:127.0.0.1:1984 root@SERVER`, работает всегда,
   не зависит ни от домена, ни от бота.
2. **С домена по секретному пути** — включается пунктом «Панель на домене».
   nginx проксирует `location ^~ /<путь>/` на панель целиком, поэтому доступны
   и мини-апп внутри Telegram, и **обычная форма входа в браузере**.

### Как пускает внутрь

| способ | чем доказывает | где работает |
|---|---|---|
| код 2FA | приходит в Telegram-бота, живёт 5 минут | браузер, оба пути |
| подпись Telegram | HMAC `WebAppData` от админа бота | мини-апп |
| токен панели | файл `/opt/gotelegram-admin/token`, root-only | только `?token=…` в адресе, через туннель |

Токен — аварийный путь и **поля ввода для него в интерфейсе нет**: он не
истекает, и предлагать его рядом с одноразовым кодом значило бы подталкивать к
худшему из двух. Открывается по `?token=…`, дальше живёт обычной сессией.

### Вход через localhost без второго фактора

Клиент, пришедший **прямо на петлевой слушатель** (то есть по SSH-туннелю),
пускается без кода и без токена: право на сервер он уже доказал входом по SSH.
Признак — отсутствие всех заголовков обратного прокси (`X-Forwarded-Host`,
`X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`) **и** петлевой адрес сокета.
Проверка стоит после сессии и подписи мини-аппа, до токена, поэтому прежние пути
не отменяет. `/api/session` отвечает такому клиенту состоянием доступа, иначе
фронтенд через 15 минут закрыл бы рабочую панель окном «продлите кодом», а при
ненастроенном боте кода взять неоткуда.

**Размен, который надо держать в голове:** на `127.0.0.1:1984` может постучаться
любой процесс той же машины, в том числе непривилегированный — под `www-data`
работает nginx, отдающий сайт-маскировку. Раньше от него защищал root-only файл
токена, теперь не защищает ничто. Выключатель `GOTELEGRAM_TRUST_TUNNEL=0`
возвращает прежний порядок целиком.

### Сессия

- живёт **15 минут**;
- затем **60 секунд** на продление кодом — в это окно данные не отдаются;
- не продлили → «сессия закончена», продлили → снова 15 минут;
- вход по токену **тоже заводит сессию**, клиент токен забывает;
- cookie переживает сессию (`+6 ч`) — доступа не даёт, нужна лишь чтобы сервер
  узнал вернувшегося и сказал «сессия закончена», а не «нужен токен».

Сроки: `GOTELEGRAM_SESSION_TTL` / `_GRACE` / `_COOKIE_SLACK`.

### Лимиты на код

| корзина | лимит | когда |
|---|---|---|
| публичная (`net`) | 5/час | запрос из интернета |
| туннельная (по IP) | 30/час | запрос по туннелю |
| продление (`renew`) | 12/час | есть живая или продлеваемая сессия |

Корзины раздельные: долбёжка из интернета не запирает вход администратору.
Плюс общий `TFA_REQUEST_COOLDOWN` 30 с и 5 попыток на один код.

Код уходит **только по нажатию кнопки**, автоматической рассылки нет.

Три слоя, потолок 300 МБ на компонент, из них 150 МБ живых:
`RUST_LOG`-директивы гасят три рутинных типа INFO у `telemt` (было ~227 000

файлов. Компоненты: `journal`, `nginx`, `gotelegram*` в `/var/log`, `atop`.

Предохранитель: `_logb_trim_dir` для `/var/log` с пустой маской возвращает 0 —
иначе бюджет сносил бы чужие `syslog.1` и `auth.log.2`.

## 10. Открытые пункты

1. **SSH-меню не перекроено** под структуру бота (см. §3) — нужно согласие
   владельца, `install.sh` идёт на боевые серверы.
2. **Управления ботом нет в самом боте** — установка, `.env`, остановка есть
   только в SSH.
3. **Причина отключения WARP в 2.10.3 неизвестна.** Виновником считали
   блокировку 8888 у Cloudflare — это опровергнуто. Настоящая причина не найдена.
4. **Повышенный `no live writers` под WARP** (~9/мин против ~2/час) — наблюдается,
   не объяснено.
5. **Сессии только в памяти** — перезапуск службы выкидывает всех. Поведение
   осознанное, но продление кодом теперь смягчает его.
6. **Реальный IP клиента недоступен в Pro-режиме** (§4). Все per-IP механизмы за
   nginx работают по одной общей корзине.
7. **TG2 (203.0.113.40) недоступен** — `telemt` обслуживает клиентов, `nginx`
   и `sshd` принимают TCP и не отвечают. Похоже на забитый диск, нужна консоль
   хостинга.
