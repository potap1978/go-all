# Проверки меню

Две группы: статические гоняются где угодно, живые — на установленном сервере.

Ручной обход по всем подсистемам — [MENU_REVIEW.md](MENU_REVIEW.md): 71 пункт
с пометками, что уже покрыто стендом, а что проверяется только руками.

## Статические — `./tests/run_static.sh`

| файл | что проверяет |
|---|---|
| `check_menu.py` | у каждой кнопки бота есть обработчик, у каждого раздела — возврат |
| `check_i18n_bot.py` | каждый запрошенный ключ есть в обоих словарях бота |
| `check_i18n_ssh.py` | то же для SSH-меню: 477 обращений против `lib/lang/*.sh` |
| `live_walk_ssh.sh` | 21 экран SSH-меню (нужен установленный сервер) |
| `test_bot_features.py`, `test_admin_features.py` | модульные тесты |
| `test_bootstrap.py` | загрузка в `bootstrap.sh` на локальном стенде: застой и повторы, старые файлы целы после сбоя, честные сообщения, токена нет в `ps` и в выводе при ~/.curlrc (~45 с) |

Статические ловят то, чего не видно на работающем сервере: ветку «прокси ещё не
установлен» на настроенной машине не отрисовать никогда, а ключ в ней может
отсутствовать.

## Живые — на сервере с установленным goTelegram

```
GT_BOT_DIR=/opt/gotelegram-bot python3 tests/live_walk_menu.py <telegram-id>
GT_BOT_DIR=/opt/gotelegram-bot python3 tests/live_walk_input.py <telegram-id>
GT_ROOT=/opt/gotelegram        bash   tests/live_walk_ssh.sh
python3 tests/live_validate_telegram.py <bot-token>   # после live_walk_menu.py
```

`live_walk_menu.py` обходит меню бота в ширину настоящими обработчиками: жмёт
каждую кнопку, разбирает отрисованный экран, находит следующие. Мутирующие
действия (рестарт, смена режима, `certbot renew`, удаление ключей) перечислены
в самом файле и не запускаются.

`live_validate_telegram.py` прогоняет собранные экраны через настоящий Telegram,
**не отправляя ни одного сообщения**: Telegram разбирает `parse_mode` и
`reply_markup` раньше, чем ищет чат, поэтому отправка на `chat_id=1` возвращает
либо ошибку разметки, либо `chat not found`. Так ловятся незакрытые теги и
неэкранированные `<`/`&`, которых на стороне бота не видно.

`live_session_life.py` проверяет жизнь сессии панели: вход, работа, истечение
через 15 минут, окно продления в 60 секунд, продление кодом, упущенное окно.
Ждать четверть часа не нужно — сроки берутся из окружения, и стенд поднимает
свой экземпляр с сессией на 6 секунд. Отправка в Telegram подменяется и код
перехватывается: гонять живые сообщения владельцу ради теста незачем.

```
GT_PANEL=/opt/gotelegram-admin/server.py python3 tests/live_session_life.py
```

`live_walk_mutating.py` — **только для тестового стенда**: жмёт пункты, которые
действительно что-то делают (бекап, расписание, перезапуск прокси, смена
анти-DPI профиля, включение и выключение WARP), проверяет последствие в системе
и возвращает исходное состояние. `certbot renew` не трогается и здесь: лимиты
Let's Encrypt общие на домен.

`live_walk_input.py` проверяет ввод текста, команды и Reply-клавиатуру — в том
числе что клавиатура со старыми подписями работает после смены языка. Полный
цикл ключа (создать → лимит → выключить → включить → удалить) прогоняется на
одноразовом `zz_audit_tmp`; ключи владельца не трогаются.
