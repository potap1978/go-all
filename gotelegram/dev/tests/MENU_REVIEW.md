# Тест-ревью меню: обойти все области

Список составлен так, чтобы каждый прогон задевал все подсистемы — ключи,
конфиг, nginx, telemt, файрвол, WARP, бэкапы, панель, словари. Пункты, которые
уже покрыты стендами, отмечены: их можно не кликать руками.

Условные обозначения: **[A]** — покрыто автоматическим стендом,
**[Р]** — только руками, **[!]** — меняет состояние сервера,
**[✗]** — не запускать (объяснено, почему).

---

> Составлено под версию **2.10.24**. Числа в скобках — то, что стенды выдавали
> на момент составления; расхождение само по себе не ошибка, но повод посмотреть.

## 0. Перед началом

```bash
bash tests/run_static.sh                                   # структура и словари
GT_BOT_DIR=/opt/gotelegram-bot python3 tests/live_walk_menu.py <telegram-id>
python3 tests/live_validate_telegram.py <bot-token>         # разметка через Telegram
GT_BOT_DIR=/opt/gotelegram-bot python3 tests/live_walk_input.py <telegram-id>
GT_ROOT=/opt/gotelegram bash tests/live_walk_ssh.sh
GT_PANEL=/opt/gotelegram-admin/server.py python3 tests/live_session_life.py
```

Это закрывает: достижимость всех экранов, наличие обработчиков, полноту
словарей, разметку сообщений, ввод и мусорный ввод, жизнь сессии панели.
Ожидаемо: бот 152 экрана / 0 проблем, Telegram принимает 103 экрана, ввод
44/44, SSH 21/21, сессия 20/20. Дальше — то, что стенды не проверяют.

Снять исходное состояние, чтобы вернуть:

```bash
python3 -c "import json;print(json.load(open('/opt/gotelegram/config.json')))"
systemctl is-active telemt nginx gotelegram-bot gotelegram-admin
```

## Чего эти пункты НЕ покрывают

Честно, чтобы не создавать ложного ощущения полноты:

- поведение при потере сети посреди действия;
- одновременная работа двух администраторов;
- восстановление из бекапа (нужен одноразовый стенд);
- переключение Lite ↔ Pro (перестраивает сервер);
- shared-443 совместно с 3x-ui;
- реальная работа под DPI-блокировкой — проверяется только на живом клиенте.
