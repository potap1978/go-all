Date: 2026-09-05. Base: main `e405672`; development branch: `codex/audit-v2.4.1`.

The lead agent implemented and integrated changes. Meitner independently reviewed account recovery; Ptolemy reviewed networking and lifecycle. Both reviewed the fixes and returned GO for their respective scopes. No credentials or private raw logs are included here.

## Fixed findings

| Trigger | Previous failure | Fixed behavior |
|---|---|---|
| Two administrators or an old client keyboard | Wrong container/client could change | Explicit container and IPv4 callback; idempotent desired state |
| File write/rename failure | False success or inconsistent mode/key | Checked atomic writes and related settings committed together |
| Nonce consumption failure | Confirmation could execute again | No mutation unless the nonce is durably consumed |
| Rule cleanup/application failure | Partial client routing reported success | Checked errors, snapshot recovery, retained unresolved recovery |
| Failed account-file removal | Old live registration mistaken for candidate and revoked | Abort before API; additional candidate identity check |
| Failed rollback | Candidate credentials deleted too early | Retain both identities and protect recovery snapshots |
| HTTP 500 on device deletion | Credentials discarded despite failed deletion | Validate HTTP status and retain pending cleanup credentials |
| Stopped or unavailable sibling | Shared identity/resources could be removed | Include stopped containers; unknown state preserves resources |
| Incomplete uninstall | Manager/recovery state deleted anyway | Abort on discovery/cleanup failure or unresolved recovery |
| Concurrent lifecycle operations | Watcher undid OFF; uninstall overlapped rekey | Container runtime lock and shared host operation lock |
| 3X-UI registration/license restore failure | Paid selection lost or rollback falsely confirmed | Preserve selection; verify restored traffic; retain recovery state |
| Key named free / HTTP 400 / input hint | Callback collision and unclear errors | Namespaced key callback, classified error and corrected format hint |

### External limitation observed

Cloudflare returned HTTP 400 Bad Request while binding new devices to the saved Plus key. An isolated fresh registration reproduced it. The precise cause is unknown; this is not proof of a general Cloudflare outage.

The bot correctly reported failure. All old identity hashes remained unchanged and all three clients continued returning `warp=plus`. New test registrations were deleted with confirmed HTTP 204. A successful fresh Plus rekey was therefore not verified in this run; successful commit is covered by isolated tests. Existing tunnels were not switched to Free because rebinding Plus currently fails.
