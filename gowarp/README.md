# WARP Manager v2.5.2

Cloudflare WARP и WARP+ для **3X-UI** и **AmneziaWG** на Linux VPS.

Канал: [YouTube @antenkaru](https://www.youtube.com/@antenkaru).

## Главное меню

После запуска `gowarp` сразу открывается меню. Состояние подсистем находится в шапке; реклама и справка доступны отдельно. Навигация: главное меню → один экран настроек → действие.

| Пункт | Действие |
|---|---|
| 1 | Установить / переустановить WARP |
| 2 | Включить / выключить WARP |
| 3 | Сменить WARP IP — перевыпуск регистрации |
| 4 | WARP+ ключ |
| 5 | Клиенты AmneziaWG через WARP |
| 6 | Настройка 3X-UI: JSON, инструкция, порт |
| 7 | Telegram-бот |
| 8 | Статус и диагностика |
| 9 | Инфо и промо |
| 10 | Полное удаление |
| 0 | Выход |

Пункты 5 и 6 показываются для соответствующих подсистем. Номера остальных пунктов сохраняются. В режиме «оба» включение/выключение применяется к обеим подсистемам и всем установленным AWG-контейнерам.

## WARP+ за одно действие

`gowarp` → **4** → **Включить WARP+** → вставить ключ или выбрать сохранённый → выбрать подсистему → применить.

Имя нового ключа создаётся автоматически. Больше не нужно отдельно сохранять ключ, назначать его активным, менять режим и запускать перевыпуск. В Telegram на экране ключей доступны кнопки применения к 3X-UI или AWG, перехода на Free, добавления и удаления.

Ключ берётся из приложения **1.1.1.1**: настройки аккаунта → License Key. Наличие ключа само по себе не доказывает наличие платной подписки. Проверяйте подписку в приложении. Поддерживаются форматы `XXXXXXXX-XXXXXXXX-XXXXXXXX` и `XXXX-XXXX-XXXX-XXXX`.

| Результат | Что означает |
|---|---|
| Ключ принят | Cloudflare принял запрос привязки устройства |
| Тип аккаунта Free | Cloudflare сейчас сообщает бесплатный тип; проверьте подписку в приложении |
| Limited / Unlimited | Cloudflare сообщает платный тип аккаунта; прохождение трафика проверяется отдельно |
| `warp=plus` | Запрос через конкретный туннель прошёл через WARP+ |
| `warp=on` | Запрос прошёл через бесплатный WARP |
| `warp=off` | Этот запрос прошёл без WARP |
| Нет ответа | Проверка не завершилась; это не подтверждение Free или WARP+ |
| Ошибка 1056 | Достигнут лимит устройств; освободите место в аккаунте и повторите |

Один ключ подписки может использоваться несколькими устройствами в пределах лимита Cloudflare. Каждый AWG-контейнер, клиент 3X-UI и телефон занимают отдельное устройство. **WireGuard-идентичность устройства не должна копироваться между одновременно работающими контейнерами.**

## Как проходит трафик

**3X-UI:** клиент → Xray → SOCKS5 `127.0.0.1:40000` → WARP → интернет.

Прокси предназначен для TCP. Какие сайты идут через него, определяют правила Xray. Основной маршрут VPS сохраняется. WARP не гарантирует доступ к конкретному сервису или конкретный регион IP.

**AmneziaWG:** клиент → входящий VPN → интерфейс `warp` внутри контейнера → Cloudflare → интернет.

В пункте 5 выбираются клиенты: ✅ через WARP, ☐ напрямую. В CLI изменения применяются кнопкой `ok`; `0` отменяет их. Правила применяются на работающем контейнере, без его перезапуска. Для пересылаемых TCP-пакетов устанавливается MSS clamp, MTU WARP — 1280. Исходящий туннель и endpoint используют IPv4.

Для WARP используются стандартные WireGuard-инструменты: менеджер ставит их в `/opt/warp-tools` каждого контейнера, поэтому интерфейс `warp` создаёт модуль ядра `wireguard`, а не `amneziawg`. Входящий AmneziaWG продолжает использовать свои бинарники и настройки.

## Установка и обновление

Требуется root, Bash ≥4, Debian/Ubuntu и доступ к Cloudflare. Для 3X-UI используется официальный клиент Cloudflare; для AmneziaWG — запущенные Docker-контейнеры `amnezia-awg`, `amnezia-awg2` и т. п. Для WARP в каждый AWG-контейнер ставятся стандартные `wg` и `wg-quick` из пакетов Alpine; если основной репозиторий недоступен, пакеты берутся с зеркал, подпись проверяется.

[подписка и доступ](https://boosty.to/potap1978/purchase/3134076?ssource=DIRECT&share=subscription_link).

Скачивайте скрипт **в файл**, затем запускайте. Не используйте `bash <(curl …)` для обновления установленной команды. После установки:

```bash
gowarp
```

Старая конфигурация автоматически мигрирует с резервной копией. Сохраняются порт, настройки бота, ключи и выбор клиентов. Если старый ключ по ошибке использовался как его название, название заменяется безопасной меткой. Установленная команда заменяется атомарно. Работающий Telegram-бот перезапускается на новой версии; выключенный бот не запускается.

Для AmneziaWG используется wgcf 2.2.31, сборка сверяется по SHA-256. Если на сервере лежит другая сборка, она заменяется при первом запуске новой версии и перед каждым перевыпуском. Причина: сборки 2.2.30 и 2.2.32 Cloudflare сейчас отбивает на регистрации ошибкой 429.

При установке/перевыпуске AWG новая регистрация готовится до отключения существующего туннеля. Результат проверяется запросом через WARP. При отказе новый профиль откатывается; прежнее устройство не удаляется до подтверждения трафика. Результаты считаются отдельно для каждого контейнера, частичный успех сопровождается ошибкой и пояснением. При нехватке свободного слота менеджер не удаляет рабочее устройство для освобождения места.

Cloudflare выдаёт новое устройство wgcf с одного IP не чаще раза в минуту, на частые регистрации отвечает 429. Если контейнеров несколько, перевыпуск идёт по очереди: перед следующей регистрацией goWARP ждёт около минуты и повторяет попытку после 429. Три контейнера перевыпускаются примерно за три минуты.

Перевыпуск может поменять IP, но выдачу конкретного или обязательно нового адреса определяет Cloudflare. Для подключения WARP+ в 3X-UI ключ применяется к существующей регистрации.

## Настройка 3X-UI

1. В `gowarp` откройте пункт **6** и получите JSON с актуальным SOCKS5-портом.
2. В настройках Xray добавьте outbound с тегом `warp`, протоколом SOCKS, адресом `127.0.0.1` и вашим портом.
3. Добавьте правила routing, направляющие выбранные домены в outbound `warp`.
4. Сохраните настройки и перезапустите Xray через панель.

Пример outbound с портом по умолчанию:

```json
{
  "tag": "warp",
  "protocol": "socks",
  "settings": {
    "servers": [{"address": "127.0.0.1", "port": 40000}]
  }
}
```

Если Xray работает в другом контейнере, `127.0.0.1` относится к этому контейнеру: нужна отдельная настройка сетевой доступности SOCKS5.

## Проверка

Общая диагностика — пункт **8**. Проверка WARP+ — пункт **4** → «Проверить».

3X-UI, порт по умолчанию:

```bash
curl -sS --max-time 20 --proxy socks5h://127.0.0.1:40000 \
  https://1.1.1.1/cdn-cgi/trace
```

AmneziaWG2:

```bash
docker exec amnezia-awg2 curl -sS4 --max-time 20 --interface warp \
  https://1.1.1.1/cdn-cgi/trace
```

Ожидается `warp=plus` для WARP+ или `warp=on` для Free. Дополнительно проверяйте с подключённого VPN-клиента: локальная самопроверка контейнера не заменяет проверку клиентского маршрута.

При больших задержках сначала сравните прямой выход VPS и конкретный WARP-путь. Наличие handshake само по себе не означает исправную передачу данных. Проверенный локальный UDP-порт (`ListenPort`) и endpoint сохраняются при перевыпуске, чтобы не менять рабочий сетевой путь без необходимости.

## Автопроверка и самолечение

С версии 2.5 служба `gowarp-health` проверяет WARP каждые 10 секунд и сама поднимает упавший туннель.

| Проверка | Как часто | Что делает при сбое |
|---|---|---|
| 3X-UI: статус warp-cli | 10 с | переподключение, затем разрыв и новое подключение, затем перезапуск warp-svc |
| 3X-UI: регистрация пропала | 10 с | новая регистрация |
| 3X-UI: трафик через SOCKS5 | 60 с, после провала 10 с | после трёх провалов подряд лечение по тем же ступеням |
| AmneziaWG: интерфейс warp | 10 с | подъём туннеля |
| AmneziaWG: handshake старше 180 с | 10 с | перезапуск туннеля, затем смена порта Cloudflare: 2408, 500, 1701, 4500 |
| AmneziaWG: трафик через туннель | 60 с, после провала 10 с | перезапуск, только если по туннелю перестали приходить байты |
| AmneziaWG: правила клиентов | 10 с | повторное применение без перезапуска туннеля; сверяются адреса выбранных клиентов, а не только число правил |
| AmneziaWG: блок автозапуска в `start.sh` | 10 с | вставляется заново, если его нет или он от версии до 2.5.2; при неудаче повтор через час |
| AmneziaWG: тип интерфейса WARP | 10 с | интерфейс `amneziawg` или userspace `tun` пересобирается на стандартном `wireguard`; нет стандартных инструментов — скачать их, при неудаче повтор через час, дальше до суток; ядро без `wireguard` (LXC, OpenVZ) — туннель не трогается |
| AmneziaWG: задержка через WARP | вместе с проверкой трафика | больше 1 с три проверки подряд — предупреждение в журнале и шапке меню |

Ручное выключение пунктом 2 или кнопкой бота служба не перебивает. Пока идёт установка, перевыпуск или удаление, служба ничего не чинит. Короткие сбои она пропускает: статус warp-cli считается сбоем, если держится 20 секунд, а пропавшая регистрация только через минуту, потому что новая регистрация меняет устройство. После неудачной попытки пауза растёт от 10 секунд до 30 минут. Сразу после запуска контейнера проверка 30 секунд не вмешивается: туннель поднимают `start.sh` и сторож контейнеров. Действия пишутся в `/var/log/warp-manager.log` с пометкой `HEALTH`, итог виден в шапке меню.

Выбранный ключ WARP+ и режим служба никогда не меняет. Если выбран WARP+, а трафик 3X-UI три проверки подряд идёт как Free, служба применяет ключ ещё раз. Если не помогло, она ждёт 1 час и дальше удваивает паузу до 24 часов. Существующую регистрацию служба заменяет новой, только когда доступен API Cloudflare; иначе перезапускает warp-svc.

Состояние службы: `systemctl status gowarp-health`. Один проход вручную: `gowarp --healthcheck`.

## Файлы и восстановление

| Путь | Назначение |
|---|---|
| `/etc/warp-manager/config` | Настройки менеджера |
| `/etc/warp-manager/keys.list` | Ключи; доступ только root |
| `/root/wgcf-containers/<container>/` | Отдельные аккаунт и профиль wgcf |
| `/opt/warp/warp.conf` внутри контейнера | Рабочий WARP-профиль |
| `/opt/warp/clients.list` внутри контейнера | Выбранные клиенты: публичные ключи, по одному в строке |
| `/opt/warp/disabled` внутри контейнера | Сохранённое выключенное состояние |
| `/var/log/warp-manager.log` | Журнал действий |
| `/usr/local/bin/gowarp-awg-watch` | Восстановление после запуска контейнера |
| `/var/lib/warp-manager/rekey-bak/<container>/` | Копия регистрации и снимок контейнера на время перевыпуска и смены клиентов |

Блок автозапуска заменяется атомарно после проверки синтаксиса; при ошибке записи прежний файл сохраняется. Выключение WARP сохраняется после перезапуска контейнера. Повторное включение восстанавливает сохранённый выбор клиентов. Удаление менеджера доступно только отдельным пунктом 10 с подтверждением.

## Исправления 2.5.2

Совместимость с goAmnezia pro 1.0.4. Она пересоздаёт контейнеры профилей при починке, переносе порта и смене подсети и переносит в новый контейнер файлы goWARP.

- Выбор клиентов WARP хранится по публичным ключам, а не по адресам. Адреса блок автозапуска берёт из конфига сервера при каждом старте контейнера, поэтому выбор переживает смену подсети и перенумерацию клиентов. При обновлении прежний список адресов переводится в ключи.
- Снимок на время перевыпуска и смены клиентов лежит на хосте в `/var/lib/warp-manager/rekey-bak/<container>/container/`, а не в `/tmp` контейнера, и не пропадает при пересоздании. Снимок прежних версий переносится из контейнера на хост.
- Автопроверка пересобирает на стандартном `wireguard` не только интерфейс `amneziawg`, но и userspace-интерфейс `tun`. Он появляется, когда WARP поднимается без стандартных инструментов.
- Полное удаление доходит до конца, даже если контейнеров `amnezia-awg*` больше нет. goWARP снимает бота, службы, сторожа и wgcf, а устройства WARP удалённых контейнеров удаляет в Cloudflare. Если не отвечает Docker, удаление останавливается и ничего не трогает.
- При удалении из `start.sh` вырезается только блок goWARP, поздние правки Amnezia и goAmnezia остаются. Копия `start.sh.final-backup` больше не создаётся, а оставшаяся от прежних версий удаляется без восстановления.
- После удаления в контейнерах не остаётся `/opt/warp-tools`.
- Автопроверка возвращает блок goWARP в `start.sh`, если файл переписали снаружи. Так делает «Поднять заново» в goAmnezia 1.0.4: оно пишет в работающий контейнер свою копию `start.sh`, снятую до установки goWARP. Без блока WARP после перезапуска контейнера поднимался без правил клиентов, пока их не возвращала автопроверка.
- Обновление при отсутствии контейнеров AmneziaWG больше не считается сбоем и не повторяется при каждом запуске. Если контейнеры есть, но были остановлены, их блок и выбор клиентов обновит автопроверка после запуска.
- Автопроверка сверяет адреса в правилах клиентов с выбором. goAmnezia отдаёт новому человеку адрес удалённого без перезапуска контейнера, и раньше он мог уйти через WARP по старому правилу.
- На ядре без модуля `wireguard` (LXC, OpenVZ, старые ядра) WARP остаётся на `tun`: пересборка там невозможна, и туннель зря не дёргается.

## Исправления 2.5.1

WARP в контейнерах AmneziaWG всегда поднимается стандартными инструментами WireGuard на модуле ядра `wireguard`. Версия 2.3 поднимала его инструментами Amnezia. На хосте с модулем ядра `amneziawg` 1.0 такой интерфейс отвечал с задержкой до нескольких секунд, а 2.5.0 не могла его заменить: перевыпуск срывался вместе с откатом.

При обновлении goWARP:

- пересобирает WARP-интерфейсы `amneziawg` на `wireguard` с тем же ключом, перерыв несколько секунд;
- выдаёт отдельное устройство WARP контейнерам, которые делили один ключ от 2.3;
- доводит до конца откат перевыпуска, сорванный в 2.5.0: возвращает прежний WARP и снимает блокировку.

Если стандартные инструменты скачать не удалось ни из репозитория, ни с зеркал, WARP поднимается инструментами контейнера, а автопроверка повторяет попытку раз в час.

## Исправления 2.4.1

Кнопки клиентов Telegram привязаны к контейнеру и IPv4-адресу (с 2.5.2 — к ключу клиента). Повторное нажатие задаёт тот же выбор. Ошибки записи, маршрутизации и сохранения подтверждения возвращают ошибку; при доступном откате восстанавливаются прежние настройки. Запуск, остановка и watcher используют общую блокировку, обновление заменяет блоки автозапуска без перевыпуска регистраций.

Незавершённый откат сохраняет обе регистрации и резервные копии; повторный перевыпуск и удаление блокируются до восстановления. Сохраняйте файлы `recovery-required` в `/var/lib/warp-manager/rekey-bak/`, каталоги `.candidate.*` в `/root/wgcf-containers/` и `/etc/warp-manager/3xui-recovery` до проверки восстановленного соединения.

Если Cloudflare не подтвердил удаление устройства, данные для повтора остаются с правами root в `/var/lib/warp-manager/pending-retirements/`. Автоматического повтора пока нет: перед удалением необходимо проверить, что регистрацию не использует ни один контейнер, включая остановленные.
